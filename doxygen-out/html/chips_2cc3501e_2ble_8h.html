Detailed Description

CC3501E BLE host helpers (enable/scan + control, opcodes 0x30..0x3B) and the portable BLE backend attach.

Thin wrappers over the firmware BLE handlers. WIRE GAP: the protocol header carries the BLE opcodes + alp_cc3501e_ble_adv_start_t + alp_cc3501e_ble_gatt_register_hdr_t/_reply_hdr_t (GATT_REGISTER, 0x38 – documented field-by-field, not a directly-castable struct), but has NO payload struct for CONNECT (0x36) or the other three GATT ops (0x39..0x3B); those wire layouts are defined only by the firmware handlers (firmware/cc3501e/src/protocol.c handle_ble_*) and are documented per-function + in cc3501e.c. GATT async notifications (EVT_BLE_GATT_WRITE_REQ, 0x3F) need the async-event path (not wired on this HW rev); these wrappers issue the outbound commands only.

#define CC3501E_BLE_NAME_MAX   31u

One parsed BLE scan (advertising-report) record handed to the caller.

Mirrors the on-wire BLE scan record (addr[6] | addr_type | rssi(int8) | name_len | name[name_len]) with the inline device name copied out into a NUL-terminated buffer. Names longer than CC3501E_BLE_NAME_MAX are truncated. A device that advertises no name leaves name empty.

Enable the CC3501E BLE controller + NimBLE host (BLE_ENABLE, 0x30).

The firmware worker-routes BLE_ENABLE off the SPI ISR: it brings the Wi-Fi stack up first (shared HIF), then runs nimble_host_start (~2 s). Like cc3501e_wifi_get_mac, the host re-issues until the radio op completes; the bridge is briefly down during the op, so timeout_ms is floored internally to cover the bring-up window. No reply payload – success is the OK status.

Parameters
ctxInitialised bridge handle.
timeout_msCaller budget (floored to the radio-down window).
Returns
ALP_OK once the BLE host is up; ALP_ERR_NOT_READY if BLE is not built in the firmware; otherwise the mapped error.

Register a GATT attribute table with the firmware (BLE_GATT_REGISTER, 0x38).

The firmware handle_ble_gatt_register takes the payload as an OPAQUE attribute-table descriptor (>= 1 byte) laid out per the wire-format doc block in <alp/protocol/cc3501e.h>: the host ships the descriptor bytes verbatim and the firmware parses them. On success, parses the reply (status | num_handles | attr_handle(LE16)*num_handles) and copies up to handles_cap handles into handles_out in declaration order.

Note
Service registration must complete BEFORE advertising starts. The firmware's cc3501e_nimble_gatt_register re-runs NimBLE's ble_gatts_start() (via ble_gatts_reset(), see firmware/cc3501e/hal/ti/cc3501e_nimble_host.c), and NimBLE's own ble_gatts_mutable() constraint refuses that while advertising, scanning, or connected – register the service, THEN call cc3501e_ble_adv_start.
Parameters
ctxInitialised bridge handle (BLE must be enabled).
descriptorOpaque attribute-table descriptor bytes (non-NULL).
lenDescriptor length (1..ALP_CC3501E_MAX_PAYLOAD).
handles_outReceives up to handles_cap attribute handles, in declaration order (may be NULL only if handles_cap is 0).
handles_capCapacity of handles_out.
num_handles_outReceives the number of characteristics the firmware registered (may be NULL).
timeout_msCaller budget.
Returns
ALP_OK once registered; ALP_ERR_INVAL on a NULL/empty/oversized descriptor; ALP_ERR_BUSY if the firmware's NimBLE lifecycle guard refused the register (advertising/scanning/connected – see the
Note
above) – returned promptly, NOT after exhausting timeout_ms (the guard's answer is deterministic, so it is not retried); a real transport fault still surfaces as its own ALP_ERR_IO / ALP_ERR_TIMEOUT; otherwise the mapped error.

Run a BLE scan and collect discovered advertisers (BLE_SCAN_START, 0x34).

Requires the BLE controller + NimBLE host to be up (call cc3501e_ble_enable first). Worker-routed in the firmware: a NimBLE ble_gap_disc runs for a fixed window (a few seconds), de-duplicating by advertiser address, then the collected reports are returned as the SCAN_START reply payload (a sequence of BLE scan records, no envelope). Poll-by-repeat absorbs the bridge-down window while the radio scans, identical to cc3501e_wifi_scan.

Parameters
ctxInitialised bridge handle.
out_recordsCaller array of cap cc3501e_ble_scan_record_t.
capCapacity of out_records.
countReceives the number of records parsed (may be NULL).
timeout_msUpper bound on the poll-by-repeat budget (floored to the firmware scan window so a slow scan is not misread as IO).
Returns
ALP_OK once the scan completed (even with zero records); ALP_ERR_BUSY if a scan is already decoding on this SAME ctx (issue #740) – a plain, non-atomic same-call-stack reentrancy guard (see cc3501e_poll_events's concurrency warning; a caller polling one ctx from multiple threads must serialize its own calls). A different ctx has entirely separate storage and may always scan concurrently; ALP_ERR_NOT_READY if BLE is not enabled / not built; mapped error otherwise.
