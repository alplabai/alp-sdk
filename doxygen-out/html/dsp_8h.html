Detailed Description

Alp SDK digital-signal-processing chain abstraction.

Composable filter / window / FFT chains run against in-RAM sample buffers (standalone API) or, in a later release, inline with an alp_adc_stream_* source on SoMs whose backend can offload to a hardware DSP block (the V2N supervisor's GD32G5 FFT / FAC units).

This header declares the standalone surface: build a chain with alp_dsp_chain_open against a list of alp_dsp_stage_t descriptors, then feed sample buffers through with alp_dsp_chain_apply_samples (filter-terminated chain) or alp_dsp_chain_apply_bins (FFT-terminated chain). The bridge-wired counterpart (alp_adc_filter_t / alp_adc_spectrum_t) sits in <alp/adc.h> and lands in v0.5.x.

Backends:

  • CMSIS-DSP when ALP_HAS_CMSIS_DSP=1 (preferred — arm_fir_*, arm_biquad_cascade_df1_*, arm_rfft_fast_f32).
  • Portable C fallback otherwise (naive convolution + radix-2 Cooley-Tukey). Documented as O(N*M) / O(N^2) — fine for unit tests and small (~< 256-point) chains; not suitable for the hot path. Applications that want spectral or filtered ADC data at line rate should target a SoM with a HW backend (V2N family today; AEN once the wave-2 bridge ships).

Chain validation rules (enforced at alp_dsp_chain_open):

  • 1..ALP_DSP_MAX_STAGES stages.
  • At most ONE ALP_DSP_STAGE_FFT, and if present it MUST be the terminal stage.
  • A ALP_DSP_STAGE_WINDOW (if present) MUST immediately precede ALP_DSP_STAGE_FFT. Window without a terminating FFT is rejected – it has no defined audible meaning in the filtered-samples path.
  • Per-stage param ranges (n_taps / n_sections / n_points) are bounded – see the ALP_DSP_MAX_* macros.

Typical usage (filter-terminated):

static const float fir_taps[8] = { ... };
alp_dsp_stage_t stages[] = {
{ .kind = ALP_DSP_STAGE_FIR,
.u.fir = { .coeff_format = ALP_DSP_COEFF_FORMAT_F32,
.n_taps = 8, .taps = fir_taps } },
};
alp_dsp_chain_t *c = alp_dsp_chain_open(stages, 1u);
size_t got = 0;
int16_t out[256];
alp_dsp_chain_apply_samples(c, in, 256u, out, 256u, &got);
alp_dsp_chain_close(c);

Design one second-order biquad section (RBJ cookbook).

Computes the five normalised coefficients for a single ALP_DSP_STAGE_IIR section from a centre/cutoff frequency and Q, so callers do not hand-derive filter math. A 2nd-order Butterworth low-pass, for example, is ALP_DSP_BIQUAD_LOWPASS with q = 0.70710678 (1/sqrt(2)).

Parameters
[in]kindResponse type (alp_dsp_biquad_kind_t).
[in]f0_hzCutoff (LP/HP) or centre (BP/notch) frequency; must satisfy 0 < f0_hz < fs_hz/2.
[in]fs_hzSample rate in Hz; must be > 0.
[in]qQuality factor; must be > 0 (Butterworth LP/HP uses 1/sqrt(2); higher Q = narrower/peakier).
[out]coeffs_outReceives { b0, b1, b2, a1, a2 } normalised (a0 = 1), ready to pass as an IIR stage's coeffs with n_sections = 1 and ALP_DSP_COEFF_FORMAT_F32.
Returns
ALP_OK, or ALP_ERR_INVAL on a NULL pointer, a bad kind, or a frequency/Q outside the valid ranges above.

Apply an FFT-terminated chain to an in-RAM sample buffer.

Valid only when the chain ends with an FFT stage. Pre-FFT stages (FIR / IIR / WINDOW) run sequentially against the running sample buffer; the FFT consumes exactly n_points samples from the window output and emits bins per the configured output_format.

Output element count:

  • ALP_DSP_FFT_OUTPUT_COMPLEX – 2 * n_points (interleaved re/im pairs).
  • ALP_DSP_FFT_OUTPUT_MAGNITUDE – n_points (full two-sided per-bin magnitudes).
  • ALP_DSP_FFT_OUTPUT_MAGNITUDE_ONESIDED – n_points/2 + 1 (positive-frequency half; the natural real-FFT output).
Streaming semantics: pre-FFT FIR / IIR stages carry their filter
state ACROSS calls (a sliding filter), while the FFT itself consumes exactly n_points samples from in each call. Feeding successive (optionally overlapping) windows therefore yields an STFT-style stream; alp_dsp_chain_close resets all filter state.
Parameters
[in]chainHandle from alp_dsp_chain_open.
[in]in_mvInput samples (mV, int16_t). Must provide at least n_points samples (extra are silently truncated; n_points is the FFT size from the terminal stage).
[in]in_nInput sample count.
[out]out_binsOutput buffer (float).
[in]out_capCapacity of out_bins (elements, not bytes). Must be >= the output element count above.
[out]gotReceives the number of output elements written.
Returns
ALP_OK / ALP_ERR_INVAL / ALP_ERR_NOSUPPORT (chain does not end with FFT) / ALP_ERR_OUT_OF_RANGE (in_n < n_points or out_cap < required).

Validate and open a DSP chain.

The implementation copies the stage params (including coefficient arrays) into the chain so the caller's source memory can be freed immediately on return.

Parameters
[in]stagesArray of n_stages descriptors. Must be non-NULL when n_stages > 0.
[in]n_stagesStage count, 1..ALP_DSP_MAX_STAGES.
Returns
Open handle on success, or NULL with alp_last_error set to one of:
  • ALP_ERR_INVAL on NULL pointer, zero stage count, bad enum value, or chain ordering violation (FFT not terminal, WINDOW not preceding FFT, etc).
  • ALP_ERR_OUT_OF_RANGE on per-stage bound violation (n_taps / n_sections / n_points outside the ALP_DSP_MAX_* / ALP_DSP_MIN_FFT_POINTS limits, or n_points not a power-of-two).
  • ALP_ERR_NOMEM when the static chain pool is exhausted (compile-time pool size).

Compute summary statistics over a real float buffer in one call.

Fills out with the mean, RMS, population variance, min/max, and the peak magnitude (+ its index) of x. This is the portable scalar-stats counterpart to the FFT chain: the backend runs CMSIS-DSP arm_mean_f32 / arm_rms_f32 / arm_min_f32 / arm_max_f32 / arm_absmax_f32 on Cortex-M (when the cmsis-dsp module is linked) and a single portable-C pass otherwise, so application code never calls arm_* directly and the same source builds on every target.

Parameters
[in]xSample buffer; must be non-NULL and hold n floats.
[in]nSample count; must be > 0.
[out]outDestination stats struct; must be non-NULL.
Returns
ALP_OK on success, or ALP_ERR_INVAL when x or out is NULL or n is 0 (in which case out is left untouched).
Note
alp_dsp_stats_t::variance is the POPULATION variance (divides by n), not the sample variance (n - 1) that CMSIS-DSP's arm_var_f32 returns – the value is the same on both the CMSIS and portable paths.
