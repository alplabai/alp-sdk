Detailed Description

CC3501E TCP/UDP socket host helpers (opcodes 0x20..0x24).

A minimal BSD-style socket API offloaded to the CC3501E's IP stack: the host opens a handle, connects it, sends + receives bytes, then closes it. Each call is one worker-routed firmware op (the socket bodies block on the lwIP core thread), so every wrapper is a poll-by-repeat over the bridge like the Wi-Fi getters. v1 is IPv4-only; addresses are 4 octets in network (big-endian) order.

Connect a socket to a peer (SOCK_CONNECT, opcode 0x21).

For STREAM sockets this runs the TCP handshake to ip : port; for DGRAM sockets it sets the default peer for later cc3501e_sock_send calls. The firmware body blocks on the handshake, so this is a worker-routed poll-by-repeat until it resolves.

Parameters
ctxInitialised driver context.
handleSocket handle from cc3501e_sock_open.
ipDestination IPv4 address, 4 octets in network order (ip[0] is the most significant octet, a.b.c.d).
portDestination TCP/UDP port, host byte order (the firmware converts to network order on the wire).
timeout_msUpper bound on the connect poll budget.
Returns
ALP_OK once connected; ALP_ERR_NOT_READY on the stub build; mapped error (e.g. ALP_ERR_IO on a refused/timed-out handshake) otherwise.

Open a socket on the CC3501E IP stack (SOCK_OPEN, opcode 0x20).

Allocates a socket in the firmware IP stack and returns its handle. The handle is opaque and non-zero (0 is the invalid handle); pass it to every later socket call for this socket. Worker-routed poll-by-repeat: re-issued while the firmware reports RESP_ERR_BUSY until the socket is allocated.

Parameters
ctxInitialised driver context.
familyAddress family (ALP_CC3501E_SOCK_FAMILY_IPV4; IPv6 reserved in v1).
typeALP_CC3501E_SOCK_TYPE_STREAM (TCP) or ALP_CC3501E_SOCK_TYPE_DGRAM (UDP).
protocolIP protocol number, or 0 for the type's default (TCP for STREAM, UDP for DGRAM).
handle_outReceives the socket handle on success (must not be NULL).
timeout_msUpper bound on the poll-by-repeat budget.
Returns
ALP_OK with handle_out set; ALP_ERR_NOT_READY if the firmware IP stack is unavailable (stub / no-Wi-Fi build); mapped error otherwise.

Receive bytes from a socket (SOCK_RECV, opcode 0x23).

Requests up to cap bytes from the socket's receive queue into buf. A zero-length result (recv_len_out set to 0 with ALP_OK) means no data was available within the firmware's receive window, or the peer closed the connection – the caller polls again to distinguish (or stops on a subsequent zero after a close). Worker-routed poll-by-repeat over the bridge.

Parameters
ctxInitialised driver context.
handleSocket handle from cc3501e_sock_open.
bufDestination buffer for received bytes.
capCapacity of buf (also bounds the firmware request).
recv_len_outReceives the number of bytes written to buf (may be NULL).
timeout_msUpper bound on the receive poll budget.
Returns
ALP_OK with recv_len_out set (possibly 0); ALP_ERR_NOT_READY on the stub build; mapped error otherwise.

Send bytes on a socket (SOCK_SEND, opcode 0x22).

Queues len bytes on the socket and reports how many the stack accepted in sent_out. len is bounded by one frame (<= ALP_CC3501E_MAX_PAYLOAD - 8, the send-header size); larger buffers must be split by the caller. Worker-routed poll-by-repeat.

Parameters

handleSocket handle from cc3501e_sock_open.
dataPayload bytes to send.
lenNumber of bytes in data.
sent_outReceives the accepted byte count (may be NULL).
timeout_msUpper bound on the send poll budget.
Returns
ALP_OK once queued; ALP_ERR_INVAL if len exceeds one frame; ALP_ERR_NOT_READY on the stub build; mapped error otherwise.
