Detailed Description

CC3501E meta + diagnostics host helpers (backend-independent).

Thin wrappers over cc3501e_request for the meta (0x00/0x02/0x04) and diagnostics (0x70/0x71) opcodes. The firmware answers these from in-RAM bookkeeping (no radio op), so they use a short request budget and never poll-by-repeat.

Read extended firmware diagnostics (GET_DIAG_INFO, opcode 0x04).

Decodes the 16-byte alp_cc3501e_diag_info_t reply field-by-field: the firmware release fw_version (distinct from the protocol version that cc3501e_get_version returns), the reset_cause (alp_cc3501e_reset_cause_t), the active role (alp_cc3501e_role_t), uptime_ms, free_heap_bytes, and the last_error the firmware last emitted (alp_cc3501e_resp_t). Non-disturbing: no side effects on radio state. v2-firmware-only – v1 firmware rejects with RESP_ERR_INVALID.

Parameters
ctxInitialised driver context.
outReceives the decoded diagnostics snapshot on success.
Returns
ALP_OK with out filled; ALP_ERR_INVAL on a NULL out; ALP_ERR_IO on a short reply; otherwise the mapped error.

Read the firmware frame counters (DIAG_GET_STATS, opcode 0x70).

The reply data is two little-endian 32-bit counters: frames the firmware answered OK, and frames it answered with a non-OK status. The protocol header defines the opcode but NO reply struct for these, so they come back through out-params rather than a typedef.

Parameters
ctxInitialised driver context.
frames_okReceives the count of OK-answered frames.
frames_errReceives the count of error-answered frames.
Returns
ALP_OK with both counters filled; ALP_ERR_INVAL if either out-param is NULL; ALP_ERR_IO on a short reply; otherwise the mapped error.

Liveness probe: PING the CC3501E firmware (PING, opcode 0x00).

Sends a header-only PING and treats the firmware's OK status as proof the link + firmware are alive. Cheaper + more direct than cc3501e_get_version (which round-trips the protocol version); use this when only "is it alive?" matters.

Parameters
ctxInitialised driver context.
Returns
ALP_OK on a successful round-trip; ALP_ERR_IO on a desync / no reply; ALP_ERR_NOT_READY if ctx is not initialised.

alp_status_t cc3501e_soft_reset ( cc3501e_t *  ctx)

Request an in-band firmware soft reset (RESET, opcode 0x02).

The firmware ACKs the command and then performs a DEFERRED reboot (it drains the reply first). Unlike cc3501e_reset / cc3501e_hard_reset – which pulse the WIFI_EN / nRESET GPIO lines – this needs no host pins; it is a firmware-side reboot over the wire. The bridge link drops after the ack, so re-establish it with cc3501e_sync (and confirm with cc3501e_ping) once the firmware is back up.

Parameters
ctxInitialised driver context.
Returns
ALP_OK once the reset is acked (reboot follows); otherwise the mapped error.
