Detailed Description

Alp SDK analog-to-digital converter abstraction.

One-shot ADC reads against studio-resolved channel indices, plus DMA-backed continuous-acquisition streaming on SoMs whose backend supports it. The channel-config side (resolution, gain, reference, acquisition time) lives in devicetree on the Zephyr backend; this header only exposes the runtime knobs apps actually tune.

The DAC surface moved to its own dac.h header.

Backends:

  • Zephyr : adc_* driver class. On the V2N family (V2N + V2N-M1, both of which carry the GD32G553 supervisor MCU) the SDK routes through the GD32 IO MCU bridge (per the 2026-05-12 hardware decision — see metadata/e1m_modules/v2n/gd32-io-mcu-map.tsv).
  • Yocto : Industrial I/O sysfs (/sys/bus/iio/devices/).
  • Baremetal: vendor HAL ADC sequencer.

Typical usage (one-shot):

alp_adc_t *th = alp_adc_open(&(alp_adc_config_t){
.channel_id = ALP_E1M_ADC0, // E1M; use ALP_E1M_X_ADC0 on E1M-X
.resolution_bits = 12,
.reference = ALP_ADC_REF_INTERNAL,
});
int32_t uv = 0;
alp_adc_read_uv(th, &uv); // 0..3300000 µV typical

Units

The one-shot and streaming surfaces intentionally use different units and sample widths. The one-shot path favours precision (32-bit microvolts resolve any supported 8-16 bit code against a 3.3 V reference without rounding, ~50 uV/LSB at 16 bits); the streaming path favours wire and ring-buffer density (16-bit millivolts halve the DMA/bridge bandwidth per sample, and mV granularity is what the 12-bit hardware actually delivers at streaming rates). The sample widths are wire formats and will not change; every function name carries its unit as a suffix so the split is visible at the call site:

  • alp_adc_read_raw — int32_t, native ADC code (no unit).
  • alp_adc_read_uv — int32_t, signed microvolts (µV).
  • alp_adc_stream_read_mv — uint16_t samples, unsigned millivolts (mV).
  • alp_adc_filter_read_mv — int16_t samples, signed millivolts (mV) (DSP chains need signed headroom).
  • alp_adc_spectrum_read_bins — float FFT bins (input scale mV, so bin magnitudes are in mV·sample).

Conversion: 1 mV = 1000 µV — a stream sample s sits at s*1000 on the alp_adc_read_uv scale (modulo the quantisation the 16-bit mV format implies).

v0.2 + v0.5 additive (filter/spectrum types). alp_adc_filter_t * alp_adc_filter_open ( const alp_adc_filter_config_t *  cfg)

Open a streaming ADC source with a FIR/IIR DSP chain applied.

Composes alp_adc_stream_open + alp_dsp_chain_open under one handle. The chain MUST NOT contain an FFT stage; spectral output lands in alp_adc_spectrum_open (v0.5.x).

Parameters
[in]cfgConfiguration. Must be non-NULL.
Returns
Handle on success; NULL with alp_last_error set to:
  • ALP_ERR_INVAL on NULL cfg, NULL stages, n_stages == 0, or an FFT-terminated chain.
  • ALP_ERR_OUT_OF_RANGE on channel_id >= the selected form factor's ADC count, or any per-stage bound violation.
  • ALP_ERR_NOSUPPORT on SoMs without a streaming ADC.
  • ALP_ERR_NOT_READY when the backend transport is not configured.
  • ALP_ERR_BUSY when all stream slots are in use.
  • ALP_ERR_NOMEM when the handle pool or chain pool is exhausted.

◆ alp_adc_open()

alp_adc_t * alp_adc_open ( const alp_adc_config_t *  cfg)

Acquire and configure an ADC channel.

Resolves cfg->channel_id via the alp-adc<N> devicetree alias, applies the channel-config registers, and returns a handle ready for one-shot reads. When the backend supports the optional tuning fields (oversampling_ratio, sample_cycles, non-default resolution_bits) and any of them are non-zero, the SDK pushes them to the channel before returning the handle. For DMA-backed continuous acquisition use alp_adc_stream_open.

Parameters
[in]cfgConfiguration. Must be non-NULL; channel_id must be less than the selected form factor's ADC count (ALP_E1M_ADC_COUNT or ALP_E1M_X_ADC_COUNT).
Returns
Open handle on success, or NULL if the channel can't be resolved, configured, or the pool is exhausted.

Read one block of FFT bins from the spectrum stream.

Internally buffers up to N raw samples (N = the chain's FFT n_points) before running the chain. Until N samples have accumulated, returns ALP_OK with *got = 0 – not an error. Each successful block resets the accumulator (no overlap; overlapping windows land in a later revision).

Output element count when a block is emitted:

  • ALP_DSP_FFT_OUTPUT_COMPLEX – 2 * N (interleaved re,im pairs).
  • ALP_DSP_FFT_OUTPUT_MAGNITUDE – N.

◆ alp_adc_stream_open()

alp_adc_stream_t * alp_adc_stream_open ( const alp_adc_stream_config_t *  cfg)

Open a DMA-backed continuous-conversion stream on an ADC channel.

The SDK reserves one of the backend's internal stream slots and binds it to cfg->channel_id at cfg->sample_rate_hz. On the V2N family (V2N + V2N-M1) up to two slots are available concurrently (one per GD32 DMA controller); on SoMs without a comparable HW streaming backend the call returns NULL with last-error = ALP_ERR_NOSUPPORT.

Parameters
[in]cfgConfiguration. Must be non-NULL.
Returns
Open handle on success, or NULL with alp_last_error set to one of:
  • ALP_ERR_INVAL on NULL cfg or zero sample-rate,
  • ALP_ERR_OUT_OF_RANGE on channel_id beyond the selected form factor's ADC count,
  • ALP_ERR_NOSUPPORT on SoMs without a streaming backend,
  • ALP_ERR_NOT_READY when the backend transport is not configured (e.g. V2N supervisor with no bus ids set),
  • ALP_ERR_BUSY when all stream slots are already in use,
  • ALP_ERR_NOMEM when the handle pool is exhausted.

Drain pending samples from the stream's backend ring (uint16, mV).

Samples are UNSIGNED 16-bit MILLIvolts – the stream wire format (see the "Units" section in the file header; multiply by 1000 for the alp_adc_read_uv microvolt scale). The backend's per-call sample ceiling is hardware-defined (32 on the V2N family's GD32 IO MCU); callers wanting more than that per logical batch must loop. A return value of ALP_OK with *got == 0 means the backend ring was empty since the last read – not an error.
