Detailed Description

Alp SDK portable PID controller.

A small, caller-owned PID (proportional-integral-derivative) control loop for motor / thermal / power / attitude regulation. Unlike the DSP chain, a PID needs no pool or handle – the caller allocates an alp_pid_t (typically static or on the stack), initialises it once with alp_pid_init, and calls alp_pid_step every control tick.

The implementation is pure C (no vendor dependency) and builds on every OS target. It is gated by CONFIG_ALP_SDK_PID (the pid library knob in board.yaml); the profile's HW-accelerator bindings (CONFIG_ALP_PID_FPU / CONFIG_ALP_PID_TIMER) select a faster path on SoMs that expose one, transparently to this API.

Features: output clamping, integrator anti-windup, and derivative-on-measurement (which avoids the "derivative kick" a step change in setpoint would otherwise inject into the D term).

static alp_pid_t pid;
const alp_pid_config_t cfg = {
.kp = 0.8f, .ki = 0.2f, .kd = 0.01f,
.out_min = -1.0f, .out_max = 1.0f,
.deriv_on_measurement = true,
};
alp_pid_init(&pid, &cfg);
for (;;) {
float u = alp_pid_step(&pid, setpoint, measured, dt_s);
actuate(u);
}

Initialise a PID controller from a configuration.

Copies cfg into pid and clears the integrator + derivative history. Safe to call again at any time to re-tune (it resets state).

Parameters
[out]pidController to initialise (non-NULL).
[in]cfgTuning + limits (non-NULL). If alp_pid_config_t::out_max < alp_pid_config_t::out_min the values are treated as "no clamp".
Returns
ALP_OK, or ALP_ERR_INVAL if pid or cfg is NULL.

Clear the integrator and derivative history (keeps the tuning).

Use when the loop has been disengaged (e.g. motors disarmed) so a stale integrator does not slam the output on re-engage. NULL is a no-op.

[in,out]pidController, or NULL.

Advance the controller one tick and return the control output.

Computes u = Kp*e + Ki*integral(e) - Kd*d, applies anti-windup to the integrator and saturates u to the configured output range.

Parameters
[in,out]pidController from alp_pid_init (non-NULL).
[in]setpointDesired value.
[in]measurementMeasured value.
[in]dt_sTime since the previous step, seconds; must be > 0 (a non-positive dt_s returns 0 and does not advance state).
Returns
The saturated control output, or 0.0f if pid is NULL or dt_s <= 0.
