Detailed Description

Alp SDK IoT abstraction (Wi-Fi-station + MQTT in v0.1).

Backends:

  • Zephyr : wraps net_*, MQTT client API.
  • Yocto : wraps the Linux network stack + Mosquitto/Paho.
  • Baremetal: ALP_ERR_NOSUPPORT (no networking on E1M-AEN bare-metal v0.1).
ABI status: [ABI-STABLE]
v0.2-v0.4; Wi-Fi station + MQTT (TLS) signatures stable. See docs/abi-markers.md for the convention.

Definition iot.h:114

Default-initialize an alp_mqtt_config_t for broker id.

Identity from id (the broker_uri); canonical defaults: client_id / username / password = NULL (unauthenticated, backend-assigned client id), keepalive_s = 60 (the conventional MQTT keepalive interval), clean_session = true (start without stale broker-side session state – the simpler, more common default), tls = NULL (documented as equivalent to a zero-initialised alp_mqtt_tls_config_t – OS default CA path, no client cert, verify peer). Set tls for an mqtts:// broker that needs a pinned CA / client certificate.

Note
Expands to a compound literal (a GCC/Clang extension in C++ – the SDK's toolchains; standard through C23). Usable as an initializer or an expression. On a compiler that rejects compound literals in C++ (e.g. MSVC), initialize the config's fields individually.

◆ alp_mqtt_msg_cb_t

typedef void(* alp_mqtt_msg_cb_t) (const char *topic, const uint8_t *payload, size_t len, void *user)

Per-message MQTT callback.

Callback context (issue #756)
Invoked SYNCHRONOUSLY, on the calling thread, from inside alp_mqtt_loop – m's loop() call has not yet returned while this callback runs. It is SAFE to call alp_mqtt_close on m from within this callback (a "self-close"): the close is detected and its actual teardown deferred until this alp_mqtt_loop call returns, so it neither deadlocks nor leaves m usable afterwards. It is likewise safe to call alp_mqtt_close on m from a DIFFERENT thread while this callback is running (an ordinary close blocks until the loop call – and this callback – have returned). Do not perform long-blocking work here; it runs inline on whichever thread is driving alp_mqtt_loop.
