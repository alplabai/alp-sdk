Detailed Description

Alp SDK watchdog abstraction.

Backends:

  • Zephyr : wdt_* driver class.
  • Yocto : /dev/watchdogN ioctl.
  • Baremetal: vendor HAL WDT peripheral.

Most SoCs disable the watchdog after a feed-miss reset so the boot code can choose whether to re-arm it; the ALP wrapper does not mask that — apps are expected to know whether they re-installed the timeout after a recovery boot.

Typical usage:

alp_wdt_t *wdt = alp_wdt_open(&(alp_wdt_config_t){
.wdt_id = ALP_E1M_WDT0, // E1M; use ALP_E1M_X_WDT0 on E1M-X
.timeout_ms = 5000,
.on_timeout = ALP_WDT_RESET_SOC,
});
while (running) {
do_work();
alp_wdt_feed(wdt); // every iteration; must be < 5 s
}

#define ALP_WDT_CONFIG_DEFAULT (   id)     ((alp_wdt_config_t){ .wdt_id = (id), .timeout_ms = 1000u, .on_timeout = ALP_WDT_RESET_SOC })

Default-initialize an alp_wdt_config_t for watchdog id.

Identity from id; canonical defaults: timeout_ms = 1000 (a conservative 1 s feed deadline — timeout_ms must be non-zero, so zero-init is not valid here and the default supplies a usable value), on_timeout = ALP_WDT_RESET_SOC (full SoC reset, the safest action). Shorten timeout_ms for a tighter deadline after expansion.

Note
Expands to a compound literal (a GCC/Clang extension in C++ – the SDK's toolchains; standard through C23). Usable as an initializer or an expression. On a compiler that rejects compound literals in C++ (e.g. MSVC), initialize the config's fields individually.

alp_status_t alp_wdt_disable ( alp_wdt_t *  wdt)

Disable the watchdog if the SoC supports it.

Many M-class watchdogs are write-once-armed and cannot be disabled without a reset. ALP_ERR_NOSUPPORT is the expected return on such hardware; the caller can treat it as informational.

Parameters
[in]wdtHandle from alp_wdt_open.
Returns
ALP_OK on success; ALP_ERR_NOSUPPORT if the SoC's WDT is one-shot; ALP_ERR_NOT_READY if wdt is closed.

alp_wdt_t * alp_wdt_open ( const alp_wdt_config_t *  cfg)

Install a watchdog timeout and arm the timer.

The watchdog starts feeding-required immediately on return. Apps must call alp_wdt_feed before timeout_ms elapses or the configured on_timeout action triggers.

Parameters
[in]cfgConfiguration. Must be non-NULL with non-zero timeout_ms; wdt_id must be a valid watchdog index on the active SoM (ALP_E1M_WDT0..1 or ALP_E1M_X_WDT0..1).
Returns
Open handle on success; NULL if cfg is invalid, cfg->wdt_id is out of range, the underlying device isn't ready, or the SoC rejected the requested timeout (too long for the hardware).
