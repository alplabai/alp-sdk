Detailed Description

Alp SDK Bluetooth Low Energy abstraction (peripheral + central).

v0.3 deliverable. v0.1 ships only the public surface; every entry point returns ALP_ERR_NOSUPPORT and *_open() returns NULL.

Backends (locked decision per the v0.1 brainstorming output):

  • Zephyr : Zephyr bt host stack + the active SoC's BLE controller.
  • Yocto : BlueZ over D-Bus.
  • Baremetal: ALP_ERR_NOSUPPORT (BLE off the bare-metal v0.1 path).

The header takes a deliberately small slice of the BLE feature surface — peripheral advertise + GATT server, central scan + connect + GATT client. Mesh, audio, and direction-finding are explicitly out of scope for v1.0 and would arrive as separate <alp/ble_mesh.h> / <alp/ble_audio.h> headers.

Typical peripheral-role usage:

alp_ble_t *ble = alp_ble_open();
alp_ble_uuid_t srv = {.b = {...}};
alp_ble_advertise_start(ble, &(alp_ble_adv_config_t){
.name = "MyDevice",
.services = &srv,
.num_services = 1,
.interval_min_ms = 100,
.interval_max_ms = 200,
.connectable = true,
});

Default-initialize an alp_ble_adv_config_t with local name id.

Identity from id (the advertised local name); canonical defaults (matching the peripheral-role example above): services = NULL / num_services = 0 (no service UUIDs advertised – add them after expansion), interval_min_ms = 100 / interval_max_ms = 200 (a common, moderate advertising cadence), connectable = true.

Note
Expands to a compound literal (a GCC/Clang extension in C++ – the SDK's toolchains; standard through C23). Usable as an initializer or an expression. On a compiler that rejects compound literals in C++ (e.g. MSVC), initialize the config's fields individually.

◆ alp_ble_scan_cb_t

typedef void(* alp_ble_scan_cb_t) (const alp_ble_scan_result_t *r, void *user)

Scan-result callback.

Callback context (issue #756)
Invoked SYNCHRONOUSLY, on the calling thread, once per scan result, from inside alp_ble_scan_start – that call has not yet returned while this callback runs. It is SAFE to call alp_ble_close on ble's radio handle from within this callback (a "self-close"): the close is detected and its actual teardown deferred until the alp_ble_scan_start call returns, so it neither deadlocks nor leaves the radio handle usable afterwards. It is likewise safe to call alp_ble_close from a DIFFERENT thread while this callback is running (an ordinary close blocks until scan_start – and this callback – have returned).

)

Register a primary service with its characteristics.

On success populates handles_out with one attribute handle per characteristic in declaration order.

Note
Service registration must precede advertising. On backends whose host stack only supports adding services to a not-yet-started GATT server (e.g. NimBLE's ble_gatts_start() / ble_gatts_mutable() constraint on the CC3501E backend), registering while already advertising, scanning, or connected is refused with ALP_ERR_BUSY – call this before alp_ble_advertise_start.
Parameters
[in]bleHost handle from alp_ble_open.
[in]defService + characteristics. Must be non-NULL.
[out]handles_outReceives the attribute handles for each characteristic. Caller-allocated array of def->num_chars elements.
Returns
ALP_OK / ALP_ERR_NOT_READY / ALP_ERR_INVAL / ALP_ERR_NOMEM / ALP_ERR_BUSY (registration ordering constraint – see
