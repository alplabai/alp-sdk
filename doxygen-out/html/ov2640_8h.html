Detailed Description

OmniVision OV2640 2 MP UXGA CMOS image sensor — config-side driver.

Public surface for the OV2640 as deployed on the ESP32-CAM and countless Chinese-domestic UXGA camera modules. Symbols carry the chip's natural prefix ov2640_* — no alp_.

Scope split
  1. SCCB (I²C-compatible, fixed 0x30 7-bit) — chip-ID readback, resolution / format / brightness / colour-bar config. This driver covers that side.
  2. DVP 8-bit parallel — pixel egress. Routed to the SoC's camera receiver behind <alp/camera.h>; this driver does not touch it.
ABI status: [ABI-EXPERIMENTAL]
Verification status: [UNTESTED] — driver compiles + passes NULL-arg smokes;
no HiL silicon bring-up yet. Treat all numbers + lifecycle sequencing as paper-correct only until the v1.0 verification sweep lands. First SoM verification on V2N's GD32 bridge DVP path arrives in v0.5.x. The lifecycle / setter API below is stable; pixel path bring-up may add helpers without breaking these symbols.
Driver status: [stub-impl]
Resolution / format setters store the request and validate the chip-ID; the OmniVision-vendor 600+ register init table for each preset lands in a follow-up once the maintainer adds the reference init script to the internal design archive. Until then the setters return ALP_ERR_NOSUPPORT after stashing the request, mirroring the existing ov5640 shape.

Datasheet: OmniVision OV2640 (Rev 2.2, Apr 2006).

alp_i2c_t *  bus,
uint8_t  i2c_addr 
)

Bind a driver context to an open I²C bus and verify the chip ID.

Selects the SENSOR bank, reads PIDH:PIDL, compares against OV2640_CHIP_ID.

Parameters
devOutput: caller-allocated driver context.
busI²C bus handle from alp_i2c_open.
i2c_addr7-bit SCCB address (always OV2640_I2C_ADDR).
Returns
ALP_OK on chip-ID match, ALP_ERR_INVAL on bad args, ALP_ERR_IO on chip-ID mismatch, propagated I²C error on bus failure.
