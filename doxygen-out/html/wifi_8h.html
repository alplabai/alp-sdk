Detailed Description

CC3501E Wi-Fi host helpers + portable Wi-Fi backend attach.

Thin wrappers over cc3501e_request that match the opcodes + payloads in <alp/protocol/cc3501e.h>. Several of these poll the firmware "by repeat": the firmware accepts the request, kicks off a worker (scan / DHCP / association), and returns ALP_ERR_BUSY (RESP_ERR_BUSY) on each repeat until the worker finishes – so the host re-issues the SAME command on a bounded retry/backoff until it gets RESP_OK with the result, or the timeout elapses. This is how the bring-up proves the firmware's worker seam from the host with no async-event line on this HW rev.

enum cc3501e_wifi_sec_t

Decoded Wi-Fi security kind (from a scan record's security_info).

The CC3501E scan reports the raw TI 16-bit SecurityInfo; these are the human-meaningful buckets the console maps it to. sec_type lives at (security_info >> 8) & 0x3f (TI WLAN_SCAN_RESULT_SEC_TYPE_BITMAP); the SAE bits (0x08|0x10) in that bitmap mark WPA3, the WPA2 bit is 0x04, open is 0.

Start a Wi-Fi soft-AP (WIFI_AP_START, opcode 0x14).

Brings the CC3501E up as an access point advertising ssid. The on-wire payload is identical to cc3501e_wifi_connect – an alp_cc3501e_wifi_connect_t header (ssid_len / psk_len / security) followed by the inline SSID then the inline passphrase, packed with no padding. AP bring-up is a radio op (the firmware worker-routes it and the bridge is briefly down), so while the firmware reports RESP_ERR_BUSY the request is re-issued on a bounded backoff until RESP_OK or the deadline.

Parameters
ctxInitialised driver context.
ssidNUL-terminated AP SSID (<= 32 bytes; longer is rejected).
sec_typeSecurity selector – CC3501E_WIFI_CONNECT_SEC_OPEN / _WPA2_PSK / _WPA3_SAE (matches alp_cc3501e_wifi_connect_t::security on the wire).
passNUL-terminated passphrase (may be NULL/"" for an open AP).
timeout_msUpper bound on the AP-start poll budget (floored to the radio down-window).
Returns
ALP_OK once the AP is up; ALP_ERR_TIMEOUT if still starting at the deadline; ALP_ERR_INVAL on an over-long SSID/passphrase; mapped error otherwise.

Read the CC3501E's Wi-Fi station MAC address (GET_MAC, opcode 0x03).

GET_MAC is poll-by-repeat on the firmware side: the firmware may answer RESP_ERR_BUSY while the radio identity is still being read out of the device, so this loops the GET_MAC request on a bounded backoff while it returns ALP_ERR_BUSY, until RESP_OK fills the 6-byte MAC or timeout_ms elapses. Proving this round-trips exercises the firmware worker seam from the host.

Parameters
ctxInitialised driver context.
macReceives the 6-byte MAC (CC3501E_MAC_LEN) on success.
timeout_msUpper bound on the poll-by-repeat budget.
Returns
ALP_OK with mac filled; ALP_ERR_TIMEOUT if the firmware stayed busy; ALP_ERR_IO on a short reply; or the mapped error otherwise.
Note
WIRE: GET_MAC has an opcode but the protocol header defines NO reply payload struct; this helper assumes the reply data is exactly the 6 MAC bytes (after the status byte). See cc3501e.c for the gap note.

alp_status_t cc3501e_wifi_scan ( cc3501e_t *  ctx,
cc3501e_scan_record_t *  out_records,
size_t  cap,
size_t *  count,
uint32_t  timeout_ms 
)

Run a Wi-Fi scan and collect the results (WIFI_SCAN_START, 0x10).

Poll-by-repeat: re-issues WIFI_SCAN_START while the firmware reports RESP_ERR_BUSY (scan in progress). Once the scan completes the firmware returns RESP_OK with the discovered access points packed into the reply payload as a sequence of alp_cc3501e_scan_result_t records (each fixed 10-byte header immediately followed by its ssid_len inline SSID bytes, no padding). This parses up to cap records out into out_records and writes the count to count.

Parameters
ctxInitialised driver context.
out_recordsCaller array of cap cc3501e_scan_record_t.
capCapacity of out_records.
countReceives the number of records parsed (may be NULL).
timeout_msUpper bound on the poll-by-repeat budget.
Returns
ALP_OK once the scan completed (even with zero records); ALP_ERR_NOT_READY if ctx is NULL or not initialised; ALP_ERR_BUSY if a scan is already decoding on this SAME ctx (issue #740) – a plain, non-atomic same-call-stack reentrancy guard (see cc3501e_poll_events's concurrency warning; a caller polling one ctx from multiple threads must serialize its own calls). A different ctx has entirely separate storage and may always scan concurrently; ALP_ERR_TIMEOUT if the firmware stayed busy; mapped error otherwise.
Note
WIRE: the protocol header defines alp_cc3501e_scan_result_t but NO count/list envelope and documents the records as async events (EVT_WIFI_SCAN_RESULT). This helper assumes the firmware returns the records as the SCAN_START reply payload. See cc3501e.c for the gap.

alp_cc3501e_wifi_status_t *  out

Poll the non-blocking STA connection state (WIFI_STATUS, opcode 0x1B).

Reads the firmware's connection-state latch without a radio op (ISR-safe on the firmware side): how the host collects the outcome of an async cc3501e_wifi_connect submit – CONNECTING while the association runs, then CONNECTED or FAILED once the WLAN connect event lands. The reply is the fixed 4-byte alp_cc3501e_wifi_status_t wire layout (state | fail_reason | rssi_dbm | reserved), decoded into out.

Parameters
ctxInitialised driver context.
outReceives the decoded status snapshot: state is a alp_cc3501e_wifi_conn_state_t, fail_reason a alp_cc3501e_wifi_fail_t (valid when state == CONN_FAILED) and rssi_dbm the STA RSSI (valid when state == CONNECTED).
Returns
ALP_OK with out filled; ALP_ERR_INVAL if out is NULL; ALP_ERR_IO on a short reply; otherwise the mapped error.
