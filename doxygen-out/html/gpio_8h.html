Detailed Description

CC3501E GPIO proxy host helpers (opcodes 0x50..0x53) + the portable GPIO proxy backend wiring.

The CC3501E fronts a set of E1M pads (IO11/IO13/IO15..IO21); these helpers let the host drive/read them over the inter-chip bridge. pad is the RAW CC3501E GPIO index (the firmware drives the pad 1:1, refusing the bridge's own SPI/UART pads); the logical IO11.. -> raw-index map lives in board metadata, not on the wire. These ops are synchronous + fast in the firmware (no worker), so they use the caller's timeout_ms with no radio-down-window floor – but they still retry on a transient IO (the bridge is briefly down if a radio op is running concurrently).

alp_status_t alp_gpio_cc3501e_attach ( cc3501e_t *  ctx)

Attach the live bridge handle to the GPIO proxy backend.

Call once after cc3501e_init(). Without it (or with an empty route table) every alp_gpio_open() pin delegates to the platform GPIO driver, so the proxy is a no-op until both a bridge is attached and the route table is populated. Only defined when CONFIG_ALP_SDK_GPIO_CC3501E_PROXY is set.

Parameters
ctxInitialised bridge handle.
Returns
ALP_OK; ALP_ERR_INVAL on a NULL ctx.

Arm/disable an edge interrupt on a proxied CC3501E GPIO (GPIO_SET_INTERRUPT, 0x53).

The firmware arms the pad's HW edge interrupt; on this CS-less, no-host-IRQ rev the async EVT_GPIO_INTERRUPT delivery has no slave->master attention line, so the edge is latched on the CC3501E for a future poll/EVT path – arming the controller is real, the host notification is deferred to the next board rev.

Parameters
ctxInitialised bridge handle.
padRaw CC3501E GPIO index.
edgeOne of alp_cc3501e_gpio_edge_t (NONE disables). NOTE: the CC35xx controller has no both-edges trigger, so EDGE_BOTH returns ALP_ERR_INVAL – arm RISING or FALLING.
enabledfalse = disable, true = enable.
timeout_msCaller budget.
Returns
ALP_OK once armed/disabled; otherwise the mapped error.
