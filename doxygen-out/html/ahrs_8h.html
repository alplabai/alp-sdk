Detailed Description

Alp SDK portable AHRS (attitude and heading reference system).

A caller-owned Madgwick orientation filter that fuses a 3-axis gyro with a 3-axis accelerometer into a drift-corrected orientation quaternion (the IMU variant; a magnetometer-aided MARG variant may be added later). The accelerometer pins roll/pitch against gravity so the estimate does not drift the way a raw gyro integrator does.

Like alp_pid_t this needs no pool or handle: allocate an alp_ahrs_t (static or stack), alp_ahrs_init it once, then call alp_ahrs_update_imu every sample and read Euler angles with alp_ahrs_euler. Pure C (libm only); builds on every OS target, gated by CONFIG_ALP_SDK_AHRS (the madgwick_ahrs board.yaml library knob). Faster HW paths (FPU / TMU CORDIC) bind transparently on SoMs that expose them.

static alp_ahrs_t ahrs;
alp_ahrs_init(&ahrs, &(alp_ahrs_config_t){ .beta = 0.1f });
for (;;) {
// gyro in rad/s; accel in any consistent unit (it is normalised)
alp_ahrs_update_imu(&ahrs, gx, gy, gz, ax, ay, az, dt_s);
float roll, pitch, yaw;
alp_ahrs_euler(&ahrs, &roll, &pitch, &yaw);
}

Read the current orientation as aerospace Euler angles.

Converts the internal quaternion to intrinsic Z-Y-X (yaw-pitch-roll) Euler angles in DEGREES. Any output pointer may be NULL to skip it.

Parameters
[in]ahrsFilter (non-NULL); NULL leaves outputs untouched.
[out]roll_degRoll about X, degrees, or NULL.
[out]pitch_degPitch about Y, degrees [-90, 90], or NULL.
[out]yaw_degYaw about Z, degrees, or NULL.

Initialise the filter to the identity orientation.

Sets the quaternion to (1,0,0,0) (level, facing +x) and copies the gain from cfg. Safe to call again to re-seed.

Advance the filter one sample (gyro + accelerometer fusion).

Runs one Madgwick IMU update: integrates the gyro and applies a gradient-descent correction toward the gravity direction measured by the accelerometer, then renormalises the quaternion.

Parameters
[in,out]ahrsFilter from alp_ahrs_init (non-NULL).
[in]gxGyro X, rad/s.
[in]gyGyro Y, rad/s.
[in]gzGyro Z, rad/s.
[in]axAccel X (any consistent unit; the vector is normalised, so raw counts are fine).
[in]ayAccel Y.
[in]azAccel Z.
[in]dt_sTime since the previous update, seconds; must be > 0 (a non-positive dt_s is ignored).
Note
If the accelerometer vector is zero (free-fall or a dropout) the update falls back to gyro-only integration for that sample.
