bool alp_storage_config_t::allow_unsafe_write

Must be explicitly set true to permit alp_storage_write / alp_storage_erase on the Yocto backend (ignored elsewhere).

instance_id alone does not tell that backend whether it is addressing user data or the boot medium: /dev/mmcblk<N> is the WHOLE-DISK node (GPT/MBR + bootloader at offset 0), and on some boards /dev/mtd0 IS the bootloader/FIP partition. Left false (the default from ALP_STORAGE_CONFIG_DEFAULT), alp_storage_write/alp_storage_erase return ALP_ERR_INVAL before touching the device, on every instance_id, no exceptions. alp_storage_read/alp_storage_get_info are unaffected – a read cannot damage the boot medium.
