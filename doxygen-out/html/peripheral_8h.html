Detailed Description

Alp SDK peripheral abstraction (I2C, SPI, GPIO, UART).

Thin C99 surface that the alp-studio pin allocator targets. The studio picks a peripheral instance per block at codegen time; this header is what the generated init/usage code (and any hand-written application code) calls into.

Each peripheral handle is opaque. Backends are picked by the <alp/backend.h> registry mechanism; the Zephyr backends live under src/backends/<peripheral>/ and the Yocto / baremetal backends fill in alongside their respective build trees.

ABI status: [ABI-STABLE]
v0.1 surface; locked across every release since v0.1. See docs/abi-markers.md for the convention.

Default-initialize an alp_i2c_target_config_t for bus id.

Identity from id. own_addr_7bit, on_write, and on_read are all mandatory – alp_i2c_target_open rejects a reserved address (0x00-0x07 / 0x78-0x7F) or a NULL callback with ALP_ERR_INVAL – so they default to 0 / NULL / NULL, a deliberate "you must set this" sentinel: 0x00 falls in the reserved range, so a caller who forgets to set own_addr_7bit fails loudly at open() rather than silently claiming an unintended address. on_stop and user default to NULL (both documented optional). Set own_addr_7bit / on_write / on_read before calling open().

alp_status_t alp_deinit ( void  )

Release SDK-global runtime state acquired by alp_init.

Peripheral handles are NOT closed for the caller – close every open handle first. Idempotent; safe to call without a prior alp_init. After it returns, alp_init may be called again to re-initialise.

Returns
ALP_OK on success (the only result the current implementation produces).

◆ alp_delay_us()

void alp_delay_us ( uint32_t  us)

Busy-wait for at least us microseconds.

Backends use the platform's cycle-accurate spin primitive (Zephyr's k_busy_wait, Yocto's clock_nanosleep with a busy-loop fallback, vendor-HAL spin on baremetal). Does not yield to other threads – callers needing scheduler-friendly waits should use alp_delay_ms for sub-thread-tick durations or k_msleep / equivalent directly.

◆ alp_init()

alp_status_t alp_init ( void  )

Initialise the Alp SDK runtime.

Applications SHOULD call this once at startup, before the first alp_*_open call. Today the call is thin – the backend registry is linker-section based and needs no runtime setup, so every current backend works even when the call is skipped – but future backends (bridge links, clock bring-up, vendor HAL init) are allowed to rely on it, so portable application code must not.

Idempotent: calling it again after a successful return is a no-op that returns ALP_OK.

Thread-safety: safe to call concurrently – an atomic once-guard ensures exactly one caller performs the bring-up work; the others return ALP_OK immediately. Do NOT race alp_deinit against alp_init or against in-flight peripheral calls: the deinit/re-init sequence is single-threaded by contract.

Returns
ALP_OK on success (the only result the current implementation produces). Future backends may surface ALP_ERR_NOT_READY / ALP_ERR_IO when their bring-up work fails.
ABI status: [ABI-EXPERIMENTAL] – v0.9 new.

◆ alp_last_error()

alp_status_t alp_last_error ( void  )

Read the most recent error encountered on this thread.

alp_*_open functions return NULL on failure for the v0.1 ABI stability reason; this helper lets callers learn why. Common cases:

  • ALP_ERR_INVAL — NULL config, bus_id out of range
  • ALP_ERR_NOT_READY — DT alias unset or device not ready
  • ALP_ERR_NOMEM — handle pool exhausted
  • ALP_ERR_OUT_OF_RANGE — config exceeds the active SoC's caps (e.g. 16-bit ADC requested on a SoC whose ADC tops out at 12 bits)
  • ALP_ERR_NOSUPPORT — Zephyr driver returned -ENOTSUP

The value is thread-local — concurrent open() calls on different threads don't clobber each other's diagnostic. A successful open() on a thread clears its slot. Every thread's initial state (before that thread has called any alp_*_open) is ALP_OK.

Returns
The thread's last error code, or ALP_OK if no error has been recorded since the last successful open().

◆ alp_spi_target_transceive()

alp_status_t alp_spi_target_transceive ( alp_spi_target_t *  bus,
const uint8_t *  tx,
uint8_t *  rx,
size_t  len,
size_t *  rx_len,
uint32_t  timeout_ms 
)

Stage one target-side transfer and wait (bounded by timeout_ms) for the external controller to clock it.

tx is driven onto the data-out line while the controller clocks; whatever the controller drives lands in rx. The controller may clock FEWER bytes than len – rx_len reports how many actually moved (in bytes, regardless of bits_per_word).

Timeouts: UINT32_MAX blocks until the controller completes the transfer (deasserts /CS) – call from a thread that may wait indefinitely. A finite timeout_ms bounds the wait; on the Zephyr backend this needs CONFIG_SPI_ASYNC (a finite timeout on a sync-only build fails with ALP_ERR_NOSUPPORT rather than silently blocking forever).

After ALP_ERR_TIMEOUT the transfer is STILL armed in the controller driver (SPI slave hardware has no portable cancel): the handle answers ALP_ERR_BUSY – and alp_spi_target_close refuses teardown – until the external controller clocks the pending transfer. Keep tx / rx valid until a subsequent call on this handle stops returning ALP_ERR_BUSY.

One transfer at a time: a second thread calling while a transceive is in flight gets ALP_ERR_BUSY.

Parameters
[in]busHandle from alp_spi_target_open.
[in]txBytes to present on data-out. May be NULL to drive the idle pattern.
[out]rxReceive buffer. May be NULL to discard input.
[in]lenBuffer length in bytes (both directions). Must be > 0: unlike controller-mode alp_spi_transceive (where len == 0 is a no-op ALP_OK), a target cannot stage a zero-length transfer – ALP_ERR_INVAL.
[out]rx_lenBytes actually clocked by the controller. May be NULL when the caller doesn't care.
[in]timeout_msMax wait for the controller to clock the transfer; UINT32_MAX to wait forever.
Returns
ALP_OK / ALP_ERR_INVAL / ALP_ERR_NOT_READY / ALP_ERR_BUSY / ALP_ERR_TIMEOUT / ALP_ERR_IO / ALP_ERR_NOSUPPORT.

◆ alp_uart_rx_ringbuf_attach()

alp_uart_rx_ringbuf_t * alp_uart_rx_ringbuf_attach ( alp_uart_t *  port,
uint8_t *  backing,
size_t  backing_size 
)

Attach a byte-granular RX ring buffer to an open UART port.

Exclusive ownership: at most one ring buffer may be attached to a port at a time (the underlying driver exposes a single IRQ callback slot per UART device). Attaching a second buffer while the first is still attached is refused with ALP_ERR_BUSY – detach the first (or close the port) before attaching a replacement.

Lifetime: alp_uart_close() on the parent port automatically detaches an attached ring buffer (disabling RX IRQs and releasing the pool slot) before the port handle is released, so the buffer can never outlive its parent. Calling alp_uart_rx_ringbuf_detach explicitly first (e.g. to attach a replacement without closing the port) is also fine – detach is idempotent.

portUART handle from alp_uart_open().
backingCaller-owned buffer; must outlive the returned handle. Should be >= 64 bytes to absorb the worst-case FIFO drain latency.
backing_sizeCapacity in bytes (one byte is reserved for empty / full disambiguation, so usable capacity is backing_size - 1).
Returns
Handle on success; NULL with alp_last_error() set on failure. Returns NULL + ALP_ERR_NOSUPPORT on builds without CONFIG_ALP_SDK_UART_RX_RINGBUF; NULL + ALP_ERR_BUSY when a ring buffer is already attached to port.
