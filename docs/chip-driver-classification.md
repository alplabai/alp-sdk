# Chip driver classification (non-complete)

Tracks issue #500. Every chip whose `metadata/chips/<part>.yaml` has `driver_status` other than `complete` (59 of 88), with its ADR 0017 tier, proposed owner and remaining gap. The chip schema is unchanged; status values are read from the yaml and the tier/owner columns are a proposal derived here.

Status counts: partial 23, stub 28, planned 4, none 4.

Tier counts: T1 28, T1.5 2, T2 12, Adjacent 2, Unmapped 15.

## How the tier is derived

[ADR 0017](adr/0017-alp-sdk-over-the-vendor-sdk.md) defines tiers for AEN peripherals; they are applied to chips by the same criteria:

- **T1** (upstream-native): upstream Zephyr drives the part directly, alp-sdk ships DT and the `<alp/*>` mapping only. Checked against an upstream Zephyr v4.4.1 tree (`drivers/`, `dts/bindings/`). "Tier 1 candidate" means only a binding or sibling-family driver was found and part coverage is unconfirmed.
- **T1.5** (in-tree thin driver over a vendor HW library): criterion (a), the library exposes no Zephyr device. Library license must still be confirmed Apache-2.0-compatible.
- **T2** (vendor-consumed): a genuine vendor driver, stack or runtime exists; alp-sdk maps onto it and does not rewrite it.
- **T3** (SE-mediated): no non-complete chip qualifies.
- **Adjacent**: repo-authored driver with no upstream equivalent, which the yaml itself calls ADR-0017-ADJACENT.
- **Unmapped**: neither an upstream nor a vendor driver exists, so the ADR has no tier for the existing Alp-authored register driver. Proposed owner is Alp Lab by default; the ADR needs a decision (upstream contribution, accept in-tree, or drop).

`hil_silicon` is silicon verification only and `driver_status` is code completeness; neither implies buildability, and `ov9281` and `dp83825` show the two can disagree. "HIL" in the gap column means silicon verification is still outstanding. Owner is a proposal; Alp-owned work needs a focused child issue before it starts.
