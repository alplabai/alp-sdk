> **Release candidate.** v0.17.0-rc1 is a pre-release for validation; the final v0.17.0 follows. CC3501E bridge firmware: use v0.8.0 or newer (wire 4.0), see below.

*v0.17.0 moves the bridge firmwares out of the SDK, retires the `alp_cli` command surface in favour of `tan`, and lands a large V2N/V2M, AEN, display and GD32/CC3501E bring-up wave. Pre-1.0 minor: the public ABI changes, see Breaking below.*

## Highlights

- **Bridge firmwares live in their own repos** — `firmware/cc3501e/` and `firmware/gd32-bridge/` moved to `alplabai/cc3501e-bridge-firmware` and `alplabai/gd32-bridge-firmware`, history preserved (#1370).
- **`alp_cli` command surface retired** — `tan` is the sole user-facing CLI (#1367, #1368); a per-PR `tan` build gate covers AEN + V2N (#2751).
- **GD32 bridge wire protocol v0.15 + v0.17 host side** — negotiated big frames, `BATCH`, `STREAM2`, the `ATTN` line, I2C3 master proxy opcodes and `CAM_EN_LDO` bits (#2692, #2748); `gd32g553_set_power_mode` low-power modes and persistent `BOOT_CONFIG` (#2697).
- **V2N/V2M** — Linux remoteproc attach to the TF-A-started CM33 (#2671), `<alp/gpu2d.h>` on the Mali-G31 with CPU fallback (#2678), opt-in ROS 2 Humble layer (#2672), persistent allowlisted U-Boot environment on eMMC boot partition 2 (#2675).
- **Displays** — Riverdi RVT121 LVDS panel (SN65DSI83) and a display-agnostic SDK layer (backlight, mount rotation), with the `aen-trace-runner` exhibition game on it (#2254, #2257).
- **AEN** — documented recovery of an E8 whose Secure Enclave is stuck in Recovery (#1699), D/AVE 2D backend on silicon (#2515), OSPI/HexSPI `flash_driver_api`, MCUboot and Alif SE update-log providers.
- **CC3501E wire protocol MAJOR 4.0** — `RESP_OK` moved off `0x00` and every frame, both directions, carries a CRC-16/CCITT-FALSE trailer (#1927, #2035); worker-routed opcodes carry request identity in the frame header (#2035). The host is bilingual: it talks wire MAJOR 4 natively and MAJOR 3 in legacy mode. Needs bridge firmware v0.8.0 or newer for the 4.0 wire; see below.
- **Metadata** — SoM preset schema v2, `variants[].debug.svd`, generated V2N/V2M board `.dts`, optional `slices[].flash_method_resolved`.

## CC3501E: bridge firmware compatibility

The v0.17.0-rc1 host speaks CC3501E wire protocol **4.0** (`ALP_CC3501E_PROTOCOL_MAJOR 4`, `ALP_CC3501E_PROTOCOL_MINOR 0`) and accepts firmware reporting wire **MAJOR 4** or, as a migration-window legacy mode, **MAJOR 3** (`ALP_CC3501E_PROTOCOL_MAJOR_LEGACY 3`). `cc3501e_reset()` reads `GET_VERSION` and compares the MAJOR half only; a MINOR difference never refuses the link.

| Bridge firmware | Wire | rc1 host |
|---|---|---|
| v0.8.0, v0.9.0, v0.9.2 | 4.0 | accepted, native |
| v0.7.0 | 3.1 | accepted, legacy decode (no CRC, `0x00` is OK) |
| v0.6.0 | raw integer 8 (pre-scheme) | **refused**, decodes to MAJOR 0 |
| v0.5.1 and older | raw integer 7 or lower | **refused**, decodes to MAJOR 0 |

Use **v0.9.2** (wire 4.0, GPE `0.254.38.0`) unless you have a reason not to. The signed blobs are committed under `prebuilt/` on `alplabai/cc3501e-bridge-firmware` `main`; there is **no published GitHub release or git tag** for the firmware yet (only a draft v0.9.2 release), so take `prebuilt/cc3501e-v0.9.2.bin`, or build from source at `main`. Flash order matters: the CC35 secure boot loader enforces GPE stamp monotonicity per part, see `prebuilt/BUILD_RECIPE.md`.

On a mismatch `cc3501e_reset()` returns `ALP_ERR_VERSION`, clears `initialised` and records the firmware's MAJOR/MINOR in the context, so every later call on that handle returns `ALP_ERR_NOT_READY` until the board is re-flashed and the handle reset. A pre-scheme firmware (MAJOR 0) is refused the same way.

## Known issues

- **Trace-runner A32 renderer fault** — after a cold boot the stub-launched A32 renderer can read power-on garbage from the uninitialised mailbox and trap once (`abi_fault` on an invalid rotation); the HE watchdog relaunches it within ~0.6 s and it then runs normally. Root-caused on silicon; fixed after rc1 (stub clears the mailbox on a cold page).
- **Body-control is not yet bench-tested on the Riverdi build.**

## Breaking

- **ABI (pre-1.0 minor)** — 323 symbols added, 53 changed, 27 intentional removals recorded in `docs/abi/removed-symbols.json`; snapshot `docs/abi/v0.17-snapshot.json`. `alp_display_caps_t.rotation` is `[ABI-EXPERIMENTAL]`.
  - `gd32g553_power_mode_set` removed -> `gd32g553_set_power_mode` (#2692).
  - `alp_shmem_config_t.cacheable` and `alp_rpc_config_t.cacheable` removed; carve-outs are non-cacheable by design (#2556).
  - Layout/enum changes: `alp_backend_t` gains `base_class_flags` (field order shifts), `alp_capabilities_t` gains `class_flags`, `alp_instance_cap_t` gains `ALP_INSTANCE_CAP_REPORTED = 1u << 0` (other values shift), `bmp581_odr_t` values change.
  - Other removals: `act8760_rail_set_vset`, `da9292_v2n_base_init`, `cc3501e_set_event_callback`, `GD32_SWD_EXPECTED_IDCODE`, the `alp_deepx_inference_slot_*` set, EVK macros `EVK_ADC_BOARD_ID` / `EVK_ADC_MB_AN` / `EVK_ADC_VBAT_SENSE`.
- **CC3501E wire protocol** — the host now requires wire MAJOR 4 (or legacy MAJOR 3) firmware; firmware v0.6.0 and older are refused with `ALP_ERR_VERSION`. See "CC3501E: bridge firmware compatibility" above (#2035).
- **som-preset schema** — `som-preset-v1` renamed `som-preset-v2`, `write_authority` required, `npu_population` removed; a preset declaring `schema_version: 1` fails validation (#2024).
- **Build** — the example `CMakeLists.txt` `alp_project.py --emit zephyr-conf` configure-time bridge is removed (#866); `ota.server.tls_ca_bundle` is removed from `board.schema.json` (#1493).
- **Third-party** — the GD32G5x3 firmware library is no longer redistributed (#2702); `coreMQTT-SN` is dropped (#1784).
