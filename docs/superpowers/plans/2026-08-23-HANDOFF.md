## Environment traps found the hard way

Worth reading before the first command; each of these cost real time.

- **`test-all.sh` exits 0 while reporting `N stage(s) failed`.** Never branch on
  `$?`. Read the stage table at the end of the log. Same trap with twister: a
  bare run can exit 0 on a failed test, and a *skipped* test still counts inside
  "N of N passed" — read `<out>/twister.json` per-testcase status.
- **Never pipe a long-running command through `tail`.** `tail` cannot emit until
  stdin closes, so the run looks hung and you lose the output. Redirect to a
  file and read the file.
- **On Windows, a git worktree is unusable from WSL** until its `.git` file is
  rewritten to a *relative* `gitdir:`. A worktree's `.git` holds an absolute
  Windows path that WSL mangles into
  `/mnt/c/.../<worktree>/C:/Users/...`, so every gate that shells out to
  `git ls-files` or `git rev-parse` dies. Fix:
  `printf 'gitdir: ../alp-sdk/.git/worktrees/<name>\n' > <worktree>/.git`.
  Works under both Windows git and WSL git. Not an issue on a native Linux box.
- **`py -3` resolves to Python 3.9 on the Windows box**, while
  `pyproject.toml` declares `requires-python = ">=3.10"`. Several scripts use
  `Path.write_text(..., newline="")`, which is 3.10+. Use an explicit ≥3.10
  interpreter. On Linux `python3` is fine — check `python3 --version` once.
- **`scripts/gen_soc_peripheral_instances.py` needs `$ZEPHYR_BASE`** or it falls
  back to a conventional `<topdir>/zephyr` that may not exist, and
  `generated-files` fails with a `MISSING ...dtsi` line.
- **Merge conflicts in generated files have a tool**:
  `scripts/resolve_generated_conflicts.py` regenerates `alp.lock`, the ABI
  snapshot, `metadata/catalog.json` and the `--emit` goldens *over the merged
  tree* rather than picking a side. It deliberately refuses to run while a
  non-generated conflict is unresolved, because it would otherwise hash conflict
  markers.

## Inherited reds — not yours

`test-all.sh` cannot go fully green on a branch cut from `dev` today. **The
list below is host-dependent — re-measure it on your own box before citing
it.** Measured 2026-08-23 on the alplab-gw Linux box (`ZEPHYR_BASE=/home/caner/zephyr`,
Zephyr v4.4.1, python3 3.12.3):

- **`required-gate-scripts` — INHERITED.** `scripts/check_emit_snapshots.py`
  reports 4 changed goldens: `scaffold.minimal-v2n101`,
  `scaffold.peripheral-v2n101`, `scaffold.sensor-v2n101`,
  `scaffold.multicore-mailbox-aen801`. Proven inherited by running the gate in
  a pristine `git worktree add <tmp> f78427c6b` with none of the branch's
  changes present — same four DIFFs. Note the stage prints ~650 lines and the
  failing script's own output can be EMPTY, so `grep FAIL` on the stage log
  finds nothing; the way to identify it is
  `for s in $(python3 scripts/quality_tasks.py --gate-scripts); do python3 "$s" >/dev/null 2>&1 || echo "$s"; done`.
- **shellcheck and pytest `tests/scripts` were GREEN here**, contradicting the
  two reds this section previously listed (SC2054/SC2034, and 7 ×
  `FileNotFoundError: 'west'`). `west` resolves on this box, which is what the
  pytest failures were about. Do not assume those two are red.
- **`alp-lock` is NOT inherited — it is usually yours.** Any edit under
  `metadata/` moves `digests.metadata` and `stage_alp_lock` fails until you run
  `python3 scripts/west_commands/alp_lock.py --workspace .` and commit
  `alp.lock`. Confirmed clean on the pristine `dev` worktree.
- **`generated-files` false-fails on an UNCOMMITTED change to any generated
  path.** The stage regenerates, then `git add -N` + `git diff`s
  `include/alp docs/abi src/cap.c src/status_strings.c metadata/catalog.json
  metadata/error-catalog.json metadata/pinmux metadata/socs/renesas/rzv2n/n44.json
  docs/portability-matrix.md docs/peripheral-support-matrix.md
  docs/verification-status.md docs/diagnostics`, so a working-tree edit to a
  public header shows up as "OUT OF SYNC" even when no generator produced it.
  **Commit first, then run the stage.** Cost an hour on #1637.

Per `alp-lab:opening-github-prs-and-issues`, a red inherited from base is not
yours to fix in a disjoint PR — but do not claim "full local gate green" either.
