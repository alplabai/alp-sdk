### Added — tier-2 model-perf: the bench-measured perf-point contract (schema + validator + capture doc) (#1520)

Lands the *contract* half of the tier-2 edge-AI fit/perf lifecycle
(docs/superpowers/specs/2026-07-24-edge-ai-lifecycle-roadmap.md sub-project
1): `metadata/schemas/model-perf-v1.schema.json` defines one bench-measured
performance point, keyed on **measurement identity** rather than on a model
or a SoM alone — SKU, hw_rev, compile target (backend + accel_config + core
+ the exact compiler build), the exact source-model bytes, and the vela
profile when one applies. Compiler build (`target.compiler_version`, e.g.
`vela 4.1.0`) is in the identity key because a compiler upgrade alone can
move `arena_bytes`/`latency_ms` for otherwise-identical everything else —
without it, a re-capture under a newer compiler silently overwrites the old
point at the same filename.

A dedicated collector (`_collect_model_perf_files`,
`scripts/validate_metadata.py:2005`) walks the whole
`metadata/model_perf/` tree and FAILS on anything that isn't exactly
`<SKU>/<hash>.yaml` two levels deep — a stray file, a `.yml` sibling, or a
point nested one level too deep (`<SKU>/_fixture/<hash>.yaml`, the precise
evasion the `_fixture` refusal below exists to catch) — rather than the
one-level glob it replaces silently never opening it.
`scripts/validate_metadata.py:2166` (`_check_model_perf_semantics`) adds the
semantic cross-checks a schema can't express: the path reproduces the body
(directory == `sku`, filename == a content hash of the identity fields —
`scripts/validate_metadata.py:2060`, `_model_perf_identity_hash`); the SKU
exists; the `(backend, accel_config)` pair and `core` are ones the SKU
actually resolves (cross-checked against `alp_model.targets.resolve_targets`
and `npus[].paired_core`); `hw_rev` is a key in the family
`hw-revisions.yaml`; an `ethos_u` point records its `vela:` system/memory
profile (vela otherwise silently falls back to its own DRAM-backed default,
`Ethos_U85_SYS_DRAM_Mid` / `Dedicated_Sram_384KB`, on silicon with no DRAM)
and a non-`ethos_u` point carries no leftover `vela:` block; `req_sram_kib`
covers `arena_bytes`; `p95` is never below `mean` and `p50` is never above
`p95`; a `latency_ms` block needs at least
`scripts/validate_metadata.py:2001` (`_MODEL_PERF_LATENCY_RUN_FLOOR = 30`)
runs; `capture.date` parses as ISO-8601; and any `_fixture`-named SKU
directory or filename is refused outright in the published tree.

`tests/scripts/test_model_perf_metadata.py` carries one real fixture point
(E1M-AEN801's actual `ethos-u55-256` target on its actual paired `m55_hp`
core and its actual `r1` hw_rev, under `tests/fixtures/model_perf/`) plus a
one-field mutation per rule above, so none of the eleven checks can go
quietly vacuous. `docs/bench/model-perf-capture.md` is the capture recipe,
written before any bench time is spent: it names its own three open
blockers plainly (which vela profile a module should compile under,
whether `req_sram_kib` should also cover the model's const/weight region,
and that no AEN example times an inference yet -- `<alp/inference.h>`
exposes no latency accessor), and its step 3 now spells out `req_sram_kib`
as `ceil(arena_bytes / 1024)` -- rounding down (as vela's own summary CSV
and the `.alpmodel` manifest's `Target.requires.sram_kib` both do) fails the
"covers arena_bytes" check on almost any real capture.

**`metadata/model_perf/` stays empty.** This PR lands the contract only — a
perf point comes off real Alp Lab bench silicon or it does not exist, and
none has been captured. The three blockers above gate that follow-on bench
work, not this PR.
