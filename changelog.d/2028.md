### Removed — the custom `AE822_ALP_M55_HE` J-Link device install script, which corrupted MRAM (#2028)

`scripts/bench/aen/install-jlink-alif-device.sh` registered a custom J-Link
device `AE822_ALP_M55_HE` into `~/.config/SEGGER/JLinkDevices/`, pairing the
generic Cortex-M55 connect with a patched-sector-size copy of Alif's
`Ensemble.FLM`, for probes that could not select SEGGER's built-in
`AE822FA0E5597LS0_M55_HE` profile. Bench-measured 2026-09-05: cold-cycle
persistence with the patched FLM was only 1 of 4 runs byte-exact, and
`aen-wdt-feed` failed 2 of 2 with 380 then 247 mismatched bytes out of
78752 — non-deterministic, with stable reads (two readbacks byte-identical,
`cmp` = 0), so not a floating-read artifact. A corrupted image then fails
SES verification (`cc_verify_image: cert_verify_wrapper returned
0xF1000009`, `[ERROR] Error code 0x0000000e; object_type=0x4;
image_id=ALP-HE`, flags `u s`) and never boots.

The replacement is SEGGER's built-in `AE822FA0E5597LS0_M55_HE` profile,
which works now that the bench probe is J-Link V13 firmware
(`JLINK_EMU_HasCapEx(0x00000052)` returns 1, was 0): 3 of 3 flashes
cold-cycle byte-exact, 0 mismatched bytes, flags `u VB`.
`scripts/bench/aen/bench-env.sh` already defaults `JLINK_DEVICE_FLASH` to
the built-in profile, so the install script was a loaded footgun rather than
a live fallback. The full corruption evidence and the "use the built-in
profile instead" guidance remain in
`scripts/bench/aen/flash-jlink-mramxip.sh`'s `#1902` comment block, which
already warns at runtime if `JLINK_DEVICE_FLASH=AE822_ALP_M55_HE` is set.

`scripts/check_cross_platform.py`'s `INTENTIONALLY_BASH_HELPERS` allowlist
entry for the deleted script is removed with it.
