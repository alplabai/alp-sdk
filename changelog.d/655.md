### Added — a metadata source for the V2N/V2M GD32G553 supervisor pin wiring, generating the board pinctrl.dtsi/_defconfig (#655)

`metadata/e1m_modules/v2n/supervisor-links.yaml` is a new, hand-authored,
family-scoped source (schema `supervisor-links-v1`, covers both `v2n` and
`v2n-m1`) for the on-module GD32G553 supervisor bridge's Renesas-side pin
wiring: `gd32_spi` (SCI7 clock-synchronous Simple-SPI, alias `alp-spi1`,
plus a deliberately-unmuxed `gpio_chip_select` on P97), `brd_i2c` (RIIC8/
BRD_I2C, alias `alp-i2c0`, `peer_address_7bit: 0x70`), and `console`
(SCI_UART0, `status: disabled` -- the EVK "Pmod USB-UART", not a CM33
console on this board; the floating-RX fault is recorded in the console
pins' own `evidence:` strings). Every pin row and the GPIO chip-select
carries a non-derivative `evidence:` citation (the RZ/V2N PFC table,
`docs/errata-e1m-x-v2n.md`, or `metadata/chips/gd32g553.yaml`) -- never a
generated file.

`scripts/gen_zephyr_board.py` grows two new emitters, `_v2n_pinctrl_dtsi()`
and `_v2n_defconfig()`, wired into `emit_zephyr_board()`'s
`elif family in ("v2n", "v2n-m1")` branch: the committed
`zephyr/boards/alp/e1m_v2n101_m33_sm/alp_e1m_v2n101_m33_sm-pinctrl.dtsi` +
`..._defconfig`, and their byte-identical `e1m_v2m101_m33_sm` siblings, are
now GENERATED, gated byte-for-byte by
`tests/scripts/test_gen_zephyr_board.py`. The board `.dts` stays
hand-authored in this slice -- `test_v2n_dts_stays_hand_authored` (renamed
from `test_v2n_dts_pinctrl_defconfig_stay_hand_authored`) narrows the
claim set from three files to five and pins the `.dts` as the one file
still outside it.

`scripts/validate_metadata.py` registers the new schema
(`SUPERVISOR_LINKS_SCHEMA` / `SUPERVISOR_LINKS_DATA`) and adds
`_check_supervisor_links_cross_refs()`: every
`(silicon_peripheral, silicon_pad)` pair in `supervisor-links.yaml` --
every pin row plus `gd32_spi.gpio_chip_select` -- must resolve to exactly
one `owner: "renesas"` row in `metadata/pinmux/v2n.yaml`, with
`core: "m33"` where that row carries a `core:` key at all (the console's
`UART0_TXD0`/`UART0_RXD0` rows legitimately carry none, per
`metadata/e1m_modules/v2n/core-ownership.yaml`'s own note on why absence
is never "a55 by elimination"). `brd_i2c.peer_address_7bit` is
cross-checked against `metadata/chips/gd32g553.yaml`
`i2c.default_address_7bit` the same way -- recorded to be verified, not an
independent authority.
`tests/scripts/test_gen_zephyr_board.py::TestSupervisorLinksPinmuxCrossCheck`
proves the cross-check actually goes red on an unresolvable pair.

`metadata/e1m_modules/v2n/core-ownership.yaml`'s six `evidence:` fields
(`GD32_SPI.*`, `RIIC8_*`) previously cited the hand-authored
`alp_e1m_v2n101_m33_sm-pinctrl.dtsi` / `...cm33.dts` by line number; now
that the `.dtsi` is generated output, those citations are repointed to
the same non-derivative sources `supervisor-links.yaml` uses (the PFC
table, the errata entry, the RIIC8 clk-gating patch, `gd32g553.yaml`) --
every substantive fact (the errata E3 P9.6/SCK7 collision, the RIIC8
bus-fault-until-power-cycle history) is preserved, none dropped.
