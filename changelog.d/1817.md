### Added — BOD gains a devicetree node; TSENS documented as an ADC channel, not a new node (#1817)

Four E8 analog blocks the datasheet lists as features had no path in alp-sdk. Of the four:

- **ADC24** already had a node (`adc24_0` in `ensemble_e8_peripherals.dtsi`) — the gap is that no
  example enables it, which is example-authoring work outside a single dtsi-file change; left
  undone here.
- **On-die temperature sensor**: the HWRM (§19.5 TSENS Overview) states it has no register block
  of its own — "The TSENS is connected internally to input channel 6 of ADC120 and ADC122" — so
  there is no devicetree node to add. A comment on `adc12_0`/`adc12_2` now records this so a future
  reader does not go looking for a `tsens@...` node that was never going to exist. Surfacing it as
  a named temperature reading (vs. raw ADC counts) is backend/application work, left undone.
- **Internal precision reference (VREF_P/VREF_N)**: the issue itself scopes this to
  `metadata/socs/alif/ensemble/e8.json` and board metadata, not `ensemble_e8_peripherals.dtsi` —
  outside this change's file scope. Left undone.
- **BOD (Brown-Out Detect)**: added a disabled node, `bod0`, at the shared `BOR_BOD` register
  block (HWRM Table 10-4 + Table 19-32, base `0x4200_4000`) with `interrupts = <100 3>`
  (`M55HE_IRQS[100]` `BOD_IRQ`, HWRM Table 8-5). No Zephyr brown-out class API exists upstream and
  alp-sdk carries no vendored one, so a new minimal binding
  (`zephyr/dts/bindings/misc/alif,bod.yaml`) declares the node without a driver — matching this
  batch's `alif,lpcmp.yaml` precedent (#1816). BOD is distinct from BOR (outright reset, not
  modelled by this node) and from the external supervisor errata ER004 requires (out of scope,
  filed elsewhere). The Datasheet's own §3.7.4/Table 3-5 (not the HWRM, which has no §3.7.4 —
  the same content is at HWRM §8.1.5) also documents `BOD_DMA_REQ`; the actual request number,
  `DMA2_REQ[7]`, is HWRM Table 8-6. DMA wiring is #1815's territory, not modelled here.
