### Fixed — provisioning tool fixes from the first V2M103 silicon run (#2554)

The first real-hardware pass of `scripts/provision_som.py` surfaced four defects and one missing option, each now covered by a test under `tests/scripts/test_provision_*.py`.

`scripts/provision/linux_target.py:420` ("if [ $n -ge {poll_ms} ]; then exit 3; fi; done") fixes the EEPROM write-cycle ACK poll: the old `[ $n -ge N ] && exit 3` body was a false test after any retry, so the `until` loop exited 1 and every real write reported failure after a good write.

`scripts/provision/steps.py:1257` ("Steps finished in EARLIER invocations") makes `record` merge the evidence of steps already `done`/`skipped` in the state file, with this run's facts winning, so `--only`/`--from` runs still fill the ledger. `Gd32Flash` now records `gd32_fw_version` from `<gd32-fw>/VERSION`, and `census` records `dtb_name` from `/proc/device-tree/{model,compatible}`.

`scripts/provision_som.py` gains `run --hw-rev rN`, applied after the bundle hash so earlier steps stay valid when a batch mixes module revisions. Target SSH now pins each unit's host key instead of trusting any: `HostKeyAlias=<SKU>-<serial>-<sd|emmc>`, `UserKnownHostsFile=<ledger>/<serial>.known_hosts` and `StrictHostKeyChecking=accept-new` at `scripts/provision/linux_target.py` ("accept-new"), so the first contact records the key and a different unit behind the same IP is refused; the SD and eMMC images carry different host keys, hence one alias per boot source. `--hw-rev` is validated against the family's `hw-revisions.yaml` and refuses (exit 2) an unknown, wrong-case or non-`production` key. Output is forced to `errors="replace"` at startup so a U+FFFD from serial text no longer crashes a cp1252 Windows console.

**BEHAVIOUR CHANGE.** V2N101/102 and V2M101/102 are one physical PCB (board 2625), so `metadata/e1m_modules/v2n/hw-revisions.yaml` now declares `board_datecode: "2625"` like `v2n-m1`, and `r2` is a `production` revision (`board_rev: "R2"`). The datecode changes the EEPROM `hw_rev` field and `CONFIG_ALP_SDK_SOM_HW_REV` for every V2N/V2M build from `r1` to `2625-r1`. Units provisioned earlier with a bare `r1` mismatch the new build (fatal with `CONFIG_ALP_SDK_HW_REV_MISMATCH_FATAL`) until they are re-provisioned. Firmware for an r2 unit must be built with `som.hw_rev: r2`. The composed string is limited to 7 characters (`2625-r2` fits, `2625-r10` does not).
