### Added — aen-sdhc-probe captures the registers sdhc_dwc reset() should restore (#2181)

`sdhc_dwc_reset()` re-applying the DWC SDHC controller's configuration was
unmeasured: no before/after capture existed for the registers
`sdhc_dwc_set_def_config()` programs at init. `sdhc_dwc_reset()` is
`sdhc_dwc_hw_reset(dev, SW_RST_ALL)` and nothing else — it never re-calls
`sdhc_dwc_set_def_config()` — so this is verification debt, not a
demonstrated bug.

Changes:
- `examples/aen/aen-sdhc-probe/src/sdhc_reset_capture.h` — new
  `struct sdhc_reset_regs` (the seven registers the issue names) and a
  pure, host-testable `sdhc_reset_regs_equal()`.
- `examples/aen/aen-sdhc-probe/src/main.c` — new PROBE 3, only compiled on
  a board where `sdhc0` is enabled: captures the register set before
  `sdhc_hw_reset()`, calls it, captures again, prints both, and prints
  MATCH/MISMATCH. Produces the evidence for a later bench run; this change
  does not itself run on silicon.
- `tests/unit/sdhc_reset_regs_compare/` — native_sim unit test pinning
  `sdhc_reset_regs_equal()`'s comparison logic without hardware.

Still open: the actual before/after register values on real silicon, and
whether `sdhc_dwc_reset()` needs a `sdhc_dwc_set_def_config()` call added —
both need a bench run on the reworked-mux carrier and, if a MISMATCH is
confirmed, a maintainer decision on whether it is a driver bug.
