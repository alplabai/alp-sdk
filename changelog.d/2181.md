### Added — aen-sdhc-probe captures the registers sdhc_dwc reset() should restore (#2181)

`sdhc_dwc_reset()` re-applying the DWC SDHC controller's configuration was
unmeasured on real silicon: no before/after capture existed for the
registers `sdhc_dwc_set_def_config()` programs at init. #2122 already made
`sdhc_dwc_reset()` re-call `sdhc_dwc_set_def_config()` after its
`SW_RST_ALL`, unconditionally, so RESTORED is the expected reading of
today's code; this is verification of #2122's fix against silicon, not a
demonstrated bug.

Changes:
- `examples/aen/aen-sdhc-probe/src/sdhc_reset_capture.h` — new
  `struct sdhc_reset_regs` (the seven registers the issue names), a pure,
  host-testable `sdhc_reset_regs_equal()`, and
  `sdhc_reset_regs_matches_def_config()` — the primary check, since
  `sdhc_dwc_init()` already calls `sdhc_dwc_reset()` at `POST_KERNEL`
  before `main()` runs, so a capture taken at `main()` entry is itself
  post-`set_def_config()`, not pre-reset; comparing it to the post-probe
  capture alone could never catch a silently no-op `set_def_config()`.
- `examples/aen/aen-sdhc-probe/src/main.c` — new PROBE 3, only compiled on
  a board where `sdhc0` is enabled: captures the register set at `main()`
  entry (boot state), calls `sdhc_hw_reset()`, captures again, and checks
  the after-capture against `set_def_config()`'s fixed values (RESTORED /
  NOT RESTORED) as the primary verdict, with the before/after comparison
  (MATCH/MISMATCH) as a secondary check. Produces the evidence for a later
  bench run; this change does not itself run on silicon.
- `tests/unit/sdhc_reset_regs_compare/` — native_sim unit test pinning
  both `sdhc_reset_regs_equal()` and `sdhc_reset_regs_matches_def_config()`
  without hardware.

Still open: the actual before/after register values on real silicon. If NOT
RESTORED is confirmed there, that would be a #2122 regression worth its own
issue, not a gap in `sdhc_dwc_reset()`'s current source.
