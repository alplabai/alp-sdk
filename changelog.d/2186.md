### Fixed — a changelog citation that looked anchored could go unverified, and a new one could skip its anchor entirely (#2186)

`scripts/check_changelog_citations.py` text-verifies a citation only when its
anchor parses; every other citation is range-checked (the line exists, the text
is never compared). On `dev` before this change the gate printed
`750 citation(s) resolved across 327 fragment(s) + CHANGELOG.md (396 anchored
and text-verified, 354 range-checked only, 14 skipped)` — a pass that asserted
nothing about the text of almost half the citations in the repo. Three holes
fed that bucket, and each is closed here.

**A new citation must be anchored.** A citation on a line added relative to a
base now fails the gate unless it carries a parsed, text-verified anchor
(`scripts/check_changelog_citations.py:903` ("def _added_lines(base: str)")).
"Added" is `git diff --unified=0 $(git merge-base BASE HEAD) -- changelog.d/`
against the working tree, so staged and unstaged edits count, and every line of
an untracked fragment counts — a fragment is graded while it is being written.
Diffing from the merge base rather than from BASE keeps lines BASE gained after
the branch point, or that a merge of BASE brought in, from being charged to the
branch. BASE is `DIFF_BASE`, default `origin/dev`
(`scripts/check_changelog_citations.py:846` ("def _resolve_base()")). With no
base available the rule degrades loudly: an explicit `DIFF_BASE` that does not
resolve exits 2, and an unset one with no `origin/dev` prints a WARN and a
`new-citation rule: NOT APPLIED` line naming why. Every passing run now prints
what it graded and how many citations the rule saw on added lines. The diff is
read with `core.quotePath=false` and a path's trailing TAB stripped, and any
`+++` header that is neither `b/<path>` nor `/dev/null` exits 2: before that, a
committed fragment named with a space or a non-ASCII character parsed as "no
path", and its lines silently escaped the rule. Existing un-anchored citations
are grandfathered — nothing can anchor one without guessing — and CHANGELOG.md
is exempt, because the release-cut fold moves hundreds of grandfathered
citations into `[Unreleased]` at once and moving a citation is not writing
one. A foreign-repo citation is still only SKIPPED. CI turns the rule on for a
PR into `dev` with `DIFF_BASE=HEAD^1`
(`.github/workflows/pr-metadata-validate.yml:609` ("github.base_ref == 'dev' && 'HEAD^1'")),
the first parent of the PR's merge commit, which the checkout now fetches with
`.github/workflows/pr-metadata-validate.yml:232` ("fetch-depth: 2"). Not on a
PR into `main`: `HEAD^1` is `main` there, and every line of every fragment
`dev` has not folded yet would count as new (272 errors measured), so the gate
warns that the rule did not run. A `workflow_dispatch` of `dev` runs it
vacuously, since `origin/dev` is HEAD.

**A near-miss anchor is a hard error, on every citation.** Two shapes read as
anchored to a human and anchored nothing. The paren opened before the
citation, `` (`path:NNN`, "text") ``, puts the quote inside the citation's own
parenthetical, where `_ANCHOR` never looks
(`scripts/check_changelog_citations.py:299` ("_PAREN_BEFORE = re.compile(")):
this is the shape `changelog.d/2195.md` used for 5 of its 8 citations, two of
them 187 and 10 lines off and green throughout. The other is `(` plus a
delimiter right after the citation that `_ANCHOR` then declined — text under 4
or over 120 characters, unterminated, or holding a delimiter past its first
character, such as `` (`: 1`) `` or `` (`i2s"`) ``
(`scripts/check_changelog_citations.py:286` ("_ANCHOR_OPEN = re.compile(")).
The detector in #2184 caught only a delimiter at offset 0, and its error text
said so; that caveat is gone because the hole is. Every near-miss error shows
the correct form; the paren-before one fills it in with the author's own quote
when that quote does not open with a backtick, and the other uses a
placeholder. `--fix` reports a near miss as needing a human rather than
counting it un-anchored. Old citations are included because a near miss is an
author who tried to anchor, and grandfathering them kept known-wrong lines
green: `dev` held 9 in the first shape and 0 in the second, and 4 of the 9
cited the wrong line —
`changelog.d/1988.md` pointed at lines 1261, 1321 and 1123 of
`scripts/gen_zephyr_board.py` (each 39 lines short, now 1300, 1360 and 1162)
and at line 232 of `metadata/e1m_modules/aen/on-module-links.yaml` (now 235).
All 9 are repaired: the quote moved after the citation, then `--fix`
re-derived the four drifted ones from it. `changelog.d/2076.md` and
`changelog.d/2140.md` needed only the syntax; `changelog.d/1958.md` quoted a
before-and-after edit rather than an anchor, so its quotes moved out of the
parenthetical and the citation got a real anchor. A range's anchor has to quote
its FIRST line, because `--fix` restarts the range at the line the anchor is
found on (#2177), so `changelog.d/1516.md` now quotes line 14 of its `:14-15`
and `changelog.d/1916.md` cites only the `:285` it quotes; `changelog.d/README.md`
now states that rule. An anchor whose quote is broken across a markdown line
now says so instead of claiming the code moved.

**`--against-merge` grades what will land.** CI already grades the merge
result: `pr-metadata-validate.yml` runs on `pull_request` and its
`.github/workflows/pr-metadata-validate.yml:224` ("uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1")
pins no `ref:`, so it checks out `refs/pull/N/merge`. The gap was local, where
a green run on the branch tip said nothing about citations into files `dev`
had since moved. The new mode builds BASE merged into HEAD with
`git merge-tree --write-tree`, never the three-argument form, and grades that
tree straight from the object store, touching no file, index or ref
(`scripts/check_changelog_citations.py:928` ("def _merge_tree(base: str, base_ref: str) -> str:")).
Its dirty-tree check runs `git --no-optional-locks status`, since a plain
`git status` rewrites the index. It grades committed HEAD only and warns when
the working tree is dirty; a HEAD that does not merge cleanly exits 1 naming
the conflicted files; a base that is already an ancestor of HEAD is reported
as grading HEAD's own tree, not a merge; and it refuses `--fix`, because the
merge is not in the working tree. `scripts/test-all.sh` runs it as its own
`changelog-citations-merge` stage with `origin/dev` passed explicitly, since
`DIFF_BASE` is shared with the clang-format stage
(`scripts/test-all.sh:823` ("DIFF_BASE=origin/dev python3 scripts/check_changelog_citations.py --against-merge")).
A host without `git merge-tree --write-tree` (git before 2.38: Ubuntu 22.04
ships 2.34, Apple's git is 2.37) or without `origin/dev` gets a `[GAP]` SKIP
naming the reason instead of a failed stage, and the pytest cases that need
it skip there too. Still open: `pr-metadata-validate.yml` has no
`merge_group` trigger, so the merge CI grades is the one computed at the PR's
last push, and a `dev` that moves afterwards is caught only by a re-run.

The two deferred nits from the issue had already landed with #2194. The
mutation count in `main()`'s `--fix` placement comment was re-measured against
the grown suite: moving the `--fix` block below the early return still leaves
all 64 tests passing. The 22 new tests
(`tests/scripts/test_check_changelog_citations.py:1055` ("def test_against_merge_grades_the_merge_not_the_tip("))
were mutation-proven: 21 separate mutations of the new code each turn at least
one of them red.
