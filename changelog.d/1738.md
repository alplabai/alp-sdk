### Fixed — `check_emit_snapshots.py` was red on `dev` because scaffold doc links pin to a checkout-dependent GitHub ref (#1738)

`scripts/check_emit_snapshots.py` failed on a clean `origin/dev` checkout: four
scaffold goldens (`scaffold.minimal-v2n101`, `scaffold.peripheral-v2n101`,
`scaffold.sensor-v2n101`, `scaffold.multicore-mailbox-aen801`) no longer matched
the emitter. The gate runs only inside `scripts/test-all.sh` and has no
standalone PR workflow, so the red was invisible unless someone ran the full
local gate set -- and every branch inherited it.

The drift is entirely the GitHub ref that a scaffolded README's doc links pin to.
`scripts/alp_template.py::_docs_ref()` returns `v<version>` when
`metadata/sdk_version.yaml` says `status: released` **and** that tag actually
resolves in the checkout, else `main`. Tag resolution is a property of the
CHECKOUT, not of the code: a full clone with tags fetched emits
`blob/v0.16.0/docs/...` while CI's shallow, tagless clone emits
`blob/main/docs/...` from the very same commit. No committed golden can be
byte-identical on both, so whichever environment last ran `--update` was green
and the other was red -- which is why simply regenerating the goldens had
previously been the wrong fix (it moved the red onto CI rather than removing it).
The same segment also moves at every release even on one host, which would have
made these four goldens a recurring red at each version bump.

Fixed by tokenising that one segment in the checker's existing normalisation
chain, alongside the `sdkCommit` value already tokenised there for the same
"can never be stable across the writing and checking hosts" reason:
`https://github.com/alplabai/alp-sdk/blob/<ref>/` becomes
`.../blob/<DOCS_REF>/`. Only the ref is tokenised -- the doc path each link
points at stays real, so a doc that moves or disappears still fails the gate,
and links to any other repository are left untouched.

The four goldens are regenerated with the token (4 files, one line each; no
other content moved). `scripts/check_emit_snapshots.py` now reports all 37
`--emit` surfaces byte-identical, and does so from both a tags-fetched checkout
and a tagless shallow clone. Five unit tests in
`tests/scripts/test_check_emit_snapshots.py` cover the released-tag form, the
`main`/`v<version>`/next-release equivalence, that a moved doc path still
differs, and that other repositories' links are untouched.

This removes the standing "expected failure" that made every
`required-gate-scripts` run need a hand-applied artifact discriminator to tell a
real break from this one. #1686 (the underlying emit non-determinism) remains
open and is unchanged by this; it is now a gate-green condition rather than a
permanent red.
