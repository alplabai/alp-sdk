### Fixed — `flash-all-flowd.sh` can flash a serial-less bench again, and a refused batch now explains itself (#2189)

`scripts/bench/aen/flash-all-flowd.sh` invoked the Flow D writer with
positional arguments only, forwarding neither `--atoc-unqueryable` nor
`--replace-atoc`. Since #2029 made `--atoc-unqueryable` mandatory when the
resident ATOC cannot be queried, **every entry in the batch aborted with exit
8 on a bench slot with no `SE_UART` exported, and the batch flashed nothing at
all** — and on a slot with no SE-UART wired at all, where Flow D is the only
load path, that left the batch runner entirely non-functional. `#2027`/`#2080`
re-armed the query path for slots that do export `SE_UART`, which is why this
went unnoticed there.

The regression dates from `ff2f316d` (#2029, merged 2026-09-07);
`flash-all-flowd.sh` was itself edited afterwards by `d1ac97d` (#2032/#2064)
without its call site being updated.

**The flag is opt-in, not hardcoded.** A new whole-argv scan at
`scripts/bench/aen/flash-all-flowd.sh:51-59`
(`--atoc-unqueryable) ATOC_UNQUERYABLE=(--atoc-unqueryable) ;;`) collects it
and forwards it verbatim at
`scripts/bench/aen/flash-all-flowd.sh:125`
(`flash-jlink.sh` invocation). Hardcoding it at the call site would have made
the batch replace the ATOC blindly on every run with the acknowledgement
recorded nowhere — the #2025 hazard, re-entered through the batch runner — so
the property #2029 and #2027 both protect is preserved: the operator says
"I cannot check" once, deliberately. `--replace-atoc` is deliberately **not**
forwarded; `scripts/bench/aen/flash-jlink.sh:39-42`
(`will pass this on every single Flow D`) states why the two flags must never
be merged or aliased.

The parser is the same whole-argv `for` shape `flash-jlink.sh` already uses for
this flag rather than `flash-run.sh`'s `while`/`shift` loop, because this
script's positionals are a variable-length app list: a parser that stops
honouring flags at the first non-option token would silently ignore
`flash-all-flowd.sh aen-wdt-feed --atoc-unqueryable`, and silently ignoring
this flag is the bug being fixed. Verified both orderings are honoured and that
the flag never lands in the app list.

**Exit 8 now has its own summary arm**, at
`scripts/bench/aen/flash-all-flowd.sh:164-170`
(`FLASH-REFUSED (no resident-ATOC check available)`), where before it fell to
the catch-all `FLASH-ERROR (exit $frc)` — the one Flow D exit code the summary
map did not explain.

Unlike every other arm, this one **breaks the batch** instead of continuing.
That is a deliberate departure from the script's "a failed app is logged and
the batch continues" design, and it is scoped to this single code: exit 8 is a
run-level configuration refusal decided before any probe or target access, so
it cannot differ between apps and every remaining entry would abort
identically. Continuing produced a `BATCH SUMMARY` that was 100% failure with
no board ever written and no line naming the cause. Entries already processed
keep their real verdicts and the `BATCH SUMMARY` still prints. Every other
exit code keeps the per-app resilience unchanged.

**Regression coverage**, in a new
`tests/scripts/test_bench_flash_all_flowd.py`, which drives the real batch
runner against a stub `flash-jlink.sh` that records its own argv and exits
with a scripted status — no probe, no module, no SETOOLS install. It pins
both orderings of the flag
(`tests/scripts/test_bench_flash_all_flowd.py:205`
(`test_atoc_unqueryable_after_the_app_list_is_still_honoured`)), that it
reaches every child rather than only the first, that it never lands in the
app list, that it is absent when nobody asked for it
(`tests/scripts/test_bench_flash_all_flowd.py:248`
(`test_the_flag_is_opt_in_and_never_hardcoded`)), that `--replace-atoc` is
not forwarded, and the whole exit-8 contract — the `FLASH-REFUSED` label, the
early stop, the earlier entries keeping their own verdicts, and the
`BATCH SUMMARY` still printing
(`tests/scripts/test_bench_flash_all_flowd.py:285`
(`test_exit_8_is_labelled_stops_the_batch_and_still_summarises`)). One test
pins the *other* direction too: a per-app failure must still continue the
batch, so a later "simplification" cannot turn one bad verify into a dead
run.

Every assertion was mutation-proven against the fixed script: dropping the
forwarding, hardcoding the flag, swapping the whole-argv scan for
`flash-run.sh`'s `while`/`shift` loop, deleting the exit-8 arm, turning its
`break` into a `continue`, relabelling it back to the catch-all, and
forwarding `--replace-atoc` each turn the expected test red and no other.

`scripts/bench/aen/README.md`'s batch-runner row documented the pre-change
contract — no flag in the signature, exit 8 unexplained, the serial-less
batch described as unusable — and is updated in the same change: the
signature, the opt-in acknowledgement semantics, the `FLASH-REFUSED` label
and early stop, and the summary contract.
