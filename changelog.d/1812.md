### Fixed — `alp_power_configure_wake_source()` lied about arming a wake source it could never honour on stock AEN builds (#1812)

On a default `alp_e1m_aen801_m55_he/ae822fa0e5597ls0/rtss_he` build, pinned
upstream Zephyr 4.4.0's Alif E8 SoC does not `select HAS_PM`, so `CONFIG_PM`
is unreachable and `src/backends/power/zephyr_pm_policy.c` (gated `depends
on PM`) never compiles in. `src/backends/power/zephyr_stub.c`'s wildcard
priority-0 fallback wins `alp_backend_select("power", ...)` instead.
`alp_power_open()` and `alp_power_configure_wake_source()` both returned
`ALP_OK`; only `alp_power_request_sleep()` returned `ALP_ERR_NOSUPPORT` — a
caller found out its setup was pointless only after asking to sleep. No AEN
example called the portable `<alp/power.h>` surface at all, so nothing in CI
noticed.

Shipping the full `alif_aipm` SE-backed power backend the issue's "Proposed
resolution" describes (`SERVICES_power_wakeup_config` /
`_mem_retention_config` / `_stop_mode_request` / the VTOR-save calls for warm
resume) is out of scope for this change: it needs bench time on real E8
silicon this pass didn't have, and faking a sleep path that has never
actually entered STOP on hardware would be worse than the bug it replaces.
Landing that backend is tracked as follow-on work; #1813 settles the
`<alp/power.h>` shape it needs first.

What lands now is the issue's accepted minimum: the failure moves to
configuration time. `zephyr_stub.c`'s `stub_open()` now reports
`alp_power_capabilities()->flags == 0` (it can arm nothing), and
`stub_configure_wake_source()` returns `ALP_ERR_NOSUPPORT` for any bitmap
other than `ALP_POWER_WAKE_NONE` instead of accepting it silently —
sharing the reported-capability + error contract #1813 adds to
`<alp/power.h>`. `examples/aen/aen-power-smoke` now calls
`alp_power_open()` / `alp_power_capabilities()` /
`alp_power_configure_wake_source()` / `alp_power_request_sleep()` (the exact
repro from this issue) and logs the result, informationally, before its
existing WFI/SysTick proof; this is now exercised by the AEN801 board-target
build gate. `tests/zephyr/peripheral/src/main.c`'s native_sim power-mode
ZTESTs (the same stub-backend path, no `CONFIG_PM`) assert the new
configuration-time contract directly.
