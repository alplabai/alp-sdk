### Added — the E8 low-power peripheral bank has a devicetree presence (#1816)

`zephyr/dts/alif/ensemble_e8_peripherals.dtsi` declared `lpgpio`, `lpi3c0`, `lptimer0` (channel 0
only) and `rtc0` from the low-power domain and nothing else, even though the AE822 Datasheet
(Alif_E8_Datasheet_v1.2) Table 3-3's footnote names this bank as precisely the survivor set for
STANDBY and STOP: "If RTSS-HE is powered down, then the LPI3C, LPUTIMER, LPI2C1, LPCPI, LPI2S,
LPPDM, and LPSPI0/1 in the same subsystem are also powered down" — i.e. the peripherals that keep
running while the rest of the chip sleeps had no way to be named in a devicetree at all.

Added, all `status = "disabled"` matching every other block in the file: `lpuart` (reuses the
upstream `ns16550` driver already binding `uart0..7`, since the HWRM states "all information
related to UART in this section also applies to LPUART"), `lpi2c1` (master-only, reuses the
upstream `snps,designware-i2c` driver already binding `i2c0/i2c1/i2c2` — distinct from the
slave-only, SE-mastered LPI2C0 the file already excludes for a documented reason), `lpspi0` +
`lpspi1` (the same `alif,dwc-ssi-spi` driver as `spi0`; per the HWRM the pair shares device pins
and forms a single channel, master-only on LPSPI0 and slave-only on LPSPI1, and shares ONE IRQ
line), `lpi2s` (`snps,designware-i2s`, the same driver as the main-domain `i2s3` example node),
`lppdm` (the driver + Kconfig already existed — `zephyr/drivers/audio/alif_pdm.c` — only the node
was missing; its single OR'ed IRQ line is documented against the main-domain `pdm` node's three
discrete lines), `lpcam` for LPCPI (`alif,cam`, whose binding already carried an `lp-cam` property
anticipating exactly this instance), and `lptimer1`/`lptimer2`/`lptimer3` (the three sibling
channels `lptimer0`'s own comment already documented how to add). Every reg/IRQ value is
transcribed from the HWRM's Table 10-5 Low Power Peripherals Memory Map and the M55-HE local
interrupt-number table, cross-checked against the three already-verified entries in this file
(`lpi3c0`=50, `rtc0`=58, `lptimer0`=60) rather than read cold. Three new clock IDs
(`ALIF_LPUART_CLK`, `ALIF_LPCPI_CLK`, `ALIF_LPI2S_76M8_CLK`) were added to
`alif-ensemble-clocks-ext.h`; `ALIF_LPSPI_CLK` and `ALIF_LPPDM_76M8_CLK` already existed, unused
by any node until now.

`lpcmp0` (LPCMP, the STOP-mode wake source the datasheet gives 20 µA / 10 µs response) is a
genuinely different, simpler IP from the four HSCMP instances `alif,cmp` already binds — no
driver exists for it, so a new binding (`zephyr/dts/bindings/comparator/alif,lpcmp.yaml`) declares
the node without claiming it is usable from application code.

Left undone: the LPSPI0/LPSPI1 master/slave mode-select bit (`HE_CLK_ENA[SPI_MODE]`) has no DT
property yet, and neither does LPI2C1's own software clock gate (`HE_CLK_ENA[I2C_CKEN]` bit 13) —
a board enabling either must handle these registers itself, which is driver-level follow-up, not
blocked by these disabled nodes. `lpuart` has a real, currently-unresolved correctness gap, not
just an unwired nice-to-have: none of the three `ALIF_PARENT_CLK_*` options is the LPUART's real
PCLK source (`RTSS_HE_CLK`, boot-time selectable, not a `fixed-clock` node), so the first board to
enable it gets a garbled baud rate until `clock_control_alif.c` grows a real `RTSS_HE_CLK` case or
an enabling overlay pairs a `clock-frequency` override with its own UART_CKEN-gate handling (see
`ALIF_LPUART_CLK`'s own comment for why neither is done here). LPI2C0's precision-reference/VREF
and BOD/die-temperature companions are tracked separately (#1817).
