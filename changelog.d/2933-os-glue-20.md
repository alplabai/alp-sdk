### Fixed — yocto: GPIO IRQ dispatcher and configure races, I2C close-vs-op guard (#2933, #2980)

GPIO: the line request fd is now O_NONBLOCK so the dispatcher's event
read() under g_irq.mu can no longer park the thread, and every slot
carries a generation snapshotted with the polled fd so a close + reopen
that reuses the same slot and fd number is not mistaken for the polled
pin.  alp_gpio_configure() keeps the active edge flags for an input and
disables the IRQ explicitly when switching to output, instead of
silently dropping edge detection while irq_enabled stays set.

I2C: ops are counted with alp_handle_op_enter/leave and
alp_i2c_close() drains them via alp_handle_begin_close_blocking()
before closing the fd, so a close racing an in-flight transfer can no
longer hit a recycled fd number.  SPI and UART need the same guard.
