### Fixed — connectivity examples never attached the CC3501E bridge on E1M-AEN801, so `alp_wifi_open()` returned NULL (#2112)

On E1M-AEN801, the portable `<alp/iot.h>` Wi-Fi API only reaches the on-module
CC3501E bridge once an application has attached a live `cc3501e_t` handle:
`cc35_open()` returns `ALP_ERR_NOT_READY` while the backend's static bridge
context is unset
(`src/backends/wifi/cc3501e.c:39` ("return ALP_ERR_NOT_READY;")), and
`alp_wifi_open()` (`src/wifi_dispatch.c:70` ("alp_wifi_t *alp_wifi_open(void)"))
then returns NULL. None of `mqtt-telemetry`, `iot-fleet-ota`, or
`iot-dashboard` called `cc3501e_bridge_bringup()` or `alp_wifi_cc3501e_attach()`
before `alp_wifi_open()`, so on real AEN801 silicon all three failed at
`alp_wifi_open()` and never reached `alp_wifi_connect()` — only the
`examples/aen/aen-cc3501e-*` apps and `iot-dashboard`'s own doc comment
already showed the working pattern
(`examples/aen/aen-cc3501e-bringup/src/cc3501e_bridge.c:114`
("(void)alp_wifi_cc3501e_attach(fw);")).

Fixed at the example level, not the backend: each of the three AEN-targeted
connectivity examples now copies the same `cc3501e_bridge.{c,h}` bring-up
template every `examples/aen/aen-cc3501e-*` app uses and calls
`cc3501e_bridge_bringup()` once before its first `alp_wifi_open()` —
`examples/connectivity/mqtt-telemetry/src/main.c:141`
("alp_status_t bridge_rc = cc3501e_bridge_bringup(&bridge);"),
`examples/connectivity/iot-fleet-ota/src/main.c:400`
("alp_status_t     bridge_rc = cc3501e_bridge_bringup(&bridge);") — called
once in `main()` before the poll loop, not inside `fleet_wifi_up()`, which
runs every tick and would otherwise re-run the WIFI_EN/nRESET reset sequence
on every poll — and
`examples/connectivity/iot-dashboard/src/main.c:158`
("alp_status_t     bridge_rc = cc3501e_bridge_bringup(&s_bridge);"). The
portable backend itself is unchanged: `docs/cc3501e-bridge.md` already
documents that the bring-up helper, not the dispatcher, is what attaches the
bridge, so the fix stays at the application layer that owns SoM bring-up.
`mqtt-telemetry` and `iot-fleet-ota`'s `board.yaml` gained the
`peripherals: [spi, gpio]` block the bridge helper needs (`iot-dashboard`
already carried it, anticipating this exact gap) —
`examples/connectivity/mqtt-telemetry/board.yaml:55`
("peripherals:") and `examples/connectivity/iot-fleet-ota/board.yaml:53`
("peripherals:").

No new gating mechanism: `alp_gpio_open()`/`alp_spi_open()` return NULL fast
(no backend registered for that SoC ref) when the bring-up call runs under
`native_sim`, so `cc3501e_bridge_bringup()` fails with
`ALP_ERR_NOT_PRESENT_ON_THIS_SOC` and each example falls through to the same
NULL/NOT_READY framing path it used before this fix — bench-verified via a
local `native_sim` run of all three (`[mqtt] wifi: cc3501e_bridge_bringup ->
ALP_ERR_NOT_PRESENT_ON_THIS_SOC`, then the unchanged `alp_wifi_open() -> NULL
(ALP_ERR_NOT_READY)` framing path, ending on the harness's `[mqtt] done`
marker). `examples/connectivity/iot-connected-camera` is deliberately left
untouched: its `board.yaml` targets `E1M-V2N101` only (no AEN scenario is
built anywhere in-tree) and its own README documents that choice —
`examples/connectivity/iot-connected-camera/README.md` ("## Why V2N rather
than AEN?") — and its `alp_wifi_open()` NULL there is V2N's Linux-owned radio
being unreachable from the M33 Zephyr core, not a missing bridge attach.

**Verification.** `main.c` + `cc3501e_bridge.c` compile cleanly for both
`native_sim/native/64` and the real `alp_e1m_aen801_m55_hp` board target in
all three examples (`app/libapp.a` links with no warnings from the new
files). The real-board link itself is blocked by three pre-existing defects
this fix does not touch and does not attempt to fix: mbedtls's
`ssl_misc.h` `mbedtls_error_pair_t` include-order error (`mqtt-telemetry`,
`iot-fleet-ota`), undefined `z_impl_sys_rand_get` with TLS off
(`mqtt-telemetry`, `iot-fleet-ota`), and `iot-dashboard`'s lvgl finding no
`zephyr,display` node — all three reproduced locally, unchanged by this
fix, on `origin/dev` before this branch.
