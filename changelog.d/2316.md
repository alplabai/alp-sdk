### Fixed — the loader refuses an OPTIGA attestation root on SKUs where the OPTIGA is not fitted (#2316)

`security.psa.attestation_root: optiga_trust_m` was accepted whenever the SoM
preset named the OPTIGA Trust M under `on_module:` or set
`capabilities.optiga_trust_m: true`, without checking population. E1M-AEN801
and E1M-AEN803 do both, but their `optiga_trust_m` i2c_devices entry is
`assembled: false`. The loader now refuses that combination with the same
message shape as the #2311 OSPI guard: SKU, part, and
`assembled: false in metadata/e1m_modules/<SKU>.yaml`.
`examples/connectivity/production-deployment`, which targets E1M-AEN801,
switches to `attestation_root: tfm_internal`, and its README says where
`optiga_trust_m` does apply (E1M-AEN501/601/701).
