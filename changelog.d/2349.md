### Fixed — `clang-format · diff-only` diffed the wrong lines when a PR's head was a merge commit (#2349)

`pr-static-analysis.yml`'s "Determine diff base" step fed `git diff` the PR's
raw `base.sha` -- a two-dot diff. On a long-lived branch whose head is a
merge commit (e.g. `Merge origin/dev into <branch>`), that includes hunks
the merge itself reshaped, not just the branch's own changes, and disagrees
with what `gh pr diff` and the GitHub PR page render. The step now resolves
`git merge-base base.sha HEAD` first, matching the three-dot semantics
GitHub itself uses to render a PR diff.
