### Fixed -- UART read: RX overrun and ring overflow are reported, not silent (#2934)

**`alp_uart_read()` no longer returns `ALP_OK` with a corrupted frame on Zephyr.** The polled path calls `uart_err_check()` before every `uart_poll_in()` and returns `ALP_ERR_IO` on an RX overrun, framing or parity error; the check is per poll because on ns16550 UARTs (the Alif UART0..3) each poll reads LSR, which clears the very latch `uart_err_check()` reports. While an RX ring buffer is attached, `alp_uart_read()` drains the ring and blocks on a semaphore signalled by the RX interrupt instead of polling a controller the ISR already owns. The ISR counts bytes the ring cannot store and any hardware FIFO overrun it sees via `uart_err_check()`; the next `alp_uart_rx_ringbuf_pop()` (valid bytes still delivered in `got`) or ring-backed `alp_uart_read()` (reported before it consumes anything) returns `ALP_ERR_IO` once for that loss. On ns16550 TX polling clears the same latch, so `alp_uart_write()` checks for a line error before each byte and latches it for the next read or ring pop to report as `ALP_ERR_IO`. A standalone `alp_uart_rx_ringbuf_detach()` now wakes a blocked ring-backed read instead of waiting out its timeout. The Alif baremetal `alp_uart_read()` now waits on `GetRxCount()` against the deadline instead of returning as soon as the asynchronous receive started.

### Changed -- `alp_uart_read()` returns `ALP_OK` only when all `len` bytes arrived (#2934)

**A deadline with fewer than `len` bytes, including some, is now `ALP_ERR_TIMEOUT` on every backend** (Zephyr polled and ring paths, the sw_fallback and testing doubles, Yocto, Alif baremetal); it used to be `ALP_OK` with no count, so a caller could not tell a short read from a full one. The bytes received so far are consumed and the buffer is unspecified; for partial or streaming reads use `alp_uart_rx_ringbuf_pop()` on Zephyr, or 1-byte `alp_uart_read()` calls where there is no ring (Yocto, baremetal). The fixed-frame chip callers (`a02yyuw`, `tmc2209`) already treated `ALP_OK` as a full read, so a short read now surfaces instead of passing as complete. The variable-length `quectel_bg77`, `quectel_bg95` and `ublox_sara_r5` `*_read_response()` helpers now read byte by byte against one deadline, so they still return what arrived: `ALP_OK` on at least one byte, `ALP_ERR_TIMEOUT` on none. `alp_uart_read()` in `<alp/peripheral.h>` documents the new contract, the overrun behaviour, and the shared single-consumer role of `alp_uart_read()` and `alp_uart_rx_ringbuf_pop()`.
