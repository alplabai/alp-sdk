### Fixed — CC3501E OTA docs: PROMOTE only works in the same boot as FINISH (#2741)

`cc3501e_ota_promote()` was documented as the way to promote an image left STAGED across a reset. That is not possible on bridge firmware v0.9.x: the TI PSA-FWU swap request lives only in CC3501E RAM and is set only by FINISH's install step, so after any reboot the firmware's swap request returns `PSA_ERROR_BAD_STATE` (-137), recorded as `OTA_STATUS reserved[0]` = 119, and no swap happens (bench-proven on E1M-AEN803, #2728).

The docs now say PROMOTE must follow FINISH in the same CC3501E boot, that an image still reported STAGED after a reset cannot be promoted, and that the recovery is OTA_ABORT (or a new BEGIN) plus a full re-send: `include/alp/chips/cc3501e/ota.h` for `cc3501e_ota_finish()` and `cc3501e_ota_promote()`, and in `include/alp/protocol/cc3501e.h` the `OTA_PROMOTE` opcode comment, `reserved[0]` = 119, and `ALP_CC3501E_OTA_PENDING_STAGED`. `docs/cc3501e-bridge.md` also stops saying FINISH arms the swap-reboot, which has been wrong since #1123.

The `aen-cc3501e-bringup` example's `-DCC3501E_OTA_PROMOTE=ON` mode always runs in a later boot than the run that staged the image, so it can never swap. Its comments now say it shows the refusal, and after an acked promote it reads `OTA_STATUS` and prints `reserved[0]` and `pending`.

No firmware change. Reporting a distinct status for this case, or re-arming the swap request on PROMOTE, is left to the bridge firmware.
