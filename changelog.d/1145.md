### Fixed — the DRP-AI bring-up doc still offered a rejected boot mechanism as a live option, and the doc-drift gate carried two allowlist entries to let it pass (#1145)

`docs/bring-up-drpai-v2n.md`'s deploy section pointed readers at a second,
unmerged `CONFIG_ALP_FDT_FILE` / `CONFIG_ALP_SD_ROOT` implementation on
`feat/1145-drpai-v2n-bringup` and told them to "see #1175 before relying on
either". Three things about that were no longer true:

- **#1175 is closed.** `dev` carries the fix (#1182, eMMC half completed in
  #1186); the branch's version was deliberately not landed, because two
  mechanisms both setting the boot dtb is worse than either. Reasons are
  recorded on #1175 and #1238 — it is history, not a pending alternative.
- **Its one stated advantage is gone.** The V2M gap `dev`'s hardcoded
  filename left open is closed in-tree by `CONFIG_ALP_E1M_FDTFILE`
  (`meta-alp-sdk/recipes-bsp/u-boot/u-boot/fdtfile-v2m.cfg`, wired per
  MACHINE in `meta-alp-sdk/recipes-bsp/u-boot/u-boot_%.bbappend`; #1252).
- **Nothing has still booted a board**, so that caveat stays — but it is now
  attached to the mechanism that actually ships.

`scripts/check_doc_drift.py`'s `_ALLOWLIST` existed only to excuse that
paragraph: `ALP_FDT_FILE` and `ALP_SD_ROOT` are symbols this repo will never
define. Both are dropped. `ALP_E1M_FDTFILE` is added in their place — a real
identifier, but defined in
`meta-alp-sdk/recipes-bsp/u-boot/u-boot/0002-rzv2n-dev-ALP-E1M-production-boot.patch`
and set in a `*.cfg`, neither of which the meta-alp-sdk harvest scans
(`*.conf` / `*.bb` / `*.bbappend` / `*.inc` only), and the one `.bbappend`
that names it spells it `CONFIG_`-prefixed, which the harvest regex
deliberately does not strip. Same shape as the existing `ALP_CA55_1P8GHZ`
entry. Net: the allowlist shrinks by one and no longer vouches for a symbol
that does not exist.

**No change to the DRP-AI enablement itself.** `ALP_SDK_USE_DRPAI_V2N` still
defaults OFF and `ALP_ENABLE_DRPAI` still defaults `"0"`; #1145's two gates
are untouched. The backend has not been baked with `PACKAGECONFIG[drpai]`
enabled and has not run on DRP-AI silicon (#1268).
