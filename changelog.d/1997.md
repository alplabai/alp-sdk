### Fixed — `pr-plain-cmake` compiled `tests/**` without watching it (#1997)

`.github/workflows/pr-plain-cmake.yml` builds with `-DALP_BUILD_TESTS=ON`,
and `CMakeLists.txt:311` does `add_subdirectory(tests)` — so files under
`tests/` decide which targets that workflow compiles and which of its 54
ctest cases run. `tests/**` was not in either `paths:` block, so those
files could not trigger the workflow that exercises them.

Surfaced by #1996, which guards `alp_test_inference_drpai_regression`
behind `CMAKE_SYSTEM_NAME STREQUAL "Linux"` (so `scripts/test-all.sh` can
pass on Windows, #1995). That is exactly a change to which targets the
plain-CMake build produces, and `pr-plain-cmake` did not run on it at all;
the evidence that the target still builds on Linux exists only because the
run was dispatched by hand.

Two changes, because the path filter alone does not close the class:

* `tests/**` added to both `paths:` blocks, so the workflow runs.
* The `yocto backend + tests` job now asserts by name that
  `alp_test_inference_drpai_regression`,
  `alp_test_inference_ort_regression` and
  `alp_test_inference_deepx_regression` are still listed by `ctest -N`
  before running them.

The second matters because a vanished target is silent: CMake produces a
smaller build and ctest a shorter list, both exit 0, and nothing compares
either against an expectation — a guard that wrongly excludes a target on
the platform that owns it looks identical to a guard that works. Those
three are asserted because their definition is conditional; presence is
checked by name rather than by counting tests, so adding a test never
trips it. This is the same posture the `yocto-zcbor` leg already states
for its own `ALP_SDK_MODEL_ZCBOR_REQUIRED=ON` flag: fail loudly rather
than degrade quietly.

Verified in both directions. On Linux all three are present — run
`34021819100`, job `plain-cmake · yocto backend + tests`:
`Built target alp_test_inference_drpai_regression` and
`8/54 Test #8: alp_test_inference_drpai_regression ... Passed`. On a
Windows host, where `inference_drpai.cpp` cannot compile and #1996
deliberately drops the target, the same assertion reports
`MISSING: alp_test_inference_drpai_regression` and exits 1.
