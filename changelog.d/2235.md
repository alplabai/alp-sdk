### Fixed — AEN803 board twins for four peripheral examples, and the AEN bench build guard covers board-qualified `.conf` files (#2235)

`alp-console`, `blink`, `pwm-led-fade` and `drone-autopilot` under
`examples/peripheral-io/` shipped only E1M-AEN801 board overlays, so a
bench build on the E1M-AEN803 default was refused. Each now ships the
AEN803 twin (same PCB and silicon; none of these apps' pads sit on the
OSPI0 bus the two SKUs populate differently), with a build-only AEN
scenario in its `testcase.yaml` naming both SKUs and a bounded root in
`.github/workflows/pr-twister-aen.yml`, so the overlays are compiled in CI.
`examples/peripheral-io/qenc-readout` gets a root there too.

`scripts/bench/aen/build.sh` now refuses a board-qualified `.conf` that
would not apply to the resolved board, the same way it already refused a
mismatched overlay, and both checks accept Zephyr's short qualified stem
(`alp_e1m_aen803_m55_he_rtss_he`). Only `alp_e1m_*_rtss_he`/`_rtss_hp`
stems count, so a native_sim `.conf` or an explicit `EXTRA_CONF_FILE`
fragment never trips it (`tests/scripts/test_build_sh_board_qualified_guard.py`).
