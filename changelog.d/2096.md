### Added — synthetic SoM preset fixture pre-empts the unresolved-base routing gap #2053 will leave (#2096)

#2053 (open as PR #2102) will resolve `mram_main.base` from `"TBD"` to a real
address on all seven AEN presets -- the only shipped-preset producer of an
authored-but-unresolved `memory_map:` base anywhere in the tree, so landing it
will also remove the only end-to-end path through
`scripts/alp_orchestrate/memory.py::_resolved_row()`'s unresolved-base leg and
`scripts/alp_orchestrate/carveout.py::_region_ipc_eligibility()`'s
`cls == "unresolved"` tail. The tests that cover those legs today are
expected to get re-pointed at direct calls into the private helpers as part
of that same PR, which would keep the legs green in isolation but prove
nothing about the WIRING that routes an unresolved row into them in the
first place -- a future change that filtered unresolved rows out earlier
(say in `carveout.py::_candidate_regions()`, before
`_region_ipc_eligibility()` is ever called) would then leave every direct
pin green while the live guard went dead.

`tests/scripts/_orchestrate_support.py` gains
`_synthetic_aen_unresolved_base_root()`, a sibling of the existing
`_synthetic_nx9101_root()`: a scratch metadata root carrying a synthetic
`E1M-AEN899` preset (not a real SKU) under `alif:ensemble:e3` -- an Alif SoC
that DOES declare an on-die MRAM aperture, so the aperture-dependent branches
are reached rather than short-circuited by `aperture is None`. Its
`memory_map:` is a verbatim copy of `metadata/e1m_modules/E1M-AEN301.yaml`'s
seven rows, `mram_main`'s `base: "TBD"` included. Two new tests drive it
through the full `load_board_yaml` -> `resolve_memory_regions()` /
`resolve_carve_outs()` pipeline rather than calling the private helpers
directly, alongside (not replacing) the existing direct-call pins -- so the
wiring coverage survives #2102's landing rather than being lost by it.
