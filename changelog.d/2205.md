### Fixed — `i2s_dw` on the Alif E8: a channel "disable" that stops nothing left TX RUNNING with no ISR to drain it, and init never masked `IMR` bit 6 (#2205)

**The silicon fact.** On the Alif E8's `i2s3` (`0x49017000`, a DesignWare I2S
built with TDM support), `TER` bit 0 (`TXCHENX`) and `RER` bit 0 (`RXCHENX`)
cannot be cleared. Measured on `e1m-aen-evk-03` at a hardware breakpoint just
after the init-time clears, with the block idle (`IER 0x00000F00`,
`IRER`/`ITER`/`CER` `0`), `RER` and `TER` both read `0x00FFFF01`. The E8 SVD
(peripheral `LPI2S`) documents both bits read-only, "always enabled" in the TDM
configuration, with bits 8-23 as the per-slot enables; the E7 SVD has them
read-write and no slot fields. So `i2s_tx_channel_disable()` and
`i2s_rx_channel_disable()` have always been no-ops on the E8. The bench record
is the #2205 row of `docs/test-plan.md`.

**What that broke.** `rx_stream_start()` relied on `i2s_tx_channel_disable()`
to stop a running TX. On the E8 TX kept running in hardware while
`dev_data->dir`, the only field `i2s_dw_isr()` consults, had moved to
`I2S_DIR_RX`, so nothing drained TX's queue. `tx.state` still read
`I2S_STATE_RUNNING`, so the backend never took its ERROR recovery: every later
`write()` waited on the backend's 2-block slab
(`src/backends/i2s/zephyr_drv.c:411` ("k_mem_slab_init(&s->mem_slab, s->slab_buf, block_bytes, 2)"))
until its own timeout, and the stream never came back. The same `dir` field
also stayed on RX after an RX session, so a TX restarted without a fresh
`configure()` was never serviced.

**The fix, in `zephyr/drivers/i2s/i2s_dw.c` and `i2s_dw.h`.** The `&= ~1`
channel-disable calls stay: an ignored write on the E8, real on the E7.

- **A START pre-empts a RUNNING stream of the other direction.** An RX START
  parks a RUNNING TX in `I2S_STATE_ERROR` through `tx_stream_park_keep_clock()`
  (`zephyr/drivers/i2s/i2s_dw.c:625` ("static void tx_stream_park_keep_clock")),
  the exit #2149's queue-empty underrun already took and now shares:
  `ITER.TXEN` cleared, TX interrupts masked, `CER.CLKEN` kept,
  `clk_restart_skip_ok` armed. The next `write()` gets `-EIO`, and the
  backend's existing ERROR→PREPARE→START retry restarts TX on the kept clock
  without reprogramming it. The #2150 phase 1 / #2171 contract holds: the armed
  flag keeps `tx_clock_is_live()` true, so the RX teardown that follows leaves
  `CER.CLKEN` set (`zephyr/drivers/i2s/i2s_dw.c:1222` ("tx_stream_park_keep_clock(&dev_data->tx, dev);")).
  A TX START pre-empts a RUNNING RX the same way, into `I2S_STATE_ERROR`
  through `rx_stream_disable()`
  (`zephyr/drivers/i2s/i2s_dw.c:1350` ("rx_stream_disable(&dev_data->rx, dev);")),
  which keeps `CER.CLKEN` whenever TX's clock is live; a TX START that fails in
  `queue_get()` leaves RX alone. Both run under `irq_lock()` together with the
  `dir` switch, before the new direction's interrupts are unmasked, and the
  RX pre-emption runs before `tx_stream_start()` consumes
  `clk_restart_skip_ok`, so a TX retry that pre-empts RX never gates the clock
  even for an instant.
- **A reader or writer blocked on the pre-empted stream is released with
  `-EIO`.** The backend waits with `SYS_FOREVER_MS`
  (`src/backends/i2s/zephyr_drv.c:426` (".timeout        = SYS_FOREVER_MS,")), and once
  `dir` has moved nothing else would ever give the semaphore. A TX START
  pre-empting RX gives `rx.sem`
  (`zephyr/drivers/i2s/i2s_dw.c:1358` ("k_sem_give(&dev_data->rx.sem);")); the
  woken reader finds the queue empty and returns `-EIO`. Before this, the
  backend's own automatic TX retry after an RX START (write `-EIO` → PREPARE →
  write → START) left an RX reader blocked forever, and `alp_i2s_close()` on
  that RX handle then deadlocked in `alp_handle_begin_close_blocking()`
  (`src/i2s_dispatch.c:174` ("alp_handle_begin_close_blocking(&i2s->lifecycle, &i2s->active_ops)")),
  because the DROP that would reset the semaphore only runs after that wait.
  An RX START pre-empting TX gives `tx.sem` the same way
  (`zephyr/drivers/i2s/i2s_dw.c:1228` ("k_sem_give(&dev_data->tx.sem);")), and
  `i2s_dw_write()` now fails a writer that wakes to find its stream parked in
  ERROR instead of queueing into it and reporting success
  (`zephyr/drivers/i2s/i2s_dw.c:589` ("if (dev_data->tx.state == I2S_STATE_ERROR) {")).
- **`dev_data->dir` follows START.** `rx_stream_start()` and
  `tx_stream_start()` set it, as `configure()` still does
  (`zephyr/drivers/i2s/i2s_dw.c:1360` ("dev_data->dir = I2S_DIR_TX;")).
- **The #2179 ISR guard masks every unserviced source**, not only TXFE and
  RXDA, limited to the named `IMR` bits
  (`zephyr/drivers/i2s/i2s_dw.c:980` ("unserviced &= I2S_IMR_ALL_Msk;")).
- **`i2s_dw_initialize()` writes the full named `IMR` mask in one store**
  (`zephyr/drivers/i2s/i2s_dw.c:1080` ("i2s_set_interrupt_mask(I2S_IMR_ALL_Msk, i2s);")).
  It used to read-modify-write only bits 0/1/4/5, so a previous image's
  unmask of bit 6 would have survived into every boot (the block is outside
  the SYSRESETREQ reset domain), and nothing in the driver services that
  source. Nothing in-tree unmasks bit 6 today, and no capture shows it
  unmasked: this closes a hole, it fixes no observed fault.
  From the E8 SVD: bit 6 is `TXFU`/`TXFUM`, the Tx FIFO underrun, now defined
  in `i2s_dw.h`; `IMR` resets to `0x00000073`; and bits 2-3 have no field in
  `ISR` or `IMR` in either the E7 or the E8 SVD. `I2S_IMR_ALL_Msk`
  (`zephyr/drivers/i2s/i2s_dw.h:139` ("#define I2S_IMR_ALL_Msk")) is therefore
  `0x73`, and no 1 is written to bits 2-3. The E7 SVD has no bit 6 either
  (`IMR` resets to `0x00000033`); no in-tree board binds this driver on an E7.
- **The channel-enable helpers read-modify-write**
  (`zephyr/drivers/i2s/i2s_dw.h:508` ("i2s->paddr->RER |= I2S_RER_RXCHEN_Msk;")).
  The plain write of `0x1` zeroed the E8's per-slot enables in bits 8-23:
  harmless in standard I2S mode, wrong under TDM.
- **Offset `0x44` is documented** as `TOR0` on the E7 and `I2S_TICR0` on the
  E8, where one read clears both `TXFO` and `TXFU`
  (`zephyr/drivers/i2s/i2s_dw.h:262` ("I2S_TICR0 (TXCHOU)")).
- **Stale comments corrected.** The file header, `i2s_dw_isr()` and
  `i2s_dw_initialize()` used to say that no `ISR`/`IMR` capture exists. #2179
  has since closed on an A/B capture that proves the RX-start storm (TXFE
  unmasked while `dir` is `I2S_DIR_RX`), in which `rx_stream_start()`'s TX mask
  prevented it and the ISR guard never fired; the comments now say so. The
  all-zero `CER`/`TER` read after a RESETPIN reset is now described as an
  unclocked block rather than a reset value. `rx_stream_start()`'s "disabling
  the channel does not deassert TXFE" note described a disable that never
  happened on silicon, and is gone.

**Tests.** `tests/unit/i2s_dw_underrun` now models the E8: SVD reset values,
and `TER`/`RER` bit 0 reading 1 whatever the driver wrote
(`tests/unit/i2s_dw_underrun/src/test_i2s_dw_underrun.c:204` ("fake_ter(void)")).
It also counts every `CER.CLKEN` clear the driver makes, through a wrapper
around the driver's own `i2s_clock_disable()`, because a 1→0→1 glitch inside
one call is invisible in the final register value. The two assertions that
encoded a writable bit are gone: test (a) checks `ITER.TXEN` instead, and test
(r) no longer checks `RER`/`TER` bit 0. Eleven new cases, plus two extended
ones, each went RED with their own change reverted and GREEN with it restored:

- (s) init masks an inherited TXFU unmask;
- (t) the guard masks an unserviced TXFU;
- (u) and (v) a TX or RX restart after the other direction's session is
  serviced;
- (w) a RUNNING TX pre-empted by an RX START is ERROR, keeps `CER.CLKEN`
  through that START and the RX teardown, gets `-EIO` on the next write, and
  restarts without reprogramming the clock: no `set_rate()`, and no live `CCR`
  rewrite;
- (x) a RUNNING RX pre-empted by a TX START is ERROR;
- (y) the enable helpers preserve bits 8-23;
- (z) and (aa) a reader or writer blocked with `SYS_FOREVER_MS` on the
  pre-empted stream is released with `-EIO`;
- (ab) a TX START that fails `-ENOMEM` leaves a RUNNING RX running;
- (ac) a TX retry pre-empting a RUNNING RX makes zero `CER.CLKEN` clears;
- (k), extended: an RX START refused with `-EBUSY` leaves TX RUNNING with
  `ITER.TXEN` set.

An after-hook now DROPs both streams, so one aborted case can no longer starve
the shared slabs for every later case. 30 of 30 pass on native_sim/native/64.

**Known and deferred.**

- `i2s_dw_configure()` still repoints `dev_data->dir`, so configuring one
  direction while the other is RUNNING stalls the running one until the new
  direction's START pre-empts it. That START now releases a reader or writer
  blocked on the stalled stream with `-EIO`, so the stall ends in an error and
  `alp_i2s_close()` no longer deadlocks on it. Removing the `configure()`
  assignment turns the #2179 tests (m) and (q) RED, so it needs its own change.
  It is the one full-duplex gap still listed in the file header.
- `i2s_global_enable()` still writes `IER` whole, which zeroes the E8's
  `TDM_SLOTS` field (reset `0xF00`). The same write leaves `INTF_TYPE` at 0,
  standard I2S, and `TDM_SLOTS` is the slot count of a TDM frame, so this only
  matters once TDM is used.
