### Fixed — `_emit_extra_library_profile` could raise instead of returning its declared diagnostic (#1961)

`scripts/alp_orchestrate/kconfig.py`'s `_emit_extra_library_profile` is
contracted to return a `#`-prefixed diagnostic line, never raise, when the
`extra_libraries[].profile:` file it walks is missing, unreadable, or
malformed. Its `try`/`except (OSError, yaml.YAMLError)` was narrower than
the failure modes of the I/O it wraps: `.resolve()` sat outside the `try`
entirely and raises `RuntimeError("Symlink loop from ...")` on a symlink
loop (`ELOOP`), and `read_text(encoding="utf-8")` raises
`UnicodeDecodeError` -- a `ValueError` subclass, not an `OSError` -- on
non-UTF-8 bytes, before the YAML parser ever runs. Both escapes propagated
an unhandled exception out of a function whose whole point is to keep a
malformed `extra_libraries:` profile from taking the rest of the emit down
with it.

`.resolve()` now runs inside the same `try` as the read+parse, and the
`except` tuple widens to `(OSError, RuntimeError, ValueError,
yaml.YAMLError)`. tan-cli's documented planner fallback
(`PYTHONPATH=<sdk>/scripts python -m alp_orchestrate --emit build-plan`)
runs this exact code out of an SDK checkout, so this closes the alp-sdk
side of the defect tan-cli tracked as tan-cli#1122 and had already fixed in
its own relocated copy (`python/tan/planner/kconfig.py`), reconverging the
two copies.

New `tests/scripts/test_kconfig_extra_library_profile_never_raises.py`
table-drives the seven shapes tan-cli's sibling gate exercises (non-UTF-8
bytes, a symlink loop, a permission-denied path, a directory where a file
is expected, malformed YAML, a missing file, a valid profile), plus a
platform-independent deterministic reproduction of the symlink-loop shape
(real unprivileged `os.symlink` needs Developer Mode/admin on Windows, so
that table entry skips there instead of failing).
