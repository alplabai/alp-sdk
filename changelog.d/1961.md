### Fixed — `_emit_extra_library_profile` could raise instead of returning its diagnostic, and a same-shaped crash sat ahead of it on the same path (#1961)

`scripts/alp_orchestrate/kconfig.py`'s `_emit_extra_library_profile` is
contracted to return a `#`-prefixed diagnostic line, never raise, when the
`extra_libraries[].profile:` file it walks is missing, unreadable, or
malformed. Its `try`/`except (OSError, yaml.YAMLError)` was narrower than
the failure modes of the I/O it wraps: `.resolve()` sat outside the `try`
entirely and raised `RuntimeError("Symlink loop from ...")` on a symlink
loop (`ELOOP`), and `read_text(encoding="utf-8")` raises
`UnicodeDecodeError` -- a `ValueError` subclass, not an `OSError` -- on
non-UTF-8 bytes, before the YAML parser ever runs.

The fix drops `.resolve()` entirely -- nothing downstream of it needs a
canonicalized path, only `read_text` does -- rather than widening the
`except` tuple to catch its `RuntimeError`. A real symlink loop still
fails, but via `read_text`'s own `OSError` (`[Errno 40] Too many levels of
symbolic links`), which the original `except (OSError, yaml.YAMLError)`
already caught; the `except` tuple only needed to grow by
`UnicodeDecodeError`. This is the same shape as tan-cli's relocated copy
(`python/tan/planner/kconfig.py`, tan-cli#1122), so the two now match.

The `kconfig.py` fix reconverges; `validate.py`'s does not. tan-cli's
`python/tan/planner/validate.py:180-181` carries the identical
unguarded `prof_path = (REPO / prof).resolve()` / `if not
prof_path.is_file():` this fragment's `validate.py` fix wraps, with no
`try`/`except` at all -- filed as tan-cli#1217 rather than folded into
this alp-sdk-only PR.

Separately, and load-bearing for reachability: `scripts/alp_orchestrate/
validate.py`'s `_validate_consistency` -- run by *every* `load_board_yaml`
call, i.e. every `--emit` mode including `--emit build-plan` (tan-cli's
documented planner fallback, `PYTHONPATH=<sdk>/scripts python -m
alp_orchestrate --emit build-plan`) -- does its own `(REPO /
prof).resolve()` + `.is_file()` on the identical user-supplied
`profile:` path, and runs strictly *before* the kconfig emitter above is
ever reached. Left unguarded, a symlink-loop or permission-denied
`profile:` still crashed `load_board_yaml` with an unhandled
`RuntimeError` / `PermissionError` regardless of the kconfig.py fix, so
the defect stayed reachable on tan-cli's own documented fallback command.

That guard's first cut (`except (RuntimeError, PermissionError)`) was
itself POSIX-shaped and still crashed on Windows: a real symlink loop
built with `ln -s` from WSL on an NTFS drive, driven through the real
CLI with Windows CPython 3.11.3, showed `.resolve()` returning
*without* raising at all, and `.is_file()` raising a plain `OSError`
(`WinError 1920`, "The file cannot be accessed by the system") -- not
a `RuntimeError` and not a `PermissionError`. The `except` tuple is now
`(OSError, RuntimeError)` (`PermissionError` is already an `OSError`
subclass), which covers both the POSIX shape (`RuntimeError` from
`.resolve()`) and the Windows shape (`OSError` from `.is_file()`) --
verified by re-driving the real CLI against a real symlink loop on
both platforms, not by widening the catch and trusting it. Both calls
are now wrapped and raise a normal `OrchestratorError` (the CLI's
usual clean exit-1 path) instead, on both platforms.

New `tests/scripts/test_kconfig_extra_library_profile_never_raises.py`
table-drives the eight shapes issue #1961's acceptance list + tan-cli's
sibling gate exercise (non-UTF-8 bytes, a symlink loop, a
permission-denied path, a directory where a file is expected, a parent
that is a file, malformed YAML, a missing file, a valid profile), a
deterministic reproduction of the symlink-loop failure mode (monkeypatches
`pathlib.Path.resolve` -- the call that actually sits outside `kconfig.py`'s
pre-fix `try` -- not `read_text`, which was never the broken call), and an
end-to-end check (`load_board_yaml` -> `_slice_alp_conf`) for the one
shape that survives board.yaml load-time validation. `tests/scripts/
test_orchestrate_libraries.py` covers `validate.py`'s half with three
tests, not one: `test_extra_libraries_profile_symlink_loop_clean_error`
monkeypatches `pathlib.Path.resolve` to the POSIX `RuntimeError` shape,
`test_extra_libraries_profile_permission_denied_clean_error` monkeypatches
`pathlib.Path.is_file` to the POSIX `PermissionError`/EACCES shape, and
`test_extra_libraries_profile_windows_shape_clean_error` monkeypatches
`pathlib.Path.is_file` to the Windows `OSError`/`WinError 1920` shape --
each scoped to its own profile path only (real unprivileged `os.symlink`
needs Developer Mode/admin on Windows, so none of the three can use a
real symlink loop directly). The third test is the one that actually
pins this round's fix: reverting the `except` clause to
`(RuntimeError, PermissionError)` leaves the first two green and turns
only the third red, which is exactly how the Windows gap shipped unseen
in the first place.

Deliberately out of scope: `scripts/alp_orchestrate/orchestrator.py`'s
`_resolve_app_path()` (`cores.<id>.app:`) has the identical unguarded
`.resolve()` on a different user-supplied field. #1961 scopes to
`profile:` -- smaller blast radius, narrower review surface -- so that
one is tracked separately as #1987 rather than folded in here.
