### Fixed — OV5647 driver now turns its own auto-white-balance off, leaving the E8 ISP as the sole white-balance actor (#2255)

Power-on `0x5001` reads `0x01` (AWB on) on E1M-AEN803 silicon: with the
driver never driving it, the sensor's own AWB stayed enabled and could
fight the ISP's own white-balance stage. `ov5647.c` now writes
`0x5001 = 0x00` (new `OV5647_ISP_CTRL01`) as part of the common init
block, matching mainline `drivers/media/i2c/ov5647.c`'s `OV5647_REG_AWB`
default of off. This is distinct from — and must not be confused with —
Alif's `0x5001 = 0x01` addition that run 58 traced issue #2248's CSI
"incorrect frame sequence" fatals to: bench run 217 held a mid-stream
`0x5001 = 0x00` write with zero CSI errors and every dequeue `ALP_OK`,
and `0x5002`/`0x4050`/`0x4051` remain never written. The run-217 A/B
moved the E8 ISP's own AWB statistics only a few percent, so the colour
cast under investigation is not attributed to the sensor's AWB.

The init-path write is verified on silicon (bench run 218): `0x5001` reads `0x00` from the first frame, with no CSI error at stream start. With the sensor AWB off, the E8 AWB currently settles below unity red gain (`rGain 0xd1`), so this change lands only together with the re-fitted AWB/CCM calibration.
