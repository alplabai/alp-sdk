### Investigated — widening the issue-citation harvester past driver-status blocks was measured and declined (#1958)

`scripts/check_issue_citations.py` (#1950) harvests `#NNNN` citations only
out of a `driver_status:` field's trailing YAML comment and an `@par Driver
status:` Doxygen paragraph, by design. #1958 asked whether widening it to
`changelog.d/`, `CHANGELOG.md`, ADR prose and `notes:` blocks was cheap
enough to do, and said to check the same historical-marker heuristic against
the noise floor there first.

Measured, not guessed: applying the (#1963-tightened) historical/futurity
classifier to a naive `#NNNN` harvest over all four locations on the real
tree found 1627 citations, of which 17 would have hard-failed the gate. All
17 were read by hand; every one is a false positive. Changelog/ADR prose
narrates history in vocabulary the driver-status word list was never tuned
for -- `### Added — GD32 bridge ADC/PWM/DSP\n\nADC oversample + resolution
control (#494), ...` and `**Settled (#1244):** ...` and "#495, #494 and #496
... wasn't complete" all carry none of `_HISTORICAL_RE`'s marker words near
the citation, so each reads as a live blocker though every cited issue
closed long ago. Worse, `CHANGELOG.md`'s released sections describe a past
tree on purpose (the same carve-out `check_changelog_citations.py` already
makes for `path:line` citations there): a "the order code stays TBD
(#1241)" note that was accurate the day it shipped becomes an unfixable
false positive the moment #1241 later closes, with no way to "correct"
already-published history short of rewriting it.

Re-derivability: the decision-relevant column is the 17-total split across
the four locations -- 4 in `changelog.d/`, 7 in `CHANGELOG.md`, 5 in
`docs/adr/`, 1 in a `notes:` block -- which is re-derivable by anyone: grep
`#\d+` over those four locations, drop every hit whose clause is
`_HISTORICAL_RE`-historical, and hand-read what is left against the
snapshot. The 1627 intermediate total is a one-time observation from an
ad-hoc harvester script that was not committed; it is not independently
re-derivable without rewriting that script, and no claim in this fragment
depends on its exact value -- only the 17-total column drove the decision
to decline widening.

Widening would also have MISSED the one real drift already sitting in the
measured corpus:
`docs/adr/0023-ethernet-out-of-the-alp-surface.md:221` says "#1241, still
open" and #1241 is in fact closed -- exactly the defect class this gate
exists to catch. It is missed because the neighbouring clause's "#1244, now
fixed" trips `_HISTORICAL_RE` for the whole compound sentence, clearing
#1241's flag too. Widening would ship 17-for-17 false positives against a
`gate: true` merge-queue blocker to buy back one still-missed catch -- the
wrong trade for a gate whose stated bias is to under-flag.

Declined. Not widened; closing #1958 with this measurement rather than
leaving it open or landing the widening unmeasured. The ADR-0023 drift
found above is real and is fixed directly in this change
(`docs/adr/0023-ethernet-out-of-the-alp-surface.md:221`, "#1241, still
open" -> "#1241, now closed") since the repo's rule is docs change with
the code, not left for a mechanical gate that cannot make this call given
the false-positive rate above.
