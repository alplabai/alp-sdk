### Added — `alp companion spi1` + `cc3501e_spi1_configure/_transfer/_release`: host passthrough onto the E1M connector's SPI1 (#1841)

The E1M connector's SPI1 pins (AG10 SCK / AG9 MOSI / AG8 MISO / AH9 CS0 / AH8
CS1) land on the CC3501E, not the Alif -- a carrier device on that bus was
previously unreachable from the host. A new proto v6 opcode family
(`0x55..0x57`, worker-routed) relays the host's bytes onto the coprocessor's
own SPI1 controller: `CONFIGURE` acquires the bus and pins clock/mode/CS,
`TRANSFER` clocks one full-duplex chunk (up to `ALP_CC3501E_SPI1_MAX_XFER` =
4088 B, with `NO_TX`/`NO_RX`/`CS_HOLD` flags to drop a direction or chain
chunks into one device transaction), and `RELEASE` is the escape hatch back
to a known-free bus.

New host API: `cc3501e_spi1_configure()` / `cc3501e_spi1_transfer()` /
`cc3501e_spi1_release()` in
[`<alp/chips/cc3501e/core.h>`](include/alp/chips/cc3501e/core.h). New
console group: `alp companion spi1 configure|xfer|read|release` (see
[`cc3501e-companion-commands.md`](docs/cc3501e-companion-commands.md#alp-companion-spi1)).

TRANSFER carries a `seq` byte for wire-level duplicate suppression: the
firmware caches the last completed `(seq, result)` and replays it for a
matching seq instead of re-clocking the bus, which is what makes the host's
ordinary transport-level retry safe on a bus that can drive flash. The host
driver additionally requires a CONFIGURE to have succeeded in the *current*
session before it will send a TRANSFER -- the firmware's `g_configured`
latch and cached result are file statics that outlive an Alif reboot, so a
freshly initialised host context is forced through a real round trip (whose
own poll discards any stale cache left by a session the firmware outlived)
rather than risk a fresh ctx's first TRANSFER colliding with one and handing
back a previous session's RX bytes as `ALP_OK` with the bus never re-clocked.

Not yet silicon-validated; see `cc3501e-bridge-firmware:`'s test suite and
`docs/cc3501e-bridge.md`'s "SPI1 host passthrough" section for the wire
contract and the v0.x roadmap entry.
