### Fixed — `inference_ort.cpp`'s `open()` leaked every OrtValue created before a throw (#1494)

`alp_inference_ort_open()` drives an `std::unique_ptr<OrtState>` through
several fallible steps — `std::vector::resize`/`assign`, `std::make_unique`,
`std::string` assignment — any of which can throw. The `catch (...)` handler
released `cpu_mem_info`/`session`/`env` but never called `_release_values()`
on the input/output `OrtValue` vectors, so an exception thrown after some
input or output `OrtValue`s had already been created via
`CreateTensorWithDataAsOrtValue` leaked every one of them.

`OrtState` now owns a `~OrtState()` destructor that is the single place
releasing every vendor resource the struct holds (output values, input
values, `cpu_mem_info`, `session`, `env`, each NULL-checked) — the same
routine an early `return rc;` inside `open()`'s `try`, its `catch (...)`
handler, and `alp_inference_ort_close()` all now rely on via the
`std::unique_ptr<OrtState>`/`delete st` destroying it. `open()`'s success
path is the only one that escapes it, via `std::unique_ptr::release()`. This
also deleted three separate hand-rolled copies of the same cleanup sequence
that had to be kept in sync by hand.
