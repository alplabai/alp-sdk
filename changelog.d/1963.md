### Fixed — the issue-citation gate's historical-marker word list under-flagged real blocker phrasings (#1963)

`scripts/check_issue_citations.py`'s `_HISTORICAL_RE` matched a marker word
(`via`, `closed`, `fixed`, `resolved`, ...) anywhere in the clause around a
`#NNNN` citation, so a genuinely still-blocking claim that merely named what
would eventually land it read as historical and was silently skipped.
Probed: 4 of 11 realistic phrasings did this --- "Still partial: DMA path not
yet **fixed** (#1234)", "Blocked on #1234 **until** the pad-routing rework
**lands**", "**Waiting on** #1234 to be **resolved** before this can go
complete", "Open: #1234 **must be done** before the driver is complete".
Each reads unambiguously as a live blocker to a human and each used to be
skipped because a marker verb sat somewhere after the citation.

New `_FUTURITY_RE` (`not yet`, `until`, `waiting on`, `must be`) overrides
`_HISTORICAL_RE` back to a live blocker when one of those four
negation/futurity cues is BOUND to the marker match -- adjacent to it, with
no coordinating conjunction sitting between them (`_CONJUNCTION_RE`) -- the
marker alone no longer wins outright. Checked against the real tree's 15
harvested driver-status citations: none contain any of these cues, so the
tightening flags zero currently-passing citations; the four fixtures above
are synthetic regression tests
(`tests/scripts/test_check_issue_citations.py`), not drawn from the tree.

An earlier version of this fix checked for the cue anywhere in the clause
(co-occurrence, not binding), which over-flagged: caught in review before
it shipped, reproduced 6 for 6 against `metadata/chips/dp83825.yaml`'s
real "... this manifest itself landed via #1241 ..." prose plus five
constructed variants of the same shape -- a marker attached to one citation
and a futurity cue attached to an unrelated LATER subject, joined only by
", and"/", but"/etc., wrongly flipped the citation to a live blocker. Fixed
by requiring the cue and the marker match it overrides to be free of an
intervening coordinating conjunction (see `_is_historical`); all four
fixtures above and all 6 false-positive reproductions were re-checked
against the fixed version.

Still a word-list heuristic, not comprehension, and still biased to
under-flag by design: a blocker phrased with a marker word and none of these
four cues (bare "not fixed", no "yet"), or with a cue reachable only through
a coordinating conjunction, still slips through unflagged. That residual
gap is the accepted cost of never flipping a historical citation into a
false positive -- see the module docstring's HISTORICAL section for the
full trade-off.

**Round-21 follow-up: a conjunction is not English's only pivot.** The
binding rule above treated only a coordinating conjunction (`and`, `but`,
`or`, ...) as separating a futurity cue from the marker it would override.
A parenthetical, a colon and an em/en dash open a new sub-thought just as
plainly, inside the same `.`/`;`-delimited clause. Measured against the
conjunction-only rule, two shapes still flipped a plainly historical
citation to a live blocker:

    "register access closed via #730 (the register map must be
     re-derived from the datasheet)."     -> BLOCKER, want historical
    "landed via #1241: the C driver must be reworked."
                                          -> BLOCKER, want historical

while the `, and` / `, but` / `;` shapes the conjunction rule already
covered stayed correct. `_SUBTHOUGHT_RE` (`(`, `:`, `--`, en/em dash) now
counts as a separator alongside `_CONJUNCTION_RE`.

Measured, not asserted -- 14 phrasings, 0 misclassified after the change
(4 blocker phrasings from this issue, 3 clean historical, 7 marker/cue
splits across every separator). The whole tree is unchanged at rc=0,
15 of 15 citations historical, 0 evaluated, so neither shape occurs in the
tree today; this closes the hole before prose reaches it rather than after.

Mutation-proven: dropping `_SUBTHOUGHT_RE` from the binding check fails
exactly the three new tests --
`test_futurity_cue_after_a_parenthetical_does_not_override`,
`..._after_a_colon_...`, `..._after_an_em_dash_...` -- and leaves the other
27 green (`3 failed, 27 passed`).
