### Fixed — five backend-parity guards from the #1635 audit: an unbounded GD32-bridge instance id, three missing vendor-ext NULL guards, a missing MQTT timeout clamp, a UART sw_fallback empty-read contract violation, and an unaligned storage erase-size (#1635)

`src/backends/qenc/gd32_bridge.c`'s `br_open()` stored `cfg->encoder_id` with
no bound of its own, then narrowed it to `uint8_t` before handing it to the
chip driver's own `GD32G553_BRIDGE_QENC_CHANNELS` check — so `encoder_id ==
256` aliased to channel 0 and opened fine, unlike every sibling GD32-bridge
backend (`counter`, `adc`, `dac`, `pwm`), which all bound the instance id at
open before any narrowing. `br_open()` now rejects an out-of-range
`encoder_id` with `ALP_ERR_INVAL` (matching the qenc `zephyr_drv.c` sibling's
convention) before the id is ever narrowed.

`src/backends/adc/alif_e8.c` and `alif_e7.c`'s
`alp_alif_adc_set_trigger_source()` checked `h == NULL` but then dereferenced
`h->backend->vendor` unchecked; `src/backends/ext/renesas/power.c`'s
`alp_renesas_power_supervisor_mode_set()` checked `handle->backend == NULL`
but not `handle->backend->vendor == NULL`. Six of the seven other vendor-ext
gates already carry the full three-part guard (`h != NULL && h->backend !=
NULL && h->backend->vendor != NULL`); these three now do too.

`src/backends/mqtt/yocto_drv.c`'s `y_connect()` passed `(int)timeout_ms`
straight to `mosquitto_loop()`, unlike `y_loop()` 65 lines below it, which
clamps at `INT_MAX` so a `UINT32_MAX`-as-forever caller doesn't roll over
into a negative timeout. `y_connect()` now applies the same clamp.

`src/backends/uart/sw_fallback.c`'s `sw_read()` ignored `timeout_ms`
entirely and returned `ALP_OK` on an empty ring with the destination buffer
untouched — a silent-failure violation of the documented contract
(`include/alp/peripheral.h`: "If the deadline is reached with zero bytes
collected, the call returns `ALP_ERR_TIMEOUT`", and for `timeout_ms == 0`,
"return immediately with `ALP_ERR_TIMEOUT` if no byte is already
available"). `sw_read()` now returns `ALP_ERR_TIMEOUT` whenever it drains
zero bytes, matching the `zephyr_drv.c` sibling.

`src/backends/storage/zephyr_flash.c`'s `z_get_info()` hardcoded
`erase_size = 1u` with a comment claiming the device API is opaque — false,
`flash_area_get_device(fa)` is already called two lines below and supports
`flash_get_page_info_by_offs()`. This contradicted `include/alp/storage.h`
("Both bounds MUST align to the device's erase_size"). `z_get_info()` now
reads the real page/sector size via `flash_get_page_info_by_offs()` when
`CONFIG_FLASH_PAGE_LAYOUT` is enabled, falling back to `1u` only if that
lookup is unavailable or fails.

Considered and reverted: a `wdt_disable(dev)` call on `zephyr_drv.c`'s
`z_open()` failure path, meant to undo the channel `wdt_install_timeout()`
installs before `wdt_setup()` can fail. It is not the right undo —
`wdt_disable()` is documented as device-wide ("automatically uninstalls all
timeouts", `zephyr/drivers/watchdog.h`), never per-channel, and in the state
this path runs in (setup just failed, instance not enabled) it returns
`-EFAULT` on `wdt_nrfx.c`, `wdt_renesas_rz.c`, and `wdt_fwdgt_gd32.c` — a
no-op on exactly the drivers where the leak is real. On `wdt_counter.c` it
*does* succeed, but as a bare `counter_stop()` with no enabled-check: it
stops the shared counter backing every installed channel and clears no
bookkeeping, disarming a running watchdog while still leaking. The channel
leak on a failed `wdt_setup()` is real but needs a per-driver-class fix, not
a device-wide disable; left open.

Left for a deliberate decision, not fixed here (each is a genuine
convention split across ≥2 backends, not an "obviously right" two-line fix):
the PWM out-of-range-channel status split (`ALP_ERR_OUT_OF_RANGE` in
`pwm/yocto_drv.c`, `ALP_ERR_INVAL` in `pwm/gd32_bridge.c`, both in
`pwm/zephyr_drv.c`); `storage_dispatch.c`'s `read_only` status split
(`ALP_ERR_NOT_READY` for write, `ALP_ERR_INVAL` for erase); and
`storage/zephyr_littlefs.c`'s hardcoded `erase_size = 1u`, which may be
deliberate given littlefs's own block abstraction rather than drift. Also
left: the two tensor-rank conventions across the three inference backends
(`src/yocto/inference_ort.cpp` and `inference_deepx.cpp` both truncate rank
at 4; `inference_drpai.cpp` reports rank `0` because the MERA wrapper
doesn't expose per-input shape — a documented capability gap, not drift);
`src/backends/counter/gd32_bridge.c`'s `ALP_ERR_NOSUPPORT` for an
out-of-range `counter_id`, a fourth status alongside the `ALP_ERR_INVAL`
`adc`/`dac`/`pwm`/`qenc` siblings use, well-argued in place (E1M-X connector
identities are a form-factor bound, not a per-SoM promise) but part of the
same convention split; and the wdt channel-leak-on-failed-setup noted above.

Not open bugs: `allow_unsafe_write` (`include/alp/storage.h`) and
`allow_modeset` (`include/alp/display.h`) are documented Yocto-only /
DRM-master-path-only by design and are ignored elsewhere on purpose — not
missing guards. The audio/i2s `timeout_ms`-forever handling
(`audio/zephyr_drv.c`'s `(int32_t)timeout_ms` cast, `i2s/zephyr_drv.c`'s
missing `UINT32_MAX` case) is a real inconsistency worth a closer look, but
narrower than previously stated here: `(int32_t)UINT32_MAX == -1 ==
SYS_FOREVER_MS`, so the exact `UINT32_MAX`-as-forever case already works.
The gap is the range `(INT32_MAX, UINT32_MAX-1]`, which casts to a negative
value other than `-1` and the underlying drivers treat as no-wait — a
~25-day timeout returns immediately instead of waiting. Neither
`alp_audio_in_read` nor `alp_i2s_write` currently promises
`UINT32_MAX`-as-forever the way `camera.h`, `mproc.h`, `peripheral.h`, and
`rpc.h` do, so this is a consistency gap against those siblings rather than
a documented-contract violation; outside this patch's assigned scope.

A `tests/zephyr/peripheral` regression
(`test_v2n_supervisor_qenc_open_out_of_range_id_rejected`) covers the
GD32-bridge qenc bound check without needing real V2N hardware — the check
now runs before the supervisor acquire, so it fires the same way whether or
not a bus is configured. A `tests/unit/uart_registry` regression
(`test_sw_fallback_empty_read_returns_timeout`) covers the UART empty-read
fix directly against the `sw_fallback` ops.
