### Fixed — `mqtt-telemetry`'s `board.yaml` still told customers to `west build` (#1689)

`#1016` rewrote the `Customer workflow:` comment header in every example
`board.yaml` from "copy this directory ... and `west build`" to the
`tan init --from-example <category>/<name>` / `tan build` form that ADR-0020
makes the whole command surface. It missed
`examples/connectivity/mqtt-telemetry/board.yaml` -- `git log` on that file
shows only `c830dc3d` (#903/#904), never #1016's `cdfe1368` -- so it kept
telling customers to copy the directory by hand and build with `west`.

Rewritten to match, keeping the example's own SSID/PSK + broker-URI guidance:
`tan init --from-example connectivity/mqtt-telemetry`, set the credentials in
`src/main.c` (or wire them from provisioning), then `tan build` for the AEN
board target. The path matches the sibling convention already used by
`connectivity/iot-connected-camera`, and `mqtt-telemetry` is present in
`metadata/catalog.json`, so the command as written resolves.

Scope checked, not assumed: a wrap-tolerant sweep (the old text wrapped as
`` `west\n# build` ``, which a plain grep for "west build" misses) over every
example `board.yaml` confirms this was the last `Customer workflow:` header
naming `west`. The ~95 example `README.md` files that mention `west build` are
left alone deliberately -- those document the underlying Zephyr command that
`scripts/alp_project.py` delegates to, which is still accurate.
