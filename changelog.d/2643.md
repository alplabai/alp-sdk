### Fixed — the TFLM inference backend builds on `native_sim` against glibc 2.43 (#2643)

On a host with glibc 2.43 (Ubuntu 26.04) every `native_sim` build that links
the portable TFLM backend failed in `src/backends/inference/tflm.cpp` with
`error: declaration does not declare anything [-fpermissive]` — 22 of the 277
`native_sim/native/64` twister configurations. CI runs on Ubuntu 24.04
(glibc 2.39) and never showed it.

It is an include-order collision, not a compiler-default change. Zephyr's
toolchain header defines `__unused` as `__attribute__((__unused__))`. glibc
2.43 renamed `struct __pthread_mutex_s`'s `__elision` member to `__unused`
when it removed lock elision, so a translation unit that includes a Zephyr
header first and the host `<pthread.h>` second sees that member expand to a
bare attribute. `tflm.cpp` did exactly that: `<zephyr/logging/log.h>` came
before the TFLM headers, which reach `<pthread.h>` through libstdc++'s
`<memory>`.

The TFLM headers now come before any Zephyr header in that file, so the host
libc is parsed before the macro exists. No compiler flag, language standard or
warning setting changes, and the order is equally valid on glibc 2.39.

glibc fixed its side upstream (commit
`243bdfec8f7cd4a85a8ce6e4e9a5a5accd3ce1aa`, "Rename __unused fields to
__glibc_reserved"); the reorder stays correct once a distribution picks that
up.
