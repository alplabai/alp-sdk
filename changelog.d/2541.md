### Changed

- CI: the AEN twister legs (`twister · AEN801` / `twister · AEN803`) now keep their compiler cache between runs. Zephyr already sent every compile through ccache, but the job left it in the runner's home directory and threw it away, so all of each leg's ~100 arm-zephyr-eabi configurations compiled from scratch every time. The cache now lives in the workspace, at `.github/workflows/pr-twister-aen.yml:254` ("CCACHE_DIR: ${{ github.workspace }}/.ccache"), and is restored per SKU at the start of every run, at `.github/workflows/pr-twister-aen.yml:432` ("- name: Restore ccache objects"). Only a dev push or a new nightly run saves it, so PR runs cannot evict dev's copy from the repo's 10 GB Actions cache budget. The save also runs after a red or timed-out twister step, because a partial cache is still valid, but not after a run that failed before twister started (#2541).
- CI: the AEN twister step's time limit rises from 30 to 34 minutes, at `.github/workflows/pr-twister-aen.yml:546` ("timeout-minutes: 34"). On PR #2239's merged head (103 AEN801 + 101 AEN803 configurations) the step measured 1730 s on AEN801, 70 s under the old limit. This is a stop-gap until the cache brings the step back down. A `ccache -s -v` step now prints the cache size and hit rate on every run (#2541).
- CI: each AEN SKU leg is now split in two with twister's `--subset`, so the workflow runs four jobs, at `.github/workflows/pr-twister-aen.yml:198` ("--subset ${{ matrix.subset }}/2"). The job names change from `twister · AEN801 (M55-HE + M55-HP)` to `twister · AEN801 (M55-HE + M55-HP) · 1/2` and `· 2/2`, likewise for AEN803. Neither is a required context on `dev`. One unsplit leg of ~100 configurations measured anywhere from 1521 s to 2172 s depending on the runner, so it could time out cold. A warm cache cannot help a PR that changes Kconfig or the AEN devicetree, because that changes every configuration. The two halves together cover the same configurations as before (#2541).

### Fixed

- CI: `pr-twister.yml`'s ccache trim step called `ccache --evict-older-than 3h`, but ubuntu-latest's ccache 4.9.1 accepts only `d` and `s` suffixes, so the step failed with `ccache: error: invalid suffix (supported: d (day) and s (second)): "3h"` on every dev push and nightly run and the save after it was skipped. The native_sim shard caches were never refreshed after 2026-09-29. It now passes `10800s`, at `.github/workflows/pr-twister.yml:452` ("run: ccache --evict-older-than 10800s") (#2541).
