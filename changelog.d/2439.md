### Changed — twister runs only when a change can affect a native_sim build, and its CI caches stop missing (#2439)

Every change used to pay the full native_sim twister run -- 67-91 % of a
local `test-all.sh --target dev` wall (399-2013 s of 594-2218 s across seven
runs) and the merge-queue long pole in CI (median 21 min per queue entry,
50-63 runner-minutes per run) -- even for a changelog fragment, a doc, a
Yocto bbappend or a pytest gate.

`scripts/select_checks.py` maps the changed paths to `full` or `skip`.
`skip` needs a proof for every path: a prose/CI/other-OS prefix (`docs/`,
`changelog.d/`, `meta-alp-sdk/`, `tests/scripts/`, `tests/hil/`, most of
`.github/`, any `*.md`); a `scripts/` file outside the build-time closure
(every script a CMake/Kconfig/conf/overlay/testcase file names outside a
comment, plus everything those modules name, recomputed from the tree on each
run); or a file inside an example/test suite whose every scenario pins
`platform_allow` off native_sim and that nothing outside it references.
Anything else -- `metadata/` (read at CMake time by `alp_project.py`), a
header, CMake, Kconfig, an unknown path, a git failure, an empty diff -- is
`full`. `tests/scripts/test_select_checks.py` pins every rule and fail-safe,
and re-proves the premises on the real tree, including an audit-hook run of
the CMake-time `alp_project.py` that fails if it ever opens a file the
selector would skip. Replayed over the last 200 PRs merged to `dev`, 53
(27 %) would have skipped twister.

- `test-all.sh --target dev` skips the twister stage on `skip` (vs the merge
  base with `origin/dev`, counting uncommitted and untracked files;
  `ALP_SELECT_BASE` overrides the base). `--full` forces it; `--target main`
  and the default profile always run it.
- `pr-twister.yml` runs a `twister · select` job first. On `skip` only shard 1
  runs (its Zephyr-oracle checks still execute) with the twister step
  skipped, and the required `twister · native_sim/native/64` aggregator still
  reports success, so the merge queue is not left waiting. `push` to
  `dev`/`main`, `workflow_dispatch` and a new nightly schedule always run the
  full six shards.
- The Zephyr module cache is restored before `west init` instead of after
  `west update`, which fetched 121-194 s per shard (mean 169 s) on every run
  regardless of the hit.
- ccache is saved only by `dev` pushes and the nightly, trimmed to the entries
  that run used. PR and merge-queue runs saved about 3.1 GB each into the
  10 GB repo cache (11.1 GB in use), evicting the `dev` entries they are
  allowed to restore. Each shard now prints `ccache -s`.
- `test-all.sh` sets `CCACHE_BASEDIR` to the checkout and `CCACHE_NOHASHDIR`
  when the user's ccache config has not chosen, so a fresh clone or worktree
  at a new path reuses the cache instead of starting cold.
