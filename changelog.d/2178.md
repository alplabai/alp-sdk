### Fixed — the citation gate checks `CHANGELOG.md` even when `changelog.d/` is empty (#2178)

`scripts/check_changelog_citations.py` returned **0 without looking at `CHANGELOG.md` at
all** whenever `changelog.d/` held no fragments. It said so on stdout — "This is not a
pass; it means the directory is empty" — but an honest message and an exit code of 0 are
not the same thing, and every caller reads the exit code.

An empty fragment directory is not a quiet tree. It is the **release cut**:
`scripts/assemble_changelog.py:228` (`path.unlink()`) deletes every fragment once it has folded
them into `CHANGELOG.md`'s `[Unreleased]`, so the one moment `changelog.d/` is empty is
the moment several hundred citations have just landed in a location they have never been
checked in. The gate grades `[Unreleased]` exactly like a fragment — and skipped it
precisely there.

The early return is now reserved for the genuinely-nothing case, no fragments **and** no
`CHANGELOG.md` (`scripts/check_changelog_citations.py:577`
("if not fragments and not CHANGELOG.is_file():")). The `CHANGELOG.md` half runs either
way, and keeps its split: `[Unreleased]` describes the current tree and is graded as
**errors**; released history describes trees that no longer exist, so its broken citations
stay **warnings** — visible, never silently passed, never blocking. Collapsing that split
would make the gate unlandable without rewriting shipped release notes to suit today's
tree, which is the opposite of what a changelog is for.

This also closes an asymmetry #2175 left behind: `--fix` falls through to the checker so
its exit code is the gate's own verdict (`scripts/check_changelog_citations.py:555`
("if args.fix:")), which meant a release-cut tree with an unrepairable citation answered
`1` with the flag and `0` without it. Which verdict you got depended on how you asked.
Both now answer `1`.

Run against unmodified `dev` the change is inert: with 316 fragments present the widened
condition is unreachable, and the gate's output is byte-identical to what it was. The
behaviour only differs on the tree nothing was checking
(`tests/scripts/test_check_changelog_citations.py:581`
("def test_empty_changelog_d_still_grades_a_broken_unreleased_citation(")).

That tree was not hypothetical. Running the actual release cut against today's `dev` —
`scripts/assemble_changelog.py` then `scripts/check_changelog_citations.py` — went red
with 5 broken citations, all one class: `[Unreleased]` prose citing a `changelog.d/**`
fragment that the fold itself had just deleted
(`scripts/assemble_changelog.py:228` ("path.unlink()")). `--fix` correctly refused all
five, because no anchor can resurrect a path that no longer exists. This is unresolvable
by construction, not a broken citation — the same shape `_FOREIGN_PREFIXES` already
covers for a citation into another repository
(`scripts/check_changelog_citations.py:163`
("_FOREIGN_PREFIXES = (")) — so a
`changelog.d/**` citation made FROM `CHANGELOG.md` itself is classified the same way, but
only when the file it names is genuinely gone: the skip is gated on `not (REPO /
rel).is_file()`, not on the citing document alone. Keying it on the source alone was itself
over-broad — a `changelog.d/**` citation whose target has **not yet** been folded away (a
hand-edited `[Unreleased]` entry citing a fragment that still exists) was being SKIPPED
too, the exact grading this fragment's own gate exists to keep, silently lost the same way
#1387's citation was. It is now graded normally, same as any other citation. The same
citation made FROM INSIDE A FRAGMENT is unaffected either way and keeps grading exactly as
before, because fragments legitimately cross-reference each other before the fold ever
runs. That target-aware branch, applied identically in `_check_one` and `_fix_one`, is
what keeps the release-cut tree green without also swallowing a citation whose target
survived.
