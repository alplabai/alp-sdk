### Added — RZ/V2N pinmux rows can carry an AMP `core` attribution; cross-core conflict detection is still to come (#1157)

- `metadata/pinmux/<family>.yaml` pads can now carry an optional `core` field
  distinguishing which AMP core (`a55` Linux vs `m33` Zephyr) drives a
  Renesas-owned V2N pad. Sourced from a new
  `metadata/e1m_modules/v2n/core-ownership.yaml`, keyed by `(peripheral,
  pad)` and populated only with silicon-verified pads (the GD32 supervisor
  SPI's `MOSI`/`MISO`/`SCLK`/`CS0` and `RIIC8` `SCL`/`SDA`, all CM33-owned).
  An ownership entry that matches zero rows, more than one row, or that
  duplicates another entry's `(peripheral, pad)` key is a hard generator
  error. Unattributed rows carry no `core` field -- absence means "not
  attributed", never "shared" or "a55 by default".
- This lands the field, not the check: nothing yet compares a Linux-side
  claim against a Zephyr-side claim, so #1157's motivating collision
  (`docs/errata-e1m-x-v2n.md` E3 -- Linux's `P9.6` gpio-hog versus the
  CM33's `P96`/`SCK7` mux) still surfaces as a bench surprise, not a
  validation error. Cross-core conflict detection is follow-up work; this
  PR uses `Refs #1157`, not `Closes #1157`.
