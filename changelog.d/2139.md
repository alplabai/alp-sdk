### Fixed — `abi_snapshot.py --diff` reported a moved+value-changed symbol as `REMOVED` + `ADDED`, hiding the real change (#2139)

MOVED detection (`_diff()`'s REMOVED/ADDED pairing) required an identical content
hash between the disappearing and reappearing symbol, so a header split that also
changed the symbol's value — #2129's `evk_sdio_select_t` enumerator swap
(`EVK_SDIO_SDCARD` 1->0, `EVK_SDIO_M2E_KEY` 0->1) riding along with the
`alp_e1m_evk.h` -> `alp_e1m_evk_routes.h` split — read as a plain removal plus an
unrelated addition. The freeze gate in `.github/workflows/pr-generated-files.yml`
blocks on any `REMOVED` line, so the only way through was a false
`docs/abi/removed-symbols.json` entry claiming the typedef no longer exists, and
the enumerator swap itself never showed up anywhere a reviewer would see it.

`diff()` now prefers an exact-hash MOVED match as before, and falls back to a
value-may-differ match when the symbol name is **unambiguous** — exactly one
header lost it, exactly one header gained it, reachable via the same one-hop
`#include` graph MOVED already used. That reports `MOVED` plus an accompanying
`CHANGED` line
(`scripts/abi_snapshot.py:1225` ("CHANGED {r_cat[:-1]} {a_header}::{r_sym} (moved from {r_header})"))
with the same per-field/enumerator detail a same-header CHANGED already gets, or a
"content hash changed" fallback for a record schema with nothing more descriptive
than the hash
(`scripts/abi_snapshot.py:790` ("content hash changed")). Several headers losing or
gaining the same name at once is left alone rather than guessed at — it falls back
to the pre-fix REMOVED + ADDED behaviour
(`scripts/abi_snapshot.py:1198` ("value_changed = False")). The freeze gate's own
`^  REMOVED ` grep is unaffected: a true removal (no reachable candidate at all)
still reports a bare `REMOVED` and still fails the gate. `CHANGED` follows the
existing pre-1.0 policy already documented for a same-header value change — it
prints for review but does not trip the freeze gate, only `--diff`'s own exit code
(`docs/abi/README.md:154` (`(issue #2139) -- a consumer of the`)).

**Round 2 (review):** the unambiguous-name check above keyed only on
`(category, symbol)`, so a struct `alp_x_t` REMOVED from one header and an
unrelated ENUM (or fnptr) `alp_x_t` ADDED in a header the first still reaches
paired as a false MOVED + CHANGED — hiding a genuine removal from the freeze
gate. The pairing and its ambiguity counts now also key on the typedef's own
`kind` (struct/union/enum/opaque/fnptr/alias; `None` for every non-typedef
category, so functions/macros/variables are unaffected)
(`scripts/abi_snapshot.py:1215` ("and a_kind == r_kind")), refusing to pair
across a kind change even when the bare name is unambiguous.

Seven regression cases in `tests/scripts/test_abi_snapshot.py` total: moved+changed
reports MOVED + CHANGED, not REMOVED + ADDED
(`tests/scripts/test_abi_snapshot.py:531` ("def test_diff_reports_moved_and_changed_when_value_also_changed(tmp_path):")),
the concrete `evk_sdio_select_t` enumerator-swap shape reports the enumerator-level
detail, a genuine deletion still reports a bare REMOVED (existing
`test_diff_reports_genuine_deletion_as_removed`, unchanged), an ambiguous
same-name multi-header case falls back to plain REMOVED + ADDED for all of them
(`tests/scripts/test_abi_snapshot.py:618` ("def test_diff_falls_back_when_moved_name_is_ambiguous(tmp_path):")),
a struct-disappears/enum-appears same-name pair still reports REMOVED + ADDED
(`tests/scripts/test_abi_snapshot.py:649` ("def test_diff_reports_removed_added_when_typedef_kind_changes_across_headers(tmp_path):")),
the same for struct-to-fnptr
(`tests/scripts/test_abi_snapshot.py:681` ("def test_diff_reports_removed_added_when_struct_becomes_fnptr_across_headers(tmp_path):")),
and a same-kind (enum-to-enum) move with changed values still reports
MOVED + CHANGED, proving the `kind` check refuses a mismatch and nothing else
(`tests/scripts/test_abi_snapshot.py:708` ("def test_diff_reports_moved_and_changed_for_same_kind_enum_across_headers(tmp_path):")).

`docs/abi/removed-symbols.json` is untouched here — #2129 owns its `evk_sdio_select_t`
entry and drops it once this merges.
