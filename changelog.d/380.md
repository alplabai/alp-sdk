### Changed — i.MX93 reports interim peripheral counts from the Zephyr device tree (#380)

`metadata/socs/nxp/imx9/imx93.json` carried only `mipi_dsi: 1` and `lcdif: 1`, so every other `ALP_SOC_*_COUNT` on E1M-NX9101 was 0 and the derived `ALP_CAP_HW_*` capabilities read false. Nine keys are now populated from the pinned Zephyr v4.4.1 device tree (`dts/arm64/nxp/nxp_mimx93_a55.dtsi`, cross-checked against `dts/arm/nxp/imx/nxp_imx93_m33.dtsi`): `i2c: 8`, `spi: 8`, `uart: 2`, `i2s: 1`, `can_fd: 2`, `watchdog: 2`, `timer_tpm: 6`, `ethernet_1g: 1`, `usb_2: 2`. The file's `notes` name the nodes behind each count.

These are not reference-manual figures. A device tree lists the nodes Zephyr describes, not everything on the die, so each count is a lower bound: all nine keys are in `peripherals_unverified`, `include/alp/soc_caps.h` prints them in an `UNVERIFIED` comment above the block, and `pending_reference_manual_ingestion` stays `true`. The IMX93RM.pdf pass is still owed and #380 stays open for it.

Three things were left out on purpose. The TPM instances use the key `timer_tpm` rather than `timer_32bit`, because `gen_soc_caps.py` falls `PWM_COUNT` back to `timer_32bit` and no native PWM leg is claimed for NX9101; `ALP_SOC_TIMER_COUNT` is 6 and `ALP_SOC_PWM_COUNT` stays 0. The SAR ADC is not keyed, because an `adc_<N>bit` key needs a resolution the device tree does not state. GPIO is not keyed, because `gpio` is a pin count and the four `nxp,imx-rgpio` nodes carry no `ngpios`.

Regenerated: `include/alp/soc_caps.h`, `metadata/catalog.json`, `docs/peripheral-support-matrix.md`.

One visible consequence: `tan validate` no longer raises ALP-B010 for `can` on E1M-NX9101, because the SoC file now lists `can_fd`. The ALP-B010 test fixture and the example in `docs/diagnostics/ALP-B010.md` use `dac` instead, which the file still does not list.
