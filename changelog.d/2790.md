### Fixed — a static `libalp_sdk.a` keeps every Linux backend, not just camera (#2790)

A static plain-CMake link only pulls the archive members something
references, and the class dispatchers reference only their catch-all stub or
software fallback. Every backend that sits in its own TU beside that stub was
dropped, and the app silently got the stub: the 17
`src/backends/<class>/yocto_drv.c` backends (adc, audio, camera, can,
counter, display, i2s, i3c, mqtt, power, pwm, rpc, rtc, security, storage,
usb, wdt), rpc's `yocto_uio_drv.c` and jpeg's `zephyr_stub.c`. #2616 had fixed
camera alone with one hand-written link option.

`ALP_BACKEND_REGISTER` now exports `_alp_backend_force_<class>_<name>` on
plain-CMake builds (new `ALP_BACKEND_FORCE_DEFINE` in `<alp/backend.h>`).
`cmake/alp-sdk-static-backends.cmake` reads every `alp_sdk` C source once
all sources are added and puts `--undefined=` for each registration on
`alp::sdk`'s INTERFACE link options. A new backend therefore needs no CMake
line of its own. Shared builds and non-ELF hosts are untouched.
`ALP_BACKEND_ANCHOR_FORCE` stays as a plain declaration, so existing callers
still compile.

A consumer that compiles its own copy of a backend opts out with the
`ALP_SDK_NO_FORCED_BACKENDS` target property. Three yocto tests do so,
because they rely on the sw_fallback or on their own copy of a backend.
`alp_test_static_link_backends` replaces the camera-only `nm` check and
requires all 19 registry entries in a static test binary. Without the fix,
all 19 are missing and camera selects the stub.

Behaviour change: on a Linux host without OpenAMP, a static app's
`alp_rpc_open()` now reaches `rpc/yocto_drv.c`, whose NOSUPPORT build
answers `ALP_ERR_NOSUPPORT`. A shared build has always behaved this way, and
the dispatcher does not fall back to the next backend when `open()` fails.
