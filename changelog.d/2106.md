### Fixed — `drone-autopilot`'s hardware scenario named a board target it ships no overlay for, silently dropping every `alp-*` alias (#2106)

`examples/peripheral-io/drone-autopilot`'s only board overlay is
`boards/alp_e1m_aen801_m55_hp_ae822fa0e5597ls0_rtss_hp.overlay`, written for
#1383 item 2 to close the same devicetree-alias gap
`examples/peripheral-io/pwm-led-fade` closed for #1375. `testcase.yaml`'s
`alp_sdk.examples.drone_autopilot.aen` scenario, unchanged since the
example's introduction (`4a1c1a732`), named a different board target --
`ensemble_e8_dk/ae822fa0e5597ls0/rtss_hp` -- and #1383's overlay-adding
commit never corrected it. Zephyr resolves a `boards/` overlay by
fully-qualified board target name, so building for that target picked up no
overlay and no `alp-*` alias, with no error or warning (the scenario is
`build_only: true`, so nothing ever ran to surface it).

`board.yaml` names `som.sku: E1M-AEN801` / `preset: e1m-evk`, the README's
"Hardware" section says E1M-AEN801 + E1M-EVK, and the sibling
`examples/aen/aen-pwm-utimer-pwmleds` / `examples/aen/edgeai-vision-aen`
scenarios that target the same overlay both use the fully-qualified
`alp_e1m_aen801_m55_hp/ae822fa0e5597ls0/rtss_hp` form -- so the overlay was
right and the scenario's `platform_allow` was wrong. Corrected
`testcase.yaml`'s `platform_allow` to `alp_e1m_aen801_m55_hp/
ae822fa0e5597ls0/rtss_hp`, and updated the README's two `ensemble_e8_dk/...`
mentions (the `[UNTESTED]` banner and the `west build -b ...` command) to
match.

Verified against the generated devicetree rather than a green build alone: on
the corrected target `build/zephyr/zephyr.dts` carries `alp-i2c0 = &i2c2`,
`alp-uart1 = &uart3`, and `alp-pwm0`..`alp-pwm3 = &esc0`..`&esc3`, all
attributed back to the overlay; on the old `ensemble_e8_dk/...` target none
of the six aliases appear anywhere in the generated tree.

No other `examples/peripheral-io/*` scenario declares a non-`native_sim`
`platform_allow`, so this was the only occurrence of the mismatch in that
directory. #2120's declared-target-with-no-overlay gate scopes to
`alp_e1m_*` platform_allow entries and would not have caught this one, since
the declared (wrong) target here was the vendor `ensemble_e8_dk` board, not
an `alp_e1m_*` one; not widened here.
