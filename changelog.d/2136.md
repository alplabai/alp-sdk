### Added — CC3501E host-side link-failure ring (#2136)

**Before:** a bridge wedge left no usable evidence. `cc3501e_request_locked()` overwrote
`ctx->rx_scratch[0]` on every pre-decode failure, and the firmware side could not fill the gap
either — a wedge-probe build's warm `nRESET` does not preserve retained RAM across the reset
(cc3501e-bridge-firmware#148).

**After:** `cc3501e_t` carries an 8-entry `link_log` ring (`<alp/chips/cc3501e/core.h>`),
filled only when a request bails with no reply status decoded. Each entry records the opcode,
which wire phase the attempt reached, the mapped status, the request- and reply-header bytes,
READY-line evidence, and the recovery-attempt count — enough to tell a deaf-armed slave apart
from a desynced or crashed one. Read it via `cc3501e_link_log_count()` /
`cc3501e_link_log_get()`, or `alp companion linklog`; the recovery callback also dumps it right
before printing its own recovery line.

The ring now survives the very recovery it exists to outlive:
`cc3501e_link_check_and_recover()`'s own up-to-24-PING probe used to overwrite the whole ring 3x
over before a bench operator ever saw it, evicting the original wedging op's entry in favour of
8 identical PING failures. The probe now suppresses ring writes for its own duration
(`ctx->link_log_suppress`) and counts its failures separately
(`cc3501e_link_log_probe_fail_count()`, surfaced in the recovery-notify dump) instead of evicting
anything. Each entry's `hdr_bytes` / `reply_hdr` are now zeroed and flagged invalid
(`CC3501E_LINK_LOG_HDR_BYTES_VALID` / `CC3501E_LINK_LOG_REPLY_HDR_VALID`) unless that phase's own
transceive actually returned `ALP_OK` — previously a bail could present a prior attempt's stale
`rx_scratch` residue as if it were this attempt's wire data. `cc3501e_link_log_count()` /
`_get()` now take the driver's request lock so a read can never observe a torn write, with
`cc3501e_link_log_fail_streak()` and `cc3501e_link_log_recover_streak()` (the streak as it stood
before the confirming PING that follows a warm reset resets it) added alongside for the same
reason. The never-reachable `CC3501E_LINK_LOG_PHASE_VERDICT` macro was removed rather than kept
as documented dead code.
