### Fixed — nine handle pools still claimed a slot with an unlocked check-then-set, and nothing stopped a tenth (#1630)

`if (!in_use) { in_use = true; }` is two operations. Two callers opening
concurrently can both read the flag false, both take the slot, and alias their
handles — so one caller's `close()` frees state the other is still using. #1115
converted the pools it knew about onto `alp_slot_try_claim()`'s atomic
compare-exchange (`src/common/alp_slot_claim.h`) and nine survived, because that
remediation worked from a hand-written site list rather than from a grep. #629
had the same shape. Each issue closed and the class kept shipping.

Converted, alloc and free path both, to `alp_slot_try_claim()` /
`alp_slot_release()`:

- `src/backends/storage/zephyr_littlefs.c` — the worst of the nine. Two aliased
  handles onto one littlefs mount is two `lfs_t` states over one flash area:
  filesystem corruption on a persistent store, not a lost handle.
- `src/backends/inference/tflm.cpp` — the single shared default tensor arena.
  Two interpreters both won it and ran inference over each other's activations
  instead of one getting a clean `ALP_ERR_NOMEM`. This one is a bare scalar with
  no loop and no array subscript, which is precisely why every array-shaped grep
  in #1115's remediation walked past it.
- `src/backends/mproc/zephyr_drv.c` — all three pools (shmem, mbox, hwsem), which
  are verbatim copies of each other.
- `src/backends/ble/zephyr_drv.c` (connection pool),
  `src/backends/usb/zephyr_drv.c`, `src/backends/dac/zephyr_drv.c`,
  `src/backends/power/zephyr_pm_policy.c`.

All eight array-shaped pools keep `in_use` in a parallel `bool[]` rather than
inside the slot struct, so the winner may `memset` the whole slot after claiming
it; the `offsetof` form used by the in-struct pools is neither needed nor
compilable here.

**The sweep is the precondition; the gate is the deliverable.** New
`scripts/check_slot_claim_atomic.py` rejects the antipattern anywhere under
`src/`. It matches the *set* half — any plain assignment of an `in_use` flag to
`true` — rather than the `if (!in_use)` test half, for two reasons:
`alp_slot_try_claim()` never assigns the flag, so its absence is a complete
signal; and the test half is not always a negation — the TFLM site guarded a
singleton with `if (g_default_arena_in_use) { fail; }`, which no
array-shaped-negation grep can see. Comments are stripped before scanning, since
`src/` carries a dozen lines that quote the antipattern while explaining why the
code below no longer does it.

Four sites are allowlisted because their claim is already serialised by a held
lock, and each entry has to name that lock so the list cannot grow by assertion:
`src/zephyr/handles.c` (`k_mutex_lock(&kind##_lock, K_FOREVER)`),
`src/yocto/peripheral_gpio.c` (`pthread_mutex_lock(&g_irq.mu)`),
`src/backends/can/yocto_drv.c` (`pthread_mutex_lock(&d->lock)`), and
`src/backends/can/testing_drv.c` (a per-handle filter table reached through one
handle, not a shared static pool).

`.github/workflows/pr-metadata-validate.yml` now triggers on `src/**`. It did
not before, listing only `src/common/stub_backend.c` and `src/common/stub/**`,
so a PR adding a tenth unlocked claim would never have run the new gate — and,
already today, would never have run `check_stub_issues.py` (which sweeps
`src/backends/**/*_stub.c`) or `check_sw_fallback_tags.py` (which sweeps
`src/backends/**/sw_fallback.c`) either. Same trigger hole, three gates.

`src/zephyr/handles.c` carries a *different* defect that is deliberately not
touched here: `kind##_slots[i] = (struct type){ 0 };` re-owns a slot while an
operation may still be in flight. That is the close-versus-op class tracked by
#1644.
