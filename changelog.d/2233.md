### Fixed — Flow D MRAM writes sector-pad neighbours and prove themselves with a fresh-session read-back, not `verifybin` (#2233)

Two defects measured on real hardware during the #2067 persistence proof made
every Flow D MRAM writer unsafe as written. SEGGER's built-in
`AE822FA0E5597LS0_M55_HE` loader always erases and reprograms WHOLE 16 KiB
sectors and never reads a sector's prior contents first, so a `loadbin` that
does not start and end on a sector boundary silently turned every other byte
in its first/last sector to `0xFF`. Separately, `verifybin` was comparing
against J-Link's own in-process flash cache, never a fresh chip read — a
`Verify successful.` proved nothing about what MRAM actually held.

`scripts/bench/aen/flowd_sector_pad.py:65` (`class FlowdSectorPadError(Exception):`)
is a new, pure host-side helper: given the blob(s) a write touches, it merges
their sector-aligned ranges, overlays the blob bytes on a pre-read sector
image, and refuses on a blob outside the MRAM window, a non-power-of-two
sector size, or two blobs overlapping with different bytes. It also pre-reads
and proves a GUARD sector immediately before/after each padded range, so
collateral damage just outside the intended write is visible, not just damage
inside it. `scripts/bench/aen/bench-env.sh:1977` (`bench_flowd_proof() {`) is
the shared bash orchestration — plan, read the touched sectors, build the
padded images, and a FRESH read-only J-Link session that `savebin`s each
range (and its guards) back and `cmp`s it against the padded image, which
proves both that the blob landed and that its immediate neighbours survived
THIS write.

Every affected writer — flash-jlink.sh, flash-jlink-hp.sh,
flash-jlink-mramxip.sh, flash-update-log-dual.sh,
flash-update-log-firewall-probe.sh, and the #1430 provisioning
erase-storage.sh — now gates on `bench_flowd_proof()` instead of `verifybin`,
and each write session also `savebin`s its own touched sectors immediately
before the load line(s) so a host-side compare against the original pre-read
can catch (not prevent — the pre-read is not halted) a write racing this
one between the read and the load. `FLOWD_DRY_RUN=1` is a THREE-layer
guarantee, not a flag with one effect: every writer exits right after
printing its would-be write CommandFile, `bench_jlink_run()` independently
refuses any `loadbin`/`erase` CommandFile while it is set, and
`bench_flowd_proof()` itself never reports success in this mode — an earlier
version of this fix only did the first of the three, so the write session
still ran for real underneath a "dry run" label.

`erase-storage.sh` additionally now resolves where the RESIDENT ATOC package
actually starts before erasing (`scripts/bench/aen/atoc_trailer.py`,
bench-measured on one real E1M-AEN803 board, serial 2026W36-0001,
2026-09-19) and refuses outright if the erase window would overlap it — on
that board the live package started well inside the nominal customer storage
window this script erases, which a metadata-window-only erase would have
zeroed part of. `--sku`/`ALP_AEN_SKU` picks which module preset a run
targets (previously hard-coded to E1M-AEN801), and every pre-write sector
read is copied to `$BENCH_ROOT/flowd-backup/<timestamp>-erase-storage/`
before any write, printed at run time — the only restore source on a board
with no SE-UART.

None of this is a persistence proof across a power cycle: the fresh-session
read-back proves the write landed and its neighbours survived within the
SAME power cycle, not that it survives one. flash-jlink-mramxip.sh's own
"ACCEPTANCE ON THIS PATH IS A COLD-CYCLE READBACK" requirement is unchanged
and still stands on top of this proof, not replaced by it.

A third adversarial review round found the proof itself failing OPEN:
`scripts/bench/aen/bench-env.sh:2058` (`rc=$?`) used to sit after a separate
`if cmd; then break; fi`, whose OWN exit status is 0 when the `if` takes no
branch — exhausting all 3 connect retries returned success. `rc=$?` now sits
immediately after the command it reads. Every writer's write-session
invocation now captures `bench_jlink_run()`'s own exit status (a bare
`|| true` used to swallow a FLOWD_DRY_RUN backstop refusal, rc 13) and exits
13 before any race check, proof, or boot; the race check and the read-back
proof now both always run and both print, with a detected race winning the
exit code (11) even when the proof passed, instead of the race check
exiting first and hiding the proof's verdict. `erase-storage.sh` treats
FLOWD_DRY_RUN exactly like `--dry-run` (it used to back up SYNTHETIC
all-zero sectors as if real), reads the WHOLE `atoc` region rather than only
the trailer's own sector so a blank trailer next to a live signature is
refused (`scripts/bench/aen/atoc_trailer.py`'s own blank-trailer search),
rejects an unrecognised argument or a value-less `--sku`
(`scripts/bench/aen/erase-storage.sh:336` ("ATOC_REGION_SIZE=$((ATOC_KIB * 1024))")),
and no longer hard-codes `/tmp/aen-erase-storage.jlink`/`/tmp/aen-erase-storage.out`/
`/tmp/aen-storage-erased.bin` (every writer now uses `${TMPDIR:-/tmp}`, so
concurrent test runs no longer collide on the same host `/tmp`).
`scripts/bench/aen/atoc_trailer.py` also now refuses a header outside its
own package or a zero-size package, not just a bad checksum or signature.

A fourth round added `erase-storage.sh --check-only`: a READ-ONLY mode that
runs the DPIDR preflight and the whole-atoc-region trailer read/overlap
decision exactly like a real run — so the overlap GUARD ITSELF is exercised
on real silicon, not just its arithmetic — then exits
(`scripts/bench/aen/erase-storage.sh:395` (`if [ "$CHECK_ONLY" = 1 ]; then`))
before the pre-write backup, `bench_flowd_prepare_write`, or any
write-session CommandFile is ever built. Exit 0 means the erase would
proceed (the resolved package start, or "blank trailer", is printed); exit 7
means it would be refused for an overlap; exit 6 means the trailer was
undeterminable — the SAME exit codes and the SAME trailer-check code the
real path uses, not a parallel simulation. `--check-only` is mutually
exclusive with `--dry-run`/`FLOWD_DRY_RUN` (exit 1), which is the opposite
promise (no probe opened at all); `bench_jlink_run()`'s `FLOWD_DRY_RUN`
backstop is also set internally as defense in depth, exported only AFTER
the existing `--dry-run`-aliasing check so it does not also skip the real
reads this mode exists to run.

A fifth round found the trailer layout itself wrong by one word, on real
E1M-AEN803 silicon (serial 2026W36-0001, 2026-09-19): `mem32` twice plus a
`savebin` tail agreed on `0x8057FFF0` = `4966A80E 8057FF90 8056A3C0
00015C40`, but `header_address`/`package_start`/`package_size` were being
unpacked from trailer offsets `+0x0/+0x4/+0x8` instead of the REAL
`+0x4/+0x8/+0xC` — `+0x0` holds an opaque word (`word0`, bench-measured
`0x4966A80E`, unknown meaning, possibly a checksum, never validated).
`scripts/bench/aen/atoc_trailer.py:101` (`word0, header_addr, pkg_start, pkg_size = struct.unpack("<IIII", data)`) now reads all four words at the
right offsets; the old offsets misparsed `word0` as `header_address` and
refused every real trailer, so `erase-storage.sh --check-only --sku
E1M-AEN803` exited 6 ("undeterminable") on real hardware instead of the
expected 7 (overlap) — the guard failed CLOSED, but the overlap decision
was never reached. Every fixture that built a trailer (`test_atoc_trailer.py`,
`test_bench_flowd_write.py`, `test_flowd_review_round3.py`) reproduced the
same wrong layout, which is why the tests passed anyway; new tests build a
trailer from the EXACT measured 16 bytes and confirm the OLD (wrong)
three-word layout is now refused, not misparsed into a false proceed.
