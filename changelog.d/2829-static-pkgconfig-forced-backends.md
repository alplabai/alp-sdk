### Fixed — a non-CMake static link of `libalp_sdk.a` on Yocto no longer drops the second backends (#2829)

`gcc app.c -lalp_sdk` pulled only the archive members something referenced, so `src/backends/can/yocto_drv.c` and every other Linux `yocto_drv.c` were dropped and the app silently ran on `sw_fallback`; only CMake consumers got the `--undefined=_alp_backend_force_<class>_<name>` options (#2790). A static Linux build now writes `alp-sdk.pc` (`lib/pkgconfig/`, installed together with `libalp_sdk.a` and the `<alp/*>` headers) whose `Libs:` carries those options before `-lalp_sdk` and whose `Libs.private:` carries the libraries the forced backends need. A recipe or Makefile links with `$(pkg-config --static --cflags --libs alp-sdk)`. The new `alp_test_static_link_pkgconfig` ctest links the probe through the `.pc` with a plain `cc` and checks every non-anchor backend is in the binary. The `meta-alp-sdk` recipe still builds the shared library and is unchanged.
