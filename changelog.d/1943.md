### Fixed — `scripts/validate_metadata.py` no longer imports `alp_model` (#1943)

`resolve_targets()` / `npu_backend()` / `accel_config()` moved from
`scripts/alp_model/targets.py` into `scripts/alp_project_loader.py`. The
model-perf-v1 semantic cross-check that `validate_metadata.py` runs on every
PR had grown a load-bearing, module-scope
`from alp_model.targets import resolve_targets, _npu_backend, _accel_config`,
which meant `scripts/alp_model/` (13 files) — due for deletion now that the
host-side model engine lives in tan-cli's `tan.model` — could not be removed
without breaking that gate on every PR (#1470, #1884, #1896).

Per the just-recorded ADR-0026 §C/§D decision that alp-sdk stays canonical
for rendered bytes and tan consumes rather than re-implements, the
resolution logic moved to an in-repo home (`alp_project_loader.py`) rather
than repointing the gate at tan-cli. `scripts/alp_model/targets.py` keeps the
two names its own `build.py` still imports (`resolve_targets`, `TargetSpec`)
as a thin re-export — `alp_model` is not deleted by this change; that is a
follow-up PR's own job, now that nothing PR-blocking depends on it. A new
`tests/scripts/test_validate_metadata_no_alp_model_import.py` AST-walks
`validate_metadata.py`'s imports so a re-introduced dependency on `alp_model`
fails the suite instead of going unnoticed again.
