### Fixed — `scripts/validate_metadata.py` no longer imports `alp_model`, unblocking ADR-0028 Task 6 (#1943)

`resolve_targets()` / `npu_backend()` / `accel_config()` moved from
`scripts/alp_model/targets.py` into `scripts/alp_project_loader.py`. The
model-perf-v1 semantic cross-check that `validate_metadata.py` runs on every
PR had grown a load-bearing, module-scope
`from alp_model.targets import resolve_targets, _npu_backend, _accel_config`,
which meant ADR-0028 Task 6 — deleting `scripts/alp_model/` (13 files) now
that the host-side model engine lives in tan-cli's `tan.model` — could not
be executed without breaking that gate on every PR (#1470, #1884, #1896).

Per the just-recorded ADR-0026 §C/§D decision that alp-sdk stays canonical
for rendered bytes and tan consumes rather than re-implements, the
resolution logic moved to an in-repo home (`alp_project_loader.py`) rather
than repointing the gate at tan-cli. `scripts/alp_model/targets.py` keeps its
historic import surface as a thin re-export (`_npu_backend`/`_accel_config`
alias the now-public `npu_backend()`/`accel_config()`), so
`scripts/alp_model/build.py` and the package's own test suite are
unaffected — `alp_model` is not deleted by this change; that is Task 6's own
follow-up PR.
