### Fixed — `scripts/validate_metadata.py` no longer imports `alp_model` (#1943)

`resolve_targets()` / `npu_backend()` / `accel_config()` moved from
`scripts/alp_model/targets.py` into `scripts/alp_project_loader.py`. The
model-perf-v1 semantic cross-check that `validate_metadata.py` runs on every
PR had grown a load-bearing, module-scope
`from alp_model.targets import resolve_targets, _npu_backend, _accel_config`,
which meant `scripts/alp_model/` (12 files) — due for deletion now that the
host-side model engine lives in tan-cli's `tan.model` — could not be removed
without breaking that gate on every PR (#1470, #1884, #1896).

Per the just-recorded ADR-0026 §C/§D decision that alp-sdk stays canonical
for rendered bytes and tan consumes rather than re-implements, the
resolution logic moved to an in-repo home (`alp_project_loader.py`) rather
than repointing the gate at tan-cli. `scripts/alp_model/targets.py` is
deleted outright rather than kept as a re-export shim: its only remaining
caller, `scripts/alp_model/build.py`, now imports `resolve_targets` from
`alp_project_loader` directly (this repo has no legacy customers to shield,
so the shim was worth zero once its one caller could be repointed).
`tests/scripts/test_alp_model_targets.py` — coverage of this resolution
logic, not of anything else in the package — is renamed to
`test_alp_project_loader_targets.py` so it survives Task 6 instead of
matching a `git rm tests/scripts/test_alp_model_*.py` glob.
`tests/scripts/test_validate_metadata_no_alp_model_import.py` no longer
AST-walks `validate_metadata.py`'s imports (a proxy a transitive or
in-function `import alp_model` would pass); it copies the real `scripts/`,
`metadata/`, and `zephyr/boards/alp` trees, deletes `scripts/alp_model/`
from the copy, and actually runs `validate_metadata.py` against it.

`alp_model` is **not** deleted by this change — Task 6 remains its own PR —
and the earlier claim that "nothing PR-blocking depends on it" once that
happens was wrong. Two things still block a clean Task 6, named here so the
next PR isn't surprised by either:

* `scripts/alp_model/`'s own test suite is not touched by this fix:
  `tests/scripts/test_alp_model_{adapters,build,manifest,package,tensorio}.py`,
  `test_deepx_yolo_internal.py`, and `test_vela_yolo_internal.py` all import
  the package directly and must be deleted in the **same** PR as
  `scripts/alp_model/` itself, or `pytest tests/scripts/` aborts collection
  the moment the package is gone.
* `docs/bring-up-drpai-v2n.md` documents `ALP_DRPAI_TVM_HOME`, whose only
  in-tree definition is `scripts/alp_model/adapters/drpai.py`. `check_doc_drift.py`
  harvests `scripts/**/*.py` as one of its "does this identifier exist
  somewhere real" sources; deleting the adapter without giving that doc a
  new home for the identifier fails `check_doc_drift.py` on the Task-6 PR.

Cross-repo note: this fix's edits to `scripts/alp_project_loader.py` change
its sha256, and tan-cli pins that exact file's content hash verbatim in
`python/tests/gates/test_planner_relocation_freshness.py`'s
`HAND_PORT_HASHES` table (the file is hand-ported into tan's own planner
modules). Not red in alp-sdk today, but tan-cli's freshness gate will flag
the pin as stale the next time someone re-audits that table against an
alp-sdk commit at or past this one.
