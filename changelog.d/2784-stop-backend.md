### Added — Alif SE STOP / STANDBY power backend for the E8 M55-HE (#2784, unit U7)

`alp_power_request_sleep(STOP | STANDBY)` now has an implementation on the Alif Ensemble E8 M55-HE (E1M-AEN801 / E1M-AEN803): `src/backends/power/alif_se_power.c`, registered for `alif:ensemble:e8` behind `CONFIG_ALP_SDK_POWER_ALIF_SE`. **Off by default, experimental, untested on silicon.**

- **Complete, explicit OFF profile.** `se_service_set_run_cfg` / `set_off_cfg` are not side-effect-free (a one-field read-modify-write dropped `memory_blocks` bit 20 and cleared the VBAT retention-LDO enables and the CVM retention masks), so every `off_profile_t` member is assigned by name: STOP keeps the VBAT AON domain, `dcdc_mode` OFF, `aon_clk_src` LFXO only when the live clock tree confirms it (else LFRC; with LFXO `XTAL32K_CAP_CONT` is set to 63), `memory_blocks` BKRAM (gen2 bit 21) plus the HE TCM banks the retention asks for, I/O flex 1.8 V, `wakeup_events` / `ewic_cfg` from the gen2 masks, and `vtor_address` preserved from the live profile so the wake goes through SES -> ATOC. The profile is read back after the SE call, the retention bits it needs are re-asserted, and the request is abandoned if they do not stick.
- **Wake sources, only what is real.** `ALP_POWER_WAKE_RTC` is the on-module RV-3028 on INT -> P15_0 -> `WE_LPGPIO0` (primary RTC; the internal LPRTC is not trusted for timed wake); `ALP_POWER_WAKE_TIMER` is the LPTIMER for `wake_after_ms < 1000` (its LFRC clock runs ~4.5 % fast); `wake_after_ms >= 1000` uses the RV-3028 countdown (`rv3028c7_timer_start`, #2794).
- **Refusals before any change.** `ALP_ERR_BUSY` when a debugger is attached (`DHCSR.C_DEBUGEN`; bench override `CONFIG_ALP_SDK_POWER_ALIF_SE_ALLOW_DEBUGGER`) or an armed source is already pending; `ALP_ERR_NOSUPPORT` with the D-cache on; `ALP_ERR_NOT_READY` when the core's low-power-state requests are not OFF. A failure after the quiesce disarms the sources and restores the domains.
- **EWIC entry.** Read-modify-write of `AON.RTSS_HE_CTRL` (WIC on, EWIC selected, `COLD_WAKEUP` cleared), SLEEPDEEP, WFI, following the DFP's subsystem-off sequence; the kernel tick is stopped for the sleep.
- **Wake path.** The cycle record now carries what was armed; on the cold boot the LPTIMER status is read before its driver initialises and the RV-3028 flags and calendar in the I2C pass, filling `alp_power_boot_wake_info()` (`wake_source`, `slept_ms` from the RV-3028 calendar). The record moves from a `__noinit` placeholder into the 4 KB Utility SRAM: a new `bkram` devicetree node (`0x4902C000`, `zephyr,memory-region = "ALP_BKRAM"`, bench-verified on the E8 on 2026-10-09: 4 KiB read/write, survives `SYSRESETREQ`, lost on a cold power cycle; `BKRAM_CKEN` is asserted before every access), used only when `CONFIG_ALP_SDK_POWER_ALIF_SE` is on. A STANDBY record is no longer dropped when `STOP_MODE_STAT` is clear.
- **Tests and example.** `tests/unit/power_alif_se` (profile construction with a poison pre-fill, refusals, unwinds, wake decode), extra `power_som_domains` cases, `tests/scripts/test_alif_se_power_svd.py`, and the bench example `examples/aen/aen-power-stop` (MRAM image, three STOP cycles).

**Bench result (U8h, E1M-AEN803 on an E1M-EVK).** STOP works: LPTIMER (500 ms and 5 s), RV-3028 countdown (11 s) and RV-3028 alarm all woke, every verdict passed, BKRAM survived, and the post-wake clocks were at nominal (115200 baud) thanks to the boot-time clock restore, now on by default. MRAM | SERAM in `memory_blocks` is required (without it the SE reboots instead of resuming and the return is classified as a non-STOP wake); `vtor_address` = `SCB->VTOR` is optional. About 0.043 A in STOP against 0.058 A awake on the EVK board rail at 16 V (a board-level reading, not a SoC measurement). **Not proven:** STANDBY, the HE TCM bank sizes, retention of application RAM, other SoMs.

**Review fixes.** The LPGPIO combined line (IRQ 57, Alif DFP rtss_he soc.h, LPGPIO_COMB_IRQ_IRQn) now has an acknowledge-only handler, and the wake pad is armed (falling edge) and disarmed inside the interrupt-off entry section (`PRIMASK`, as the DFP). A failure after the SE call writes the live profile and the `RET_CTRL` / `VBAT_ANA_REG1` snapshots back and verifies them; all 14 profile members are compared on the readback. BKRAM placement exists only with `CONFIG_ALP_SDK_POWER_ALIF_SE`, with non-cacheable RAM attributes. A STOP wake with no usable record releases every present control pad. `wake_after_ms` is a minimum: the LPTIMER count is rounded up against the fastest clock (never early; on LFRC ~5 % late as measured, up to ~16 % at the bottom of the trim range); a TIMER request served by the RV-3028 countdown reports TIMER; STANDBY keeps PD0 and PD2; a stale STANDBY record is dropped after an RV-3028 power-on-reset; a sleep that returns with no fired source is `ALP_ERR_IO`.

**Bench U8 fix.** The first STOP on the E1M-AEN803 was refused with `ALP_ERR_NOT_READY`: `aen-power-stop` did not enable `&gpio5` / `&gpio11`, so the backlight and PHY-reset pads were unusable and the quiesce failed (the failing rollback also left a RUN-mode record in BKRAM). The example now carries the overlay. Every refusal in the STOP backend, and every unusable pad or failed domain quiesce / restore in the power layer, now prints its step, reason and raw return code on the console.

**Bench U8 fix 2.** The re-run refused at step 6 with `OFF profile dcdc_mode: wrote 0x0, SE reports 0x7f`: hal_alif v2.3.0 does not transport `dcdc_mode` for the OFF profile (`se_service_set_off_cfg()` sends 0 = `DCDC_MODE_OFF`, `se_service_get_off_cfg()` never fills the member in), and the backend compared stack garbage. The read-back buffers are now fully initialised and `dcdc_mode` is probed with a sentinel: unchanged means "not transported" (skipped, logged once; the SE receives `DCDC_MODE_OFF`), changed means a future hal_alif and is compared strictly. The other 13 members stay strict, `undo_se()` uses the same compare, and `aen-power-stop` prints `VBAT_STOP_MODE_REG` decoded on every boot.

**Bench U8c fixes and instrumentation.** The 500 ms LPTIMER wake never fired and the board came back only on a debugger nRESET. The LPTIMER is now armed last, inside the interrupt-off entry, and proven live (enabled, unmasked, counting, not already fired); a timer that already fired is refused with `ALP_ERR_BUSY`, so the SoC is never put to sleep with no wake source. A pin reset (`RTSS_HE_RESET` NSRST) after a sleep is reported as an aborted sleep (`valid`, `realised_mode` RUN, no wake source), not as a wake; the domains are still restored. With the bench scratch option, two raw register snapshots (immediately before the WFI, and at `PRE_KERNEL_1` of the next boot) are kept in BKRAM and printed by `aen-power-stop`, together with the SE's RUN and OFF profiles. Bench-only options (default off) select the vendor sample's `aon_clk_src` (LFXO), `vtor_address` (own VTOR), `memory_blocks` (MRAM | SERAM) and a longer LPTIMER ceiling; `aen-power-stop` has variant fragments. The post-STOP clock restore (the vendor sample re-applies the RUN profile at `PRE_KERNEL_1`) is a TODO for after the data (addendum 6).

**Bench U8c review fixes.** The LPTIMER liveness check polls `CURRENTVAL` (it reads 0 until the 32 kHz domain's first edge, ~30 us) bounded to ~4 LF ticks and refuses only on timeout; the PRE snapshot is taken before any refusal, `RTSS_HE_CTRL` / SysTick words are patched after their writes, the BOOT snapshot saves the AON/LPTIMER/VBAT words before the riskier CLKCTL reads, and slots carry a boot sequence number and the bench cycle (PRE is invalidated once printed). The NSRST syndrome bit is trusted as a pin-reset marker only if it was probed before the sleep and does clear (the SVD calls the field write-only with reset value 1), so a stale bit can never turn a genuine wake into an aborted sleep. The bench-only options now depend on the BKRAM bench scratch option, and variant (iii) moves the RV-3028 countdown cycle to 11 s so it changes only the LPTIMER interval.

**Bench U8d fixes.** The LPTIMER liveness check treats both 0 and 0xFFFFFFFF as "not loaded" and needs a second, strictly smaller read; an LPTIMER wake is rejected when far more time passed since entry than the interval plus a boot (the periodic timer stays pending after any reset). `STOP_MODE_STAT` is acknowledged (exactly `0x10`, never bit 0) once the boot decode is done, and the record and the bench counter carry an image identity so a fresh flash starts clean instead of reading a sticky status as a wake. At boot the backend re-applies a complete RUN profile when the PLL is not locked or the PLL clock select is not the running tree (`CONFIG_ALP_SDK_POWER_ALIF_SE_RESTORE_CLOCKS`, default on). `rv3028c7_init()` clears a stale EVF by writing 0 to it (and never enables EIE). More diag words and a one-shot read-only RV-3028 register dump at an `/INT`-asserted refusal. See ADDENDUM 7 of the design.


**Bench U8e/U8g.** The vendor OFF profile is the backend default: `vtor_address` = `SCB->VTOR` and `memory_blocks` MRAM | SERAM | BKRAM (STOP woke 2 of 2 on the bench with both, never without). The boot-time clock restore no longer takes the Utility SRAM away: it uses the vendor power domains, names BACKUP4K in `memory_blocks`, re-asserts the retention enables, keeps the SDK's BKRAM data in a RAM shadow until the block passes a write/readback, and a sleep refuses (`bkram_unusable`) when it does not. A same-boot rollback no longer needs the BKRAM record. The `/INT` pre-sleep check turns the LPGPIO clock on before reading the pad and only counts RV-3028 flags whose enable is set; a stale UF is cleared. The restore's health check looks at PLL lock and the three `PLL_CLK_SEL` bits that matter for this core, not an exact value.
