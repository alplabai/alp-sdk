### Fixed — `check_tan_docs_surface.py`'s forwarding-verb exclusion never matched the current `tan`'s `--help` output (#1519)

`_has_legacy_passthrough_args()` skipped flag verification for a legacy
FORWARDING verb (`lock`/`migrate`/`quality`) by checking whether its `Usage:`
line ended in `[ARGS]...` — the frozen Rust/Clap spelling. The current Python
`tan` renders the same catch-all through Typer/Click as `[ARGS...]`, so the
check never fired against a real, installed `tan`: `endswith("[ARGS]...")` is
`False` for every verb tan ships today. Latent rather than a live break — the
failure direction was fail-safe (stricter, never falsely green), and
`docs/cli.md` has no section for any of those three verbs yet — but the first
one added would hit a hard flag-mismatch failure with no working escape
hatch.

Both spellings are now accepted. Also corrected the out-of-scope docstring
bullet that named `tan new-som` as the example forwarding verb whose
tabulated flags can't be mechanically checked — `new-som` is native
`[OPTIONS]`-only and its thirteen `docs/cli.md` flags are in fact this
check's main verified surface; the example is now `tan lock`/`migrate`/
`quality`. Test fixtures re-pointed at a real forwarding verb (`lock`, with
the `[ARGS...]` spelling) plus a new regression test proving `new-som`'s
`[OPTIONS]`-only usage line is checked, not skipped as forwarding.
