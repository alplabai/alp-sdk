### Added — `<alp/dsp>` streaming integer-ratio decimator: anti-alias FIR + keep-1-in-N (#2134)

Phase 1 of #2134 only: this adds the standalone decimator to the portable
`<alp/dsp>` layer. It does **not** wire it into the audio-in backend yet —
`alp_audio_in_open(.sample_rate_hz = 16000)` on a board whose PDM can't be
clocked for 16 kHz still fails the same way it did before this change. That
wiring is a separate, later phase (blocked on #2132 / #2133 landing first,
since both touch `src/backends/audio/zephyr_drv.c` and `include/alp/audio.h`,
which this phase deliberately did not touch).

Reuse check first: `<alp/dsp.h>`'s existing `alp_dsp_chain_t` FIR/IIR/window/FFT
pipeline (`alp_dsp_chain_apply_samples`, `include/alp/dsp.h:265`
("alp_status_t alp_dsp_chain_apply_samples(alp_dsp_chain_t *chain,")) has no
rate-changing stage — its contract is `got <= min(in_n, out_cap)`
(`include/alp/dsp.h:258` ("Receives the number of output samples written")),
which a decimator (`out < in`) cannot satisfy without redefining that shared
contract. Nothing else under `<alp/dsp>` filters or resamples. New API added
instead of extending the chain.

New public surface (`alp_dsp_decimator_t` + `alp_dsp_decimator_init` /
`_process` / `_reset`, `include/alp/dsp.h:581`
("alp_status_t alp_dsp_decimator_init(alp_dsp_decimator_t *dec,")):
caller-allocated, no heap (`include/alp/dsp.h:512`
("CALLER-allocated, no heap.  Unlike @ref alp_dsp_chain_t")) — unlike the
pool-backed `alp_dsp_chain_t`, this is a plain value type the caller declares
on the stack/static/embedded in another struct. Supports ratios 2, 3, 4, 6
(covering 48000->16000/8000 Hz and 32000->16000/8000 Hz) and 1..2 interleaved
int16 channels with independent per-channel filter state. `alp_dsp_decimator_process`
(`src/dsp_dispatch.c:547` ("exact_out = (dec->phase + in_frames) / dec->ratio")) computes the
exact output frame count for a call up front from the running phase before
touching any state, so an undersized `out_cap` is rejected with the decimator
left completely unchanged (no partial consumption) — arbitrary block sizes
across calls give bit-identical output to one big call, with the keep-1-in-N
phase preserved across the boundary.

Filter: one Q15 fixed-point, 135-tap, Kaiser-windowed-sinc anti-alias
low-pass (`src/dsp_dispatch.c:489` ("static const int16_t *_alp_dsp_decim_lookup")),
designed by the committed `scripts/gen_dsp_decimator_coeffs.py` (Kaiser beta
3.395, ~40 dB target stopband) and re-verified against the embedded tables.
The same tap count and beta serve every ratio by holding the normalised
transition width constant instead of the passband-edge fraction, so the
achieved specs land in a tight, uniform band instead of degrading at the
largest ratio: ripple 0.17-0.18 dB, stopband attenuation 39.3-39.9 dB above
each ratio's output Nyquist, group delay 67 input samples (~11.2 to ~33.5
output samples depending on ratio) — full per-ratio numbers are in
`alp_dsp_decimator_init`'s Doxygen. Convolution runs in an int64 accumulator
with a Q15 rescale (`src/dsp_dispatch.c:573`
("Q15 rescale (arithmetic right shift -- sign-extending on")) and explicit int16 saturation; no CMSIS-DSP
dependency (`arm_fir_decimate_q15` requires its block size to be a multiple
of the decimation ratio, which conflicts with the arbitrary-block-size
requirement here, so this stays on the portable-C path for phase 1).

Host tests (native_sim, `tests/unit/dsp_decimator/`): an in-band 1 kHz tone
plus an above-output-Nyquist 12 kHz tone at 48 kHz/ratio 3 — the issue's own
worked example — comes out with the in-band tone at the right level and the
alias attenuated >=35 dB (`tests/unit/dsp_decimator/src/test_dsp_decimator.c:64`
("test_ratio3_inband_tone_passes_alias_attenuated")); exact frame counts across
1/7/256/1023-frame blocks match a single-block run bit-for-bit
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:119`
("test_exact_frame_counts_across_odd_blocks")); stereo channels stay independent
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:178`
("test_stereo_channels_independent")); an unsupported ratio is rejected
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:228`
("test_unsupported_ratio_rejected")); and reset reproduces a fresh `init`
exactly (`tests/unit/dsp_decimator/src/test_dsp_decimator.c:284`
("test_reset_reproduces_fresh_init")). Mutation-checked: swapping ratio 3's
filter for an identity (pass-through) tap table reddened only the
alias-attenuation assertion, and an off-by-one in the phase-wrap comparison
reddened only the exact-frame-count and out-cap tests; both were reverted
after confirming the red, and the suite is green again.

ABI: `docs/abi/v0.16-snapshot.json` regenerated (current, tracks `HEAD`) — the
diff is additive only (3 new functions, 2 new macros, 1 new struct).
