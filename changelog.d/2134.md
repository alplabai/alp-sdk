### Added — `<alp/dsp>` streaming integer-ratio decimator: anti-alias FIR + keep-1-in-N (#2134)

Phase 1 of #2134 only: this adds the standalone decimator to the portable
`<alp/dsp>` layer. It does **not** wire it into the audio-in backend yet —
`alp_audio_in_open(.sample_rate_hz = 16000)` on a board whose PDM can't be
clocked for 16 kHz still fails the same way it did before this change. That
wiring is a separate, later phase (Refs #2134; blocked on #2132 / #2133
landing first, since both touch `src/backends/audio/zephyr_drv.c` and
`include/alp/audio.h`, which this phase deliberately did not touch).

Reuse check first: `<alp/dsp.h>`'s existing `alp_dsp_chain_t` FIR/IIR/window/FFT
pipeline (`include/alp/dsp.h:247`
("alp_dsp_chain_t *alp_dsp_chain_open(const alp_dsp_stage_t *stages, size_t n_stages);")) has no
rate-changing stage — its contract is `got <= min(in_n, out_cap)`
(`include/alp/dsp.h:262-263` ("Receives the number of output samples written")),
which a decimator (`out < in`) cannot satisfy without redefining that shared
contract. Nothing else under `<alp/dsp>` filters or resamples. New API added
instead of extending the chain.

New public surface (`alp_dsp_decimator_t` + `alp_dsp_decimator_init` /
`_process` / `_reset`, `include/alp/dsp.h:602`
("alp_status_t alp_dsp_decimator_init(alp_dsp_decimator_t *dec, uint32_t ratio, uint8_t n_channels);")):
caller-allocated, no heap (`include/alp/dsp.h:515-520`
("@par Allocation: caller-owned, no heap")) — unlike the pool-backed
`alp_dsp_chain_t`, this is a plain value type the caller declares on the
stack/static/embedded in another struct. At 1104 bytes on M55 it is larger
than Zephyr's default `CONFIG_MAIN_STACK_SIZE` (1024 B), so the Doxygen
recommends `static` storage or embedding it in backend/app state rather than
a thread's own stack (`include/alp/dsp.h:522`
("@par Size: 1104 bytes on M55")). Supports ratios 2, 3, 4, 6 (covering
48000->16000/8000 Hz and
32000->16000/8000 Hz) and 1..2 interleaved int16 channels with independent
per-channel filter state. `alp_dsp_decimator_process`
(`src/dsp_dispatch.c:555` ("const size_t exact_out = (dec->phase + in_frames) / dec->ratio;")) computes the
exact output frame count for a call up front from the running phase before
touching any state, so an undersized `out_cap` is rejected with the decimator
left completely unchanged (no partial consumption) — arbitrary block sizes
across calls give bit-identical output to one big call, with the keep-1-in-N
phase preserved across the boundary.

Filter: one Q15 fixed-point, 135-tap, Kaiser-windowed-sinc (beta 6.976)
anti-alias low-pass (`src/dsp_dispatch.c:497`
("static const int16_t *_alp_dsp_decim_lookup(uint32_t ratio)")), designed by
the committed `scripts/gen_dsp_decimator_coeffs.py` and re-verified against
the embedded tables via its `--check` mode
(`scripts/gen_dsp_decimator_coeffs.py:168` ("def check():")). The passband
edge is held at a fixed offset below the output Nyquist (`fs_in /
(2*ratio)`); the stopband edge sits at `fs_out - passband_edge` (`fs_out =
fs_in / ratio`) rather than at the output Nyquist itself — the wider
transition band that buys is what lands stopband attenuation around 70 dB
at this tap count instead of ~40. Content between the output Nyquist and
`fs_out - passband_edge` is therefore NOT stopband-attenuated; it folds into
the transition band above the stated passband (ratio 3: 8.0-8.8 kHz folds
into the 7201.6-8798.4 Hz transition). Each table's centre tap is nudged so
it sums to exactly 32768 — unity DC gain in Q15, not just in the float
design (`scripts/gen_dsp_decimator_coeffs.py:95-96`
("centre = (N - 1) // 2")). Measured on the shipped Q15 taps: ripple
0.0044-0.0062 dB, stopband attenuation 65.46-70.31 dB across the four ratios
(worst case is ratio 3 — its wider fs_in gives it the tightest transition
band of the four) — full per-ratio numbers are in `alp_dsp_decimator_init`'s
Doxygen (`include/alp/dsp.h:559-587`
("@par Filter design")). Convolution runs in an int64 accumulator with a Q15
rescale and explicit int16 saturation (`src/dsp_dispatch.c:591-601`
("int64_t acc = (int64_t)coeffs[half] * (int64_t)window[half];")); no CMSIS-DSP
dependency: `arm_fir_decimate_q15` requires its block size to be a multiple
of the decimation ratio, which conflicts with the arbitrary-block-size
requirement here, so this stays on the portable-C path for phase 1. A CMSIS
Helium path is a possible phase-2 optimisation if board measurement warrants
it, following the same chunking approach the SW fallback backend already
uses for CMSIS FIR input, `src/backends/dsp/sw_fallback.c:225`
("while (off < in_n) {").

CPU: the tap table is symmetric (odd-length linear-phase FIR), so the
convolution is folded to 68 multiplies instead of 135
(`src/dsp_dispatch.c:591-594` ("acc += (int64_t)coeffs[j] * (int64_t)(window[j] + window[taps - 1u - j]);")),
`coeffs` / `n_channels` are hoisted to locals once per call instead of
re-reading `dec->` each iteration, and the circular-buffer wrap uses a
compare (`src/dsp_dispatch.c:571` ("if (widx == taps) {")) instead of `%
taps` (the write index only ever steps by 1, so a full udiv+mls was wasted
work). The fold is bit-identical to the unfolded form: integer addition and
multiplication are exact (no floating-point reordering), and re-deriving the
symmetric-sum identity `sum(c[j]*w[j])` == `c[half]*w[half] +
sum(c[j]*(w[j]+w[N-1-j]))` for j in [0,half) holds for any symmetric table,
which was confirmed against the shipped tables over 20 random windows per
ratio. No ABI change (int64 accumulation is unchanged; `32768 * sum(|c|)`
still exceeds 2^31 for ratios 2, 3, and 4, so it stays int64).

Host tests (native_sim, `tests/unit/dsp_decimator/`): a table-driven test
covers EVERY supported ratio (`tests/unit/dsp_decimator/src/test_dsp_decimator.c:92-100`
("static const decim_ratio_spec_t k_ratio_specs[] = {")) — a tone at ~0.9x
the ratio's passband edge must stay within a generous tolerance of the
injected amplitude, and a tone just above the ratio's stopband edge must be
attenuated by at least (stated stopband - 0.5 dB), which catches a
wrong-ratio table (the #2134 review's case-3u-serves-the-ratio-6-table
mutation: a swapped table's actual cutoff sits at the wrong ratio's edge, so
the passband tone lands out of band). Exact frame counts across 1/7/256/1023-frame
blocks match a single-block run bit-for-bit AND match the absolute `n_in /
ratio` count (`tests/unit/dsp_decimator/src/test_dsp_decimator.c:206`
("zassert_equal(got_ref, n_in / ratio,"));
stereo channels stay independent
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:242`
("ZTEST(alp_dsp_decimator, test_stereo_channels_independent)")); an
unsupported ratio is rejected
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:292`
("ZTEST(alp_dsp_decimator, test_unsupported_ratio_rejected)")); and reset
reproduces a fresh `init` exactly
(`tests/unit/dsp_decimator/src/test_dsp_decimator.c:348`
("ZTEST(alp_dsp_decimator, test_reset_reproduces_fresh_init)")).

Mutation-checked, each confirmed red then reverted: (1) swapping ratio 3's
table lookup to serve the ratio-6 table reddened
`test_every_ratio_passband_and_stopband_tones`'s passband assertion for
ratio 3 (its actual cutoff moved to the wrong edge); (2) the phase-wrap
off-by-one `dec->phase < dec->ratio` -> `<=` reddened both the new absolute
`n_in / ratio` assertion and the existing chunked-vs-single-block comparison
in `test_exact_frame_counts_across_odd_blocks`. The suite is green again
after both reverts.

`scripts/gen_dsp_decimator_coeffs.py --check` parses the tables embedded in
`src/dsp_dispatch.c` and re-derives them from the design parameters, failing
if they've drifted (`scripts/gen_dsp_decimator_coeffs.py:168`
("def check():")); a pytest exercises both the pass and a deliberately
corrupted-tap fail case
(`tests/scripts/test_gen_dsp_decimator_coeffs.py:35`
("def test_check_fails_when_a_tap_is_wrong(tmp_path):")), skipping if numpy
isn't installed (`tests/scripts/test_gen_dsp_decimator_coeffs.py:16`
("pytest.importorskip")).

ABI: `docs/abi/v0.16-snapshot.json` unchanged vs `HEAD` (`abi_snapshot.py
--diff` reports no diff) — the decimator surface (3 new functions, 2 new
macros, 1 new struct) was already captured in this phase-1 slice.
