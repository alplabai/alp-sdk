### Fixed — four AEN bench scripts invoked JLinkExe directly with no DPIDR gate

`bench_jlink_assert_aen_dpidr()` (`scripts/bench/aen/bench-env.sh`) exists
because this bench's AEN E8 probe and its GD32-bridge probe (on the
*different* V2N-M1 board) share a cloned OEM serial, `603000869` — `JLinkExe`
selects only by serial and has no USB-path selector, so an unguarded connect
is ambiguous by construction and can attach to, halt, or flash hardware on a
different labgrid place than the one held. Eight scripts already called it;
four invoked `JLinkExe` directly and did not: `flash-run.sh` (its Flow A
read-back), `flash-all-flowd.sh` (`read_console()`'s post-flash read),
`read-update-log-proof.sh`, and `reread.sh`. Each now runs a read-only
connect-first preflight and calls `bench_jlink_assert_aen_dpidr()` before the
first command that halts, loads, or reads target memory, matching the
existing scripts' pattern. `flash-run-dualcore.sh` was checked too: it drives
only SETOOLS over the SE-UART and delegates its J-Link reads to `reread.sh`,
so it had nothing to guard.

Refs #813. #813 itself is a labgrid exporter misconfiguration on the
gateway (the `swd` resource for `e1m-aen-evk-01` resolves to the wrong USB
path) and is out of scope for alp-sdk — this closes only the in-repo half,
so a bare `-SelectEmuBySN` in these scripts can no longer land on a board a
different reservation covers.
