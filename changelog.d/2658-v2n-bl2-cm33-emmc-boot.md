### Fixed — the V2N/V2M Cortex-M33 now starts under eMMC boot (#2658)

Under eMMC boot (DSW1 mode 1, `bl2_bp_mmc`) BL2 started the CM33 but read its image from byte `0x200000` of the eMMC boot partition, which nothing writes, so the CM33 ran on unwritten bytes. The CM33 image lives only in xSPI (`mtd1` + `0x1a0000`). The new TF-A patch `0002-rzv2n-read-the-CM33-image-from-xSPI-in-every-boot-mode.patch` makes BL2 read it from the xSPI slot in every boot mode, and sets up the xSPI controller under eMMC and eSD boot, where the vendor code skipped it. The flash layout is unchanged. The first bench run under eMMC boot read flash id `0x0` because the boot ROM leaves the xSPI0 pin outputs off outside xSPI boot (`PFC_OEN` `0x10413c40` is expected to reset to `0x3f`); the patch now clears only `OEN_XSPI_CLKP`, `OEN_XSPI_CS0N` and `OEN_XSPI_RESET0N` before `xspi_setup()`, and BL2 skips BL22 and leaves the CM33 stopped when no flash answers. Syntax-checked only (an earlier revision was bitbake-built); not yet verified on a module.
