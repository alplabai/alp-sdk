### Added — provisioning step + bench helper to erase the AEN801 customer storage window (#1430)

A SoM was shipping with another application's bytes in the window the customer's first NVS write
lands in. alp-sdk#1334 measured, on real E8 silicon, ~110 KiB of a **stale previously-flashed
Zephyr application image** in the E1M-AEN801 customer storage window. It is not live data (the
region was erased and the board cold-cycled to `[SES] ATOC ok` / `RESULT PASS`), but a customer
who dumps the part sees another app's shell strings, and the first NVS write silently destroys
bytes that look meaningful. #1334 closed on the measurement and left the shipping question open;
this is the standing "erase before ship" step.

New `scripts/bench/aen/erase-storage.sh` (Flow D, SWD) plus a new
"Before the SoM ships — erase the customer storage window" section in `docs/aen-provisioning.md`.
Three facts drive the implementation, all already established in-tree:

- **The erased value on this MRAM is `0x00`, not `0xFF`** — measured from the running
  application's own flash parameters, `write_block_size=16 erase_value=0x00` (#1430). The written
  pattern is therefore `/dev/zero`, and it doubles as the `verifybin` reference so "erased" is a
  byte-compare rather than a claim.
- **A J-Link `erase` does not clear MRAM on this part** — the GOTCHA in
  `scripts/bench/aen/flash-jlink-mramxip.sh` ("a J-Link `erase` does NOT clear MRAM"). The erase is
  a `loadbin` through the part-number device profile, which is the only profile that unlocks
  J-Link's built-in Alif MRAM loader.
- **The band immediately above is SE-owned.** The window is DERIVED from the `storage` row of
  `metadata/e1m_modules/E1M-AEN801.yaml:229` (`base: 0x80560000, size_kib: 96`), never hardcoded,
  and the script refuses (exit 5) unless it ends exactly at the `atoc` base on the next line
  (`metadata/e1m_modules/E1M-AEN801.yaml:230`, `base: 0x80578000`). SETOOLS top-anchors the signed
  ATOC there and grows it downward, so an overshoot corrupts live SE data and drops the board to
  `No ATOC`. That guard was validated against the known-bad pre-#1289 128 KiB layout, which it
  refuses.

Gates match the sibling Flow D helpers: exit 4 when the SW-DP IDR says this is not the AEN E8
(the bench has three J-Links and two share OEM serial `603000869`), exit 2 when the part profile
cannot connect, exit 3 on a failed verify **or** on no verify result at all (#1488). The script
deliberately does not reset or boot the board.

**`[UNVERIFIED-ON-BENCH]`** — the finding is bench-measured (#1334), but this erase step has not
been run against a module. A first run still owes the J-Link transcript with `verify successful`
and a post-erase cold power-cycle showing the SE still boots its ATOC. `--dry-run` exercises the
window derivation and prints the CommanderScript without opening a probe.
