### Fixed — three Yocto `poll()` sites checked only `POLLIN`, so a torn-down fd hot-spun an RX thread instead of terminating (#1962)

`src/backends/can/yocto_drv.c`, `src/backends/rpc/yocto_drv.c` and
`src/yocto/peripheral_gpio.c` each `poll()` a socket/endpoint/line fd with an
**infinite** timeout and then guarded only on `revents & POLLIN`. When the
underlying fd is torn down or becomes invalid, `poll()` returns a POSITIVE
`rc` with `POLLERR`/`POLLNVAL`/`POLLHUP` set in `revents` — not `-1` — so the
existing `rc < 0` guard never sees it, the `POLLIN` guard just `continue`s,
and the very next `poll()` call returns immediately again: the RX/dispatcher
thread burns a full core forever, with no deadline to ever stop it (strictly
worse than the bounded MQTT case fixed under #1938).
`src/yocto/peripheral_uart.c:444` ("POLLERR | POLLNVAL") already got this
right; the three sites below now follow the same shape:

* `src/backends/can/yocto_drv.c:335` ("POLLERR | POLLHUP | POLLNVAL") —
  `_rx_loop()` now breaks (the same terminal action its existing `rc < 0`
  branch already takes) instead of `continue`-ing back into another
  immediate poll().
* `src/backends/rpc/yocto_drv.c:410` ("POLLERR | POLLHUP | POLLNVAL") —
  `rpc_rx_main()` now reports `ALP_RPC_LINK_LOST` (the same call its
  `rc < 0` and read()-EOF branches already make) and breaks.
* `src/yocto/peripheral_gpio.c:371` ("POLLERR | POLLHUP | POLLNVAL") — the
  shared `irq_dispatcher()`'s own wake_fd going bad is as fatal to the whole
  dispatcher as its `rc < 0` branch, so it takes the same exit path.
* `src/yocto/peripheral_gpio.c:401` ("POLLERR | POLLHUP | POLLNVAL") — a
  single pin's `line_fd` going bad (its gpiochip hot-removed, say) disables
  just that slot instead — treating one bad pin as fatal to the shared
  dispatcher would silently kill IRQ delivery for every other, unrelated
  pin too.

No new shared helper: the three sites take three different terminal actions
(thread-break, link-notify, per-slot-disable-vs-whole-dispatcher-exit), so a
one-line `revents & (POLLERR|POLLHUP|POLLNVAL)` mask read inline at each site
stays clearer than a new header for a single boolean check.

Host-provable without hardware: `tests/yocto/can_yocto_self_close.c`,
`tests/yocto/rpc_yocto_self_close.c` and
`tests/yocto/peripheral_gpio_self_close.c` each drive the real production
loop over a closed socket fd / closed pipe read-end (`POLLNVAL` is
deterministic on a closed fd number no other fd was allocated over yet), and
were run against the pre-fix code first: `wait_until()` /
`wait_until_irq_disabled()` time out and (for CAN/RPC) the RX thread never
joins, hanging the test binary until an external timeout kills it. Against
the fix, all three return within the bound every time.

**Owed on silicon** (`src/backends/**` and `src/yocto/**` are bench-held per
#1937; the AEN bench is down, #1883, 0-of-10 boots): observe, on a real
board, per file, that a torn-down transport — a SocketCAN interface removed
under a live `CAN_RAW` socket, an RPMSG endpoint torn down by a remoteproc
reset, a `/dev/gpiochipN` line fd invalidated by a hot-unplugged GPIO
expander — makes the corresponding RX thread / dispatcher slot terminate
promptly instead of hot-spinning a core. This change is author-only until
that bench pass runs.
