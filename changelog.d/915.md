### Fixed — every AEN preset claimed 32 MiB of HyperRAM the module does not carry (`memory.dram_mbit: 256`)

No currently shipping E1M-AEN SKU populates *any* memory on the OSPI bus —
neither the Macronix `MX25UM25645GXDI00` NOR on OSPI0 CS0 nor the Winbond
`W958D8NBYA5I` HyperRAM on CS1. All six presets nevertheless carried
`memory.dram_mbit: 256`, derived from the HyperRAM's `capacity_mbit` under a
comment asserting it was "populated on every AEN BOM variant". That is a
customer-facing claim of 32 MiB of external RAM on a module that has none,
and the preset was the last place in the tree still making it: the generated
board DTS, `zephyr/kconfigs/vendor-alif-peripherals.kconfig:961`, and
`docs/bring-up-aen.md:44` ("SoM's OSPI memories are NOT populated")
all already documented MRAM-only.

Both capacities on `E1M-AEN301/401/501/601/701/801` are now `0`, and the
population of each part is stated where population belongs — `assembled:
false` on `ospi_memories.ospi0`, `.ospi1` and `hyperram`
(`metadata/e1m_modules/E1M-AEN801.yaml:60-62` (`assembled:      false`)),
replacing the `optional` ("assembled per BOM variant") that had left the
question open. `capacity_mbit` stays: it is the designed-in part's capacity,
not a capacity the module carries, so a populated variant would flip one flag
rather than re-derive the bus.

`0` is deliberately not `TBD`. `0` is a resolved fact ("this SKU populates
none"); `TBD` is an open question ("nobody has written the capacity down
yet"), which is `E1M-NX9101`'s state and must stay distinguishable from this
one — see `metadata/schemas/som-preset-v1.schema.json:120` ("is a RESOLVED fact and").
Both `dram_mbit` and `flash_mbit` therefore relax from `minimum: 1` to
`minimum: 0`.

### Schema — `on_module.hyperram` gains `assembled:`

The `hyperram` `$def` is `additionalProperties: false` and had no `assembled`
property at all, so the schema could not express an unpopulated HyperRAM even
though its `ospi_memory` sibling could. Added with the same three-state shape
(`true` / `false` / `"optional"`) that
`metadata/schemas/som-preset-v1.schema.json:320` ("Population status: true (default), false (DNI)")
already carries for OSPI memories.

### Changed — the portability matrix distinguishes "no external DRAM" from an unstated capacity

`scripts/gen_portability_matrix.py`'s `notes_for()` only tagged a positive
`dram_mbit`, so correcting the six AEN presets to `0` would have replaced a
false "256 Mbit DRAM" note with silence — indistinguishable from
`E1M-NX9101`'s genuinely-unknown `TBD`. `0` now renders `no external DRAM`;
`TBD` still renders nothing, because a Notes cell has nothing true to say
about it.

**No behaviour change.** Nothing reads `memory.dram_mbit` or
`memory.flash_mbit` except that one Notes cell, and nothing reads
`ospi_memories[].assembled` or `hyperram.assembled` at all — the
`assembled == "optional"` skip at `scripts/alp_orchestrate/slugs.py:112`
(`dev.get("assembled") == "optional"`) applies only to `i2c_devices[]`.
Storage-partition resolution keys off `on_module.ospi_memories`' *keys* and
`capacity_mbit`, both unchanged.
