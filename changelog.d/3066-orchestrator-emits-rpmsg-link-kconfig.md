### Fixed -- the orchestrator now switches `<alp/rpc.h>` on for `ipc:` rpmsg entries (#3066)

**A Zephyr core named by a `kind: rpmsg` `ipc:` entry gets `CONFIG_ALP_SDK_RPC_LINK=y` in its `alp.conf`.** `mproc-rpc-usb.kconfig` promised that heterogeneous projects get `ALP_SDK_RPC` enabled by the generated per-core fragment, but the orchestrator only ever emitted `CONFIG_DCACHE=n` for such entries, so every example hand-wrote the MBOX / IPC_SERVICE / OPENAMP block. The new symbol `imply`s that stack, so each board tree takes what it can run: the Alif MHUv2 + static-vrings backend on the AEN M55 cores, the new V2N/V2M CM33 backend (#3067) on the M33, and nothing on `native_sim`. A 16 KiB heap is emitted with it unless the memory section already set one. Firmware that drives the V2N link with raw OpenAMP (`rpmsg-v2n`, `microros-ros2-v2n`) sets `CONFIG_IPC_SERVICE_BACKEND_ALP_V2N_RPMSG=n`.
