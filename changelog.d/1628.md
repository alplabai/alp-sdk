### Fixed — `zephyr_video` / `v2n_n44_isp` camera backends did not compile against the pinned Zephyr v4.4.1 `drivers/video/` API (#1628)

Both `src/backends/camera/zephyr_video.c` and `src/backends/camera/v2n_n44_isp.c`
still called the pre-v4.4 Zephyr video API (`VIDEO_EP_OUT`, single-arg
`video_stream_start`/`_stop`, unversioned `video_buffer_alloc`), which no
longer compiles against the v4.4.1 pin — CI never caught it because every
in-repo `CONFIG_VIDEO=y` configuration disabled both
`ALP_SDK_CAMERA_ZEPHYR_VIDEO` and `ALP_SDK_CAMERA_V2N_N44_ISP`. Both files are
now ported to the same v4.4 API `alif_isp_pico.c` already used: `enum
video_buf_type` on caps/format/buffers, `video_buffer_alloc(size, K_NO_WAIT)`,
typed `video_stream_start`/`_stop`, and a proper drain-and-release on close
(`video_buffer_release` now exists upstream).

Buffer sizing also changed: when the driver leaves `video_format.pitch` at 0,
`open()` now derives bytes-per-pixel from the negotiated fourcc via Zephyr's
`video_bits_per_pixel()` (rounded up with `DIV_ROUND_UP`, so a non-byte-aligned
table entry can't under-allocate by truncating) instead of assuming a flat 2
B/px — the old flat guess under-allocated RGB888 (3 B/px) and ARGB8888 (4
B/px) frames. A fourcc `video_bits_per_pixel()` can't size at all now returns
`ALP_ERR_NOSUPPORT` rather than silently under-allocating, **except** for
JPEG/compressed frames, which fall back to the same flat `w*h*2` heuristic
bound the pre-#1628 code used for every unsizeable format (compressed frames
have no fixed bits-per-pixel to derive). `alp_camera_open()`'s documented
`@return` list in `include/alp/camera.h` now names `ALP_ERR_NOSUPPORT` and
`ALP_ERR_OUT_OF_RANGE` as reachable from this path.

The case where no format could be negotiated at all (a driver without
`get_format`) now returns `ALP_ERR_NOT_READY` instead of opening a handle
backed by a 64-byte dummy allocation the caller has no way to distinguish
from a correctly-sized one.

`tests/zephyr/camera_video` is a new native_sim/native/64 twister scenario
that is the only in-repo build compiling both backends against the real
Zephyr v4.4.1 drivers — `CONFIG_ALP_SDK_CAMERA_V2N_N44_ISP=y` is compile
coverage only (silicon_ref selection still picks `zephyr_video` under
native_sim). It covers the general open/start/capture/release/stop/close
round trip, the pitch==0 RGB888 sizing fix via a `alp,fake-video-pitch0`
fixture, and the pitch==0 JPEG fallback via a `alp,fake-video-jpeg0` fixture.
