### Fixed — two camera backends still called the pre-v4.4 Zephyr video API (#1628)

`src/backends/camera/zephyr_video.c` (the portable backend, registered at
`silicon_ref="*"`) and `src/backends/camera/v2n_n44_isp.c` used the endpoint-id
video API that Zephyr removed in v4.4, while `west.yml` pins **v4.4.1**: the
`VIDEO_EP_OUT` argument was replaced by an `enum video_buf_type` carried on the
caps/format structs, and `video_buffer_alloc()` gained a `k_timeout_t`.

Both are ported to the upstream API, mirroring
`src/backends/camera/alif_isp_pico.c`, which already talked it — the port copies
that file rather than reconstructing an API shape from memory. Buffer sizing
stops assuming a flat 2 B/px, which is only correct for the packed 16-bit
formats and under-allocates for the rest.

`alif_isp_pico.c`'s own header comment described itself as the only backend on
the new API and named the other two as "still using the pre-v4.4 endpoint-id
helpers". That is now false in both directions, so it is rewritten rather than
left to mislead the next reader into porting work that is already done.
