### Fixed — provisioning tool: identity proof before the first write, payload-store marker, bench gaps (#2687)

- **First contact is proved before any write.** With no eMMC CID recorded for the serial (a run that starts past `bootstrap`, e.g. `--from dsw1_emmc_insert_sd`), `need_linux` now makes the SSH host echo a nonce to its `/dev/console` and reads it on this unit's serial line before the first write; a host that does not is refused. Once per host and power-on.
- **Payload store needs a marker.** The store opens only on a card that holds `/var/lib/alp-payload/.provisioning-sd`; any other card (a release microSD) keeps the store off and every file is pushed, so the license-gated `dxm1_*` files never land on a card that ships.
- **`--replace-identity`** (requires `--reprovision-from`) archives the committed and staged manifest and secure-page blobs as `<serial>.manifest.<old-hwrev>-<date>.bin` / `<serial>.secure-page.<old-hwrev>-<date>.bin` before `eeprom_manifest` and `secure_page` stage and promote the new ones, instead of failing after the EEPROM write.
- **A failed shutdown names its cause.** When the console `sync`/`poweroff` returns rc=127 or the console shows `EXT4-fs error` / `error -5`, the cut outcome is `unreadable (...)` with those lines verbatim, in the step's `power_cut` evidence and the operator prompt.
- **A halt survives the operator prompt.** The halted state is kept across the `dsw1_*` prompts unless the console printed anything after the halt; a silent halted unit no longer turns the next cut into `blind`.
- **`--only functional_test,record` finds the Linux host.** With no `bench.yaml` `linux.host` and no login on this boot, `need_linux` logs in on the console and reads the address, as `boot_sd_linux` does.
- **`clkgen_verify` without a boot capture** reports `not verified: no boot console captured in this run` (skipped) instead of failing on a missing U-Boot line; with a capture it verifies as before. An OTP image mismatch still fails.
- **Not done:** `dxm1_npu_flash` still has no NAND readback (the tool has no read-back command for the DX-M1 SPI-NAND; the dxrt-cli firmware version after the cold boot is the only check), and #2687 item 4 (unmapped bmap blocks) is untouched. Not yet benched.

Review fixes (#2687): `need_linux` discovery goes through the Ctrl-C console probe and never sends an Enter to a U-Boot / SCIF ROM / halted unit; `clkgen_verify` records `clkgen_uboot_fixup: unread (...)` or `seen: <line>` so an unverified unit is distinguishable in the record; `eeprom_manifest` no longer archives the secure-page blobs (only `secure_page` does); the fs-fault match no longer catches `error -52`; the archived hw_rev must be filename-safe.
