### Docs — ADR-0002 amended to record the real `ALP_ERR_NOT_READY` / `ALP_ERR_INVAL` convention (#1646)

Cluster 1's fix (`changelog.d/1646.md`'s original entry, folded into `CHANGELOG.md` at release)
normalized `op_enter`-status drift but deliberately left ADR-0002's own text unamended, noting
"retrofitting real ADR-0002 compliance across the codebase is a separate, much larger change
than #1646." This entry is that separate, docs-only follow-up: it does not touch dispatcher
code, it writes down what the code (as landed by cluster 1) actually does.

`docs/adr/0002-error-mechanism.md` gained a dated Amendment (2026-08-27, original text left
intact) with two parts. First, a **scope correction**: the ADR's "programmer error" parenthetical
(lines 55-56) contrasts three `open()`-time codes only — it never defined `ALP_ERR_INVAL` for the
whole public API, so the ~115 non-`open()` sites returning `ALP_ERR_NOT_READY` for a NULL primary
handle were never in violation; they were simply outside what the ADR governed. Second, the
**convention as measured**: `ALP_ERR_NOT_READY` for a handle (primary, or a secondary handle
threaded through the same `alp_handle_op_enter` lifecycle guard — `alp_ble_gatt_notify`'s `conn`,
per cluster 1's fix above, is the only such site in the whole surface); `ALP_ERR_INVAL` for a
malformed argument outside that guard (NULL `cfg`, a NULL out-buffer with nonzero length);
`ALP_ERR_NOSUPPORT` for a missing capability. Three pre-existing, deliberate outliers
(`src/adc_dispatch.c`, `src/jpeg_dispatch.c`, `src/update_log_dispatch.c`'s unfused NULL-handle
checks) are named and left unchanged — one is an explicit v0.1 ABI-preservation contract, and
nothing consumes the distinction for any of the three. `docs/adr/README.md`'s ADR-0002 row notes
the amendment.

`metadata/error-catalog.json`'s `ALP_ERR_NOT_READY` summary changed from "Peripheral not
initialised." (too narrow — a closed or mid-operation handle is "not ready" without ever having
been uninitialised) to "The handle is not in a state to perform this operation." No cross-repo
follow-up needed: tan-cli's `explain`-command tests assert a locally-defined fixture string, not
this catalog value.

signex could not be checked for a dependency on these status codes — no signex checkout exists on
the host this amendment was written from. Noted as an open gap in the Amendment text rather than
asserted clean.
