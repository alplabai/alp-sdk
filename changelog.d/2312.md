### Fixed — the ethos_u adapter compiled with no vela memory profile at all, so a model that DID place operators on the NPU could still report zero SRAM and pass the on-device fit gate against any arena (#2312)

`scripts/alp_model/adapters/ethos_u.py`'s `compile()` ran `vela` with neither
`--memory-mode` nor `--system-config`, so vela fell back to its own
DRAM-backed built-in profile (`Ethos_U85_SYS_DRAM_Mid` /
`Dedicated_Sram_384KB`) and reported the entire working set in
`dram_memory_used` — measured, `tests/fixtures/models/tiny_int8.tflite` at
`ethos-u85-256`: `sram_memory_used = 0.0`, `dram_memory_used = 0.28125`, a
clean vela exit. `req_sram_kib = 0` then passed the fit gate at
`src/backends/inference/alp_model_select.c:95`
("return e->arena_sram_kib == 0u || t->req_sram_kib <= e->arena_sram_kib;")
against ANY arena. `compile()` now passes `--memory-mode` from the target
SoC's own `npu_toolchain.vela.memory_mode`
(`metadata/schemas/soc-spec-v1.schema.json`), resolved once by
`alp_project_loader.resolve_targets` onto `TargetSpec` and threaded here --
`scripts/alp_model/adapters/ethos_u.py:92-108`
("def _profile_flags(target: TargetSpec | None) -> list[str]:") --
and `scripts/alp_model/build.py:99-100`
("opts=backend_opts, target=spec)") now passes the resolved `target=spec`
into every adapter's `compile()`. `--system-config` is passed only when the
profile names one AND a vendor `.ini` is actually on hand via
`ALP_VELA_CONFIG` (`scripts/alp_model/adapters/ethos_u.py:61`
("_VELA_CONFIG_ENV = ")); naming a
vendor-only system-config with no `--config` is vela's own hard `rc=1`, so an
unresolvable name is withheld rather than guessed at. A compile that placed
operators on the NPU but still reports zero SRAM anywhere is now refused
loudly by `scripts/alp_model/adapters/ethos_u.py:156-176`
("def _refuse_zero_sram_footprint(*, accel_config: str, npu_ops: int) -> None:")
instead of shipped as a `req_sram_kib = 0`; a full CPU fallback (no operators placed) still
legitimately reports `(0, 0)` and is not refused. Mirrors tan-cli's
`_footprint()`/memory-profile handling (tan-cli#789, tan-cli#1011,
`python/tan/model/adapters/ethos_u.py`).

### Fixed — the ethos_u adapter misread vela's summary CSV as bytes, so a small model's SRAM requirement could round down to zero (#2312)

`scripts/alp_model/adapters/ethos_u.py`'s `_parse_vela_summary()` treated
vela's `sram_memory_used` summary-CSV column as bytes (`sram_bytes // 1024`)
when it is already KiB — a 72 KiB model wrote `req_sram_kib = 0`, which passes
the on-device fit gate at `src/backends/inference/alp_model_select.c:95`
("return e->arena_sram_kib == 0u || t->req_sram_kib <= e->arena_sram_kib;")
against ANY arena. Fixed to read the column as KiB and round UP
(`math.ceil(sram_kib)`) at `scripts/alp_model/adapters/ethos_u.py:145`
("return round(sram_kib * 1024), math.ceil(sram_kib)"), matching the fix
already shipped in tan-cli#789 and tan-cli's `_footprint()`
(`python/tan/model/adapters/ethos_u.py`).

### Changed — `req_sram_kib` is arena-only by design; the const/weight region is never counted (#2312, tan-cli#1011)

Settles the open question from #2312 (follow-up to #1470): `perf.req_sram_kib`
/ the `.alpmodel` manifest's `Target.requires.sram_kib` count the compiled
tensor **arena** alone (vela's `sram_memory_used` column), never the
const/weight region (vela's `on_chip_flash_memory_used` column). The const
region is carried in the model blob itself and sized by the blob's own byte
length (`blob_len`), provisioned by the integrator per the target's
`vela_memory_mode` placement — it is never summed into `req_sram_kib`. No
schema field changed and no `.alpmodel` version bump; the on-device selector
at `src/backends/inference/alp_model_select.c:95`
("return e->arena_sram_kib == 0u || t->req_sram_kib <= e->arena_sram_kib;")
is unchanged, comparing the arena against the arena as it always has. This
mirrors tan-cli's recorded
contract (tan-cli#1011) and the SRAM-port pinning in
`src/backends/inference/ethos_u_aen.cpp`. Documented in
`docs/bench/model-perf-capture.md` and
`metadata/schemas/model-perf-v1.schema.json`'s `perf.req_sram_kib`
description.
