### Fixed — AEN M55-HP boards no longer claim the M55-HE's storage partition, `lptimer0` or LP peripherals (#2984)

`storage_partition@560000` is owned by the M55-HE: the `storage` row of every `E1M-AEN*` SoM preset now reads `accessible_from: [m55_he]`, and the M55-HP boards keep the node with `status = "disabled"` (so the MPU window maths still compiles) instead of exposing it as a second writer; the `system-manifest` emit no longer lists `m55_hp` on it. The disabled node still resolves by label, so an HP image that names `storage_partition` still compiles but has no flash-map entry for it; keep storage use on the HE. `lptimer0` is now per-app: the generated E8 boards (both cores) set it `status = "disabled"`, and an app that needs it enables it in its board overlay (`examples/aen/aen-power-stop` HE and HP overlays do, so the `alp,power-wake-timer` STOP wake still arms; `aen-lptimer-regcheck` already did). The HE-local LP peripherals (`lpuart`, `lpi2c1`, `lpspi0/1`, `lpi2s`, `lppdm`, `lpcam`, `rtc0`, `lptimer1..3`, `lpcmp0`, `bod0`, `lpi3c0`, `dma2`, `evtrtr2`) moved from `ensemble_e8_peripherals.dtsi` to the new HE-only `ensemble_e8_he_peripherals.dtsi`, so an HP board never sees M55HE_IRQS[] interrupt numbers. The M55-HE boards are unchanged. `scripts/gen_zephyr_board.py` now emits all of this from the preset.
