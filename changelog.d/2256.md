### Fixed — E8 ISP-Pico's TPG branch refuses a 0x0 port rect instead of leaving `VSI_MPI_ISP_SetChnAttr` to fail with `-EINVAL` (#2256)

`isp_configure()`'s test-pattern-generator branch (`zephyr/drivers/video/isp_pico.c`)
set the TPG pixel format but never `port_fmt.width`/`height`, so
`VSI_MPI_ISP_SetChnAttr` got a 0x0 port rect and failed with `-EINVAL`
("Setting the Channel config failed!", bench-confirmed on E1M-AEN803
2026W36-0009). The binding (`zephyr/dts/bindings/video/vsi,isp-pico.yaml`)
now carries `tpg-width`/`tpg-height`; a board overlay enabling a TPG image
must set them from a silicon-confirmed geometry, or `isp_configure()` now
refuses to start instead of silently continuing with 0x0. Adds a
`native_sim` unit test for the new `isp_tpg_geometry_is_valid()` guard
(`tests/unit/isp_pico_tpg_geometry`).

This is stage 1 of #2252 / finding 1 of #2256 only. Finding 2 — every TPG
frame still raising the ISP's `INTR_SIZE_ERR` because the TPG pattern's
real internal frame size lives inside the closed libisp/VSI middleware, not
in the DFP or `hal_alif`'s `vsi_comm_isp.h` — stays blocked pending an
Alif/VeriSilicon register reference or vendor answer; the DT properties
above intentionally default to 0 (fail closed) rather than guessing a
value.
