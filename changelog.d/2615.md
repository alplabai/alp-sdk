### Added — camera metadata: typed chip `mipi`/`drivers`, camera modules, carrier camera connectors, SoM/SoC CSI + I2C dispatch (#2615)

Camera unification, PR 1 of 6 (follows #2612 / #2614): data and validation only, no generator or build output changes.

- **chip-v1:** `mipi` is now typed (`lanes_supported`, `role: csi2_tx | dsi_rx`) and chips gain a `drivers` block (Zephyr compatible; Linux compatible, Kconfig symbol, link frequencies). Filled for OV9281 (Linux `ovti,ov9282`, `CONFIG_VIDEO_OV9282`, 400 MHz), IMX219, OV5647, IMX335 and IMX296 where the facts are in-tree.
- **`metadata/camera_modules/`:** new camera-module-v1 schema and one module per Zephyr sensor shield plus Raspberry Pi Camera Module 2 (IMX219).
- **Carrier:** `camera_connectors` (CAM0 = J5) on `e1m-x-evk`, referencing the existing `XEVK_*` macros; `validate_metadata.py` checks each reference resolves.
- **SoM / SoC:** V2N/V2M presets route `E1M_X_I2C2` to RIIC2 and `E1M_X_CSI0` to CSI0, with `E1M_X_GPIO_IO18`/`IO20` marked `TBD`; the RZ/V2N SoC spec gains a `linux_dt` map (RIIC2 pinmux, CSI0 receiver and capture labels).
- **board.yaml:** `cameras: [{connector, module}]`; an unknown module or connector is a validation error (`ALP-B003`).
