### Added — camera metadata: typed chip `mipi`/`drivers`, camera modules, carrier camera connectors, SoM/SoC CSI + I2C dispatch (#2615)

Camera unification, PR 1 of 6 (follows #2612 / #2614): data and validation, no generator. No build artefact changes except the CAM0 enable polarity fix: the composed route table and carrier netlist (and their `--emit` snapshots) and the generated `alp_e1m_x_evk_routes.h` now carry `XEVK_PIN_CAM0_EN` as active-low with a corrected doc line, and the V2N/V2M presets gain the route entries below.

- **chip-v1:** `mipi` is now typed (`lanes_supported`, `role: csi2_tx | dsi_rx`) and chips gain a `drivers` block. Zephyr: compatible and sensor endpoint flags. Linux: compatible, Kconfig symbol, per-lane-count link frequencies, regulator supplies, clock name, reset property, endpoint flags and supported input clocks, each read from the driver source. Filled for OV9281 (Linux `ovti,ov9282`, `CONFIG_VIDEO_OV9282`, 400 MHz), IMX219, OV5647, IMX335 and IMX296.
- **`metadata/camera_modules/`:** new camera-module-v1 schema and one module per Zephyr sensor shield plus Raspberry Pi Camera Module 2 (IMX219). Modules carry `zephyr_host_overrides` (the CSI-2 host / ISP properties a shield sets outside the sensor node), so a generated shield loses nothing from the hand-written ones; a parity test compares every sensor shield overlay with its module.
- **`metadata/os/linux-kernel-drivers.yaml`:** which sensor drivers kernel 6.1.141-cip43 carries natively and which come from alp patches 0018-0020 (pending).
- **Carrier:** `camera_connectors` (CAM0 = J5) on `e1m-x-evk`, referencing the existing `XEVK_*` macros, with `supply: fixed-3v3`; `validate_metadata.py` checks each reference and the `lane_polarity` length. `XEVK_PIN_CAM0_EN` is `active_low` (an N-FET pulls J5 pin 11 low, so IO18 high turns the camera off).
- **SoM / SoC:** V2N/V2M presets route `E1M_X_I2C2` to RIIC2 and `E1M_X_CSI0` to CSI0, with `E1M_X_GPIO_IO18`/`IO20` marked `TBD`; the RZ/V2N SoC spec gains a `linux_dt` map (RIIC2 pinmux keyed by peripheral signal and checked against the peripheral map, CSI0 receiver and capture labels).
- **board.yaml:** `cameras: [{connector, module}]`; an unknown or duplicated connector or an unknown module is a validation error (`ALP-B003`), as are unresolved macros and a wrong `lane_polarity` length in an inline `camera_connectors:`. Documented in `board-config-schema.md` and the ALP-B003 page.
