### Added: `gd32g553_boot_config_get` / `gd32g553_boot_config_set` -- opt-in persistent "SD out" at GD32 boot (#2697)

The GD32 bridge firmware (protocol 0.15, opcode `BOOT_CONFIG` `0x42`, allowed on I2C) can now persist a flag that makes it drive `PD11` (E1M `IO29`, the EVK's active-low `SDIO_MUX_EN`) high from every reset, so a provisioning run keeps the microSD disconnected across cold power cycles. The host mirrors it with `GD32G553_CMD_BOOT_CONFIG`, `GD32G553_BOOT_CONFIG_SDMUX_EN_HIGH` and the two helpers; older firmware answers `ALP_ERR_NOSUPPORT`. The default is unchanged: with nothing stored the pad is not touched, and a SET never moves a pad until the next GD32 reset. The SET is committed asynchronously by the firmware (never in its transport interrupt) into power-loss-safe A/B flash records; `gd32g553_boot_config_set()` waits ~30 ms and polls GET until the stored value matches, returning `ALP_ERR_TIMEOUT` if it never does. Wire contract: `docs/gd32-bridge-protocol.md` section 3.16.
