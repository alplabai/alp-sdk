### Fixed — OV5647 auto-exposure never held: the manual AEC/AGC bits (`0x3503`) cleared between the ISP's gate and streaming, letting the sensor's own on-chip AEC/AGC run active and override every exposure write (#2277)

The ISP's manual-mode gate set `0x3503`'s AEC/AGC-manual bits at stream
start, but something cleared them between that gate and
`MODE_SELECT_STREAMING` — leaving the sensor's own on-chip AEC/AGC
active for the whole session and silently overriding every exposure
write the ISP made.

**Fixed by re-asserting manual AEC/AGC as the last write before
streaming, and clamping exposure to the active mode:**
`ov5647_set_stream(true)` (`ov5647.c`) now re-asserts both AEC/AGC-manual
bits (`0x3503`) immediately before `MODE_SELECT_STREAMING`, and
`ov5647_set_ctrl_exposure()` clamps every `VIDEO_CID_EXPOSURE` write to
the active mode's VTS - 4 lines. The ISP AE library's own compiled-in
exposure ceiling (3145 lines, pinned to the sensor's 10 fps VTS
regardless of requested rate) is unchanged by this fix — the sensor-side
clamp is tighter and masks it.

Bench run 251 (E1M-AEN803 2026W36-0001, OV5647, 640x480 requesting
30 fps): `0x3503` reads `0x07` (AEC/AGC/VTS manual) held at stream start
and on every ~1 s poll during streaming; sensor exposure holds at 1045
lines (VTS 1049 - 4), ISP frame rate 30.00 fps.
