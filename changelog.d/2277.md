### Fixed — OV5647 AE never held exposure/gain because its on-chip AEC/AGC stayed enabled and the ISP calibration envelope was 3x too tight for a real fps (#2277)

Two independent root causes combined to keep the E1M-AEN803 + OV5647 camera pipeline from converging: (1) the sensor's own on-chip AEC/AGC (`OV5647_MANUAL_CTRL`, register `0x3503`) went inactive somewhere between the ISP's manual-mode gate and the stream actually starting, so the sensor's on-chip auto-exposure overrode every write the ISP made — fixed by re-asserting both AEC/AGC-manual bits (`ov5647.c`'s `ov5647_set_ctrl_gain()`/`ov5647_set_ctrl_exposure()`) as the last write before `MODE_SELECT_STREAMING`; (2) `isp_param_conf.h`'s compiled-in AE calibration block stayed pinned to the sensor's 10 fps VTS (3145 lines) regardless of the app's actual requested rate.

The exposure-ceiling fix went through several rounds before landing on the mechanism that actually works. A compiled-in calibration mirror (`isp_calib_param.modules.ae.autoAttr`) and re-registering the sensor default with the closed VSI_MPI_ISP library (`VSI_MPI_ISP_InitAeSnsFunc()`, then additionally cycling `VSI_MPI_ISP_AeUnRegCallBack()`/`AeRegCallBack()`) were both tried and both proven dead: bench evidence shows the library's own internal AE request stays pinned at the compiled-in 10 fps default (3145 lines) the whole session regardless of either mechanism. What actually holds the sensor within the active-mode ceiling is `isp_api_wrapper.c`'s `vsi_int_time_update()` write-back clamp — the last touchpoint before a value reaches the sensor — against `sensor_attributes.maxIntLine`, kept current for the active frame period by `isp_vsi_sync_ae_sns_default()` (simplified back to the plain field sync the clamp reads from, once the registration dance was proven to add nothing). All per-write bench-only diagnostics accumulated across that investigation (readback globals/counters, an every-30-frame sensor poll hook) were removed once bench evidence closed it out; `isp_pico.c` keeps only its lightweight per-second ISP frame-rate counter.

Bench run 251 (E1M-AEN803 2026W36-0001, OV5647, 640x480 requesting 30 fps, dim scene) PASSES: `0x3503` reads `0x07` (AEC/AGC/VTS manual) at stream start and on every ~1 s poll during streaming; sensor exposure `0x3500..02` = `0x4150` = 1045 lines = VTS(1049)-4, equal to the value written, held throughout; ISP frame rate 30.00 fps, host 30.03 fps; analog gain sits at its maximum because the scene is dark.
