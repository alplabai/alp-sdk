### Fixed — 34 chip-driver call sites busy-waited >= 1ms through `alp_delay_us()` (#1621)

`alp_delay_us()` is documented (`include/alp/peripheral.h`) as a non-yielding
busy-wait — Zephyr's backend routes it straight to `k_busy_wait()`, which
never releases the CPU to other threads. It is scoped to sub-millisecond
hardware-timing sequences only; `alp_delay_ms()` (-> `k_msleep()`, which
yields) is the contract for anything a millisecond or longer.

34 fixed-literal call sites across 16 chip drivers passed >= 1000us through
`alp_delay_us()` — up to a 1.5s spin in `ublox_sara_r5_power_on()` — stalling
every equal-or-lower-priority thread on that core for the whole window, long
enough to starve a watchdog-feed thread. Every such site is now
`alp_delay_ms()`, with an in-file comment on the caller side explaining why
sleeping instead of spinning is safe there.

One site is deliberately left as an `alp_delay_us()` spin, with an in-file
comment explaining why: `chips/gd32g553/gd32g553.c`'s SPI reply-retry ladder
(`gd32g553_reply_retry_us`) includes a 1600us tail rung, indexed off the
array by a variable rather than a fixed literal — the whole ladder is
bench-tuned to bound a live SPI slave-reply race at ~3.2ms total, and
`alp_delay_ms()` rounding up to a whole system tick would blow past that
bound.

Added `scripts/check_delay_us_literal.py`: a grep-grade CI gate under
`chips/**` that rejects a new fixed-literal `alp_delay_us(N>=1000)`, with unit
tests in `tests/scripts/test_check_delay_us_literal.py`. Wired into the
`validate` job of `pr-metadata-validate.yml` (`metadata/quality-tasks-v1.json`),
whose `paths:` filter now also covers `chips/**` and the gate script itself —
a PR that only touches a chip driver, or only the gate, now retriggers it; the
filter previously listed `include/alp/chips/**` but not `chips/**`, so the
regression lock was unreachable on exactly the change class it exists to
catch (same defect class as #1487/#1528/#1585). Regression-locked by
`tests/scripts/test_delay_us_literal_gate_paths_cover_input.py`.

By design the gate only catches a fixed *integer literal* argument — a
variable, macro, or expression argument (e.g.
`chips/eeprom_24c128/eeprom_24c128.c`'s `#define`d `EEPROM_WRITE_POLL_STEP_US`)
is caller/config-controlled and is out of scope for this bulk sweep; it is
reviewed case by case instead.
