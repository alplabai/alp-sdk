### Fixed — `check_changelog_citations.py` hard-failed correct citations into tan-cli's `python/tests/`/`python/scripts/` trees (#1522, #1525)

`_FOREIGN_PREFIXES` recognised only `python/tan/`, `crates/`, and
`contract/` as belonging to another repository; every other path under
`python/` fell through to the "no such file in this tree" hard error and
failed the blocking `pr-metadata-validate` gate on a correct citation. alp-sdk
has no `python/` directory of its own at all, so the distinction between
`python/tan/` (skipped) and `python/tests/` (hard error) was never a real
property of this tree — it was an incomplete list, and the routine prose
form of citing tan-cli's hash-pinned `python/tests/gates/
test_planner_relocation_freshness.py` was exactly what it rejected.

`_FOREIGN_PREFIXES` now matches the whole top-level directory
(`"python/"` instead of `"python/tan/"`), since alp-sdk has none of
`python/`, `crates/`, or `contract/` and every subpath under them is equally
unresolvable here. Verified against the gate's own reproduction from #1522
(`python/tests/gates/test_planner_relocation_freshness.py:129` and
`python/scripts/foo.py:10`, both now SKIPPED, not errors) and
mutation-proven: reverting to the old prefix list re-fails both cases with
the original "no such file in this tree" message, while a genuinely bogus
in-tree path still hard-fails as before.
