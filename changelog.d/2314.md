### Fixed — `gd32g553_init()` gave up on the first STATUS_BUSY in the OTA post-COMMIT/ROLLBACK trial window (#2314)

After `OTA_COMMIT`/`OTA_ROLLBACK`, a GD32 bridge running protocol 0.12
(gd32-bridge-firmware#246) reboots into an unconfirmed TRIAL image. That image
answers `STATUS_BUSY` to every opcode, `PING`/`GET_VERSION` included, until it
decodes its first CRC-valid frame. That frame confirms the trial and triggers
one more reset before the link settles (`docs/gd32-bridge-protocol.md` §10).

`gd32g553_init()` used to return on the first `ALP_ERR_BUSY`. It now retries
`ALP_ERR_BUSY`/`ALP_ERR_IO` on a bounded ladder (~2 s total), so a plain
re-init after COMMIT/ROLLBACK is all a host needs to do. Non-transient
failures (NOSUPPORT, INVAL, a genuine version mismatch) still return
immediately.
