### Fixed — `bump_version.py` left the `--emit` goldens stale after every release cut (#1461)

`scripts/bump_version.py` already regenerated `docs/abi/v<MINOR>-snapshot.json`
and `alp.lock` on every bump, but not `tests/fixtures/emit-snapshots/` — even
though the version is baked into some of them. Measured on the v0.16.0-rc1
cut, `bump_version.py --to 0.16.0` alone left 11 goldens stale: 7
`*.build-plan` goldens (`sdkVersion`, read straight from
`metadata/sdk_version.yaml` by `scripts/alp_orchestrate/buildplan.py`) and 4
`scaffold.*` goldens (a released scaffold's README doc links, pinned to
`v<version>` by `scripts/alp_template.py`). Every release bump therefore
reddened `validate · soc-spec-v1` until a human ran
`check_emit_snapshots.py --update` by hand.

`bump_version.py` now calls `check_emit_snapshots.py --update` as its last
step, the same way it already invokes `abi_snapshot.py` and `alp_lock.py`.

Regression test: `tests/scripts/test_bump_version_guards.py::test_a_full_bump_regenerates_the_emit_goldens_too`
runs `main()` end-to-end against a scratch checkout with `subprocess.check_call`
recorded, and asserts the `check_emit_snapshots.py --update` invocation is
present — it fails if a future change drops the refresh call from `main()`.

Not folded into this fix: the four `scaffold.*` goldens currently DIFF on a
full local clone (e.g. `test-all.sh --target dev`) because
`alp_template.py::_docs_ref()`'s tag-resolution check (#1508) makes the
scaffold README's doc-link pin depend on whether the local checkout has
fetched the release tag — CI's shallow, tag-blind checkout never has it and
stays green, but a full clone that has already fetched `v0.16.0` diverges from
the committed `main`-pinned golden regardless of what `bump_version.py` does.
Refreshing those 4 goldens against a tags-present clone would pin
`v0.16.0` into the golden and immediately break CI (which always computes
`main`), so they were deliberately left alone here; that tag-presence
nondeterminism is a separate, pre-existing defect in `_docs_ref()` itself.
