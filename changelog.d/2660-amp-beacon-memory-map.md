### Changed — one definition of the AMP liveness beacon, and the whole OpenAMP layout moves into SoC metadata (#2660)

The beacon layout (magic, version, heartbeat, attach epoch; offsets from the end of the rsctbl page) is defined once in `include/alp/protocol/amp_beacon.h` and used by the RPC backend, the `rpmsg-v2n` CM33 example and `firmware/alp-stock-shim`; the three copies are gone. The beacon stays in the last 16 bytes of the rsctbl page (A55 `0x4F700FF0`). The OpenAMP layout is the SoC `openamp_carveout` block in `metadata/socs/renesas/rzv2n/n44.json`: the reservation (A55 `0x4F700000`, `0x900000` bytes, CM33-NS `0x9F700000`) plus `rsctbl`, `mhu-shm`, `vring-ctl0`, `vring-ctl1`, `vring-shm0` and `vring-shm1` as offset+size inside it. `gen_zephyr_board.py` emits every CM33 board `.dts` node of that layout from it (and the comments quoting its addresses), `scripts/gen_amp_window.py` generates the A55 constants and UIO node names of all six regions into the backend's `alp_amp_window.h` (which `g_uio_regions` uses), and the new `check_amp_window.py` gate pins the Linux reserved-memory node and the six generic-uio nodes, the board `.dts` nodes and the header to it, requires each to lie inside the carveout, and rejects a second copy of the beacon magic or word addresses in C sources or a wrong one in the `tests/hil` specs. The CM33 RAM console buffer (#2747; A55 `0x4F710000`, CM33-NS `0x9F710000`, `0x4000`) is `openamp_carveout.ram_console` in the same block, and the board `.dts` node, `CONFIG_RAM_CONSOLE_BUFFER_SIZE` and `ALP_AMP_RAM_CONSOLE_*` come from it. The `mhu-uio` register block (`0x10480000`) is not part of the carveout and is unchanged. No address changes; **not bench-verified**, ordered steps in `docs/HIL/amp-window-from-metadata.md`.
