### Fixed — `<alp/storage.h>` littlefs backend shadowed by raw flash on Zephyr (#2911)

`zephyr_littlefs` could never be selected on a littlefs build: it ranked below `zephyr_flash` (priority 90 vs 100) and both accepted the same kinds, so `alp_storage_open(instance_id=N)` opened raw `flash_area` N and writes could overwrite the metadata of the mounted littlefs volume. `zephyr_littlefs` now registers at priority 110 and claims `instance_id` N only when the generated `alp_storage_mounts[]` entry whose `storage_dev` is `FIXED_PARTITION_ID` N is a mounted `FS_LITTLEFS` volume, whatever its `mount:` name (`/lfs/settings`, `/lfs`, ...); it then opens `<mnt_point>/alp_storage.bin`. `zephyr_flash` now returns `ALP_ERR_BUSY` for a flash area that backs any mounted filesystem in that table, so a mounted partition is not raw-addressable through `alp_storage_open`. Unmounted `instance_id`s behave as before; a mount made by hand with `fs_mount()` and absent from `alp_storage_mounts[]` is not detected.
