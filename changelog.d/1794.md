### Fixed — mqtt-telemetry README pointed a scaffold customer at `native_sim.conf` outside their tree (#1794)

`examples/connectivity/mqtt-telemetry/README.md` referenced `native_sim.conf` twice: a bare
markdown link the scaffold doc-link rewriter (`_RELATIVE_LINK_RE` in `scripts/alp_template.py`,
`../`-prefixed links only) never touched because the file is a *child* of the example dir, not a
sibling; and a `west build` instruction naming the same file. The `iot` template's envelope
(`metadata/templates/catalog-v1.json`) does not include `native_sim.conf`, so both references
dead-ended for a `tan init --template iot` customer.

The link now uses the same `../mqtt-telemetry/native_sim.conf` detour already established for
`examples/ai/cold-chain-monitor/README.md`'s `models/README.md` link, with the same one-line HTML
comment naming the rewriter's `../`-only regex so it survives future tidying. The Build section
now states the native_sim leg is in-tree only, matching cold-chain's reworded Tests section; the
build command itself is unchanged.

`tests/scripts/test_alp_template.py::test_scaffold_readme_mqtt_native_sim_conf_link_survives_scaffolding`
pins the emitted-envelope link so a future edit back to the natural-looking `](native_sim.conf)`
fails loudly instead of shipping a silent regression.

Deliberately out of scope: adding `native_sim.conf` to the `iot` template's file envelope. That
would fix the underlying gap for real, but it changes a published template's file set, moves
goldens, and affects tan-cli's vendored parity capture — a maintainer call, not a doc fix.

### Fixed — mqtt-telemetry's TLS-status sentence rendered as two paragraphs, and its Build lead-in over-scoped a native_sim caveat onto the working real-silicon command

An adversarial review of #1798 caught a rendering regression that shipped on `dev` in that PR
and was then copied into this file's own `native_sim.conf` link (the change above) by the same
commit that added it here: the explanatory `<!-- The ../mqtt-telemetry/ detour is deliberate:
... -->` comment sat at column 0 on its own line, which CommonMark parses as an HTML block that
CAN interrupt a paragraph. It split "the native_sim leg turns mbedtls off (see" from the
`native_sim.conf` link that completes the sentence into two separate `<p>` tags, both on GitHub
and in every emitted scaffold README. The comment now sits above the paragraph as its own block,
separated by a blank line, which keeps the sentence in one `<p>`.
`examples/ai/cold-chain-monitor/README.md` carried the identical defect from the same #1798
commit; its fix is in `changelog.d/1688.md`.

The Build section's lead-in also over-promised and over-scoped: "In the alp-sdk tree, the
native_sim leg builds against the in-tree `native_sim.conf` ... and runs with:" prefaced the
WHOLE fenced block, including the real-silicon leg a scaffold customer CAN run, casting doubt on
the one command that works; and it never said outright that a scaffold customer cannot run the
native_sim leg as shown, while the scaffold rewriter turns the command's own path argument into
`.` -- the customer's own directory -- directly contradicting "in the alp-sdk tree". The lead-in
prose is now gone; the caveat is a comment inside the fenced block, attached only to the
native_sim leg, explicit that `native_sim.conf` is not in the scaffold and naming the one fix
that is actually runnable from the emitted scaffold form (copy the file in from the link above)
-- an earlier draft also offered "build this leg from an alp-sdk checkout", but that remedy
doesn't match what a scaffold customer sees: the command's own path argument and
`EXTRA_ZEPHYR_MODULES` value are already rewritten to `.` and `$ALP_SDK_ROOT`, i.e. run FROM the
scaffold, not from an alp-sdk checkout. The real-silicon leg carries no caveat. The `west
build`/`west flash` command lines themselves are byte-identical to before this fix.

`test_scaffold_readme_cold_chain_models_link_survives_scaffolding` and
`test_scaffold_readme_mqtt_native_sim_conf_link_survives_scaffolding` in
`tests/scripts/test_alp_template.py` previously asserted only that the rewritten URL substring
was present in the emitted README -- true even with the paragraph split, which is exactly why the
regression shipped past them. Both now also assert the lead-in text and the link land in the same
rendered block. `markdown_it` (the library that would let a test render CommonMark directly) is
not a declared project dependency -- absent from `pyproject.toml` and `scripts/requirements.txt`,
so not installed by the `pip install -e ".[dev,model-compile]"` step that runs `pytest
tests/scripts/` in CI -- so the added assertion is a small stdlib-only helper that pins the same
CommonMark fact (no blank line, no column-0 HTML block opener, between the two markers) without
adding one. `tests/fixtures/emit-snapshots/scaffold.edge-ai-v2n101.snap` moved to match the
cold-chain-monitor README fix; regenerated with `check_emit_snapshots.py --update`, not
hand-edited.
