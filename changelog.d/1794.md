### Fixed — mqtt-telemetry README pointed a scaffold customer at `native_sim.conf` outside their tree (#1794)

`examples/connectivity/mqtt-telemetry/README.md` referenced `native_sim.conf` twice: a bare
markdown link the scaffold doc-link rewriter (`_RELATIVE_LINK_RE` in `scripts/alp_template.py`,
`../`-prefixed links only) never touched because the file is a *child* of the example dir, not a
sibling; and a `west build` instruction naming the same file. The `iot` template's envelope
(`metadata/templates/catalog-v1.json`) does not include `native_sim.conf`, so both references
dead-ended for a `tan init --template iot` customer.

The link now uses the same `../mqtt-telemetry/native_sim.conf` detour already established for
`examples/ai/cold-chain-monitor/README.md`'s `models/README.md` link, with the same one-line HTML
comment naming the rewriter's `../`-only regex so it survives future tidying. The Build section
now states the native_sim leg is in-tree only, matching cold-chain's reworded Tests section; the
build command itself is unchanged.

`tests/scripts/test_alp_template.py::test_scaffold_readme_mqtt_native_sim_conf_link_survives_scaffolding`
pins the emitted-envelope link so a future edit back to the natural-looking `](native_sim.conf)`
fails loudly instead of shipping a silent regression.

Deliberately out of scope: adding `native_sim.conf` to the `iot` template's file envelope. That
would fix the underlying gap for real, but it changes a published template's file set, moves
goldens, and affects tan-cli's vendored parity capture — a maintainer call, not a doc fix.
