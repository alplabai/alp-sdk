### Documented — ADR-0006 promised MCUboot swap-with-revert on AEN; the AEN family ships single-slot with no secondary or scratch partition (#1393)

`docs/adr/0006-secure-boot-secure-ota.md`'s "Secure OTA" decision commits the
AEN-Zephyr backend to MCUboot's swap-with-revert dual-bank flow. The AEN
family's MRAM partition map has no secondary slot to swap into and no scratch
partition to swap through — confirmed against `zephyr/boards/alp/e1m_aen801_m55_he/
alp_e1m_aen801_m55_he_ae822fa0e5597ls0_rtss_he.dts` and its `m55_hp` sibling on
`origin/dev`:

```
boot_partition     @ 0x0        64 KiB   label "mcuboot"
slot0_partition    @ 0x10000  2688 KiB   label "image-0"   (HE; HP's is @ 0x2b0000)
reserved_partition @ 0x550000   64 KiB   label "reserved"
storage_partition  @ 0x560000   96 KiB   label "storage"
atoc_partition     @ 0x578000   32 KiB   label "atoc"
```

`1ad76193` (#1100, closing #1069, 2026-08-03) removed `slot1_partition` and
`scratch_partition` from AEN801 deliberately, to fit the disjoint dual-core
slot0 budget: the address that was slot1/OTA (`0x802b0000`) became the HP
core's slot0, and the address that was scratch (`0x80550000`) became
`reserved`. #1445 later applied the same disjoint-per-core-slot0 trade to
every other dual-core AEN SoM. `zephyr/sysbuild/aen/sysbuild.conf` records the
same trade and sets `SB_CONFIG_MCUBOOT_MODE_SINGLE_APP`. Neither
`slot1_partition` nor `scratch_partition` exists anywhere in
`zephyr/boards/alp/` — confirmed by `grep -rn 'slot1_partition\|scratch_partition'
zephyr/boards/alp/` on `origin/dev`, which returns nothing; every AEN board
directory (`e1m_aen401_m55_hp`, `e1m_aen601_m55_hp`, `e1m_aen801_m55_he`,
`e1m_aen801_m55_hp`) carries the same no-slot1/no-scratch map.

**The ADR is not rewritten to erase the original decision.** Per the issue, an
ADR is a record: a new "Amendment (2026-08-25)" section states what was
decided (swap-with-revert), what the AEN family actually ships (single-slot,
no revert target), why they diverge (the #1069/#1100 dual-core slot0 trade,
later confirmed family-wide by #1445), and that OTA on the AEN family stays
deferred until a slot budget or a different delivery shape is chosen — a
maintainer call this ADR does not make. The original "Secure OTA" bullet gets
a one-line forward-pointer to the amendment rather than being silently
edited. `docs/ota.md`'s AEN-Zephyr section gets a shorter note to the same
effect, since it was already framed as an open "v0.4 plan".

`examples/aen/aen-mcuboot-smoke/sysbuild.conf:19` carried one stale line —
`slot1 @ 0x802b0000, scratch, storage` — pre-#1100 language naming partitions
the board no longer has (`0x802b0000` is now HP's slot0). Corrected to match
the current map; the file's own `NO A/B YET: ... the swap/upgrade path is
UNTESTED` note was already accurate and is unchanged.

Refs #1066 (the swap mechanism's own no-erase-MRAM defect, re-scoped to block
re-enabling OTA rather than fix it, since it can't be regression-tested on a
single-slot board) and #1069/#1100 (the deliberate change this documentation
now trails accurately).
