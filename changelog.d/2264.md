### Fixed — the u-boot 0002 patch was malformed (corrupt hunks) and GigaDevice xSPI NOR support was missing (#2264)

- **`0002-rzv2n-dev-ALP-E1M-production-boot.patch` had two hunks with wrong `@@` line counts** — `git apply` rejected the file outright and GNU `patch` dropped the `CONFIG_ALP_E1M_FDTFILE` Kconfig block instead of erroring, so `do_compile` failed with `error: expected '}' before 'CONFIG_ALP_E1M_FDTFILE'`. Regenerated from a clean `renesas-u-boot-cip` checkout at the pinned SRCREV (`bcf29d98547d448776573abe643ecbdcbaa44b7d`) with the patch's content unchanged.
- **`CONFIG_SPI_FLASH_GIGADEVICE` is now enabled** via a new `gigadevice-xspi.cfg` fragment, so U-Boot's `sf probe` detects the GigaDevice LX-family xSPI NOR some production E1M V2N-family modules carry (`docs/soms/v2n.md`).
- **Known limit:** reads crossing the 16 MiB boundary fail in this U-Boot's Renesas xSPI driver (bench-observed `Read: ERROR 1` at `0xFFFF00+0x200`); writes above 16 MiB are untested.
