### Fixed — ISP AE writeback clamps to the sensor's registered control range, and the calibration block driving it out of range in the first place (#2271)

**Defensive clamp.** hal_alif's per-frame AE writeback called `video_set_ctrl()` for `VIDEO_CID_ANALOGUE_GAIN`/`VIDEO_CID_EXPOSURE` with no bound check, so on E1M-AEN803 + OV5647 an out-of-range EXPOSURE writeback (`intLine` 94470, `ctrl.val` = `intLine * 16` = `1511520`, against OV5647's registered range `[0, 0xFFFFF]`) was rejected with `-EINVAL` every frame forever; new patch `zephyr/patches/hal_alif/0010-isp-clamp-ae-writeback-to-ctrl-range.patch` saturates into the sensor's `video_query_ctrl()`-reported range before each write and logs (latched, once per episode) whenever a clamp actually changes the value.

**Fallback ceiling fix.** `zephyr/drivers/video/isp_pico.c`'s `isp_apply_ae()` fallback `again_max` constant, only reachable when the live `video_query_ctrl()` range lookup fails, was corrected `16368` -> `65472`.

**Calibration envelope.** `isp_param_conf.h`'s compiled-in OV5647 AE calibration block was never updated off Alif's stock ARX3A0 envelope (`expTimeRange.max` 3000000 us, decoding to the same out-of-range 94470-line writeback above); new patch `zephyr/patches/hal_alif/0011-isp-ov5647-ae-calib-envelope.patch` sets it from the same `OV5647_AE_*` facts `sensor_attributes.h` already used, and changes the OV5647 calibration's `aeTarget` from `255` to `CONFIG_VIDEO_ISP_VSI_AE_TARGET` (90). Bench run 213 (0010+0011 applied) held within the sensor's real envelope with 0 rejected writes; the exact mechanism by which the calibration block wins over `isp_apply_ae()`'s own push is not established.
