### Documented — pin the exact ROS 2 image build command + prove rclcpp/alp-perception reach the rootfs (#372)

`meta-alp-sdk/README.md` names the one supported command for a ROS 2-carrying
image (`MACHINE = "e1m-v2n101-a55"` / `"e1m-v2m101-a55"`, `bitbake
alp-image-edge`, `meta-ros2-humble` added to `bblayers.conf` per step 4b) and
spells out the in-tree chain that puts both `rclcpp` and `alp-perception` on
the rootfs: `alp-image-edge.bb`'s `IMAGE_FEATURES += "alp-ros"` ->
`alp-image-common.inc`'s `FEATURE_PACKAGES_alp-ros` ->
`packagegroup-alp-ros.bb`'s `RDEPENDS:${PN}`. A new regression test,
`tests/scripts/test_library_layer.py::test_ros2_edge_image_pulls_rclcpp_and_alp_perception`,
pins that chain so a future change dropping either package from the
packagegroup, or unlinking the feature map, fails CI instead of silently
drifting from the documented claim. `ros2.yaml` stays Tier B: ADR 0018 Tier A
requires "built in CI for at least one board", which alp-sdk CI does not
offer for the Yocto/ROS lane (no fabricated build-lane claim substitutes for
that gate).
