### Fixed — `aen-adc-regcheck`'s RESULT line reported the timing loop's leftover sample, not the gated single-shot's (#2083)

`examples/aen/aen-adc-regcheck/src/main.c`'s `struct adc_sequence seq`
(`examples/aen/aen-adc-regcheck/src/main.c:153` (".buffer       = &sample,"))
points `.buffer` at `sample`, and every call to `adc_read(adc, &seq)`
overwrites it in place. The app printed `raw sample : %d` from `sample`
right after the gated single-shot read
(`examples/aen/aen-adc-regcheck/src/main.c:162-164` ("raw sample : %d")),
then ran the `#1823` timing loop of `TIMING_ITERATIONS`
(`examples/aen/aen-adc-regcheck/src/main.c:67` ("#define TIMING_ITERATIONS 2000U"))
further `adc_read(adc, &seq)` calls
(`examples/aen/aen-adc-regcheck/src/main.c:216-218` ("(void)adc_read(adc, &seq);")),
then printed the `RESULT PASS ... raw=%d` line from `sample` again -- by then
holding whatever the LAST timing-loop iteration left behind, not the value
from the gated single-shot read this fix now captures separately.
Measured 2026-09-13 on `e1m-aen-evk-03` in one boot:

```
raw sample : 8 (0x0008)  [analog pad on ch0 is a bench unknown]
RESULT PASS: adc12_0 setup+read rc=0, single-shot ran, controller idle, raw=139
```

The gated single-shot value is now captured into its own variable,
`gated_sample` (`examples/aen/aen-adc-regcheck/src/main.c:173` ("uint32_t gated_sample = sample;")),
immediately after the single-shot read and before the timing loop runs, and
the `RESULT PASS` line
(`examples/aen/aen-adc-regcheck/src/main.c:272-274` ("RESULT PASS: adc12_0 setup+read"))
prints that instead of `sample`. The PASS gate itself
(`rc_setup == 0 && rc_read == 0 && idle_ok`), the `#1823` timing
measurement, and every other printed line are unchanged -- this is a
reporting fix only, not a change to what gates PASS/FAIL or how the
timing loop runs.
