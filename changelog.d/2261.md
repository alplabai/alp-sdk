### Added — `E1M-V2N103` / `E1M-V2M103`: the 4 GB RAM / 16 GB eMMC memory tier of the V2N-family PCB (#2261)

Two new SoM presets join `metadata/e1m_modules/`, filling out the Alp Lab
SKU catalogue's third E1M-X V2N memory tier:

- `E1M-V2N103` — "E1M-X Renesas RZ/V2N - 4 GB RAM / 16 GB ROM", a clone of
  `E1M-V2N101` (same 32 Gbit LPDDR4X, larger 128 Gbit eMMC).
- `E1M-V2M103` — "E1M-X Renesas RZ/V2N + DEEPX DX-M1 - 4 GB RAM / 16 GB ROM",
  the DEEPX-populated sibling, a clone of `E1M-V2M101` on the same terms.

Both SKUs share the V2N-family PCB and silicon with their siblings — chips,
I2C addresses, pad routes, and `TBD` markers are unchanged from the clone
source; only the SKU identity, display name, `memory.flash_mbit`, and the
per-SKU Yocto MACHINE / Zephyr board-target identifiers differ. Neither
SKU has a generated Zephyr board tree yet (same state as `E1M-V2N102` /
`E1M-V2M102`), so `topology.m33_sm.board` is the bare, unqualified target
and both are declared in `check_board_target_tree_parity.py`'s
`_NOT_YET_SUPPORTED` allowlist pending their own board bring-up.

**`E1M-V2N102` / `E1M-V2M102` eMMC size corrected.** Both presets declared
`memory.flash_mbit: 65536` (8 GB) — one tier short of the catalogue's "8 GB
RAM / 16 GB ROM" naming for these two SKUs. `flash_mbit` now reads `131072`
(16 GB); `memory.dram_mbit` (64 Gbit / 8 GB) was already correct and is
unchanged.

Propagated to the generated portability/peripheral-support matrices, the
Yocto `meta-alp-sdk` machine confs (new `e1m-v2n103-a55.conf` /
`e1m-v2m103-a55.conf`, mirroring the `E1M-V2N101` / `E1M-V2M101` confs —
both carry a `TODO(firmware-pack)` for their own per-SKU BL2 DDR param +
4 GB U-Boot SDRAM size entry, not yet built), the `tests/hil/` bench
directories (new `v2n103-x-evk/` / `v2m103-x-evk/`), the SoC-JSON
`alp_module_skus` reverse-lookup lists, and the per-family docs
(`docs/soms/v2n.md`, `docs/soms/v2n-m1.md`, `docs/board-config.md`, the
e1m-x-evk board doc, and the metadata-family READMEs).
