### Fixed — `check_atoc_reservation.py`'s preset check refused an OSPI0 row for merely being the highest address in the file, instead of scoping "the top" to the SoC's declared MRAM aperture (#2069)

`_check_preset()` (`scripts/check_atoc_reservation.py:505`) built its span list
from every `memory_map:` row with a resolved integer base, with no aperture
filter, and took `window_top = max(hi)` across the whole file. An OSPI0
HyperRAM row at XIP base `0xA0000000` — well above the App MRAM window — became
the file-wide maximum and was refused as "the boot table in disguise" purely
for being highest, even though the real `atoc` band correctly owned the top of
the actual MRAM window underneath it.

`aperture = _resolve_aperture(doc)` (`scripts/check_atoc_reservation.py:554`)
now runs before the top-of-window decision, not after it (the 4b/4c aperture
checks already ran it, just too late to inform this one). Where an aperture
resolves, "the top" is the SoC variant's aperture end (`full_hi`), not the
authored maximum, and only rows whose extent intersects the aperture —
the same predicate 4b/4c already use — are eligible to own it. A layout where
nothing tiles all the way to `full_hi` now fails explicitly too
(`scripts/check_atoc_reservation.py:566`), naming the expected top address,
instead of silently picking whatever row happened to be highest. Where no
aperture resolves (a non-Alif SoC, or a fixture with no `silicon:`) the
original file-wide-max behaviour is unchanged — deliberately fail-closed, so
losing aperture resolution still refuses an out-of-window row loudly rather
than passing it.

This gate fix stands on its own; adding an OSPI0 row to a SoM preset's
`memory_map:` is explicitly out of scope here — that population still lives in
`on_module.hyperram` / `on_module.ospi_memories.ospi0` per the #2069 decision.

Also corrected the check's own stale docstring, which named the shared OSPI0
HyperRAM as `W958D8NBYA5I` on `chip_select: 1`: both AEN801 and AEN803 declare
`chip_select: 0` (`metadata/e1m_modules/E1M-AEN801.yaml:88`,
`metadata/e1m_modules/E1M-AEN803.yaml:94`), and AEN803's fitted part is the
Infineon/Cypress `S80KS5122GABHM02`, not the Winbond part AEN801 declares
(DNI on that SKU).
