### Added — `<alp/rpc.h>` link-liveness signal (issue #1643)

A far core resetting or crashing used to be invisible: nothing surfaced the
transport's own bind/unbind signal, so `alp_rpc_send()` kept returning
`ALP_OK` into a dead vring forever, indistinguishable from an idle peer.

- **`alp_rpc_link_state_t`** (`ALP_RPC_LINK_DOWN` / `_UP` / `_LOST`),
  **`alp_rpc_link_cb_t`**, **`alp_rpc_set_link_callback()`**, and
  **`alp_rpc_link_state()`** — new, purely additive `<alp/rpc.h>` surface
  (ABI-STABLE, minor bump).
- The Zephyr backend (`src/backends/rpc/zephyr_drv.c`) now wires
  `ipc_service`'s `unbound` + `error` endpoint callbacks (previously only
  `bound` + `received` were wired, throwing the disconnect signal away) and
  reports the transitions through the dispatcher's new internal
  `alp_rpc_notify_link()` hook (`src/backends/rpc/rpc_ops.h`); the Linux
  chardev backend (`src/backends/rpc/yocto_drv.c`) reports UP once
  `/dev/rpmsg<N>` opens and LOST when its rx thread's `read()` returns
  EOF/error (the kernel dropping the endpoint, not this side's own close).
  `src/backends/rpc/sw_fallback.c` stays DOWN forever (no synthetic peer
  under native_sim); `src/common/stub/stub_rpc.c` returns `ALP_ERR_NOSUPPORT`
  for both new functions on the bare-metal build.
- `src/backends/rpc/yocto_uio_drv.c` (RZ/V2N's userspace-virtio path) is
  **not** wired in this revision — its remoteproc/virtio teardown shape has
  no equivalent to the chardev backend's poll()+read() EOF signal, and this
  issue is `needs-silicon`; tracked as follow-up.

**Behaviour change on the existing surface (documented, not slipped in):**
once a channel has observed `ALP_RPC_LINK_LOST`, `alp_rpc_send()` now fails
with `ALP_ERR_NOT_READY` instead of accepting into the dead queue -- the
SAME return value the header already documented for a NULL/closed channel,
now also covering a known-dead link.  `alp_rpc_call()` is unaffected in this
revision: it keeps its own `timeout_ms` defense and is not woken early by a
link-loss notification (unblocking an in-flight `alp_rpc_call()` from a
transport callback crosses the GHSA-xhm8-7f87-93q5 close-protocol's
handle-lifetime rules and needs its own, separately-reviewed change).

Bench-gated (`needs-silicon`): reliably distinguishing a genuine link loss
from a busy link on real V2N/AEN silicon, and confirming which of
`ipc_service`'s `unbound` vs `error` callback (or both) actually fires for a
far-core reset, has not been attempted on real hardware.
