### Fixed — streaming ADC and UART RX ring-buffer handles could recycle a pool slot while a read was still in flight (#1634)

`alp_adc_stream_t`/`alp_adc_filter_t`/`alp_adc_spectrum_t` and
`struct alp_uart_rx_ringbuf` carried only a bare `in_use` bool with no
active-op tracking. `alp_adc_stream_close()` (and its filter/spectrum
wrappers) and `alp_uart_rx_ringbuf_detach()` could recycle a pool slot
while `alp_adc_stream_read_mv()` / `alp_uart_rx_ringbuf_pop()` was still
reading it — a concurrent open/attach then reused the same struct
address and the still-running read delivered one caller's data (ADC
channel samples, UART ring bytes) into another caller's buffer.

Added `lifecycle`/`active_ops` fields (before the trailing `in_use`,
per the offsetof-zero convention) to all four structs and routed every
read entry point through `alp_handle_op_enter`/`alp_handle_op_leave`
and every close/detach through `alp_handle_begin_close_blocking`,
mirroring `i2c_regfile.c` and `counter_dispatch.c`. The sleep-poll
close variant is required (not busy-spin) because the ADC guarded op
can block for a long time inside `alp_z_v2n_supervisor_acquire()`.

Adds `tests/zephyr/adc_stream_close_race` and
`tests/zephyr/uart_rx_ringbuf_close_race`, deterministic two-thread
regression tests proving each close/detach-vs-op race against the real
struct, pool, and close/detach function. Both drive the fix through
the real public read entry point (`alp_adc_stream_read_mv()` /
`alp_uart_rx_ringbuf_pop()`) via a test-only synchronisation hook
(`alp_adc_stream_read_test_sync_hook` / `alp_uart_rx_ringbuf_pop_test_sync_hook`,
default no-op in production, mirroring
`src/backends/rpc/zephyr_drv.c`'s `g_rpc_recv_test_sync_hook`) rather
than hand-rolling the `alp_handle_op_enter`/`_leave` calls in the test
body — an earlier draft of the ADC test counted the op in by calling
`alp_handle_op_enter` directly instead of the fixed function, so it
stayed green even with the op-counting half of the fix reverted.
Mutation-tested: both suites fail with their respective close/detach
drain guard reverted, and the ADC suite additionally fails with
`alp_adc_stream_read_mv()`'s op-counting reverted to a bare lifecycle
check.

`tests/zephyr/peripheral/prj_v2n_supervisor.conf` now also sets
`CONFIG_ALP_SDK_DSP=y`: `ALP_ADC_HAS_FILTER_PATH` (the
`alp_adc_filter_*`/`alp_adc_spectrum_*` bodies in
`src/zephyr/peripheral_adc.c`) needs both that and the V2N bridge
path, and no config in the tree set both before this, so roughly 100
of the changed lines in that file were never compile-tested by any
gate.
