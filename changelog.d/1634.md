### Fixed — the UART RX ring buffer half of #1634, and the regression tests that were meant to lock six v0.17.0 fixes (#1634, #1621, #1623, #1624, #1626, #1627, #1628, #1632)

**#1634 was closed with half its fix.** The ADC stream side landed — `struct
alp_adc_stream` carries `lifecycle`/`active_ops` and `peripheral_adc.c` guards
13 sites — but the UART RX ring buffer, the other handle the issue named, did
not. On `dev` before this change `struct alp_uart_rx_ringbuf` had no lifecycle
field at all, and `alp_uart_rx_ringbuf_pop()` / `_count()` / `_detach()` gated
on a bare `!rb->in_use` read.

That is the exact defect the issue describes: a `detach()` racing a `pop()`
could `lwrb_free()` and re-`attach()` the *same struct address* while the reader
was mid-`lwrb_read()`, delivering another owner's bytes. `pop()` and `count()`
now count the op in through `alp_handle_op_enter()`, `detach()` drains via
`alp_handle_begin_close_blocking()` before tearing down, and `attach()` publishes
`LC_OPEN` only once every field is populated.

**Six regression suites and one gate were written for v0.17.0 and never reached
`dev`.** They were authored on the individual fix branches; the bundled fix that
closed the issues carried the source changes but not the tests, so each fix
shipped unlocked:

| Recovered | Locks |
|---|---|
| `tests/unit/rv3028c7_dispatch_ack` | #1623 status-flag acknowledgement |
| `tests/unit/pwm_gd32_bridge_period` | #1624 `period_ns` population |
| `tests/unit/power_alif_dcdc_bounds` | #1626 `rail_mv` bounding |
| `tests/unit/counter_registry/boards/*` | #1627 alarm cancellation |
| `tests/zephyr/camera_video` | #1628 v4.4 video API + buffer sizing |
| `tests/zephyr/adc_stream_close_race`, `tests/zephyr/uart_rx_ringbuf_close_race` | #1634 both halves |
| `scripts/check_delay_us_literal.py` | #1621 fixed-literal `alp_delay_us(N>=1000)` |

The gate is now registered in all three places a `check_*.py` needs — the
`pr-metadata-validate.yml` path filter **and** run step, and
`metadata/quality-tasks-v1.json` (so `test-all.sh` runs it locally too). Its own
coverage test caught the miss: the gate polices `chips/**`, but no path filter
covered `chips/`, so it would not have retriggered on the very change class it
exists to catch.

Only the missing halves were taken. The fix branches predate later work, so
merging them wholesale would have reverted shipped changes — #1638's
`alp_status_from_zephyr_errno()` delegation in the UART backend, and the `src/**`
trigger that #1630 added to the same workflow. Both are preserved.
