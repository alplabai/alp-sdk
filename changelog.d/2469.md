### Fixed — the boot banner marks the core the image runs on, not the board.yaml core (#2469)

The banner's `CPU:` line took its `(active)` marker from the `board.yaml`
slice the example's CMakeLists passes to `alp_project.py --core`. Most
examples hard-code that core, so an image built for the other core
announced the wrong one: `blink` built for the M55-HE of an E1M-AEN803
printed `M55-HP @400MHz (active)`.

The orchestrator now tags each core that has a Zephyr CPU cluster with it
(`scripts/alp_orchestrate/kconfig.py:604`
("cluster = core.get(\"zephyr_cpucluster\")")), and the banner and the
console's `res` command mark the core whose tag matches the last segment of
`CONFIG_BOARD_TARGET`, listing it first
(`src/zephyr/alp_soc_cpus.h:87` ("alp_soc_cpus_format(char *buf, size_t n")).
When no tag matches — `native_sim`, or a board whose cores have no cluster —
the orchestrator's marking stands. The tags are never printed.

A native_sim unit test pins the swap, the unchanged matching case, the
no-match fallback and truncation
(`tests/unit/soc_cpus_active_core/src/test_soc_cpus_active_core.c:18`
("test_he_build_of_hp_slice_marks_he")).

Verified on E1M-AEN803 serial 2026W36-0001: `blink` built for
`alp_e1m_aen803_m55_he/ae822fa0e5597ls0/rtss_he` and RAM-run on the M55-HE
now prints `CPU: M55-HE @160MHz (active) + M55-HP @400MHz + 2x Cortex-A32
@800MHz`.
