### Added -- `<alp/rpc.h>` on the V2N / V2M Cortex-M33 (#3067)

**`zephyr/drivers/ipc/ipc_alp_v2n_rpmsg.c` is an `ipc_service` backend for the CM33, so `src/backends/rpc/zephyr_drv.c` runs there unchanged.** The M33 is the OpenAMP remote of the Linux A55: the backend copies the vendor-shaped resource table into the `rsctbl` window, takes the vrings from `vring_ctrl0/1` and the buffer pool from `zephyr,ipc_shm`, receives the A55 doorbell on the MHU-B mbox and rings the A55 with the proven direct write. It publishes the v2 AMP beacon from boot (heartbeat, attach epoch odd once the vdev is bound, link reset on the A55's request, reported to `<alp/rpc.h>` as `unbound` / `ALP_RPC_LINK_LOST`), which `yocto_uio_drv.c` requires before it attaches. The board dts `chosen { zephyr,ipc }` now points at an `ipc0` node (`alp,ipc-v2n-rpmsg`) instead of the unbindable `vnd,mbox-consumer`; enable it with `CONFIG_IPC_SERVICE_BACKEND_ALP_V2N_RPMSG=y` and `CONFIG_OPENAMP_RSC_TABLE=n`, or let an `ipc:` rpmsg entry do it (#3066). `bound` / `ALP_RPC_LINK_UP` fires when the A55's first frame arrives, and sends are non-blocking. The M33 ignores `src_ept` / `dst_ept` (`ipc_service` has no such field) and serves its Nth open channel at rpmsg address 1024 + N, which the A55 passes as `dst_ept`. New build-only example `examples/v2n/v2n-alp-rpc-responder`. Build-verified for both boards; bench-unverified through `<alp/rpc.h>` (the transport is the one `rpmsg-v2n` proved).

**The resource table, beacon and doorbell moved out of `examples/multicore/rpmsg-v2n/m33_sm` into `zephyr/drivers/ipc`** so the backend and `rpmsg-v2n` share the table, beacon and doorbell and `microros-ros2-v2n` shares the table; the example's behaviour is unchanged.
