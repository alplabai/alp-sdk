### Added -- `<alp/rpc.h>` on the V2N / V2M Cortex-M33 (#3067)

**`zephyr/drivers/ipc/ipc_alp_v2n_rpmsg.c` is an `ipc_service` backend for the CM33, so `src/backends/rpc/zephyr_drv.c` runs there unchanged.** The M33 is the OpenAMP remote of the Linux A55: the backend copies the vendor-shaped resource table into the `rsctbl` window, takes the vrings from `vring_ctrl0/1` and the buffer pool from `zephyr,ipc_shm`, receives the A55 doorbell on the MHU-B mbox and rings the A55 with the proven direct write. It publishes the v2 AMP beacon from boot (heartbeat, attach epoch odd once the vdev is bound, link reset on the A55's request), which `yocto_uio_drv.c` requires before it attaches. The board dts `chosen { zephyr,ipc }` now points at an `ipc0` node (`alp,ipc-v2n-rpmsg`) instead of the unbindable `vnd,mbox-consumer`; enable it with `CONFIG_IPC_SERVICE_BACKEND_ALP_V2N_RPMSG=y` and `CONFIG_OPENAMP_RSC_TABLE=n`, or let an `ipc:` rpmsg entry do it (#3066). The A55 names the endpoint explicitly: `dst_ept` = 1024 + the order the M33 registered its channels. New build-only example `examples/v2n/v2n-alp-rpc-responder`. Build-verified for both boards; bench-unverified through `<alp/rpc.h>` (the transport is the one `rpmsg-v2n` proved).

**The resource table, beacon and doorbell moved out of `examples/multicore/rpmsg-v2n/m33_sm` into `zephyr/drivers/ipc`** so the example, `microros-ros2-v2n` and the backend share one copy; the example's behaviour is unchanged.
