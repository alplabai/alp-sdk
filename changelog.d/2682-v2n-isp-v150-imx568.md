### Changed — RZ/V2N ISP path moves to ISP Support Package V1.50 and gains a CSI-2 lane-polarity port (#2682)

The opt-in Mali-C55 ISP integration (`meta-alp-sdk/dynamic-layers/meta-rz-isp/`)
now targets Renesas ISP Support Package V1.50 (`RTK0EC0005S01001SJ`). The
package renamed its recipes and kernel symbols (`rzv-isp-driver`,
`rzv-isp-scripts`, `CONFIG_VIDEO_RZV_ISP`); the machine-compatibility
bbappends and `alp-isp-init` follow. The ISP device-tree nodes are now folded into the shipped
`e1m-v2{n,m}101-x-evk.dtb` like the CAM0 fragment (U-Boot forces that dtb name),
keyed on `ALP_CAMERA_CAM0` (the old separate `-cam0-isp.dtb` read the retired
`ALP_CAM0_SENSOR`), and mono modules (`innomaker_cam_ov9281`, `vc_mipi_imx568`)
are refused on an ISP image.

The `isp` to `isp_reserved` label rename of the reserved ISP buffer in
`e1m-v2n-som.dtsi` comes from the #2660 base and is kept: same `reg`, and no
`&isp` user referred to that label.

Kernel patch `0017` (CSI-2 lane polarity via `CRUm_SWAPCTL`) is ported onto the
package's rewritten CSI-2 receiver driver (`isp-0001`), so a carrier whose CSI
pairs arrive swapped, such as E1M-V2M103 on the X-EVK J5 connector, no longer
loses the ISP path. Patch `0016` (Y10/Y8 greyscale) is still dropped on an ISP
image.

`docs/v2n-isp.md` describes the Vision Components IMX568C port (ISP sensor
sub-driver and IQ entry points live in the private mirror; the IQ data is
untuned) and a first bring-up checklist. Builds only; not run on a board.
