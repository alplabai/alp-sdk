### Removed — the host-side model engine moved to tan (ADR-0028)

`scripts/alp_model/` and `scripts/alp_cli/model.py` are deleted; the engine
now ships as `tan.model` in `alplabai/tan-cli`. `alp model build` is gone —
use `tan model build`. alp-sdk keeps every per-NPU fact the engine reads
(`metadata/npu_ops/`, `metadata/schemas/`, the `inference_arena_sram_kib`
budgets) and the on-device `.alpmodel` reader (`src/common/alp_model.c`),
which are unchanged.

No alp-sdk build path is affected: no CMake, Yocto recipe or example imported
the Python package. `examples/aen/aen-npu-inference-alp` drives its own
`gen_model.py`, which spawns `vela` directly.

**This deletion and tan-cli's relocation (`feat/model-engine-migration`) MUST
merge together.** Merging this alp-sdk change without tan's side leaves `tan
model build` with no engine and every model build fails for every user.

Test coverage moved with the code it exercised: `tests/scripts/test_alp_model_*.py`,
`test_alp_cli_model.py`, and the two real-model e2e proofs
(`test_deepx_yolo_internal.py`, `test_vela_yolo_internal.py` — a real
compiled yolo11n via `dxcom` and a real int8 detector via `vela`) are gone
from alp-sdk and now live under `tan-cli`'s `python/tests/model/`. Three
cross-cutting tests stayed and were re-expressed against alp-sdk's own
surface instead of the departing engine: `test_silicon_ref_single_source.py`
now pins the ValueError/FileNotFoundError distinction directly against
`resolve_soc_path()` rather than through `alp_model.targets.resolve_targets()`;
`test_alp_cli_new_som.py` and `test_resolve_generated_conflicts.py` drop
their `alp_model` entries.

The `model-io` `pyproject.toml` extra (tflite + flatbuffers, installed only
for the now-departed tensor-I/O tests) is gone. `model-compile`
(`ethos-u-vela` + tflite + flatbuffers) stays: `scripts/gen_npu_ops.py` still
needs a real `vela` to regenerate `metadata/npu_ops/ethos_u/*.json`, and
`tests/fixtures/models/gen_tiny_model.py` still needs it to rebuild
`tiny_int8.tflite`, the NPU fixture `examples/aen/aen-npu-inference{,-alif}`
compile for real silicon.

Regenerated `tests/fixtures/alpmodel/minimal.alpmodel`,
`tests/unit/alpmodel_reader/src/fixture.h` and `tests/yocto/onnx_cpu_fixture.h`
from `tan.model._gen_fixture` — byte-identical except the provenance banner
(`python -m alp_model._gen_fixture` → `python -m tan.model._gen_fixture`).

### Follow-up (review response)

- **Real-model Ethos-U proof.** `tests/fixtures/models/person_detect_int8.tflite`
  (TFLite-Micro's canonical "person detect" MobileNet, int8 throughout —
  verified against the flatbuffer schema, not assumed; Apache-2.0, vendored
  from the same `tflite-micro` revision `metadata/libraries/tflite-micro.yaml`
  already pins) is now vendored PUBLIC — see its own
  `PERSON_DETECT-PROVENANCE.txt` and the new `NOTICE` entry. This unblocks
  tan-cli's `tests/model/test_vela_yolo_internal.py`, which previously had
  no reachable fixture at all (it only ever globbed the private
  `alp-sdk-internal` tree, which never carried an Ethos-U sample model) and
  so had never actually executed. It now PASSES (not skips) against this
  checkout via `ALP_SDK_ROOT`, both for `ethos-u85-256` and `ethos-u55-256`.

- **A cross-repo guard hole this migration opened, now partially closed.**
  Before ADR-0028, one generator produced `minimal.alpmodel`, `fixture.h`
  and `onnx_cpu_fixture.h` together, so they could not drift from each
  other. tan-cli's `python/tests/model/test_package.py` is the replacement
  cross-repo check, but it only runs meaningfully when `ALP_SDK_ROOT` is
  bound to the alp-sdk checkout under review — tan-cli's `parity.yml` binds
  it to a frozen `PINNED_SDK_TAG` instead, so a future alp-sdk PR that edits
  these three fixtures (correctly or not) passes every alp-sdk gate while
  tan-cli's CI keeps silently validating the OLD, pinned bytes instead of
  the new ones. Added `tests/scripts/test_alpmodel_fixture_self_consistency.py`
  as the cheap half of the mitigation: it decodes the container using
  `src/common/alp_model.c`'s own wire layout (never tan's writer) and
  asserts (1) `fixture.h`'s bytes equal `minimal.alpmodel`'s raw bytes and
  (2) both fixtures are structurally well-formed against
  `include/alp/model.h`'s `ALP_MODEL_CONTAINER_V`. This catches the two
  committed encodings drifting from EACH OTHER, or a container-version bump
  landing without a regen — it does **not** catch two fixtures edited
  consistently with each other into bytes that no longer match what tan's
  canonical `tan.model.package.write_package()` would actually emit; that
  residual gap has no cheap alp-sdk-side guard and stays mitigated only by
  bumping tan-cli's `PINNED_SDK_TAG` as a documented tan-cli release step
  (or, as a future tan-cli-side improvement, binding `ALP_SDK_ROOT` to the
  PR under test in `parity.yml` instead of a frozen tag — not made here).
