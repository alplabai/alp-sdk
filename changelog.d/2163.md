### Added — the 15 copies of `cc3501e_bridge.{c,h}` under `examples/` are now gated against drift (#2163)

`cc3501e_bridge.c` / `.h` is copied per example -- 16 identical pairs when this
gate landed, plus one deliberately different -- and nothing asserted the copies
stayed in sync. It is not boilerplate: it writes the LP-GPIO pad control
registers for `WIFI_EN` / nRESET, runs the reset pulse, and pokes the
silicon-tuned DW SSI `RX_SAMPLE_DLY` register that makes the 25 MHz link sample
MISO correctly (`examples/aen/aen-cc3501e-bringup/src/cc3501e_bridge.c:76`
("the DW SSI RX_SAMPLE_DLY register (0xf0) delays")). A silicon fix applied to
one copy and missed in the other fifteen compiles clean, passes CI, and shows
up only on hardware. #1859 is the same failure already realised once: the
hand-copied `cc3501e_gpio_routes.c` drifted to a wrong `hw_rev` pad map, and
the fix there was to generate it from one source
(`scripts/gen_cc3501e_gpio_routes.py`).

The duplication itself stays, because two documented properties depend on it:
the header presents the pair as a customer-facing template
(`examples/aen/aen-cc3501e-bringup/src/cc3501e_bridge.h:15`
("copy this pair")), and `tan init --from-example <dir>` copies
exactly one directory, so an example that reached into a shared
`examples/aen/common/` would no longer scaffold. So the new gate detects drift
rather than removing it: `scripts/check_cc3501e_bridge_copies.py` compares
every copy byte for byte against
`examples/aen/aen-cc3501e-bringup/src`
(`scripts/check_cc3501e_bridge_copies.py:55` ("CANONICAL_DIR =")), the
bring-up example the AEN `board.yaml` files already name as the shape to match.
A failure prints the first differing lines and the `cp` command that re-syncs
that copy; `--fix` re-syncs every graded copy at once.

A copy that differs on purpose is declared by name with its reason
(`scripts/check_cc3501e_bridge_copies.py:63` ("DIVERGENT_COPIES = {")), and
today there is exactly one: `examples/peripheral-io/alp-console/src`, whose
bring-up retries `cc3501e_hard_reset()` in a cold-boot soak instead of
returning the first `cc3501e_reset()` status, and carries no `RX_SAMPLE_DLY`
poke. That list is graded in both directions -- an entry naming a directory
with no copy fails, and so does one whose copy has come back into line
(`scripts/check_cc3501e_bridge_copies.py:145` ("declared divergent in")) --
because an exemption nobody removes is where the next drift hides. A directory
carrying one half of the pair without the other fails too.

Registered as a hard gate in the quick / pr / full / release profiles
(`metadata/quality-tasks-v1.json:151` ("cc3501e-bridge-copies")) and wired into
CI (`.github/workflows/pr-metadata-validate.yml:719`
("cc3501e_bridge copies are in sync")). The tree passes today: 15 copies byte-identical to the
canonical pair, one declared divergent. Note that the 18-copy survey in #2163
counted a copy under `examples/aen/aen-sdcard-readout`, which no longer carries
one -- that example ships only a `boards/` directory on `dev`.
