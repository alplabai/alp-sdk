### Added — GD32 bridge wire protocol v0.15 on the host side: negotiated big frames, `BATCH`, lossless ADC streams and the `ATTN` line (#2692)

**`gd32g553_init()` now negotiates the v0.15 link features** with a bridge that reports minor >= 15, using the 6-byte `CMD_LINK_FEATURES` form: `STATUS_SEQ`, `BIG_FRAME` (256-byte SPI frames), `ADC_STREAM2` and `BATCH`. A v0.14 bridge, or one that answers the 6-byte form with `INVAL`/`NOSUPPORT`, gets the legacy 1-byte `STATUS_SEQ` form, so an un-negotiated link is byte-identical to v0.14 in all four host/firmware pairings. The compatibility rule in `docs/gd32-bridge-protocol.md` §8 changes from "pre-1.0 lockstep including minor" to negotiated compatibility. The 256-byte SPI buffers now live in `gd32g553_t` (a few hundred bytes larger), not on the caller's stack.

**New driver API.** `gd32g553_adc_stream_begin2()` / `gd32g553_adc_stream_read2()` return raw codes with `first_index` and `dropped` (the reply is variable length; the CRC position is derived from `got`), `gd32g553_batch()` runs up to 16 allow-listed sub-operations in one transaction pair and stops at the first error, and `gd32g553_init_ex()` registers an `ATTN` hook. With `ATTN` granted the driver waits for the GD32's data-ready edge (interrupt + semaphore, never polling) instead of the 35 µs staging gap, falls back to the v0.14 drain rule per command on a lost edge, and withdraws `ATTN` after three consecutive faults; the grant itself is self-tested. `BEGIN2` reports the ring and watermark the firmware actually granted, which can exceed the request at high rates (100 kHz with a 16-sample watermark is granted 256); `gd32g553_adc_stream2_read_interval_us()` turns that into the read interval for a link without `ATTN`.

**V2N.** The CM33 boards now publish the GD32 control pads (`swdio` P70, `swclk` P71, `nrst` P74, `attn` P71) as a dedicated `alp,gd32-pads` devicetree node generated from `supervisor-links.yaml` -- not as entries of the positional `alp,pin-array`, whose index 0 is the GD32 SPI chip-select (`alp_pins` is unchanged) -- reached through reserved `GD32G553_PAD_ID_*` ids that the portable `alp_gpio_open()` **refuses** (`ALP_ERR_INVAL`; only the supervisor and the SWD driver open them, through an internal opener). The supervisor singleton re-configures `P71` as an input with a rising-edge IRQ on every init and registers a time-stamping edge hook (the driver drains the latch, reads the clock before each request, and accepts an edge only if it is not older than that reading and the line reads HIGH); `CONFIG_ALP_SDK_V2N_SUPERVISOR_ATTN=n` disables it, and a pad without a platform interrupt route keeps the staging-gap path. `P71` is the GD32's `SWCLK` whenever `ATTN` is off, so `gd32_swd` is now connect-under-reset: `gd32_swd_init(&swd)` now takes no pin handles (the driver opens its own pads) and asserts `GD32_NRST` (`P74`) first as an output with an initial low level (never driven high -- the net is shared with the PMIC), `gd32_swd_connect()` arms halt-on-reset (`DHCSR.C_DEBUGEN` + `DEMCR.VC_CORERESET`), releases it and verifies `DHCSR.S_HALT` (re-asserting NRST and failing otherwise), `gd32_swd_reset_and_run()` returns `P70`/`P71` to inputs before its final NRST release, and `gd32_swd_deinit()` returns them to inputs. During an SWD session the supervisor closes the bridge link and answers every bridge command `ALP_ERR_BUSY`. An ATTN fault and an OTA commit/rollback are now handled at the start of the next command (never between a reply and its parse), and the next command after an OTA reset re-runs the link negotiation. The portable `alp_adc_stream_*` backend uses `BEGIN2`/`READ2` when `ADC_STREAM2` is granted and still returns `ALP_ERR_BUSY` only for the discontinuity sentinel (`dropped == 0xFFFFFFFF`); `<alp/adc.h>` is unchanged.

**I2C policy (firmware-side, unconditional).** A v0.15 bridge answers any I2C opcode outside the management allow-list with `STATUS_NOSUPPORT`; no in-tree caller is affected (§5.3).
