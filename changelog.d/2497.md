### Fixed — the SE AEAD encrypt/decrypt paths no longer send an unset key size, and AEN twister builds again

`se_aead_encrypt()` and `se_aead_decrypt()` discarded
`se_aead_keybits()`'s status, so a key size it failed to resolve would have
reached the Secure Enclave packet uninitialized. `open()` validates the same
pair first, so this could not happen at runtime, but GCC at `-O2` cannot see
that and reports `'key_bits' may be used uninitialized`, which the AEN
twister job's `-Werror` turns into a build failure on every scenario that
links the SE crypto backend at `-O2` (the Trace Runner's `a32_render`, since
#2452). Both paths now return the status instead
(`src/backends/security/se_cryptocell.c:659`
("alp_status_t kb_st = se_aead_keybits")).
