### Added — build-time knobs for Alif TF-A's console UART base and pads (#1979)

Alif's TF-A port hardcodes its BL32 console to the DevKit's UART2 in two
independent places that must move together: the register base
(`platform_def.h`) and the pinmux (`devkit_e7_sp_min_setup.c`). A carrier
routing a different UART got no console output and no error -- BL32 ran
(confirmed via PSCI answering SMCs) while the console stayed at zero bytes,
as happened during the 2026-09-05 E8 A32 Linux bring-up (#1972).

`meta-alp-sdk/recipes-bsp/trusted-firmware-a/trusted-firmware-a/`
gains `alif-console-uart-build-knobs.patch`, adding six `#ifndef`-guarded
macros defaulted to the unmodified DevKit UART2 values, so an unset build is
byte-identical. The bbappend wires the E1M-AEN801 EVK's verified console
routing (SoC UART5, `P3_4`/`P3_5`, alternate function 2) behind an
`:e1m-aen801` override.

The `:e1m-aen801` and `:e1m-aen701` knobs are inert today:
`MACHINE=e1m-aen801-a32`/`e1m-aen701-a32` does not yet parse (no public
Scarthgap `meta-alif-ensemble`/`devkit-e8.conf` exists, #1968 #1971), so
nothing currently reaches this recipe. The patch is verified (`patch -p1
--dry-run`, `git apply --check`) against the real upstream source
(`alifsemi/trusted-firmware-a_alif`, branch `alif_lts-v2.10.8`), not against
real E1M-AEN801/E1M-AEN701 silicon -- that needs the Scarthgap layer to land
first. Both MACHINEs get the same UART5 knobs: they are the same AEN carrier
PCB (`metadata/pinmux/aen.yaml`) and share the `PLAT=devkit_e7` TF-A plat
directory this patch touches.

**This fixes only the TF-A/BL32 half of #1979.** The issue names a second,
independent trap on the Linux side (`UART2_STATUS "okay"` making
`serial@4901a000`/`ttyS0` win over the UART5 console at the `aliases`
level) that this change does not touch. Refs #1979 -- does not close it.
