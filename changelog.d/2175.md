### Added — `--fix` re-derives a drifted `path:line` citation from its anchor (#2175)

Merging `dev` into a branch shifts the files its `changelog.d/` fragments cite, so every
citation into a moved file drifts at once. Two failures follow, and only one of them
announces itself:

- A fragment **both sides edited conflicts, and neither side is right after the merge**.
  Measured across the AEN branches, the same citations were branch+6 and dev+9..+39 — the
  correct post-merge line was neither, so `--ours` and `--theirs` each produce a tree this
  gate reds, and a human resolving by picking a side picks a wrong answer that looks
  entirely reasonable.
- A fragment **only one side edited merges cleanly and goes silently stale** — no conflict,
  no marker, wrong line numbers. `git merge-tree` reporting `CLEAN` is not evidence that a
  branch's citations survived the merge.

`python3 scripts/check_changelog_citations.py --fix` re-derives the line number by locating
the anchor text in the cited file, then rewrites the citation in place
(`scripts/check_changelog_citations.py:249` ("def _fix_one(frag: Path, text: str) -> tuple[str, list[str], list[str], int]:")).
The anchor is the only part of a citation that survives a code move, so it is the only thing
the fixer keys on.

The checker is unchanged. Without the flag the script behaves exactly as it did — it is a
required CI gate and owns the default — and `--fix` falls through to it afterwards, so the
exit code is always this gate's own verdict on the tree the fixer just wrote
(`scripts/check_changelog_citations.py:435` ("if args.fix:")). Fixer and checker share one
file and one parser deliberately: a fixer with its own notion of what a citation *is* would
drift from the gate and then confidently "repair" fragments into a tree the gate rejects.

What it refuses to do matters more than the rewrite, because a fixer that guesses is worse
than no fixer at all:

- **Never an un-anchored citation.** There is nothing to verify against, so re-pointing one
  would be guessing; it is counted and left alone. This is the half no fixer can repair, and
  the argument for making anchors mandatory rather than optional.
- **Never inside a fenced block** — that is where a fragment documents the anchor *syntax*
  with a deliberately made-up citation, as this gate's own release note does. Detection runs
  on the blanked copy from `_strip_fenced_blocks`, whose spaces preserve every offset, so
  the rewrite still addresses the real file
  (`scripts/check_changelog_citations.py:272` ("stripped = _strip_fenced_blocks(text)")).
- **Never released history.** `changelog.d/` and `[Unreleased]` describe the current tree
  and are fixable; a released section describes a tree that no longer exists, and rewriting
  it would falsify what shipped. The released tail is split off and carried through byte for
  byte (`scripts/check_changelog_citations.py:359` ("def _run_fix(fragments: list[Path]) -> None:")).
- **Never the first match on an ambiguous anchor.** Drift is small and consistent, so the
  intended occurrence is the one nearest the originally cited line. First-match silently
  retargets the note to an unrelated occurrence, which is the exact failure this gate exists
  to catch. Every ambiguous resolution is reported with its candidate lines and the one
  chosen (`scripts/check_changelog_citations.py:328` ("new_start = min(hits, key=lambda h: abs(h - start))")).
- **Never an anchor it cannot find.** The anchored code is gone rather than moved, so it is
  reported for a human instead of re-pointed at a plausible-looking line.

A citation that still resolves is left alone, and a range keeps its width: `4372-4376`
re-anchored at 4378 becomes `4378-4382`.

Run against this tree, `--fix` rewrites nothing, touches no file, and leaves all seven
released-history warnings exactly where they are — which is the behaviour working.
