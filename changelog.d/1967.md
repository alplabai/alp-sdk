### Documented — the AEN A32 Yocto path (`meta-alif-ensemble`) does not build; docs no longer instruct a broken clone (#1967)

`meta-alp-sdk/README.md` and `meta-alp-sdk/conf/layer.conf` told users to clone Alif's
`meta-alif-ensemble` BSP at branch `scarthgap`. Verified 2026-09-05: the public repo has exactly
one branch, `devkit-ex-b0` — `scarthgap` does not exist, so the documented `git clone -b
scarthgap ...` failed outright.

Both files, plus a parenthetical aside in `docs/bring-up-aen.md`, now say plainly that the AEN A32
Yocto path is **broken today** and name why: no `scarthgap` branch (#1967), the one real branch
carries no `conf/machine/devkit-e8.conf` the carrier MACHINE `require`s (#1968), and the layer is
Yocto-series-incompatible with this repo's Scarthgap baseline regardless (#1971) — a corrected
branch name alone would not make the path usable. The `meta-alp-sdk/README.md` build-steps block
is kept (clearly marked BROKEN) only so it documents the failure mode rather than being deleted
and silently rediscovered. None of this touches the M55/Zephyr side of AEN801/AEN701, which builds
today on upstream Zephyr's `ensemble_e8_dk` board.

**#1968 and #1971 are not closed by this change** — they describe defects in the upstream
`meta-alif-ensemble` layer and this repo's `e1m-aen801-a32.conf` / `e1m-aen701-a32.conf`, which PR
#264 is rebuilding on a real base. This entry only stops the docs from lying about the current
state.
