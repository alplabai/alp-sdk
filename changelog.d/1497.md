### Fixed — `flash-jlink-mramxip.sh` discarded an operator's DPIDR override (#1497)

`scripts/bench/aen/flash-jlink-mramxip.sh` sourced `bench-env.sh` and then re-declared
`AEN_DPIDR` and `GD32_DPIDR` with bare assignments, silently throwing away any export the
operator had made. `bench-env.sh` is the documented single source and declares them
overridable (`export AEN_DPIDR="${AEN_DPIDR:-4C013477}"`), stating in its own header:
"Override any of them by exporting the variable before invoking a helper".

This was the **only** one of the six callers of `bench_jlink_assert_aen_dpidr` that did
so, and `V2N_CM33_DPIDR` was never re-declared here either — so the file used one source
for two IDs and another for the third, which rules out reading it as deliberate hardening.

The declarations now use `${VAR:-default}`. That satisfies both constraints at once: the
operator's export survives (#1497), and the declarations remain in the file rather than
being deleted (#1527 — deleting the pair to silence shellcheck weakened the wrong-board
MRAM-write gate during #1488 and had to be reverted).

**No safety change.** The gate is fail-closed on a *positive* `AEN_DPIDR` match and aborts
before any MRAM write, so the pre-fix behaviour was a misleading hard abort against a value
the operator had explicitly overridden, never a wrong-board write. This makes the script
consistent with its five siblings, it does not loosen the gate.
