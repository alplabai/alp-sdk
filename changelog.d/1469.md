### Decided — ADR-0028: tan owns the model engine; alp-sdk keeps the NPU truth

`scripts/alp_model/` (13 modules, 1,029 lines) and `scripts/alp_cli/model.py`
move to `python/tan/model/` in `alplabai/tan-cli`, making tan the single
implementation of the host-side model pipeline. alp-sdk keeps everything it is
uniquely authoritative for — `metadata/npu_ops/`, `metadata/model_zoo/`,
`metadata/schemas/`, the `inference_arena_sram_kib` budgets, and the on-device
`.alpmodel` reader (`src/common/alp_model.c`). The `.alpmodel` container format
survives unchanged as the cross-repo seam.

This applies ADR-0026's principle — hardware truth stays in the repo that owns
the hardware; a consumer of it does not — to the second duplicated surface. The
measured trigger: `tan model build` hand-ports 108 lines of this repo's
board.yaml and compile-option logic, that copy never received the alp-sdk#1271
`_PATH_OPT_KEYS` fix, and it currently corrupts DRP-AI's `input_shape`
(`"1,3,224,224"`), `input_name` (`"images"`) and `product` (`"V2N"`) by
resolving them as filesystem paths. The sha256 pin over
`scripts/alp_cli/model.py` could not see it: a pin proves the upstream file is
unchanged, never that the downstream port is equivalent.

No alp-sdk build path is affected — no CMake, Yocto recipe or example imports
the Python package. The implementation plan is
`docs/superpowers/plans/2026-08-15-tan-owns-the-model-engine.md`.
