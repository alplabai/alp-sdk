### Changed — `<alp/cap_instance.h>` reshaped to a two-word vocabulary that can say "not reported" (#1640)

`alp_capabilities_t` had one problem no bit could fix: `flags == 0` meant both
"the backend has nothing" and "the backend never spoke", and the ADC-only
`ALP_INSTANCE_CAP_HW_OVERSAMPLE` / `HW_TRIGGER` / `DIFFERENTIAL` bits lived in
the universal enum, one class away from colliding with an unrelated class's
future bit at the same position.

**`flags` is now universal-only.** `ALP_INSTANCE_CAP_DIFFERENTIAL` and
`ALP_INSTANCE_CAP_HW_TRIGGER`/`HW_OVERSAMPLE` are gone from
`alp_instance_cap_t`; the equivalent ADC facts are `ALP_ADC_CAP_HW_OVERSAMPLE`
/ `ALP_ADC_CAP_HW_TRIGGER` / `ALP_ADC_CAP_DIFFERENTIAL` in `<alp/adc.h>`,
carried in a new `alp_capabilities_t.class_flags` word whose meaning belongs
to the class header of the handle you queried. A new universal bit,
**`ALP_INSTANCE_CAP_REPORTED`**, disambiguates the old zero: unset means "the
backend never populated this descriptor", set means every other bit — in
`flags` or `class_flags` — and `channel_count == 0` is now an affirmative
answer, not silence. `alp_backend_t` grows a matching `base_class_flags`
field so a registry entry can seed `class_flags` the same way `base_caps`
already seeds `flags`; every `src/*_dispatch.c` that pre-seeds `flags` from
`base_caps` now pre-seeds `class_flags` from `base_class_flags` too, in
lockstep. `alp_capabilities_t.max_sample_rate` is renamed `max_rate_hz` to
match what it actually gates (ADC samples/s, I2C/SPI bus clock, PWM carrier).

**The 97-site trap this closes:** across `src/backends/**`, 77 backend
`open()`/`probe()` functions unconditionally wrote `caps_out->flags = 0u;`
into a `caps_out` the dispatcher had *already pre-seeded* from the registry's
`base_caps` (`src/adc_dispatch.c:108`, `src/i2c_dispatch.c:74`, and every
sibling `*_dispatch.c`) — a backend "with nothing to say" was clobbering
whatever the registry had already declared, silently. Wave 1 deletes every
one of those 97 lines; the fix is deletion, not population — a backend that
has nothing to add now leaves the pre-seeded descriptor alone. No capability
is lost *today*: of those 77 files, none had a non-zero `base_caps` to
clobber — only `src/backends/adc/alif_e7.c` and `alif_e8.c` (never touched
`caps_out->flags`) and `src/backends/gpu2d/alif_dave2d.c` (re-asserted the
same value it was seeded with) had anything real to report, and all three now
set `ALP_INSTANCE_CAP_REPORTED` explicitly. This closes a **latent** trap —
the next backend to declare a non-zero `base_caps` for a class whose backend
still zeroed `flags` would have had it silently discarded — and fixes a
real ambiguity, not a live data-loss bug.

`include/alp/counter.h`'s capability doc no longer describes the
GD32-bridge-only `channel_count` ambiguity as unavoidable: it now points at
`ALP_INSTANCE_CAP_REPORTED` as the disambiguator, noting that no counter
backend sets it yet so the two cases still collapse to "not reported" today.

Regression coverage: `tests/unit/backend_registry/src/test_capabilities.c`
(the reported/not-reported/affirmative-absence contract directly),
`tests/unit/adc_registry/src/test_adc_registry.c` and
`tests/unit/backend_registry/src/test_registry.c` (`base_caps`/
`base_class_flags` survive to the public getter), and
`tests/unit/i2c_registry/src/test_i2c_registry.c::test_sw_fallback_leaves_preseeded_caps_untouched`,
which seeds a sentinel `alp_capabilities_t` before calling the real
`sw_fallback` `ops->open()` and fails if a future edit re-introduces a
`caps_out->flags = 0u;` clobber.
