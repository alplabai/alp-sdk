### Removed — the rest of the `alp_cli` command surface: `main.py`, `validate.py`, and every command module reachable only through them (#1368)

Deleted `scripts/alp_cli/{main,__main__,validate,doctor,emit,faultdecode,
generate,init,model,monitor,new_som,run}.py` and their now-orphaned tests
(`test_alp_cli.py`, `test_alp_cli_doctor.py`, `test_alp_cli_emit.py`,
`test_alp_cli_model.py`, `test_alp_cli_new_som.py`, `test_alp_faultdecode.py`,
plus the `alp_cli.main` CLI-wiring tests inside `test_diagnostic_format.py`
and the three `alp_cli.doctor._check_libraries` tests inside
`test_library_layer.py`). `test_validate_board_yaml_entrypoints.py` lost only
its parity-pair half against `python -m alp_cli.main validate`; the
`_run_script()` half against `scripts/validate_board_yaml.py` itself is kept
— it is the only script-level guard that a warning-only ALP-B010 run exits 0,
which `docs/test-plan.md` and `docs/verification-status.md` still cite as
live evidence.
Every one of these command modules had already been natively ported to
`tan` and released (`doctor`, `emit`'s ground via `tan generate`, `explain`
(#1367), `faultdecode`, `generate`, `init`, `model`, `monitor`, `new-som`,
`run`, `validate` — all present in `tan-cli` `v0.6.0`), and no other
in-repo `import` of any of them survived outside their own tests — audited
per module by an AST import scan, not taken from the issue's own list on
faith: `tests/scripts/test_hw_rev_table_unreadable.py` also imported
`alp_cli.new_som._family_hw_revisions` directly (a third independent reader
of `hw-revisions.yaml`, `alplabai/tan-cli#563`) and is trimmed to the two
readers alp-sdk still owns — `tan new-som` carries its own native port of
that same guard now, with its own `tan-cli` test coverage.

The AST import scan is genuinely clean — and genuinely incomplete. It
cannot see a `subprocess` argv **string**, and one survived:
`tests/scripts/test_silicon_ref_single_source.py`'s
`test_new_som_scaffold_still_writes_under_output_root` spawned
`[sys.executable, "-m", "alp_cli", "new-som", ...]`, i.e. both deleted
`__main__.py` and `new_som.py`, and failed hard rather than skip (its own
docstring is explicit that a skip there would enforce nothing). Deleted
rather than re-pointed at a real `tan new-som` subprocess: alp-sdk owns no
new-som scaffolding logic any more (tan-cli's own in-process port at
`v0.6.0` carries its own coverage) and this repo's `tests/scripts/` pytest
stage never puts a `tan` binary on PATH (`scripts/bootstrap.sh`: "Tan is
installed separately"), so a real subprocess call would just trade one
hard failure for another on every host that runs this suite without a
separate tan-cli install. The next `scripts/alp_cli/**` retirement needs to
grep subprocess argv strings for the module name too, not just `import`
statements — an AST scan structurally cannot see the second shape.

`scripts/alp_cli/{__init__,diagnostic,diagnostic_format,validator,
_workspace,yaml_pos}.py` are UNCHANGED and stay: they are library modules
with real non-CLI callers (`scripts/validate_board_yaml.py`,
`scripts/check_diagnostic_schema.py`, `scripts/alp_project_loader.py`,
`scripts/alp_orchestrate/loader.py`, `scripts/gen_rzv2n_cm33_svd.py`), not
command wrappers. `pyproject.toml` already installed no `alp` console
script before this change; its comment explaining why is corrected to stop
describing `alp_cli` as a "parity CLI for direct maintenance" now that it
has none.

`docs/cli.md` drops the `tan` vs `python -m alp_cli` five-verb comparison
table and every other `python -m alp_cli <verb>` reference — there is no
front door left to compare against. `docs/getting-started.md`,
`docs/board-config-schema.md`, `docs/glossary.md`, `docs/portability-
matrix.md`, `docs/cross-platform-setup.md`, `docs/troubleshooting.md`,
`docs/bring-up-drpai-v2n.md`, and `metadata/libraries/README.md` are swept
to name `tan doctor` / `tan model build` / `tan validate` in place of the
retired `python -m alp_cli` invocations. Verified against a real, released
`tan 0.6.0` binary via `scripts/check_tan_docs_surface.py`, not just read:
OK, zero drift.

`.github/workflows/pr-bootstrap-distro-install.yml` drops its now-dead
`scripts/alp_cli/doctor.py` path-filter trigger. Comments in
`scripts/check_diagnostic_schema.py`, `scripts/alp_cli/diagnostic_format.py`,
`scripts/validate_board_yaml.py`, and `scripts/check_diagnostic_narratives.py`
that named the deleted CLI as current or canonical are corrected to name
`tan` instead.

`metadata/schemas/{bootstrap-v1,diagnostic-v1,emit-registry-v1}.schema.json`
and `metadata/emit-registry-v1.json` each carried a stale `description:`
mention of the retired `alp_cli` CLI wrappers (`emit.py`'s `alp emit` front
door, `doctor.py`'s `_prereq_install_hint`, `alp validate --format json`,
and "alp_cli tools used by maintenance") — swept to name the surviving
front doors (`west alp-emit`, `tan validate --format diagnostic-v1`/`json`,
`tan`'s own `_resolve_install_commands`) instead. Editing them moves
`alp.lock`'s `digests.metadata`/`digests.schemas`; regenerated with
`python3 scripts/west_commands/alp_lock.py --workspace .` — no `west`
topdir needed, the gate's own error message names this workaround — and
re-verified clean with `--check`.

Further user-visible fallout of the retirement, swept in this same change:
`pyproject.toml` drops the `pytest-mock>=3.10` dev dependency — its only two
consumers, `test_alp_cli.py`/`test_alp_cli_emit.py`'s `mocker` fixture uses,
retired with the rest of the CLI wrappers, and no surviving test under
`tests/scripts/` uses `mocker`. `scripts/test-all.sh`'s `stage_pytest_scripts`
prerequisite probe (previously `import pytest, pytest_mock`) drops the
`pytest_mock` half to match — a host with `pytest` but not `pytest-mock` now
runs the stage instead of SKIPping it. `docs/test-plan.md` and
`docs/verification-status.md` each drop a now-dangling "verified" row for
"alp-sdk's internal/reference Python CLI (`alp_cli`) and emitters" that cited
`tests/scripts/test_alp_cli*.py` — a glob matching zero files after this
change, with `pr-metadata-validate.yml` still covering the lane the row
pointed at. `docs/diagnostics/ALP-B000.md` and `ALP-B099.md`'s Diagnose
blocks corrected their "Only `tan validate` prints the full diagnostic
frame" overclaim — a checkout-only user has no `tan` install but does have
`scripts/validate_board_yaml.py`, the same script `tan validate` spawns, so
both are now documented. `docs/cli.md` corrects an "All of Tan's 32 verbs are
native" overclaim back to "Most" (three -- `migrate`, `lock`, `quality` --
still forward to the corresponding `west alp-*` command), and its claim that
no `alp` console script was ever installed, which was false — `alp =
"alp_cli.main:cli"` shipped through `v0.11.0` and was removed in `v0.12.0`
(`629aa75fc`), before this retirement began. `docs/bring-up-drpai-v2n.md`
adds an explicit `--sdk-root <alp-sdk>` binding to its `tan model build`
example -- `tan` is a standalone binary with no repo context to infer an SDK
checkout from. `llms.txt` drops its link to the deleted
`scripts/alp_cli/doctor.py`.
`docs/adr/0020-sdk-owns-build-execution.md` gets a new correction item
(appended, not edited in place, per that ADR's own convention) marking its
own point 6 — "11 non-build verbs all still survive in the `alp_cli`
package" — false as of this change.
