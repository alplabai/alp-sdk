### Removed — the rest of the `alp_cli` command surface: `main.py`, `validate.py`, and every command module reachable only through them (#1368)

Deleted `scripts/alp_cli/{main,__main__,validate,doctor,emit,faultdecode,
generate,init,model,monitor,new_som,run}.py` and their now-orphaned tests
(`test_alp_cli.py`, `test_alp_cli_doctor.py`, `test_alp_cli_emit.py`,
`test_alp_cli_model.py`, `test_alp_cli_new_som.py`, `test_alp_faultdecode.py`,
`test_validate_board_yaml_entrypoints.py`, plus the `alp_cli.main`
CLI-wiring tests inside `test_diagnostic_format.py` and the three
`alp_cli.doctor._check_libraries` tests inside `test_library_layer.py`).
Every one of these command modules had already been natively ported to
`tan` and released (`doctor`, `emit`'s ground via `tan generate`, `explain`
(#1367), `faultdecode`, `generate`, `init`, `model`, `monitor`, `new-som`,
`run`, `validate` — all present in `tan-cli` `v0.6.0`), and nothing else
in-repo imported any of them outside their own tests — audited per module,
not taken from the issue's own list on faith: `tests/scripts/
test_hw_rev_table_unreadable.py` also imported `alp_cli.new_som.
_family_hw_revisions` directly (a third independent reader of
`hw-revisions.yaml`, `alplabai/tan-cli#563`) and is trimmed to the two
readers alp-sdk still owns — `tan new-som` carries its own native port of
that same guard now, with its own `tan-cli` test coverage.

`scripts/alp_cli/{__init__,diagnostic,diagnostic_format,validator,
_workspace,yaml_pos}.py` are UNCHANGED and stay: they are library modules
with real non-CLI callers (`scripts/validate_board_yaml.py`,
`scripts/check_diagnostic_schema.py`, `scripts/alp_project_loader.py`,
`scripts/alp_orchestrate/loader.py`, `scripts/gen_rzv2n_cm33_svd.py`), not
command wrappers. `pyproject.toml` already installed no `alp` console
script before this change; its comment explaining why is corrected to stop
describing `alp_cli` as a "parity CLI for direct maintenance" now that it
has none.

`docs/cli.md` drops the `tan` vs `python -m alp_cli` five-verb comparison
table and every other `python -m alp_cli <verb>` reference — there is no
front door left to compare against. `docs/getting-started.md`,
`docs/board-config-schema.md`, `docs/glossary.md`, `docs/portability-
matrix.md`, `docs/cross-platform-setup.md`, `docs/troubleshooting.md`,
`docs/bring-up-drpai-v2n.md`, and `metadata/libraries/README.md` are swept
to name `tan doctor` / `tan model build` / `tan validate` in place of the
retired `python -m alp_cli` invocations. Verified against a real, released
`tan 0.6.0` binary via `scripts/check_tan_docs_surface.py`, not just read:
OK, zero drift.

`.github/workflows/pr-bootstrap-distro-install.yml` drops its now-dead
`scripts/alp_cli/doctor.py` path-filter trigger. Comments in
`scripts/check_diagnostic_schema.py`, `scripts/alp_cli/diagnostic_format.py`,
`scripts/validate_board_yaml.py`, and `scripts/check_diagnostic_narratives.py`
that named the deleted CLI as current or canonical are corrected to name
`tan` instead.

Not swept in this change: `metadata/schemas/{bootstrap-v1,diagnostic-v1,
emit-registry-v1}.schema.json` and `metadata/emit-registry-v1.json` each
carry a stale `description:` mention of the retired `alp_cli` CLI wrappers.
Editing them moves `alp.lock`'s `digests.metadata`/`digests.schemas`, and
this worktree has no `west` topdir to safely regenerate and verify that
against — left as a follow-up rather than guessed at.
