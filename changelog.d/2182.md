### Fixed — the TAS2563 fault-IRQ unmask (#2165/#2140) now has a production caller and a bench discriminator (#2182)

At #2165's head `tas2563_configure_fault_pin()`'s `INT_MASK0` unmask had no
production caller anywhere in the tree -- only its own definition and a
ZTest against the fake existed -- so the read-modify-write it performs had
never actually run against silicon. Closing that needed splitting the
function, adding a caller, and building a probe that could tell a correct
read-modify-write apart from a blind write landing on the same byte.

`tas2563_configure_fault_pin()` is now a thin wrapper around a new
`tas2563_arm_fault_irq(tas2563_t *ctx, bool chip_internal_pullup)`
(`include/alp/chips/tas2563.h:782` ("tas2563_arm_fault_irq(tas2563_t *ctx, bool chip_internal_pullup);"),
implemented at `chips/tas2563/tas2563.c:626` ("alp_status_t tas2563_arm_fault_irq(tas2563_t *ctx, bool chip_internal_pullup)")):
the chip-only half -- page select, `MISC_CFG1.IRQZ_PU`, `INT & CLK
CFG.IRQZ_PIN_CFG` and the `INT_MASK0[2]` clear
(`chips/tas2563/tas2563.c:647` ("return reg_update(ctx, TAS2563_REG_INT_MASK0, TAS2563_INT_MASK0_TDM_CLOCK, 0u);")),
with no GPIO touched and `ctx->irq_n` left unbound. `tas2563_configure_fault_pin()`
(`chips/tas2563/tas2563.c:651` ("tas2563_configure_fault_pin(tas2563_t *ctx, alp_gpio_t *irq_n, bool chip_internal_pullup)"))
now only configures the host pin, calls the new function, and binds
`ctx->irq_n` -- unchanged behaviour for every existing caller. This exists
for boards where the fault pin is not reachable via `alp_gpio` and the
caller owns it directly; on a shared IRQZ net the unmask is per chip, so
every amp sharing the net needs its own call. Three new ZTests cover the
split (`tests/zephyr/chips/src/test_audio.c:757` ("ZTEST(alp_chips, test_tas2563_arm_fault_irq_rejects_uninitialised)"),
`:767` ("ZTEST(alp_chips, test_tas2563_arm_fault_irq_unmasks_tdm_clock_error)"),
`:791` ("ZTEST(alp_chips, test_tas2563_arm_fault_irq_leaves_irq_n_unbound)")); the
existing `configure_fault_pin` tests are unchanged and still pass.

`examples/aen/aen-evk-demo`'s TAS2563 phase ("Phase 11") is now that
production caller: right after `tas2563_configure_i2s()`, every
initialised amp gets `tas2563_arm_fault_irq(&amps[i], false)`
(`examples/aen/aen-evk-demo/src/main.c:4459` ("alp_status_t arm_rc = tas2563_arm_fault_irq(&amps[i], false);")),
`false` because the 0x4D/0x4E pair share IRQZ on P5_0 behind the R124
external pull-up
(`metadata/boards/e1m-evk.yaml:344` ("R124 a fitted 10 kOhm pull-up")),
with the rc printed per amp. The phase's step-list header comment
(`examples/aen/aen-evk-demo/src/main.c:3721` ("*   6. Arm each amp's fault IRQ -- tas2563_arm_fault_irq() on every"))
gains that step and renumbers every step after it. This is now the only
production caller of either function in the tree.

A new compile-time-gated bench build, `ALP_AEN_EVK_DEMO_PROBE_FAULT_PIN`
(`examples/aen/aen-evk-demo/CMakeLists.txt:27` ("set(ALP_AEN_EVK_DEMO_PROBE_FAULT_PIN OFF CACHE BOOL")),
OFF by default and mirroring `firmware-update-log`'s
`ALP_AEN_UPDATE_LOG_FIREWALL_PROBE` gate, replaces the plain call above
with a seeded read-modify-write discriminator
(`examples/aen/aen-evk-demo/src/main.c:3942` ("static void probe_fault_pin_seeded_rmw(tas2563_t                *amp,")):
`INT_MASK0`'s POR (`FCh`) and the post-arm value (`F8h`) differ only in
bit 2, so a blind write is indistinguishable from a correct RMW unless the
register is seeded first -- seeding to `FFh` makes a correct RMW land on
`FBh` and a blind write land on `F8h`. Seeding is safe because
`tas2563_init()` still has both amps in software shutdown at this point.
The register is then restored to its POR value and re-armed, and the
restore is only trusted once a readback confirms it. Every seed/restore
sub-step is attempted regardless of the previous one's return code, and
the restore always runs even when the seed step itself could not be
verified: this bus has been observed failing open (ACKing every address
and echoing the register address back as read data), so a write can land
even when its own readback says otherwise -- bailing out early would skip
the restore and leave `INT_MASK0` at whatever the seed write left it. An
amp whose restore cannot be verified is excluded both from the stimulus
below and from the (currently unreachable with playback off)
`tas2563_resume()` path
(`examples/aen/aen-evk-demo/src/main.c:4644` ("if (!amp_fault_pin_restore_ok[i]) {")).

When the probe's restore verifies -- and only then, and only once this
amp's own `TAS2563_AMP_LEVEL_MIN` write (phase step 5), I2S configure
(step 6) and the shared `AMP_FAULT` pin's own pinctrl/gpio configure
(step 3) have all also returned success -- the same build runs a
deliberate TDM-clock-fault stimulus
(`examples/aen/aen-evk-demo/src/main.c:4039` ("static void probe_fault_pin_stimulus(tas2563_t                *amp,")):
the inverse of #2146's rule, switching an amp `ACTIVE` with no I2S clock
started at all, on purpose, to prove the unmasked fault reaches both
`tas2563_read_faults()` and the `AMP_FAULT` pin. The pin is polled up to
three times (+10/+50/+200 ms), breaking on the first asserted reading
rather than always waiting out all three delays, and every raw pin read
(idle, poll, after-clear) is routed through the same `amp_fault_pin_verdict()`
helper the rest of the phase uses, so an invalid read (a negative errno,
not 0 or 1) counts as a failure rather than silently comparing false.
If `INT_LTCH3` bit 3 (`DC_DETECT`) latches instead, the stimulus does NOT
call `tas2563_clear_faults()` -- the latch is left standing as evidence --
switches the amp to `SHUTDOWN` (retried once if the first attempt does not
return `ALP_OK`), and sets a phase-wide abort flag: no later amp in the
same run gets the stimulus (its own seeded-RMW probe still runs, since
that half never leaves software shutdown), and the phase fails via
`ctx->note` once teardown and idle-restore have still run unconditionally.
Every `SHUTDOWN` the stimulus issues is now captured and retried once,
never a bare `(void)`, and a `SHUTDOWN` that still does not return
`ALP_OK` after the retry is itself an abort condition. Each amp prints one
greppable summary line,
`"[evkdemo] FAULTPIN amp=0x.. seed=0x.. rmw=0x.. restore=0x.. stim_pin=.. ltch=0x........ verdict=PASS|FAIL"`
(`examples/aen/aen-evk-demo/src/main.c:4449` ("FAULTPIN amp=0x%02x seed=0x%02x rmw=0x%02x restore=0x%02x")),
and the phase's own return value now reflects that verdict: any amp whose
probe or stimulus did not PASS fails the phase, the same as an unarmed
`tas2563_arm_fault_irq()` now fails the phase in the default (non-probe)
build. `PAGE`/`INT_MASK0` are re-declared locally in the demo at their raw
register addresses (SLASET3D §7.5.2 p.65 / §7.5.28 p.77) rather than
exposed as a new driver accessor -- this stays a one-shot bench
discriminator, not a second app-reachable way to poke the chip. A new
`testcase.yaml` scenario
(`examples/aen/aen-evk-demo/testcase.yaml:118` ("alp_sdk.examples.aen.evk_demo.probe_fault_pin.aen:"))
builds the flag ON so a regression in this block does not go unbuilt by
CI, mirroring `firmware-update-log`'s own `..._PROBE` scenario; both
remain `build_only`, since the probe's verdict only means something on
the bench.

**Verification status: needs-silicon -- issue #2182 stays open.** Nothing
above has run on real hardware yet: the ZTests exercise the fake only, and
the bench build has not been flashed to an E1M-EVK, so the seeded-RMW and
TDM-clock-fault readings this fix makes possible are not themselves
measured yet. This fix closes the "no production caller" half of #2182 --
part 1 of the issue -- and nothing else. It does NOT settle part 3 of the
issue: neither the stale #2165 PR-body claim about
`examples/aen/aen-i2s-tas2563-probe` and the register-`0x11` accessor, nor
the contradiction between
`changelog.d/2140.md:16` ("the flag read `0x00000000` both while playing and after")
and the `0x80510004` measurement it describes, is resolved here -- both are left
for the maintainer, as the issue itself asks. Nothing above should be read
as closing #2182.

Separately, #2182's bench notes also ask this fix to enforce "digital
volume <= 128" as a speaker-safety guard. That cannot be done from inside
the driver -- there is no digital-volume accessor on `tas2563_t`, only the
demo's own `alp_audio_out_set_volume()` on the I2S side -- and it is moot
here regardless: the TDM-clock-fault stimulus above never starts I2S or
queues any audio data, so no digital volume is ever in play during it. The
lever this stimulus does depend on is `TAS2563_AMP_LEVEL_MIN` (phase step
5), the amp's own analog-gain floor -- set on every initialised amp AFTER
`tas2563_init()` (step 4) parks it in software shutdown, and now checked
per amp (`amp_level_min_ok[i]`) before the stimulus is allowed to run on
that amp at all, rather than assumed.
