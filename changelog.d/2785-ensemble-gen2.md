### Fixed — E8/E4 builds compile hal_alif's gen2 code (#2785)

**`CONFIG_ENSEMBLE_GEN2` is now set for `SOC_SERIES_E8` and `SOC_SERIES_E4`.** hal_alif selects its gen2 aiPM memory-block layout (`se_services/include/aipm.h`) and its gen2 OSPI XIP-write and AES signal-delay helpers on that symbol. Upstream Zephyr's `soc/alif` never declares it, so every AEN build compiled the gen1 code, in which `BACKUP4K_MASK` is bit20 (FWRAM on gen2). `zephyr/kconfigs/vendor-alif-peripherals.kconfig` now declares it the way Alif's own Zephyr fork does, and `alif_se_power.c` fails the build if an E8/E4 build loses it or hal_alif's masks stop matching `alif_aipm_gen2.h`. Silicon, E1M-AEN803 (tan Flow C RAM-run, 2026-11-08): `aen-ospi-regcheck` with its NOR program/erase self-test and `aen-power-smoke` pass, with the same results as on dev.
