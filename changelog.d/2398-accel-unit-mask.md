### Added — `alp_inference_config_t::accel_unit_mask` picks the accelerator unit(s) of a backend; the SDK refuses a 4th distinct DX-M1 core set (#2398)

**Not bench-verified.** `alp_inference_config_t` (`<alp/inference.h>`) gains `uint32_t accel_unit_mask` at the END of the struct, marked `[ABI-EXPERIMENTAL]` at field level. `0` is the backend default; bit `n` is accelerator unit `n` of the backend the open resolves to; a mask the backend cannot honour makes `alp_inference_open()` return `NULL` with `ALP_ERR_NOSUPPORT`. `ALP_INFERENCE_CONFIG_DEFAULT()` sets it to `0`, and zero-initialised configs keep their old behaviour.

- **Shared-library users: `sizeof(alp_inference_config_t)` grows: 24 to 28 bytes on a 32-bit target, 40 to 48 on LP64 (4-byte field plus tail padding).** Rebuild anything compiled against the old header and linked against a `libalp_sdk` shared object; a caller built against the old struct would let the library read past its config. Static links rebuild with the SDK and are unaffected.
- **Per backend:** DEEPX DX-M1 bits `0..2` are NPU cores `0..2`, any non-empty subset (`0` and `0x7` both mean all three cores). DRP-AI3 is one unit, so only `0` or `0x1`. Arm Ethos-U (Alif) is the NPU instance visible to the calling core, bit `0` only on single-NPU cores (unverified for multi-NPU parts). TFLM, ONNX Runtime and the CPU backends accept only `0`. Rejection is `ALP_ERR_NOSUPPORT` everywhere.
- **The mask is mapped to libdxrt's bound option inside `src/yocto/inference_deepx.cpp`;** libdxrt's numbering appears in no public header.
- **The real DX-M1 limit is 3 distinct core sets per DX-M1 at a time** (kernel driver `DX_NORMAL_QUEUE_MAX = 3`; all three cores counts as a set; same-set engines share a queue), not "every process must use the same core set". A 4th set makes dx-rt abort the process or kill `dxrtd`. A 4th distinct set inside one process now returns `ALP_ERR_BUSY` from `alp_inference_open()` / `alp_deepx_inference_bind_cores()` instead of reaching dx-rt's assert. Across processes nothing guards it. The `<alp/ext/deepx/inference.h>` warning, `docs/soms/v2n-m1.md` and the `dx-rt_%.bbappend` comment say so.
- **`alp_deepx_inference_bind_cores(inf, mask)` now takes the same mask** instead of an enum. It builds the new engine before deleting the old one, so it briefly holds both sets; prefer setting `accel_unit_mask` at open.
- The Yocto inference handle pool (`ALP_SDK_MAX_INFERENCE_HANDLES`) defaults to 4 instead of 2 and is configurable with the `ALP_SDK_MAX_INFERENCE_HANDLES` CMake cache variable.
- `examples/v2n/v2n-two-models` uses only `<alp/inference.h>` and sets `accel_unit_mask`.
- Documented: `libdxrt` installs `SIGSEGV`/`SIGBUS`/`SIGABRT` handlers that `exit(1)`, which affects every SDK app on V2M.
