### Added — opt-in KleidiAI execution provider for the ONNX Runtime recipe (#1258)

`meta-alp-sdk`'s `onnxruntime_1.28.0.bb` gains `PACKAGECONFIG[kleidiai]`, which
maps to `-Donnxruntime_USE_KLEIDIAI=ON` and points ORT's `FetchContent` at a
KleidiAI `v1.20.0` archive staged in `SRC_URI` (the tag ORT's own `cmake/deps.txt`
pins, sha1 identical), so the build stays offline. Enable it with
`PACKAGECONFIG:append:pn-onnxruntime = " kleidiai"`; ORT itself turns the option
off with a warning on a non-aarch64 target.

The knob is **off by default**. The issue asks for a measured win, and no
before/after on real `E1M-V2N101` silicon exists yet, so shipping it on would
put an unmeasured perf claim in every image. Nothing here is a build claim: the
change is recipe-only and awaits a `bitbake onnxruntime` pass with the knob on.
