### Documented — the customer onramp's last stale tan-cli version pin, re-verified against the shipped Python `tan` (#1191)

#1191 tracked the Rust-era Quickstart being unexecutable against Python `tan`.
Most of that surface was already fixed by earlier, unrelated PRs by the time
this landed: `README.md`, `AGENTS.md`, `llms.txt`, `pyproject.toml`,
`metadata/bootstrap.json`, `metadata/schemas/bootstrap-v1.schema.json`,
`metadata/schemas/build-plan-v1.schema.json` and `scripts/alp_cli/doctor.py`
(the last one retired outright) no longer mention `--non-interactive` as
unsupported, `tan sdk switch`, Rust/`cargo install`/`rustup`, or a `doctor
--build` check-set distinction — all re-measured here against a real,
installed `tan 0.6.0` (`pip install ./python` from the `alplabai/tan-cli`
`v0.6.0` tag into a clean Python 3.12 venv), not inferred from source or an
older doc:

- `tan init --name my-app --sdk-root <sdk> --non-interactive` → `rc=0`,
  scaffolds the project (the flag is accepted and dropped, not declared).
- `tan sdk switch some-version` → `rc=1`, `sdk.not-ported`, directs the
  caller to `--sdk-root`.
- `tan validate --sdk-root <sdk>` (no `--offline`) → `validate: ./board.yaml
  is clean`, `rc=0`.
- `tan doctor` vs `tan doctor --build` against the same project → both report
  the identical 14 checks (11 passed, 2 warning, 1 failed).
- `tan emit zephyr-conf` → `No such command 'emit'` (`rc=2`); `tan generate
  --target zephyr-conf` is the real front door and wrote its target.

What was still stale: `docs/cli.md`, `docs/getting-started.md`,
`docs/firmware-quickstart.md`, and `docs/cross-platform-setup.md` each named
`v0.5.1` as tan-cli's "current release" and described the interactive
`doctor --fix` sudo-elevation behaviour as landing in a future `v0.6.0-rc1+` —
tan-cli tagged `v0.6.0` on 2026-08-24 (which also removed `tan renode` and
its 27 `renode.*` issue codes, and raised its own alp-sdk floor to `v0.16.0`,
matching this repo's `pyproject.toml` version). All four now cite
[`v0.6.0`](https://github.com/alplabai/tan-cli/releases/tag/v0.6.0) as
current, and the `--fix` paragraphs read "as of tan v0.6.0" rather than a
still-pending `dev`-ahead-of-release framing — re-verified live: `tan doctor
--fix` outside a TTY prints `warning: --fix was requested but not run: no
interactive terminal`, matching the documented behaviour exactly.

Not attempted here: a real hardware build/flash artifact and a CI job
running this onramp end to end (issue #1191's last two checklist items) —
out of scope for a documentation-only pass; tracked for a follow-up.
