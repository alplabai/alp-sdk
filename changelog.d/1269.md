### Fixed — `examples/peripheral-io/i2c-master` opened `BOARD_I2C_SENSORS` and expected TMP112, which isn't on that bus (#1269)

The example pinned `E1M_I2C0`/`E1M_X_I2C0` (`BOARD_I2C_SENSORS`) in `board.yaml` and probed for a
TMP112 at 0x48 in `src/main.c`. TMP112 is populated on every AEN/V2N/V2N-M1 SoM per
`metadata/chips/tmp112.yaml`, but on `BRD_I2C`, not on `BOARD_I2C_SENSORS` — neither
`metadata/boards/e1m-evk.yaml` nor `metadata/boards/e1m-x-evk.yaml` lists a TMP112 in the
`i2c_devices:` block for the sensor bus this example opens. A customer running the example on
real E1M/E1M-X EVK hardware got an I2C NACK, never a temperature reading.

Repointing the bus instead of the chip was not an option that works for both boards this example
claims to support: `BRD_I2C` is a different physical controller from `BOARD_I2C_SENSORS` on both
families regardless (on the E1M-AEN family it is SoC I2C0, function C — see #1848), and no example
wired a portable `alp_i2c` bus to it at the time, so there was no portable master path to a TMP112
there yet.

The example now reads the BMP581 barometer instead, which *is* populated on `BOARD_I2C_SENSORS`
at 0x47 on both the E1M EVK (U14) and the E1M-X EVK, per each board's `i2c_devices:` metadata —
keeping the example a working demonstration on every board it claims to support.
`examples/v2n/v2n-temp-sensor` remains the correct, V2N-only pattern for reading TMP112 over
`BRD_I2C`.
