### Fixed — `alp_ble_close()` orphaned connection back-pointers (#1697)

`alp_ble_connect()` stores a raw back-pointer into the conn slot (`c->state.radio = h`),
but `alp_ble_close()`'s only teardown call was `_free_radio(h)` — it never walked
`_conn_pool`. Any still-claimed connection therefore outlived the radio it points at, and
the next `_alloc_radio()` was free to recycle that slot underneath it. Reachable on the
shipping Zephyr backend with a plain open → connect → close → reopen; no partial vendor
port required.

`close()` now force-disconnects its own radio's connections before the controller goes
away. **This was the design decision the issue flagged for a maintainer**: the alternative
was refusing the close while links are live, but every other `alp_*_close()` in the tree
returns `void`, so there is no channel to report a refusal and diverging here would be an
API change. Consistency won; a caller that wants to keep a peer link must not close its
radio.

The sweep calls `alp_ble_disconnect()` rather than open-coding the teardown, so it inherits
the existing #629 sleep-poll drain, the backend disconnect, the lifecycle reset and
`_free_conn()` — and its `ALP_ERR_NOT_READY` on a lost CAS already handles another thread
tearing the same conn down. Ordering is after the radio's own drain (no new connect can be
admitted past it) and before `ops->close()` (the backend disconnect needs a live
controller). The #1118 refcount work and the #629/#756 self-close drain are untouched.

Adds `alp_slot_is_claimed()` — the acquire-load counterpart to `alp_slot_try_claim()` —
documented as safe for *sweeping* a pool but never for gating a claim.
