### Changed — `soc-spec-v1`: an `ethos-u*` NPU entry must declare `mac_per_cycle` (#1849)

`$defs/npu` required only `type` plus `anyOf(gops, tops)`, so

```json
{ "type": "ethos-u55", "gops": 100 }
```

validated cleanly while carrying nothing to build the vela
`--accelerator-config` string (`<type>-<mac_per_cycle>`, e.g. `ethos-u55-256`)
from. Schema validation on a consumer's read path cannot catch this, because
the document already passes the schema — the gap was in the schema itself.

The issue framed this as a downstream tan-cli concern that degrades to a
silent skip. **In this repo it is worse than that, and in three different
ways**, which is the argument for fixing it here rather than adding a fourth
guard:

- `scripts/alp_model/targets.py:47` raises `KeyError`, deliberately —
  `scripts/alp_model/targets.py:44-46`
  ("it must never be silently masked into a") chose a crash over emitting
  the truncated `ethos-u55-`.
- `scripts/alp_orchestrate/kconfig.py:1175`
  (`n.get("mac_per_cycle")`) filters the incomplete entry out, which makes it
  indistinguishable from an absent `npus[]` block, and
  `scripts/alp_orchestrate/kconfig.py:1206`
  (`mac = macs[0] if macs else 256`) then defaults to **256**. On a part whose
  U55 is really 128-MAC that emits `CONFIG_ETHOS_U55_256=y` — a legal
  `ETHOS_U_NPU_CONFIG` member, so neither the `_valid_accel` guard nor
  anything downstream refuses it, and a 256-MAC command stream errors a
  128-MAC NPU at invoke (the #909 mis-size the surrounding code goes to some
  length to avoid).
- tan-cli skips the NPU entirely (its own `isinstance` guard, tan-cli#965).

Crash, silent mis-size, silent skip. None of the three is wrong on its own;
what was wrong is that the document was accepted at all. `$defs/npu` now
carries an `if`/`then` (`metadata/schemas/soc-spec-v1.schema.json:351-359`)
that refuses an `ethos-u*` entry without `mac_per_cycle` at authoring time,
where there is exactly one answer. The consumer-side guards stay: schema
validation and a downstream guard are complementary, not substitutes.

The requirement is **conditional** on purpose. `drp-ai` and `deepx-dx-m1` are
not compiled through vela and legitimately carry no `mac_per_cycle`; an
unconditional `required` would refuse two committed documents. The `if` also
carries its own `required: ["type"]`, without which it would match *vacuously*
on an entry that has no `type` at all and refuse it for the wrong field.

**Zero metadata churn**, verified rather than asserted: all 16 `ethos-u*`
entries across the nine `metadata/socs/**/*.json` documents (Alif Ensemble
e3–e8, i.MX 93) already declare `mac_per_cycle`, and the only two entries in
the tree that omit it are the two non-Ethos ones.

`tests/scripts/test_soc_spec_npu_mac_per_cycle.py` is mutation-proven in both
directions, because a conditional rule can ship broken two ways: deleting the
`if`/`then` fails the three refusal cases (u85/u55/u65, parametrised because
the rule keys on the `^ethos-u` prefix rather than an enumerated list), and
replacing it with an unconditional `required` fails a *different* three — the
two non-Ethos documents plus the zero-churn sweep.

Schema, tests and changelog only; no metadata, script or code change.
