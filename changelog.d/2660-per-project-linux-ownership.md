### Added — per-project Linux core-ownership fragment (#2660)

`alp_project.py --emit linux-ownership-dts` renders the Linux devicetree fragment (node `status` of the assignable instances plus the CPG `renesas,cm33-owned-clocks` hold) from a project's resolved `ownership:`, using the same renderer as the committed SoM-default `e1m-v2n-ownership.dtsi` (`scripts/alp_orchestrate/linux_ownership.py`, shared with `scripts/gen_linux_ownership_dt.py`). An instance owned by the M33 is now explicitly `status = "disabled"` for Linux (the default fragment is unchanged: every instance is `a55`). The linux-renesas bbappend gains `ALP_LINUX_OWNERSHIP_DTSI`: when set it installs that file over the default fragment and label-checks it with `gen_linux_ownership_dt.py --fragment` against `r9a09g056.dtsi`. `resolve_ownership` no longer rejects a non-default `board.yaml` override outright: it is accepted when the instance lists `m33` in `candidates` and carries an `m33:` block (so the CM33 overlay and the Linux fragment can both follow), still refuses `hw_blocked` instances, and refuses handing a node to `a55` without `linux_enable`. `check_amp_pad_claims.py --project <board.yaml>` checks the project's Linux fragment against the pads its resolved ownership gives the CM33. No instance lists `m33` as a candidate yet, so no shipped project changes; the per-project path is covered by tests and is not bench-verified.
