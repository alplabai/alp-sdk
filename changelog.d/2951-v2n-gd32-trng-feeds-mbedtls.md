### Fixed — the GD32 supervisor TRNG now feeds mbedTLS on V2N/V2M CM33 Zephyr builds (#2951)

**`CONFIG_ALP_SDK_SECURITY_V2N_TRNG_ENTROPY=y` now builds a Zephyr entropy driver (`alp,gd32-trng`, `zephyr/drivers/entropy/entropy_alp_gd32_trng.c`) that the V2N/V2M CM33 boards choose as `zephyr,entropy`.** Zephyr 4.4.1's mbedTLS (TF-PSA-Crypto) reads that chosen device through `mbedtls_platform_get_entropy()` and never calls `mbedtls_hardware_poll()`, so the previous poll function in `src/backends/security/zephyr_drv.c` was dead code and is removed. The PSA RNG now draws from the GD32 TRNG, `CONFIG_CSPRNG_ENABLED` is y, and the weak-RNG build refusal passes without `CONFIG_ALP_SDK_ALLOW_TEST_ENTROPY`. The board `.dts` files are regenerated from `scripts/gen_zephyr_board.py`; a host test covers the chunking policy.
