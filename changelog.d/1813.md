### Changed — `<alp/power.h>` mode ladder, retention, and wake-source contract settled while still `[ABI-EXPERIMENTAL]` (#1813)

`<alp/power.h>` could not express what the Alif Ensemble E8 actually offers,
and it is `[ABI-EXPERIMENTAL]` precisely so this can be fixed before an AEN
power backend freezes against it (`docs/abi-markers.md` confirmed before
touching the header — no ABI-snapshot major-bump gate applies pre-1.0 to an
experimental symbol).

- **`ALP_POWER_MODE_STOP`** — a fifth rung on `alp_power_mode_t`, below
  `STANDBY`. The E8's STOP ladder (datasheet Table 5-5) runs from a 900 nA
  floor up depending on what is retained; the SDK had no way to name it.
- **`alp_power_configure_retention()` + `alp_power_retain_t`** — a portable
  retention descriptor (`ALP_POWER_RETAIN_NONE` / `_UTILITY` / `_TCM` with a
  `retain_kb` field / `_FULL`), not a raw vendor bitmask, mapping onto
  `SERVICES_power_mem_retention_config`'s bitmask on a real E8 backend.
  Optional on the backend vtable (`alp_power_ops_t::configure_retention` may
  be `NULL`): a backend with no opinion accepts `ALP_POWER_RETAIN_NONE` as a
  no-op and returns `ALP_ERR_NOSUPPORT` for anything else, rather than
  silently ignoring the request.
- **`ALP_POWER_WAKE_COMPARATOR` / `ALP_POWER_WAKE_BROWNOUT`** — two wake
  bits with no earlier portable equivalent (the E8 LPCMP analog threshold
  wake and brown-out detect).
- **Reported-capability + error contract for wake sources.** `<alp/power.h>`
  previously documented "unsupported bits are silently ignored" on the
  `ALP_POWER_WAKE_*` bitmap, directly contradicting `alp_power_configure_wake_source()`'s
  own already-documented `ALP_ERR_NOSUPPORT` return. That contradiction is
  resolved in the backend's favour of the honest one:
  `alp_power_capabilities()->flags` now documents, per power class, exactly
  the `ALP_POWER_WAKE_*` bits the active backend can arm, and
  `alp_power_configure_wake_source()` rejects a bitmap containing any bit
  outside that set with `ALP_ERR_NOSUPPORT` — see #1812, which needed
  exactly this on the AEN-default `zephyr_stub` backend.

**Scope note**: this change settles the header shape and the AEN-default
`zephyr_stub` backend's honesty about it (#1812). It does **not** touch
`src/backends/power/zephyr_pm_policy.c`, `yocto_drv.c`, or
`src/backends/ext/renesas/power.c` — those backends' existing
`ALP_OK`-regardless-of-bitmap behaviour for `configure_wake_source()` is
unchanged, each for its own platform reasons (e.g. Yocto's sysfs sleep ABI
has no per-source enable knob at all; the bitmap there is already
informational). Bringing every backend's `alp_power_capabilities()` up to
the new contract precisely is tracked as follow-on work, not bundled into an
AEN-scoped change. Wiring the register-level VBAT `WKUP_CTRL` /
`SERVICES_power_wakeup_config` mapping for a real E8 STOP entry is likewise
deferred to the `alif_aipm` backend #1812 tracks — this issue is the shape,
not the silicon.

`SERVICES_power_wakeup_config` and friends assume no SE I2C/generic
peripheral-access service exists in the pinned `hal_alif` (confirmed: zero
`"i2c"` hits in `se_service.h`, `services_lib_ids.h`, and
`AUGD0014-SE-Host-Services-API-v1.109.0`), so the wake-source design here
does not route an analog comparator or brown-out arm through an I2C-shaped
SE round-trip that does not exist.
