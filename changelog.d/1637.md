### Fixed — one subsystem's `alp_wdt_close()` silently removed another subsystem's watchdog protection (#1637)

`alp_wdt_open()` validated `timeout_ms` and picked a backend but never compared
`cfg->wdt_id` against a live handle, so two subsystems could each open
`ALP_E1M_WDT0` and both believe they were protected. They were not: the backend
close path disables the whole watchdog **device**, not the handle's channel —
`src/backends/wdt/zephyr_drv.c`'s `z_close()` calls `wdt_disable(dev)` and casts
the result to `(void)` — so the first close disarmed the second owner's
deadline. No error surfaced on any path, in either caller's return value or
`alp_last_error()`. A device that believes it is watchdog-protected and is not
is worse than one with no watchdog at all, because nobody is looking.

A watchdog instance is now **exclusive**. The dispatcher's handle pool is
indexed by `wdt_id` rather than being a free list, which makes the existing
atomic slot claim (`alp_slot_try_claim`, #1115) *be* the exclusivity check: one
compare-exchange, no scan of the pool, and no TOCTOU window between "is this
instance taken?" and "take it". A second `alp_wdt_open()` on a live `wdt_id`
returns NULL with `ALP_ERR_BUSY` until the owner calls `alp_wdt_close()`, after
which the instance is claimable again.

Two consequences worth knowing:

- `cfg->wdt_id` is now bounded by the dispatcher (`ALP_ERR_INVAL` above the
  portable instance count) instead of only by whichever backend was selected.
  `src/backends/wdt/yocto_drv.c` previously passed any id straight into
  `/dev/watchdog%u`. The portable ID space is exactly `{0, 1}` —
  `ALP_E1M_WDT0..1` / `ALP_E1M_X_WDT0..1` are `0u` and `1u`.
- Two subsystems that both need a deadline must use two instances or share one
  handle. `include/alp/wdt.h` documents the rule on `alp_wdt_open()`.

Regression test: `tests/unit/wdt_exclusivity/`. It deliberately builds with
`CONFIG_WATCHDOG=n` so the `sw_fallback` backend is selected and
`alp_wdt_open()` actually succeeds under `native_sim` — with `CONFIG_WATCHDOG=y`
the priority-100 `zephyr_drv` wins selection, finds a NULL device (`native_sim`
has no `alp-wdt0` DT alias) and fails every open, so the test could only skip
and would prove nothing. The rule under test is pure dispatcher code, so
exercising it over `sw_fallback` is faithful.
