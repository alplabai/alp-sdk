### Fixed — `scripts/bench/aen/bench-env.sh`'s `AEN_BOARD` default still targeted the AEN801 tree with every bench module now an AEN803 (#2094)

`scripts/bench/aen/bench-env.sh:128` ("export AEN_BOARD") defaulted to
`alp_e1m_aen801_m55_he/ae822fa0e5597ls0/rtss_he`, and
`scripts/bench/aen/build.sh:44` ("BOARD=") uses it
unconditionally. Every module on the AEN bench is an E1M-AEN803 (module
serial `2026W36-0002` on `e1m-aen-evk-03`, EEPROM-confirmed), and #2103
generated its board tree (`zephyr/boards/alp/e1m_aen803_m55_he/`,
`zephyr/boards/alp/e1m_aen803_m55_hp/`), so a default (no-override) bench
build still silently targeted the wrong board tree even after #2084 made
the AEN803 tree buildable at all.

A bare repoint is not safe on its own: `boards/` overlays and conf
fragments auto-apply only on a match of the FULL qualified stem or the
SHORT stem (Zephyr's zephyr_file(CONF_FILES ...) CMake helper tries both),
and `build.sh` never forces `EXTRA_DTC_OVERLAY_FILE`/`EXTRA_CONF_FILE`.
Nearly all `examples/aen/*` ship only an
AEN801-qualified overlay (#2101) — flipping the default alone would trade
one wrong default for a silent, unannounced AEN801-shaped build across
every one of them.

`bench-env.sh`'s `AEN_BOARD` default is now
`alp_e1m_aen803_m55_he/ae822fa0e5597ls0/rtss_he`. `build.sh` gained a preflight at `scripts/bench/aen/build.sh:61` ("Refuse rather than silently drop an overlay/conf fragment") that computes the resolved board's FULL
and SHORT overlay filename stems and
REFUSES to build (exit 3) whenever the target app's `boards/` ships one or
more qualified `.overlay` or `.conf` files but none of that kind matches
either stem — checked as independent pools, since Zephyr applies each kind
separately and a matching overlay does not excuse a mismatched conf
fragment (or vice versa) — naming every file it found and how to fix it
(override `AEN_BOARD`, or add the missing `boards/<stem>.<ext>`). An app
with no qualified `boards/` file at all (nothing to silently drop) builds
as before, and the preflight is skipped outright when the caller's own
`-DDTC_OVERLAY_FILE=...`/`-DAPPLICATION_CONFIG_DIR=...` already forces the
selection explicitly.

This mirrors (rather than reimplements) the full/short-stem logic in
`scripts/check_example_board_overlay_parity.py`'s
`_qualified_target_to_stems()` (`dev`, #2120) — an earlier version of this
fix computed only the full stem and false-refused a real, Zephyr-valid
short-form overlay like `alp_e1m_aen803_m55_he_rtss_he.overlay`.

`scripts/bench/aen/README.md`'s `AEN_BOARD` row and quick-start example
document the new default and the refusal behaviour.

Tests: `tests/scripts/test_bench_build_overlay_guard.py` (new) covers the
refusal, the full- and short-stem matches, the no-qualified-file and
explicit-`AEN_BOARD`-override passes, the `.overlay`/`.conf` independent-
pool cases in both directions, a non-overlay/conf file being ignored, and
the `-DDTC_OVERLAY_FILE=`/`-DAPPLICATION_CONFIG_DIR=` skip.
