### Fixed — `scripts/bench/aen/bench-env.sh`'s `AEN_BOARD` default still targeted the AEN801 tree with every bench module now an AEN803 (#2094)

`bench-env.sh:105` (`export AEN_BOARD`) defaulted to
`alp_e1m_aen801_m55_he/ae822fa0e5597ls0/rtss_he`, and `build.sh:36`
(`BOARD="$AEN_BOARD"`) uses it unconditionally. Every module on the AEN
bench is an E1M-AEN803 (module serial `2026W36-0002` on `e1m-aen-evk-03`,
EEPROM-confirmed), and #2103 generated its board tree
(`zephyr/boards/alp/e1m_aen803_m55_he/`,
`zephyr/boards/alp/e1m_aen803_m55_hp/`), so a default (no-override) bench
build still silently targeted the wrong board tree even after #2084 made
the AEN803 tree buildable at all.

A bare repoint is not safe on its own: `boards/` overlays auto-apply only
on an exact fully-qualified board-name match, and `build.sh` never forces
`EXTRA_DTC_OVERLAY_FILE`. Nearly all `examples/aen/*` ship only an
AEN801-qualified overlay (#2101) — flipping the default alone would trade
one wrong default for a silent, unannounced AEN801-shaped build across
every one of them.

`bench-env.sh`'s `AEN_BOARD` default is now
`alp_e1m_aen803_m55_he/ae822fa0e5597ls0/rtss_he`. `build.sh` gained a
preflight (`scripts/bench/aen/build.sh:44`) that computes the resolved
board's overlay filename stem (`$AEN_BOARD` with every `/` replaced by
`_`) and REFUSES to build (exit 3) whenever the target app's `boards/`
ships one or more `alp_e1m_*`-qualified files but none of them stem-match
— naming every file it found and how to fix it (override `AEN_BOARD`, or
add the missing `boards/<stem>.overlay`) — rather than silently producing
an AEN801-shaped image for an operator who asked for the AEN803 target.
An app with no qualified `boards/` overlay at all (nothing to silently
drop) builds as before.

`scripts/bench/aen/README.md`'s `AEN_BOARD` row documents the new default
and the refusal behaviour.
