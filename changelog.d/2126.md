### Added — auto-recover a wedged CC3501E bridge link (#2126)

Before, a bridge wedge (observed ~3 times per 50 Wi-Fi connects on
an AEN EVK bench unit) left every request failing (`ver` → `-4`/`-5`) until the
whole board was power-cycled — the host-side warm-reset fix
(`cc3501e_recover()`) existed but nothing called it automatically.

Now `cc3501e_link_check_and_recover()` is wired into the driver's own
worker-routed failure exits and into `cc3501e_wifi_connect()`'s timeout
exit: when a top-level op exhausts every attempt with no status ever
decoded off the wire (a genuinely busy bridge that answers late no longer
false-triggers), it probes with `PING` for up to 12 s and, only if every
probe fails, warm-resets and re-confirms the link — guarded against an
open OTA/update session (tracked by an explicit per-link flag, not the
transport's peer-polled bit), an attempt-based cooldown with exponential
back-off (30 s doubling to 5 min on repeated failure, reset on success),
and `CONFIG_ALP_SDK_CC3501E_AUTO_RECOVER` (default `y`, genuinely
Kconfig-gated off — not just defaulted — when disabled). `alp companion
recover` shares the same guarded path for manual use instead of bypassing
it.

The whole reset-through-reconfirm sequence now holds the link's request
lock so no concurrent request desyncs the CS-less wire mid-reset, and only
one recovery runs at a time. A successful recovery bumps the link's epoch;
any socket handle opened before that epoch fails closed
(`ALP_ERR_NOT_READY`) instead of silently addressing a socket that no
longer exists on the other side of the reset. Subscribe to
`cc3501e_set_recover_callback()` for recovery notifications.

Measurement and post-mortem apps keep the old behaviour on purpose:
`aen-cc3501e-wedge-postmortem`, `aen-cc3501e-command-sweep` and
`aen-cc3501e-silent-scan-probe` set `CONFIG_ALP_SDK_CC3501E_AUTO_RECOVER=n`,
because a reset mid-capture destroys the evidence they exist to record.

**Breaking:** socket handles now carry the link epoch in their upper byte,
so a handle is no longer the firmware's small integer — print it as
`0x%04x`, and mask with `& 0xFF` before comparing against a firmware-side
number. A handle minted before a recovery now returns `ALP_ERR_NOT_READY`
from every socket op instead of addressing whichever socket now holds that
number. `cc3501e_sock_accepted_decode()` takes the owning link's epoch as a
new parameter, so callers decoding an accepted-socket event must pass it.
A failing op can also now take longer than its own `timeout_ms`: the
probe-and-reset sequence adds up to ~12-18 s of probing plus ~3.5 s of
reset before the call returns.
