### Added — grade changelog citations on the merge queue's own base, in a small dedicated job (#2206)

`scripts/check_changelog_citations.py` already grades a PR's merge commit on
`pull_request` -- `pr-metadata-validate.yml`'s `validate` job checks out
`refs/pull/N/merge` with no `ref:` pinned, and #2186's new-citation rule keys
off `DIFF_BASE` there. That workflow carries no `merge_group:` trigger at all,
unlike `pr-twister.yml`, `pr-static-analysis.yml`, and
`cross-platform-zephyr.yml`. So a citation `dev` breaks by moving between a
PR's last push and the merge queue landing the entry is never graded before it
lands -- it only turns the gate red on the *next*, unrelated PR, the #2122
treadmill.

A new `merge-queue-changelog-citations.yml` closes that gap without putting
the whole ~18-minute `pr-metadata-validate.yml` job on every queue entry: its
only job runs `check_changelog_citations.py --verbose` and nothing else. Its
primary trigger is `merge_group:`, matching the three files above, each of
which already carries one:
`.github/workflows/pr-twister.yml:28` ("merge_group:"),
`.github/workflows/pr-static-analysis.yml:49` ("merge_group:"), and
`.github/workflows/cross-platform-zephyr.yml:192` ("merge_group:"). The
`${{ github.workflow }}-${{ github.ref }}` concurrency group is theirs too;
`cancel-in-progress: true` is inert on a merge_group run, where `github.ref`
is the unique `refs/heads/gh-readonly-queue/dev/pr-N-<sha>` and so never
collides across entries.

It also carries a `pull_request:` trigger **path-filtered to itself**, and a
`workflow_dispatch:` with an optional `diff_base` input. Neither is
decoration. Without the path-filtered `pull_request` leg the workflow would
get no validation at all before landing -- its first real execution would be
its own PR's queue entry, where, being deliberately not a required context, a
broken job would block nothing and notify nobody. And without `diff_base` a
manual dispatch could not exercise the rule this gate exists for: `DIFF_BASE`
would be empty, `_resolve_base()` treats empty exactly like unset and falls
back to `origin/dev`, and dispatched on `dev` that makes
`merge-base(origin/dev, HEAD)` equal to `HEAD` -- zero added lines, so the
new-citation rule passes vacuously.

`DIFF_BASE` is set from
`github.event.merge_group.base_sha || inputs.diff_base` -- the merge queue's
own base on the primary trigger, the operator's input on a manual dispatch --
not `HEAD^1` (this checkout's first parent can be a *previous* queue entry
stacked ahead of this one, not `dev` itself), and not the `origin/dev`
default. The reason for rejecting `origin/dev` is **not** that a merge-queue
checkout lacks that ref: under `fetch-depth: 0` `actions/checkout` uses its
all-history refspec (`+refs/heads/*:refs/remotes/origin/*`), so
`refs/remotes/origin/dev` does exist in this job. That "no such ref"
reasoning holds only for a *shallow* checkout. The real reason is
freshness -- `origin/dev` is fetched at job time, so if `dev` moved after the
entry was enqueued it is *ahead* of the base the entry is landing on, and the
gate would grade against a tree that is not the merge result. `base_sha`
cannot drift under the run.

The script resolves `DIFF_BASE` with `git rev-parse --verify
DIFF_BASE^{commit}` in `_resolve_base()` and diffs new lines with `git
merge-base DIFF_BASE HEAD` in `_added_lines()`; both accept a raw SHA exactly
as well as a symbolic ref, so `base_sha` resolves with no local branch
pointing at it. Those two are named by function rather than by `path:line` on
purpose: `check_changelog_citations.py` sits outside the set this gate
grades, so a line citation into it would drift silently -- the exact failure
class #2206 closes.

`fetch-depth: 0` is required rather than merely generous: `git merge-base`
over a grafted shallow history can miss or misresolve the common ancestor,
and `base_sha` -- `dev`'s own tip at enqueue time -- has to be a resolvable
ancestor of HEAD for the new-citation rule to run at all rather than warn
that it did not.

`tests/scripts/test_merge_group_changelog_citations_workflow.py` structurally
pins the workflow: the trigger set is exactly `merge_group` +
`pull_request` (path-filtered to the workflow's own file) +
`workflow_dispatch` (carrying `diff_base`); the single job stays named
`changelog citations · merge queue` with no `if:`; `fetch-depth: 0` and
`persist-credentials: false` stay set; `DIFF_BASE` stays
`github.event.merge_group.base_sha || inputs.diff_base`; and
`pr-metadata-validate.yml` keeps carrying no `merge_group:` trigger of its
own.

`docs/ci/README.md`'s workflow table gains a row for
`merge-queue-changelog-citations.yml`, keeping its workflow count (25) and
its table in sync.

Not a required context: promoting `changelog citations · merge queue` is a
branch-protection/ruleset edit on GitHub's side, out of scope here (see
#2206). Recommend requiring it once it has run clean for a cycle -- until
then it carries the same weakness that let #2201 merge with a red,
non-required `python-smoke` leg: the queue does not wait for it.
