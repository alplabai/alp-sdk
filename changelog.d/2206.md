### Added — grade changelog citations on the merge queue's own base, in a small dedicated job (#2206)

`scripts/check_changelog_citations.py` already grades a PR's merge commit on
`pull_request` -- `pr-metadata-validate.yml`'s `validate` job checks out
`refs/pull/N/merge` with no `ref:` pinned, and #2186's new-citation rule keys
off `DIFF_BASE` there. That workflow carries no `merge_group:` trigger at all,
unlike `pr-twister.yml`, `pr-static-analysis.yml`, and
`cross-platform-zephyr.yml`. So a citation `dev` breaks by moving between a
PR's last push and the merge queue landing the entry is never graded before it
lands -- it only turns the gate red on the *next*, unrelated PR, the #2122
treadmill.

A new `merge-queue-changelog-citations.yml` closes that gap without putting
the whole ~18-minute `pr-metadata-validate.yml` job on every queue entry: its
only job runs `check_changelog_citations.py` and nothing else. It triggers on
`merge_group:` and `workflow_dispatch:` only -- not `pull_request`/`push`,
already covered by `pr-metadata-validate.yml` -- and its `on:`/concurrency
shape is copied from the three merge_group-triggered files above, each of
which already pairs a `merge_group:` trigger with the same
`${{ github.workflow }}-${{ github.ref }}` concurrency group:
`.github/workflows/pr-twister.yml:28` ("merge_group:"),
`.github/workflows/pr-static-analysis.yml:49` ("merge_group:"), and
`.github/workflows/cross-platform-zephyr.yml:195` ("merge_group:"). It adds no
`permissions:` block either, matching those three -- the job only reads the
checkout.

`DIFF_BASE` is set from `github.event.merge_group.base_sha`, the merge queue's
own base, at
`.github/workflows/merge-queue-changelog-citations.yml:89`
("DIFF_BASE: ${{ github.event.merge_group.base_sha }}") -- not `HEAD^1`
(this checkout's first parent can be a *previous* queue entry stacked ahead of
this one, not `dev` itself), and not the `origin/dev` default (a merge-queue
checkout sets up no such remote-tracking ref). The script resolves `DIFF_BASE`
with `git rev-parse --verify DIFF_BASE^{commit}` at
`scripts/check_changelog_citations.py:846` ("def _resolve_base()") and diffs
new lines with `git merge-base(DIFF_BASE, HEAD)` at
`scripts/check_changelog_citations.py:903` ("def _added_lines(base: str)") --
both take a raw SHA exactly as well as a symbolic ref, so `base_sha` resolves
with no local branch pointing at it.

The checkout itself uses
`.github/workflows/merge-queue-changelog-citations.yml:84`
("fetch-depth: 0"), not a shallow default: `git merge-base` over a grafted
shallow history can miss or misresolve the common ancestor, and `base_sha` --
`dev`'s own tip at enqueue time -- has to be a resolvable ancestor of HEAD for
the new-citation rule to run at all rather than warn that it didn't.

Not a required context: promoting `changelog citations · merge queue` is a
branch-protection/ruleset edit on GitHub's side, out of scope here (see
#2206). Recommend requiring it once it has run clean for a cycle -- until
then it carries the same weakness that let #2201 merge with a red,
non-required `python-smoke` leg: the queue does not wait for it.
