### Fixed — `changelog.d/` fragment names had no way to disambiguate a second fragment for one issue, so the collision got named after the PR instead (#1941)

`scripts/check_changelog_fragments.py` (via `scripts/assemble_changelog.py`'s
`FRAGMENT_NAME_RE`) required every fragment filename to be exactly
`<digits>.md`. Since the digits are the issue number, that made the filename
a unique key on issue number, and two unmerged fragments for the same issue
could not coexist — an issue legitimately closed by more than one PR (a
tiered fix, a split, two independent defects under one number) had no legal
suffixed name to fall back on. Hit for real on 2026-09-04 in PR #1932:
`changelog.d/1909.md` was already taken by an unrelated fragment for #1700,
so `changelog.d/1909-diagnostic-format-uri.md` failed the gate and was
renamed `changelog.d/1932.md` — named after the PR instead of the issue,
silently breaking the convention the number exists to encode.

`FRAGMENT_NAME_RE` now accepts `<issue>.md` or `<issue>-<slug>.md`
(`^\d+(-[a-z0-9-]+)?\.md$`), so `1909-diagnostic-format-uri.md` is legal and
still sorts and greps under `1909`. `assemble_changelog.py`'s
`_fragment_sort_key()` was updated in lockstep: it now orders by the
*leading* issue number (matched with a regex, not `str.isdigit()`) so a
suffixed fragment folds into `CHANGELOG.md` next to its plain-numbered
sibling by issue order, not lexicographically by slug. The gate's error text
changed to name both accepted shapes
(`expected \`<issue>.md\` or \`<issue>-<slug>.md\`, issue digits first`).
`changelog.d/README.md` now states the collision rule explicitly, which it
did not before.

`scripts/check_changelog_citations.py` and `scripts/bump_version.py` glob
`changelog.d/*.md` without parsing the filename for structure beyond the
`README.md` exemption, so neither needed a change.
