### Fixed — AEN flash paths refuse an ATOC package that overlaps customer `storage` (#2234)

The E1M-AEN presets reserve a 32 KiB `atoc` band at `0x80578000`, with the
customer `storage` region directly below it. SETOOLS grows the signed ATOC
package down from the top of App MRAM, and it stores an ITCM load image
(`loadAddress`) inside the package. A plain Flow A package therefore measured
89152 B and started at `0x8056A3C0`, 56384 B inside `storage`. A runtime that
writes `storage` (NVS, littlefs, settings) or `erase-storage.sh` would then
overwrite the boot image.

`scripts/aen_atoc.py` gains `validate_package_extent()` and a
`--package-map <app-package-map.txt>` mode, which read the package start and
refuse anything below the band. Every bench script that runs `app-gen-toc`
now calls it through `bench_atoc_extent_guard` in `scripts/bench/aen/bench-env.sh`:
`flash-run.sh`, `flash-run-dualcore.sh`, `flash-jlink.sh`, `flash-jlink-hp.sh`,
`flash-jlink-mramxip.sh`, `flash-update-log-dual.sh` and
`flash-update-log-firewall-probe.sh`. The `alif_flash` west runner calls it
too. For an image that never writes `storage`, set
`ALP_ATOC_ALLOW_OVER_STORAGE=1` to accept the overlap. The memory map itself
is unchanged.
