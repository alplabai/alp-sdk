### Added — provisioning refuses to ship a unit strapped to debug mode (#2660)

The RZ/V2N SYS block latches the MD_BOOT pins in `SYS_LSI_MODE` (`0x10430300`): bit 9 is the debug-mode strap (MD_BOOT3 high), bits 2..0 are `MD_BOOT[2:0]`. The census now records `soc_boot_debug_en`, `soc_md_boot` and `soc_boot_device`, `cold_boot_test` and `ship_check` refuse a unit with the debug bit set, and `functional_test` gains a blocking `boot_mode` check against `boot_mode` in `functest-expect-v2n.yaml`. The register addresses and bit layout live in a new optional `sys_lsi` block of the SoC description (`soc-spec-v1.schema.json`), not in the tool; the SYS addresses are now confirmed against the hardware manual and no longer carry the `unverified addr` marker.
