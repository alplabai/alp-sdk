### Changed — DRP-AI `alp_inference_invoke()` reports a failed job (#2980)

**`alp_inference_invoke()` on the DRP-AI3 backend now returns `ALP_ERR_TIMEOUT` or `ALP_ERR_IO` when the job failed, instead of always returning `ALP_OK`.** The vendor runtime's `Run()` is void, so when the process already holds `/dev/drpai0` open the backend reads `DRPAI_GET_STATUS` on one extra open (the driver only resets the device on the first open and the close that leaves one fd, so an extra open with the runtime's fd held does not touch it; the open and ioctl can each wait up to 1000 ms on the driver semaphore, as does the close): a job still in RUN maps to `ALP_ERR_TIMEOUT`, a recorded DRP/AIMAC error, reset or suspend to `ALP_ERR_IO`, and a failed query to `ALP_ERR_TIMEOUT`, `ALP_ERR_BUSY` or `ALP_ERR_IO`. If the runtime holds no fd the query is skipped and the result is `ALP_OK`, because a first open would reset the device. A `DRPAI_START` the driver rejects before running is not detected. The host regression test `alp_test_inference_drpai_regression` covers each mapping.
