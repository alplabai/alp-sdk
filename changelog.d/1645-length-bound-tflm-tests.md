### Fixed — TFLM refuses a tensor dim that does not fit the descriptor's `uint16_t` shape (#1645)

**`src/backends/inference/tflm.cpp` now fails `alp_inference_open()` with `ALP_ERR_NOSUPPORT` when an allocated input or output tensor has a dim outside `[0, UINT16_MAX]`.** `alp_inference_tensor_t.shape[]` is `uint16_t`, so such a dim used to be silently truncated into the descriptor on the first `get_input()`/`get_output()`. The other length bounds in #1645 (JPEG strides and max size, the RPC oversized-frame drops, the MQTT payload drain, DEEPX multi-input and dim values) landed earlier; this adds regression tests for them (`tests/zephyr/peripheral/src/jpeg_bounds.c`, `tests/yocto/rpc_{yocto,uio}_peer_length.c`, `tests/zephyr/mqtt_peer_length`), puts the RPC peer-length test under the ASan/UBSan and TSan runs, and documents the oversized-frame, dropped-response and truncated-MQTT-payload behaviour in `rpc.h`, `iot.h` and `inference.h`. The TFLM dim bound itself has no regression test: no twister scenario enables `CONFIG_TENSORFLOW_LITE_MICRO` and the TFLM module is not in the host Zephyr workspace, so it is compile-reviewed only. `tests/yocto/rpc_uio_peer_length.c` is gated on the open-amp/libmetal pkg-config check and has not been built on a host that has them.
