### Added — opt-in OV9281 on the E1M-X EVK CAM0 (J5) connector (#2612)

`ALP_ENABLE_CAM0_OV9281 = "1"` builds the cam0 dtb with `meta-alp-sdk/recipes-kernel/linux/linux-renesas/e1m-x-evk-cam0-ov9281.dtsi` (`compatible = "ovti,ov9282";`), enables RIIC2 (`&i2c2`, P34/P35) and hogs the CSI mux select (`cam0-mux-sel`, GD32 bridge line 7 = E1M IO16) low to pick J5, and adds `CONFIG_VIDEO_OV9282=y` to `camera-csi.cfg`. It is mutually exclusive with `ALP_ENABLE_CAM0_IMX219` (the bake aborts if both are set); the default dtb is unchanged. Bench-proven on E1M-V2M103 + X-EVK J5: the 6.1 driver has a single 1280x720 `Y10_1X10` mode at 400 MHz, and streaming needs patches 0016 (below) and 0017. Bring-up commands are in `docs/v2n-camera-csi.md`.

Kernel patch `0016-media-rzg2l-cru-add-Y10-Y8-greyscale-formats.patch` adds `MEDIA_BUS_FMT_Y10_1X10` (captured as `CR10`) and `MEDIA_BUS_FMT_Y8_1X8` (`GREY`) to the RZ/G2L CSI-2 receiver and CRU format tables, so the OV9281's Y10 output no longer reads back as `UYVY8_1X16` on `csi20` and `STREAMON` no longer fails with `-EPIPE`. Applied unconditionally; other sensors are unaffected.

Kernel patch `0017-media-rzg2l-csi2-honour-lane-polarities-via-SWAPCTL.patch` makes the RZ/V2H-family CSI-2 receiver honour the standard `lane-polarities` endpoint property by programming `CRUm_SWAPCTL` (bit 5 swaps all data lanes, bit 4 the clock lane; all data lanes or none). The cam0 OV9281 and IMX219 fragments set `lane-polarities = <1 1 1>;` on the `csi20` endpoint, since the CSI0 P/N pairs arrive swapped on E1M-V2M103 + X-EVK J5 (bench: without it `DLST0/1 = 0x4`, no packets; with it 30/30 frames at 16.9 fps), so no manual register write is needed. Applied unconditionally.
