### Fixed — `board.schema.json`'s `cores.<id>.app` description omitted the parent-directory fallback (#1294)

`$defs/core_entry/properties/app` said `os: zephyr` requires `app:` to itself contain
`prj.conf` or `CMakeLists.txt`, with no mention of the convention 96 of 105 example core
entries actually rely on: pointing `app:` at a sources-only subdirectory (e.g. `./src`) and
letting `alp_orchestrate.orchestrator._zephyr_app_dir` fall back to that directory's parent
CMakeLists.txt. The description now states both supported `os: zephyr` conventions
(self-contained app dir, or sources dir with parent fallback) and that `os: baremetal` has
no such fallback. Documentation only -- no validation or runtime behaviour changed.
