### Fixed — CC3501E `SOCK_RECV` no longer shares its retry seq with every other opcode (#2108)

`cc3501e_sock_recv()` drew its wire-header retry seq (proto v8, 5 bits, 1..31)
from `ctx->req_seq` -- the SAME counter every other worker-routed opcode
(event polls, `WIFI_STATUS`, BLE ops, ...) also draws from. A bridge whose
receive-ring advance is lazy-committed (a `SOCK_RECV` whose header seq AND
socket handle match the immediately preceding recv is served the SAME bytes
again; any other recv commits the next chunk) is only correct if two
DIFFERENT consecutive recvs on one handle never share a seq -- and the shared
counter wraps every 31 allocations, so two recvs separated by exactly 31
unrelated commands could draw the identical seq. The second, genuinely new
recv was then answered as a replay of the first: the bridge did not advance
its ring, and the host silently received the first recv's bytes again, with
both calls reporting `ALP_OK`. Bench evidence: one run downloaded 262144 B
over 4071 B recv calls, every call returned OK, and exactly one 4069 B block
never arrived, sitting exactly on a reply boundary.

`cc3501e_sock_recv()` now allocates from its own dedicated `ctx->sock_recv_seq`
counter (same free-running 1..31-skip-0 shape as `sock_send_seq` / `req_seq` /
`spi1_seq`), so its seq space can never collide with any other opcode's
traffic. `poll_by_repeat()`'s retry loop is unchanged in behaviour; its body
moved to a new `poll_by_repeat_seq()` that takes the seq as a parameter,
letting `SOCK_RECV` supply its own while every other caller still goes
through `poll_by_repeat()`, which allocates from `ctx->req_seq` exactly as
before. A retry within one `cc3501e_sock_recv()` call (e.g. a reply that
fails CRC on the wire) still re-sends the SAME seq across every attempt, so
it is correctly re-collected from the bridge's replay cache rather than
misread as "commit the next chunk".

Harmless against firmware without this replay logic: it ignores the seq bits
for `SOCK_RECV` exactly as it already does for every opcode that never checks
them.
