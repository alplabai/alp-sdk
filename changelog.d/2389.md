### Fixed — a wrong-format model no longer SIGPIPE-kills `alp_inference_open()` on V2N/V2M Linux (#2389)

`alp_inference_open()`'s Yocto dispatcher never checked `cfg->format` against
the backend it resolved to, so an `.onnx` blob (`format =
ALP_INFERENCE_MODEL_ONNX`) opened with `backend = AUTO` on a DRP-AI-compiled
build was piped straight into the DRP-AI backend's `tar -xf -` extractor —
the wrong parser for that container. `tar` died at the bad header, and the
extractor's `fwrite()` into the now-reader-less pipe raised **SIGPIPE**,
whose default disposition **killed the whole calling process** (exit status
141) before the extractor's own error handling ever ran, leaking the
`/tmp/alp-drpai-XXXXXX` staging directory in the process.

Two independent fixes, both in `src/yocto/inference_yocto.c`:

- **Format gate.** `alp_inference_open()` now rejects a `cfg->format` the
  resolved backend doesn't accept with `ALP_ERR_INVAL`, before the blob ever
  reaches a backend's `open()` hook
  (`src/yocto/inference_yocto.c:249` (`if (!_format_matches_backend(backend, cfg->format)) {`)).
  Each backend's accepted format is declared in `_format_matches_backend()`
  (`src/yocto/inference_yocto.c:187`
  (`static bool _format_matches_backend(alp_inference_backend_t      backend,`)).
  `AUTO` still never falls back to CPU to satisfy a format — resolving to
  DRP-AI on an NPU-bearing SoM and then rejecting an ONNX blob is the
  documented behaviour, matching `<alp/inference.h>`'s existing
  `ALP_ERR_INVAL` contract for "bad magic / unsupported model format". A
  caller who explicitly pins `ALP_INFERENCE_BACKEND_CPU` with `format =
  ALP_INFERENCE_MODEL_ONNX` still opens normally. The DRP-AI backend itself
  (`src/yocto/inference_drpai.cpp`) also rejects a non-DRPAI format
  defensively, independent of the dispatcher
  (`src/yocto/inference_drpai.cpp:370` (`if (cfg->format != ALP_INFERENCE_MODEL_DRPAI) {`)).

- **SIGPIPE-safe tar-staging write.** The extractor's pipe write now goes
  through a new helper, `alp_sigpipe_safe_write()`
  (`src/yocto/alp_sigpipe_safe_write.c:16`
  (`bool alp_sigpipe_safe_write(int fd, const void *data, size_t len)`)),
  called from `_stage_drpai_blob()`
  (`src/yocto/inference_drpai.cpp:293`
  (`bool wrote_ok = (len == 0) || alp_sigpipe_safe_write(::fileno(p), data, len);`)).
  It blocks `SIGPIPE` in the calling thread only (never process-wide) around
  the write, maps a broken pipe to a clean `false` (the caller maps that to
  `ALP_ERR_IO`), and consumes any `SIGPIPE` its own write actually generated
  before restoring the thread's original signal mask — but only when
  `SIGPIPE` wasn't already pending beforehand, so it never eats a signal
  that belongs to something else. `pclose()`'s exit-status check (already
  present) now actually runs instead of being pre-empted by the process
  dying, and the staging directory is removed on this failure path exactly
  as it already was on every other one.

**Tests.** `tests/yocto/inference_format_gate.c` drives the real dispatcher
through two fake backends (DRP-AI + CPU) and proves: AUTO-resolves-to-
DRP-AI + ONNX is rejected with the DRP-AI backend's `open()` never called;
AUTO + a matching DRPAI format opens; an explicit CPU pin + ONNX still
opens; an explicit DRPAI pin + ONNX is rejected the same way AUTO is.
`tests/yocto/sigpipe_safe_write.c` proves the write helper survives a
closed-reader pipe (the exact SIGPIPE mechanism, without needing a real
`tar` or DRP-AI device) with no process death, no leaked pending signal, and
a correct successful-write path — deliberately plain POSIX with no
Linux-only header, so it builds and passed locally on macOS (Darwin), unlike
`inference_drpai.cpp` itself. `tests/yocto/inference_drpai_regression.cpp`
gained a format-defense case
(`test_open_rejects_non_drpai_format`) that also passed locally, since it
runs ahead of the `/dev/drpai0` probe the rest of that suite needs Linux
for. The end-to-end corrupt-tar path through the real DRP-AI backend
(`_stage_drpai_blob()`, gated behind `/dev/drpai0` being present) still
needs V2N/V2M silicon and was not run here.
