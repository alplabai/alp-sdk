### Fixed — `alp_inference_open()` refuses a wrong-format model; a bad DRP-AI tar no longer kills the app (#2389)

The yocto dispatcher never compared `cfg->format` with the backend it resolved. With DRP-AI compiled in, `AUTO` picks DRP-AI (CPU must never win AUTO on an NPU SoM), so an `.onnx` blob went straight into the DRP-AI `tar -xf -` extractor. `tar` exited at the bad header, and the backend's next `fwrite()` into the closed pipe raised SIGPIPE, which **killed the calling application** (exit 141 on E1M-V2M103). The killed run also left its `/tmp/alp-drpai-*` staging directory behind.

- **Format check.** Each compiled-in backend now accepts only its own format: DEEPX needs `ALP_INFERENCE_MODEL_DXNN`, DRP-AI needs `…_DRPAI`, and the ONNX Runtime CPU backend needs `…_ONNX`. Anything else returns `ALP_ERR_INVAL`, as `<alp/inference.h>` documents for "unsupported model format". A backend that is not compiled in still returns `ALP_ERR_NOSUPPORT`.
- **SIGPIPE.** The DRP-AI tar staging blocks SIGPIPE on the calling thread for the write, drains any pending one, then restores the mask. A corrupt tar now gives `ALP_ERR_IO` with its staging directory removed.

Bench, E1M-V2M103 with DRP-AI and ORT CPU both compiled in:
- `AUTO` with an `.onnx`: `ALP_ERR_INVAL`.
- DRP-AI pinned with ONNX bytes: `ALP_ERR_IO`, and the process keeps running.
- `AUTO` with the YOLOX-S/VOC `drpai_dir` bundle: runs on DRP-AI, 20/20 invokes at 40.1 ms.
- `CPU` with the `.onnx`: runs on ONNX Runtime.

The same run moved the ONNX Runtime CPU backend to verified on silicon (#1255). With `libonnxruntime` 1.20.1, 10/10 invokes take ~1670 ms per 640x640 frame. All three output heads match Python ONNX Runtime on x86 to 3.6e-5.
