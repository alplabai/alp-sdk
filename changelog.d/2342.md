### Fixed — a mid-frame CPI stop could overrun the frame buffer on the E8 (#2342)

`zephyr/drivers/video/video_alif.c` stopped an in-flight CPI capture with a
bare `CAM_CTRL = 0` write in three places: the buffer-starvation pause
(`hw_cam_cpi_only_stop()`, #2287), `alif_cam_stream_stop()`, and
`alif_cam_flush(cancel)`. A register-level bench diagnostic (E1M-AEN803
2026W36-0001, run 339) found that write does **not** stop the DMA: it clears
`FIFO_CLK_SEL`, and the CPI kept writing roughly another whole
`CAM_VIDEO_FCFG`-bounded frame past the write (259,200 B frame -> 510,247 B
written, one of two placed canaries overwritten). Clearing the `SNAPSHOT` bit
instead is worse — it turns the capture continuous with an incrementing
address, a genuine runaway that filled all 4 MiB of SRAM0 in 250 ms with
`BUSY` stuck set and no `STOP` interrupt ever raised. `BUSY` read back 0
immediately after the `CAM_CTRL = 0` write while the DMA was still actively
overrunning the buffer, so the `BUSY` poll each of the three call sites did
right after that write proved nothing about whether the capture had
actually stopped.

The only sequence that bench-proved a frozen, intact extent is the CPI's
full 3-step soft reset (`CAM_CTRL 0 -> SW_RESET 0x100 -> 0`). All three call
sites now go through a new `hw_cam_quiesce()` helper that does exactly that,
parking `CAM_CTRL` at `FIFO_CLK_SEL` afterwards (camera clock selected, no
`START`) instead of a bare 0, and no longer poll `BUSY` first. The ISR's
post-`STOP` write (a normal completed-`SNAPSHOT` park, not a mid-frame stop)
now writes `FIFO_CLK_SEL | SNAPSHOT` instead of 0 for the same reason;
`alif_cam_cpi_resume()`'s `BUSY | START` idempotency guard still passes
against that value. `capture-mode = "continuous"` is now rejected at driver
init (`-ENOTSUP`) — every stop path in this driver assumes the CPI's
hardware auto-stop after one `SNAPSHOT` frame, which a continuous capture
has no equivalent of; nothing in this repo's DT overlays sets it today.

`CAM_AXI_ERR_STAT` (CPI+0x18) is confirmed not writable on this CPI — a
write to it bus-faults — and is never written by this driver.

Bench-proven on the register-level diagnostic only (E1M-AEN803
2026W36-0001, runs 336-339); the driver-level fix in this change has not
itself been re-run on silicon. `-Werror` rebuilds clean:
`camera-mjpeg-stream` (IMX335, IMX296, OV5647), `aen-camera-firstlight`
(IMX335, OV9281), `aen-isp-capture` (IMX335), `aen-isp-regcheck`.

Closes #2342.
