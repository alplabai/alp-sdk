### Fixed — `alp_i2s_write()` copied a caller-supplied length into a fixed-size slab block (#1619)

`src/backends/i2s/zephyr_drv.c:228` ran `memcpy(slab_block, block, bytes)` with
the caller's `bytes` into a `k_mem_slab` block whose size was computed at
`open()` and then discarded — the sidecar stored `slab_buf_bytes` but never the
per-block size, so `z_write()` had nothing to compare against. An oversize write
corrupted the neighbouring slab block and the `k_malloc` heap behind it.

Zephyr's own `i2s_write()` rejects an oversize length with `-EINVAL`, but it is
called on the line *after* the `memcpy`, so it never saw the write that mattered.

The path is reachable from portable code with no I2S knowledge at all:
`src/backends/audio/zephyr_drv.c:516` derives `bytes = frames *
bytes_per_frame(&state->cfg)` from an unclamped `frames` and hands it to
`alp_i2s_write()`, while `src/audio_dispatch.c:184` validates only
`buf == NULL || frames == 0` and `src/i2s_dispatch.c:132` only
`block == NULL || bytes == 0u`.

Fixed in two places, so the oversize request is both refused and never generated:

- `src/backends/i2s/zephyr_drv.c:161` records the negotiated block size on the
  sidecar, and `:221` rejects `bytes > s->block_bytes` with
  `ALP_ERR_OUT_OF_RANGE` *before* claiming a slab block.
- `src/backends/audio/zephyr_drv.c:514` refuses `frames` beyond the
  `frames_per_block` negotiated at open, before the byte count is derived.

`alp_i2s_write()` and `alp_audio_out_write()` now document
`ALP_ERR_OUT_OF_RANGE` in their `@return` lists, and their length parameters say
the bound is enforced rather than merely expected.

**Not verified on `native_sim`.** The added ztest
(`test_i2s_write_rejects_oversize_block`) reports `skipped` there, because
`alp_i2s_open()` returns NULL on that platform: `src/i2s_dispatch.c` selects a
backend once with no `alp_backend_select_next()` fall-through, so `zephyr_drv`
(priority 100) wins, fails `ALP_ERR_NOT_READY` on a NULL device, and
`sw_fallback` (priority 0) is never reached. Zephyr ships no `i2s_emul`, the
`vnd_i2s` build-all stub's `configure` returns `-ENOTSUP`, and i2s `sw_fallback`
returns `ALP_ERR_NOSUPPORT` from `write` by design — so no `native_sim`
configuration can exercise the guard. This needs a bench pass on E1M-AEN801; the
selection gap is filed on #1642.
