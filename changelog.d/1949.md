### Fixed — `metadata/chips/gd32g553.yaml` cited three closed issues as the reason it is still `partial`

The manifest's `driver_status: partial` comment named #495, #494 and #496 as
open. All three closed months ago -- #494 and #495 via #730, #496 via #764 --
so the file was telling a reader to go and check work that was already
finished, and giving the wrong reasons for a status that is nonetheless
correct.

The chip really is still `partial`. The comment now records why, taken from
each issue's own closing comment rather than restated:

- PWM dead-time and break stay `NOSUPPORT` because the V2N connector routes
  neither the complementary CHxN pad nor a BRK pad. That is a carrier-routing
  limit needing a future carrier revision, not firmware work.
- ADC 14/16-bit effective-resolution modes need the GD32G553 reference
  manual's effective-resolution table plus bench proof.
- End-to-end DSP-chain analog measurement is deferred because the bench ADC
  pins float.
- `PWM_CAPTURE` edges remain pending a V2N pad-routing rework.

No status word, symbol or schema changed -- `driver_status` stays `partial`,
so `check_driver_status_backing.py` and `check_chip_header_status.py` are
unaffected. Comment text only.
