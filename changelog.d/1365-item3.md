### Added — `system-manifest-v1` now EMITS `memory[]`, and its rows are typed (#1365 item 3)

The `memory[]` contract landed ahead of its producer in split C (`2fd04541`,
#1984) with `items` left as `{required: ["name"], additionalProperties: true}`
— every other field prose-declared only. Both halves close here, in one diff,
because the order matters: typing a row is free while nothing emits it and
breaking once something does.

**The producer.** `scripts/alp_orchestrate/memory.py`'s `resolve_memory_regions()`
projects `alp_project.resolve_memory_map()`'s effective table into the pane,
alongside the existing `resolve_carve_outs` / `resolve_storage_partitions`
calls in `emit_system_manifest()`. Four of the committed emit snapshots grow a
`memory:` block; the other 33 `--emit` surfaces stay byte-identical.

The key is **OMITTED, never emitted empty**. A SoM that resolves no regions at
all (an unresolvable `silicon_variant`, e.g. NX9101's `TBD`) carries no
`memory:` key, so an absent pane still means "producer older than this change,
or a layout still pending" — never "this SoM has no memory regions". Emitting
`memory: []` would have collapsed exactly the distinction split C's own text
drew.

**Three vocabularies, taken from the shipped derivation rather than from
#1365's issue body**, which predates splits A and B and proposes shapes the
code cannot fill:

- `kind` is `aperture.classify_region()`'s four verdicts verbatim — `flash`,
  `ram`, `unclassified`, `unresolved` — not the issue's two. The two extra
  values exist precisely to say *not proven*: `unclassified` is
  outside-the-aperture AND preset-authored (containment is ONE-DIRECTIONAL, so
  outside proves nothing — an Ensemble OSPI XIP window is outside and still
  flash), and `unresolved` covers both "no extent" and "this SoC declares no
  aperture", which is every non-Alif SoM. A 2-value enum would have to fold one
  of them into `ram`, asserting a class the deriver never returned.
- the authority field is `write_authority` with som-preset-v1's six values,
  passed through verbatim, not the issue's 3-value `owner`. One axis cannot
  separate flash-time from runtime authority: `customer_image` and
  `customer_runtime` would both collapse onto `customer`, which is the exact
  `he_slot0`-vs-`storage` distinction the vocabulary was widened to draw
  (#1365 review). A row that authors none carries no key — absent means
  unresolved, never `customer_runtime` (ADR-0034 clause 4).
- `status` is `ok` / `unresolved`, the word this schema's items description
  already made normative, not `ipc[]`'s `ok` / `blocked`. They are not
  synonyms: `blocked` is a verdict on an allocation request; a region either
  resolved an address or did not.

`status` keys off the **base**, not off the extent, because the schema's rule
is written about `base`. Size resolves independently: AEN's `mram_main` emits
`size_bytes: 5767168` alongside `status: unresolved` and no `base`, with a
`reason` naming the field to declare — `base: TBD` is a placeholder, and
ADR-0034 clause 4 forbids guessing past it.

**`source`** — the field an IDE derives editability from (`alp-sdk-vscode#484`)
— is `som_preset` or `soc_derived`, derived in the emitter rather than tagged
inside `resolve_memory_map()`. That function's precedence is ALL-OR-NOTHING (an
authored `memory_map:` wins the whole table), so provenance is a property of
the table, not of a row; `carveout.py` and `partition.py` already read it the
same way via `bool(som_preset.get("memory_map"))`. Tagging rows in the loader
would also have added a key to dicts that flow into `$defs/memory_region`'s
`additionalProperties: false` validation path. The issue's third value,
`board_yaml`, is dropped as having no producer: board.yaml never AUTHORS a
region, it only NAMES one.

**`dt_label` is deliberately not carried.** #1556 allows it only when verified
against the board `.dts`, and this emitter has no access to that verification,
so emitting it would ship exactly the name-derived fallback the rule forbids.
The schema now says so instead of imposing a rule on a field it does not
declare.

**The row invariant is enforced, not described.** `status: ok` with no `base`,
`status: unresolved` with no `reason`, and `status: unresolved` carrying a
`base` were all schema-legal while that rule lived in the items description —
the same "prose nothing checks" shape typing this pane exists to end. An
`if`/`then`/`else` on `memory[].items` now refuses all three, verified against
the four committed manifests (unchanged, rc=0) and the 37 emit snapshots
(byte-identical).

**The gate.** `scripts/check_system_manifest.py` was jsonschema-only and could
not express the join the schema's prose promises, so it gains one: an
`ipc[].carve_out_region` that names no `memory[].name` now fails. The storage
side stays unenforced on purpose — an `on_module.ospi_memories:` key is a legal
`flash_device` target that gets no region row, and the loader already refuses a
`flash_device` naming neither (`_known_flash_devices`). The check is skipped
when `memory:` is absent.

Two corrections to split C's own text while typing it: the pane description
said the join key was `ipc[].region`, but the emitted key is
`ipc[].carve_out_region`; and it described the key as "DECLARED AHEAD OF ITS
PRODUCER, DELIBERATELY -- no emitter writes this key yet", which stops being
true here.

Consumers pinned to a vendored copy of this schema see one new optional root
key; the root stays `additionalProperties: false`, which is the producer gate
that catches an emitter key typo (`check_system_manifest.py`). Downstream,
`tan`'s planner-oracle corpus regenerates on its next SDK pin bump — alp-sdk's
own CI does not depend on `tan`, so nothing here waits on it.

Refs #1365, #1983, #1984. Does not close #1365 on its own — the issue stays
open until its remaining follow-ups land.
