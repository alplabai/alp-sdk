### Fixed — `alp gpio read` no longer turns an output pin into a floating input (#2933)

**`alp gpio read <pin>` now samples only pins that are already inputs and refuses the rest.** The command used to call `alp_gpio_configure(ALP_GPIO_INPUT, ALP_GPIO_PULL_NONE)` before reading and never restored the pin, so reading an output silently stopped driving it. It no longer reconfigures anything: it asks the GPIO controller (`gpio_pin_get_config_dt`) for the pin's real direction and answers `pin N is not configured as an input; refusing to reconfigure it` (`-EPERM`) for anything that is not an input, because the console opens a fresh handle and the handle's cached direction is only the open default. A controller that does not implement `pin_get_config` leaves the direction unknown, and the read proceeds unchanged since it has no side effect. `alp gpio write` still configures the pin as an output. Needs `CONFIG_GPIO_GET_CONFIG=y` to enforce the refusal.
