### Fixed — Yocto boot chain: Mender A/B boot and rollback, one U-Boot env store, pinned sources, signed-FIT boot (#2960, #2961, #2962, #2964)

**Mender A/B boot (#2960).** The ALP U-Boot `bootcmd` always booted `/dev/mmcblk0p2`, so a Mender update never switched slot and a bad image never rolled back. With `conf/distro/include/mender.inc` the `bootcmd` now boots eMMC slot 2 or 3 from Mender's saved `mender_boot_part`, counts boots in `bootcount`, and runs Mender's `altbootcmd` once `bootlimit` is exceeded with `upgrade_available=1`; a slot whose kernel does not load ends in `mender_try_to_recover`. The slot is chosen by comparing against literals: the mmc spec and `root=` are never built from the saved environment, which is writable from Linux, and the Mender variables in the `0016` allowlist are now typed (`d` / `x`) so a malformed value is dropped on import. `mender.inc` also had no `mender-uboot` feature (meta-mender defaulted to GRUB/UEFI) and no `MENDER_UBOOT_AUTO_CONFIGURE = "0"`; it now sets both. The default, non-Mender `bootcmd` is byte for byte unchanged (`0018`, `mender-boot.cfg`).

**One U-Boot environment (#2961).** meta-mender built `/etc/fw_env.config` for the eMMC user area (`/dev/mmcblk0`) while U-Boot reads boot partition 2. `mender.inc` now sets `MENDER_UBOOT_CONFIG_SYS_MMC_ENV_PART = "2"` and `BOOTENV_SIZE = "0x10000"`, so the generated file is `/dev/mmcblk0boot1` at `0x220000` / `0x230000`, 64 KiB each, equal to `uboot-env-emmc.cfg`; `rzv2n-dev_defconfig` carries the same location so meta-mender's pre-merge check agrees. Writing `/dev/mmcblk0boot1` from Linux still needs `force_ro` cleared (see `meta-alp-sdk/README.md`).

**Pinned sources (#2962).** `alp-sdk`, `alp-chips`, the examples and the ROS nodes fetched `${AUTOREV}` from a mix of `main` and `dev`. They now share one `SRCREV` in `recipes-core/alp-sdk/alp-sdk-version.inc` (the `v0.18.0` tag commit `bce3c67ab78d7dda47b1ffa9ca893f34751124c3`, which matches `PV`), every `SRC_URI` names `branch=main`, and `tests/scripts/test_yocto_srcrev_pin.py` fails on `AUTOREV` or another branch. How to bump the pin is in `meta-alp-sdk/README.md`.

**Signed-FIT boot (#2964).** `ALP_FIT_SIGNED = "1"` built a `fitImage` that the unchanged U-Boot could not boot. U-Boot now loads `/boot/fitImage` from the eMMC and runs `bootm` on the configuration node of the board dtb, and enforces the signature: the public key is embedded in the control dtb as `required = "conf"`, `board_late_init()` halts if it is missing, `booti`, `bootz`, `go` and the legacy image format are not built, autoboot cannot be interrupted (`CONFIG_BOOTDELAY=-2`) and a failed boot resets. Signed builds boot from the eMMC only (no microSD) and do not preload the unsigned OpenCV accelerator / codec firmware blobs. The kernel FIT now uses load and entry address `0x48080000` (the default `0x20008000` is outside DRAM) and is stored uncompressed. The FIP must be rebuilt and reflashed with the image. The key is still a generated dev key; this is not a complete secure-boot chain.

The `ALP_CAMERA_CAM0` dtb selection (#2963) is not part of this change.
