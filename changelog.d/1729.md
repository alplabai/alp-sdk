### Fixed — a model tensor with rank > 4 was silently truncated to rank 4 by the ONNX Runtime, DEEPX DX-M1, and TFLM backends (#1729)

`alp_inference_tensor_t`'s `shape` field has exactly 4 slots. All three of
`src/yocto/inference_ort.cpp`, `src/yocto/inference_deepx.cpp`, and
`src/backends/inference/tflm.cpp` used to hand back a tensor descriptor
truncated to its first 4 dims whenever a real tensor's rank exceeded that —
sized correctly via `size_bytes`, but with a `shape[]` that no longer matched
the model and no signal to the caller that anything was wrong. Confidently
wrong tensor geometry is worse than a refusal — and, before this fix, the
*same* rank-5 model was silently truncated on TFLM while being refused on
ORT/DEEPX, so a portable app got a different answer per backend.

All three backends now reject such a model at `alp_inference_open()` with
`ALP_ERR_NOSUPPORT` instead: ORT's `_gather_tensor_info()` refuses any tensor
whose `GetDimensionsCount()` exceeds 4 (kept as a SEPARATE check from the
pre-existing hostile/corrupt-ndim ceiling — a corrupt ndim is `ALP_ERR_INVAL`,
a well-formed model this descriptor can't represent is `ALP_ERR_NOSUPPORT`,
and collapsing the two would misreport a hostile rank-1000 `ndim` as merely
"unrepresentable"), DEEPX's `open()` checks every input/output tensor's
`shape().size()` right after `GetInputs()`/`GetOutputs()` before staging any
buffers, and TFLM's `tflm_open()` checks every input/output tensor's
`dims->size` right after `AllocateTensors()` succeeds, before handing state
to the caller.

DEEPX's `get_output()` also re-checks the LIVE tensor `Run()` hands back
(`last_outputs`) — the open()-time check only sees the DECLARED
`GetOutputs()` metadata, which does not cover a model whose live output rank
differs (e.g. a dynamic/data-dependent shape).

**A sibling of the same defect, found while fixing this one and fixed with
it.** The rank cap is not the only place a real dimension was quietly
reshaped to fit the descriptor: `alp_inference_tensor_t.shape[]` is
`uint16_t`, and `inference_deepx.cpp` cast each `int64_t` extent straight
into it with no bounds check — a dim above 65535 wrapped (100000 became
34464) and a symbolic/dynamic `-1` became 65535, in both cases a
plausible-looking wrong extent, exactly the failure mode this issue is
about. `inference_ort.cpp` already refused such dims at load time in
`_gather_tensor_info` ("reject here instead of lying to the caller"); its
sibling never got that check.

The rank-vs-extent decision for ORT and DEEPX is now shared:
`src/yocto/inference_tensor_shape.h`'s `alp_inference_shape::fill_fixed_shape()`
copies a shape when it fits (rank <= 4 AND every dim in `[0, UINT16_MAX]`)
and refuses — leaving the descriptor untouched — otherwise. It has zero
dependency on the ONNX Runtime C API or dx_rt, mirroring the
`src/yocto/drpai_deploy_shapes.h` (#1635) precedent of splitting a
vendor-independent decision into its own testable header. ORT's
`_gather_tensor_info()` still does its own open()-time extent check (and
pins a non-positive/symbolic dim to 1, a documented ORT-specific choice);
`get_input()`/`get_output()` call `fill_fixed_shape()` as the actual
write path and as defense-in-depth. DEEPX's `fill_tensor_descriptor()` now
returns `bool` and calls `fill_fixed_shape()` directly, so both the
declared-shape path (`get_input`/`get_output`) and the live post-`Run()`
path are covered — DEEPX deliberately does **not** copy ORT's "pin to 1"
behaviour: that is a documented load-time choice ORT makes for symbolic
dims, and silently inventing an extent on a backend that never made that
choice would be the same lie in a new place. `UINT16_MAX` itself is
representable and still passes.

TFLM's `fill_tensor_descriptor()` still casts `t->dims->data[i]` to
`uint16_t` with no per-extent bounds check — the same sibling defect,
unfixed on that backend. Not addressed here (out of scope for this batch);
worth its own follow-up.

`include/alp/inference.h`'s `alp_inference_open()` doc and
`docs/tutorials/16-inference-mobilenet.md`'s troubleshooting section both
document the new refusal. Regression coverage:
`tests/yocto/inference_ort_regression.cpp` and
`tests/yocto/inference_deepx_regression.cpp` drive the real backend bodies
against clean-room stand-in vendor headers (`tests/yocto/fakes/`) since
neither ONNX Runtime nor DEEPX dx_rt is available in CI (#1747);
`tests/yocto/inference_tensor_shape.cpp` unit-tests `fill_fixed_shape()`
directly (rank and extent boundaries, including the 65535/-1 wrap cases),
registered as `alp_test_inference_tensor_shape` — no vendor SDK, so it is
the surface where these decisions actually run today.
