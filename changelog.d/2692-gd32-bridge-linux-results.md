### Added — the CM33 GD32-bridge test apps publish a Linux-readable result record (#2692)

`v2n-gd32-bridge-functional` and `v2n-gd32-bridge-hil-soak` kept their verdict only in CM33 secure SRAM0, which Linux cannot read, so a bench run needed a CM33 J-Link. Both now also publish a compact, versioned 20-word record (magic, layout version, pass/fail/skip, negotiated feature word, `max_payload`, `ATTN` granted/active/fallback, `BATCH` and `ADC_STREAM2` outcome, `READ2` first index / dropped / gaps, and for the soak cycles / errors / `ATTN` timeouts / elapsed seconds) at A55 `0x4F700F00` in the existing OpenAMP `rsctbl` window, right below the liveness beacon at `0x4F700FF0` — no new carve-out. The layout is `include/alp/protocol/gd32_bridge_results.h`; both apps also start the beacon (heartbeat on a timer) with their own image kind `0x200` (not the idle shim's `0x100`, so `cm33_running` rejects these images). The SRAM0 copy is unchanged.

`scripts/bench/v2n/read_gd32_results.py` reads the record on the A55 over `/dev/mem` (seqlock-safe), and `tests/hil/v2m103-x-evk/v2m103-gd32-bridge-results.yaml` asserts it. A self-gating v0.15 test skipped because the bridge did not grant the feature is reported as a SKIP in the record, not a PASS.
