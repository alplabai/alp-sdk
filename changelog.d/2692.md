### Fixed — RZ/V2N CM33: route the GD32 bridge ATTN pad (P71) to an ICU TINT slot so ATTN can engage (#2692)

The bridge protocol v0.15 ATTN line (GD32 PA14 to RZ/V2N P71, active-high) never engaged:
`alp_gpio_irq_enable()` on the ATTN pad returned `ALP_ERR_NOSUPPORT` and the supervisor stayed on
the staging-gap fallback. Upstream Zephyr 4.4 already carries the whole TINT path
(`drivers/gpio/gpio_renesas_rz.c` + `intc_renesas_rz_tint.c`, the `renesas,rz-tint` nodes in
`r9a09g056.dtsi`); the only thing missing was the board-level route: a port's `irqs` property
mapping a pin to a TINT slot.

`metadata/e1m_modules/v2n/supervisor-links.yaml` gains an optional `gd32_pads.attn.tint_slot`
(`supervisor-links-v1` schema: integer 0..31), set to 31. `scripts/gen_zephyr_board.py` emits
`&tint31 { status = "okay"; }` and `irqs = <&tint31 1>;` on `&gpio7` for both V2N SoM boards
(`E1M-V2N101`, `E1M-V2M101`); the TSSR gpioint for P71 is port 7 base 48 + pin 1 = 49 (0x31).
`metadata/e1m_modules/v2n/core-ownership.yaml` attributes P70/P71/P74 to the CM33
(ATTN route bench-verified 2026-10-07, E1M-V2M103), so `check_amp_pad_claims.py` now rejects a Linux devicetree claim on them;
`metadata/pinmux/v2n.yaml` is regenerated.

Enabling a CM33 TINT also exposed an upstream defect: with `CONFIG_RENESAS_RZ_TINT_SUPPORT_STATUS_CLEAR_REG`
(the V2H/V2N path) `intc_renesas_rz_tint.c` cleared status with `TSCLR = TSCTR | BIT(tint)`, and TSCLR is
write-1-to-clear, so a CM33 ATTN ISR dropped the pending status of any other slot pending at that moment, including A55-owned ones
(e.g. the Linux AMP.FAULT edge interrupt). `zephyr/patches/zephyr/0005-intc_renesas_rz_tint-clear-only-own-status-bit.patch`
(carried in `zephyr/patches.yml`, upstreamable) writes only `BIT(tint)`.

TINT slots are a shared ICU resource. Slot 31 is the one a Linux ICU that allocates the lowest free
slot would reach last (only when 31 slots are in use); nothing enforces that, so it is a documented
ceiling in `metadata/e1m_modules/v2n/core-ownership.yaml`. The remaining hazard is the shared-register
read-modify-write: TSSR7 holds slots 28-31 and TITSR1 holds slots 16-31, and the CM33 rewrites both
without any lock shared with Linux. Both need a bench check. `tests/scripts/test_gen_zephyr_board.py` pins the
emitted route.
