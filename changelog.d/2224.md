### Fixed — the `LABGRID_PLACE` gate only matched the phrase "labgrid place", so bare bench-farm identifiers reached public files (#2224)

`scripts/check_public_private.py`'s `LABGRID_PLACE` rule matched only the
literal English phrase, never the farm's own naming scheme for a bench
slot, so a bare identifier sailed through untouched — including into public
headers. The rule now also matches the identifier pattern itself, general
enough to cover the farm's naming scheme rather than a fixed set of
numbers, and `changelog.d/` was added to the gate's scan roots so a
fragment is caught at PR time instead of at the next release cut, when it
lands in `CHANGELOG.md`.

Every existing hit across the gate's roots plus `changelog.d/` was scrubbed
using the rule's own remedy: keep the bench-proven claim and its date, and
name the unit by module SKU and serial where the occupant on that date is
known for certain, or use neutral wording otherwise. Bench-tooling command
examples now use a placeholder instead of a real place name. The
`model-perf-v1` schema's `bench_id` guidance, its test fixture, and
`docs/bench/model-perf-capture.md` were updated to the same SKU+serial
convention. `include/alp/boards/alp_e1m_evk_routes.h` was regenerated from
the corrected `metadata/boards/e1m-evk.yaml`.

A follow-up pass found the rule still missed two more shapes: the V2N
farm's own `e1mx-<family>-<board>-<slot>` naming scheme, and a bare
`evk-0N` slot name with no SoM-family prefix at all. Both are now matched
too, carefully scoped so the real carrier part number (`E1M-EVK-2626` and
its revisions) and the public board ids (`e1m-evk`, `e1m-x-evk`) still pass
clean. The V2N farm's bench place has no recorded module serial, so every
hit there went to neutral wording rather than an invented identity.
