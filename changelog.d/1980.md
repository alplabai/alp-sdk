### Fixed — the generated board header defined an address macro for I2C parts that are not on the board (#1980)

`scripts/gen_board_header.py` never read the `assembled` key #1977 added to
`i2c_device_entry` (`metadata/schemas/board-preset.schema.json`), so every
`i2c_devices:` entry got a plain `#define EVK_I2C_ADDR_<NAME> 0x..u`
regardless of whether the part is actually fitted. On the E1M-EVK, U37 (the
PCIe I/O expander) is `assembled: false` — confirmed absent on both bench
boards and from the maintainer's I2C schedule (`changelog.d`'s own #1974
entry; the fact lives in `metadata/boards/e1m-evk.yaml:295`) — but the header
still defined `EVK_I2C_ADDR_TCAL9538_PCIE 0x71u` as if it were real. Firmware
that reads "the header defines an address" as "the part is there" would
address silicon that does not exist and get a clean `-EIO`.

**Decision: rename, don't delete or guard.** Deleting the macro breaks any
existing caller at compile time with no explanation, and #1977 kept the
entry rather than deleting it because the footprint is real and other
revisions populate it — the same is true one row down: `EVK_I2C_ADDR_TCA6408A_MAIN`
(`metadata/boards/e1m-evk.yaml:297`) is the *alternate* population of the
same U35 footprint, bench-confirmed on an earlier EVK revision and a clean
NACK on both current boards, yet `examples/peripheral-io/i2c-device-hub/src/main.c:221`
already and correctly probes it at runtime alongside
`EVK_I2C_ADDR_TCAL9538_MAIN` as a legitimate cross-revision fallback. A
compile-time `#if 0` guard or outright omission would make that pattern
impossible to write for a newly-unfitted part without hand-editing a
generated file. So `_emit_i2c_devices()`
(`scripts/gen_board_header.py:122`) now renames every macro an
`assembled: false` entry contributes — address, `alias`, and any
`calibration` shunt/max-current pair — with a `_NOT_ASSEMBLED` suffix via
the new `_tag()` helper (`scripts/gen_board_header.py:145`) rather than
emitting the plain name. The plain name a reader would reach for out
of habit is no longer defined at all, so accidental use is a compile error
instead of a silent bus probe against nonexistent silicon; the address and
the `doc:` reason both survive under the renamed macro for anyone who
deliberately wants to probe for an earlier/other revision's population, the
same way the existing TCA6408A/TCAL9538 fallback does.

`include/alp/boards/alp_e1m_evk_routes.h` regenerates with
`EVK_I2C_ADDR_TCAL9538_PCIE_NOT_ASSEMBLED 0x71u`
(`include/alp/boards/alp_e1m_evk_routes.h:131`) in place of the plain macro;
no other generated board header changes (only the E1M-EVK's `i2c_devices:`
block currently declares an `assembled: false` entry).
`metadata/schemas/board-preset.schema.json:392` and
`include/alp/boards/alp_e1m_evk.h:580` are updated to describe the new
behaviour instead of the previous "the generator does not read this key"
limitation note. No new schema key — `assembled` already exists on `dev`
via #1977; this closes only the gap where the generator ignored it.

A macro rename is an ABI change (docs/abi-markers.md); `docs/abi/v0.16-snapshot.json`
is regenerated in this same PR (`REMOVED macro
alp/boards/alp_e1m_evk_routes.h::EVK_I2C_ADDR_TCAL9538_PCIE`, `ADDED macro
...::EVK_I2C_ADDR_TCAL9538_PCIE_NOT_ASSEMBLED`) — pre-1.0, ABI may change
between minor releases (docs/release-policy.md), and the E1M-EVK routes
header carries no live caller of the removed name. `docs/abi/removed-symbols.json`
gets a matching entry so the removal reads as `ALLOWED` rather than
`REMOVED` when `tests/scripts/test_abi_snapshot.py`'s
`test_real_tree_reports_zero_removed_against_last_released_snapshot` diffs
the current tree against the actual last-released baseline
(`docs/abi/v0.15-snapshot.json` — `abi.last_released_snapshot()` skips
`v0.16-snapshot.json` because it equals the CURRENT, unreleased version);
without that entry the same test that greenlit #1622's ADC renames goes red
on this one.
