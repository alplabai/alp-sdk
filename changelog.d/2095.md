### Added — gpio-qdec input-subsystem backend for the portable QENC API (#2095)

The Alif E8's UTIMER QEC hardware channel is a measured edge counter, not a
quadrature decoder (#2037), so a quadrature encoder wired to plain GPIOs
needs Zephyr's `gpio-qdec` input driver (`compatible = "gpio-qdec"`, emits
`INPUT_EV_REL` events) instead of the sensor-class channel
`src/backends/qenc/zephyr_drv.c` already speaks. That backend's own comment
anticipated exactly this ("Real pulse counts come via the v0.3
input-subsystem fast-path") but nothing implemented it until now.

`src/backends/qenc/gpio_qdec.c` is a new QENC backend, registered at
priority 110 (`src/backends/qenc/gpio_qdec.c:129`
(".priority    = 110,")) — above `zephyr_drv`'s 100 — so it is tried
first. For each `alp-qenc<N>` alias whose devicetree node is compatible
`gpio-qdec`, it registers an `INPUT_CALLBACK_DEFINE_NAMED` that
atomically accumulates `INPUT_EV_REL` events into a per-index position
(thread-safe: `atomic_add`/`atomic_get`/`atomic_set`), returned by
`alp_qenc_get_position()` and zeroed by `alp_qenc_reset_position()`. An
alias that is NOT a `gpio-qdec` node makes `open()` decline with
`ALP_ERR_NOSUPPORT` (`src/backends/qenc/gpio_qdec.c:93`
("if (dev == NULL) return ALP_ERR_NOSUPPORT;")).

`src/qenc_dispatch.c`'s `alp_qenc_open()` gained the same open-time
fall-through `src/security_dispatch.c`'s `hash_open()` already uses (issue
#239): on `ALP_ERR_NOSUPPORT` it walks to the next-priority backend
(`src/qenc_dispatch.c:100`
("be = alp_backend_select_next(")) instead of
failing the whole open — so a sensor-class `alp-qenc<N>` alias still lands
on `zephyr_drv` exactly as before; the new backend never breaks it.

Compiled only under `CONFIG_INPUT`
(`zephyr/CMakeLists.txt:1039`
("zephyr_library_sources_ifdef(CONFIG_INPUT")), selected purely by the
alias's devicetree `compatible` — no new Kconfig knob to choose between the
two qenc backends.

`tests/unit/qenc_gpio_qdec` (new native_sim ztest) aliases `alp-qenc0` to a
`gpio-qdec` node backed by native_sim's emulated `gpio0`, and drives the
backend with `input_report_rel()` directly (the same event shape the real
driver posts) to check position accumulation, reset, and that a non-`REL`
event type is ignored.
