### Fixed — 25 stale `libraries.py` line-197 citations pointed at an unrelated parameter default (#1491)

Line 197 of `scripts/alp_orchestrate/libraries.py` was the Kconfig-transcription
site (`zephyr_kconfig_lines`) when 25 comments across `metadata/libraries/*.yaml`,
`metadata/library-profiles/README.md` and five `examples/**` files cited it —
and became stale the moment the same release that added them inserted
`scoped_names`, `_check_slice_requires` and `zephyr_library_kconfig` above it,
pushing the cited function down to line 321. Line 197 is now a parameter
default inside `resolve_selection`'s signature, so several of the citations
read as self-contradictory: naming `zephyr_kconfig_lines` next to a line
number where that function is not.

Every citation is re-pointed at the function it actually names: the
project-wide emitter `zephyr_kconfig_lines` now cites `:321`, and citations
describing the per-manifest `integration.zephyr.kconfig` transcription (no
function named) now cite `zephyr_library_kconfig` at `:283`.
`git grep -c "libraries\.py:197"` is 0.
