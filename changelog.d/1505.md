### Fixed — `docs/cli.md`'s `tan validate` section no longer claims the SDK-backed path is unported (#1505)

`docs/cli.md:394-398` said, in unqualified present tense, that without
`--offline` Tan "currently reports that the SDK-backed rich validator
subprocess is not yet ported (exit 2)", and routed readers to
`python3 scripts/validate_board_yaml.py` as a workaround "during this
transition". That path shipped in tan-cli#376 and is in released `tan`
v0.6.0: `python/tan/commands/validate_cmd.py` resolves the SDK checkout and
spawns `<sdk-root>/scripts/validate_board_yaml.py` itself, mapping the
child's exit status through `_STATUS_OUTCOME` into Tan's own envelope. The
paragraph now describes the spawn path; the standalone script invocation
below it is re-labeled as the same validator run directly rather than a
stopgap, and its example flag is corrected from the non-existent
`--board-yaml` to the script's actual `--input`.

The two neighbouring claims in the same reference page were checked against
tan-cli v0.6.0 and found still accurate, so left unchanged: `docs/cli.md:135`
("Interactive init prompts are not yet ported") -- `tan init`'s docstring
still says NOT PORTED at that tag; and `docs/cli.md:369` (the `tan kconfig`
mode's "fails loudly (exit 2)" without a bootstrapped `ZEPHYR_BASE`) -- a
different, unrelated command whose exit-2 behavior is unchanged.

Swept the same two defects out of `AGENTS.md` (lines 89-94), which carried an
identical copy of the stale porting claim and the same wrong flag. Verified
`docs/board-id.md:74`'s `--board-yaml` is NOT affected: that one invokes
`scripts/program_eeprom.py`, whose parser really does take `--board-yaml`
(`scripts/program_eeprom.py:185`).
