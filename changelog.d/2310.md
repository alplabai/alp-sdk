### Fixed — Ethos-U op tables re-pinned to vela 5.2.0, real-vela CI coverage restored (#2310)

`metadata/npu_ops/ethos_u/{u85,u55-u65}@vela-5.1.0.json` and
`scripts/gen_npu_ops.py`'s `_EXPECTED_U85_ONLY_DELTA` (17 ops) were pinned to
`ethos-u-vela` 5.1.0, but `pyproject.toml`'s `model-compile` extra declared
only `ethos-u-vela>=3.9`, so CI installed whatever the latest release was --
5.2.0 at the time this landed. #1470 had made the real-vela smoke test in
`tests/scripts/test_gen_npu_ops.py` skip rather than fail when the installed
vela disagreed with the committed pin, which kept CI green but also meant the
one test that proves the tables are fresh against a real toolchain never ran
in CI at all.

Regenerated both tables against a real `ethos-u-vela` 5.2.0
(`u85@vela-5.2.0.json`, 74 ops; `u55-u65@vela-5.2.0.json`, 55 ops), replacing
the 5.1.0 files -- the tables are keyed one-per-(variant, toolchain,
toolchain_version) identity, not versioned side by side, and
`scripts/gen_npu_ops.py` already deletes a variant's superseded-version file
on regeneration. `_EXPECTED_U85_ONLY_DELTA` is updated deliberately to the
19-op set vela 5.2.0 reports: the 17 ops pinned at 5.1.0 plus
`ASSIGN_VARIABLE` and `READ_VARIABLE`.

`pyproject.toml`'s `model-compile` extra now pins `ethos-u-vela==5.2.0`
exactly (not `>=`), so the CI job that installs it
(`pr-metadata-validate.yml`'s `pip install -e ".[dev,model-compile]"` step,
the only site that installs `ethos-u-vela` in this repo) matches the
committed tables' pin and the real-vela smoke test now runs instead of
skipping. `uv.lock` is re-pinned to the same `ethos-u-vela` 5.2.0 (it had
resolved 5.1.0 from before the exact pin existed, and no CI step runs `uv
lock --check` to catch that on its own) -- a new hermetic test reads
`uv.lock`'s own resolved version and fails if it ever drifts from
`pyproject.toml`'s pin again.
