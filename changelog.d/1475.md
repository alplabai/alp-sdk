### Fixed — `pr-bitbake.yml` spliced a fork PR's head branch name into an unguarded `run:` block, a GitHub Actions template injection (#1475)

`.github/workflows/pr-bitbake.yml`'s `Resolve target sha/ref` step ran
*before* the fork guard and interpolated `${{ github.event.pull_request.head.ref
}}` directly into its `run:` block's source text via `${{ }}`. A git branch
name may legally contain shell metacharacters — `$()`, backticks, `;`, `&`,
`|` are all valid in `git-check-ref-format` — so a fork PR opened from a
branch named e.g. `x$(id)` would have that payload substituted into the shell
script *before bash ever parsed it*, and executed on the GitHub-hosted
runner. The App-token mint step that reaches
`secrets.ALP_CI_APP_PRIVATE_KEY` runs two steps later in the same job.

Fixed by passing `github.event.pull_request.head.sha`/`.head.ref` through an
`env:` block and referencing them as quoted shell variables
(`"$HEAD_SHA"`/`"$HEAD_REF"`) instead of splicing `${{ }}` into the script
text — the value is then only ever *data*, never re-parsed as shell syntax.
The same fix was applied to the *consuming* `Dispatch build to
alp-sdk-internal` step, which forwarded the now-safe step outputs
(`steps.t.outputs.ref`) back into a second unguarded `${{ }}` splice — `${{
}}` re-substitutes into every `run:` block independently, so quoting it once
at the producer does not protect a later consumer.

The `Resolve target sha/ref` step itself mints no secret and stages no
request (it only writes step outputs), so it does not additionally need the
fork guard's `if:` — the env indirection alone removes it as an injection
vector, for every event type.

Same construct, second site: `.github/workflows/dispatch-tan-parity.yml`'s
`Dispatch planner-change to tan-cli` step spliced `${{ github.ref_name }}`
directly into a `run:` block. Lower severity — this trigger is `push` to
`dev`/`main` only, so `ref_name` is always `dev` or `main` today, not
fork-controllable — but fixed the same way for consistency, since the trigger
scope is a workflow-file fact rather than an enforced guarantee.

Swept every workflow under `.github/workflows/` for `${{ }}` in a `run:` body
deriving from `github.event.pull_request.*`, `.issue.*`, `.comment.*`,
`github.head_ref`, or `github.actor`: no further sites found.
`github.event.pull_request.head.repo.full_name` (used in the fork guard's
`if [ ... ]` comparison) and `steps.t.outputs.sha`/`github.sha` (git commit
hashes) were judged safe to leave as direct interpolation — GitHub restricts
repo full names and commit SHAs to charsets with no shell metacharacters.
