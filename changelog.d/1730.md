### Fixed — the GD32 PWM ceiling was documented as the unprescaled ~303 us (#1730)

`docs/gd32-bridge-protocol.md` and `metadata/chips/gd32g553.yaml` both
stated a "~4.63 ns LSB" and a "~303 us" longest period as the achievable
GD32 PWM figures. Both numbers are arithmetically right for the timer
running **unprescaled** off the 216 MHz CK_TIMER — and neither is what the
firmware surfaces, because it always programs a fixed 216:1 prescale to a
1 MHz tick. The real figures are a **1 us LSB and a 65.536 ms** longest
period at full 16-bit count.

The protocol document already contradicted itself on this: a dozen lines
below the ~303 us claim it correctly describes a channel reporting "the
boot default (65.536 ms period, 0 duty)".

The stale figure was not inert. #1730 was found while reviewing
`fix/1635-pwm-status-parity`, whose new comment cited the ~303 us number
as the `OUT_OF_RANGE` mechanism — a wrong justification reached for
precisely because the documented ceiling was wrong. `gd32g553.yaml`'s
`pwm_routing.notes` also claimed periods beyond ~303 us "require the
firmware's repetition-counter / prescaler logic", implying a longer period
is reachable by some other path; it is not.

Both sites now give the prescaled figures, name the unprescaled ones as
what they are, and record the consequence a caller can actually hit:
**a period longer than 65.536 ms is currently clamped by the firmware and
still reported as success**, so it cannot be detected from the return code
— read back with `CMD_PWM_GET`.

Documentation only; no behaviour changes here. The clamp itself is a
firmware defect and is not fixable from this repo — `firmware/gd32-bridge/`
has zero tracked files on `dev` and lives in the separate
`gd32-bridge-firmware` repo (ADR-0031). The `PWM_TIMER_PRESCALER` /
`PWM_TIMER_TICK_NS` / `PWM_TIMER_ARR_MAX` constants the 65.536 ms figure
derives from are in that repo; the value is corroborated in-tree by the
protocol document's own boot-default line. #1730 tracks the firmware-side
refuse-don't-clamp fix, which is bench-owed.
