### Documented — no AE822-specific `app-device-config.json` exists yet; stop leaving it to inference (#1701)

SETOOLS **1.110.00** ships no AE822-specific device config: the stock
`build/config/app-device-config.json` declares `"device": "AE722F80F55D5AS"`,
an **E7** part, not the E1M-AEN801's `AE822FA0E5597LS0`. Every customer
provisioning an AEN801 was either using a config named for different silicon
or hand-editing one with no documented basis for the edit.

`docs/aen-provisioning.md` §3 now states plainly what is and is not
established, rather than leaving it to inference:

- **`device` is very likely toolchain metadata, not silicon-relevant** — the
  SE reports the correct part identity from OTP (`ALIF_PN = AE822FA0E5597LS0`)
  regardless of which part the config file names.
- **The HFXO trim fields match our AE822** — the reference board's own clock
  register readback (`XO_REG1` → `xtal_cap:8 gm_pfet:16 gm_nfet:16`) agrees
  with the stock file's `HFXO_CAP_CTRL`/`HFXO_PFET_GM_CTRL`/`HFXO_NFET_GM_CTRL`.
- **The rest of the file — notably its `firewall` block — is unverified for
  AE822.** SETOOLS' other stock config (`app-device-config-1c.json`, a third
  part) ships a *different* `HFXO_CAP_CTRL` and an empty `firewall` block,
  which is proof these fields are part-specific in general; the E7 file's
  firewall memory-protection regions have not been bench-validated against
  AE822 and are not covered by either bullet above.

**No new device-config file ships with this change**, in either `alp-sdk` or
`alp-sdk-internal`. `app-device-config.json` is a licensed SETOOLS deliverable
(firewall/MPE permission regions, not just clock trim), so a hand-produced
copy would be inventing vendor-owned security configuration rather than
qualifying it — exactly the class of defect this repo refuses to ship blind.
alp-sdk#1701 is item 3 of the open Alif escalation tracked at alp-sdk#1700;
until Alif answers whether the stock file is intended for AE822 unmodified,
the documented guidance is to use it as-is and not hand-edit the `device`
field.
