### Documented — Alif confirmed no AE822-specific `app-device-config.json` is needed (#1701)

SETOOLS **1.110.00** ships no AE822-specific device config: the stock
`build/config/app-device-config.json` declares `"device": "AE722F80F55D5AS"`,
an **E7** part, not the E1M-AEN801's `AE822FA0E5597LS0`. Every customer
provisioning an AEN801 was either using a config named for different silicon
or hand-editing one with no documented basis for the edit.

Alif answered the open question directly:

> The provided app-device-config.json works with either E7 or E8. The part
> number field is just a text field for your own usage. The important thing
> to note is the part number selected when you execute tools-config, as that
> is what app-gen-toc and app-write-mram use.

`docs/aen-provisioning.md` §3 now states this plainly and closes the
question:

- **`device` is confirmed cosmetic, not silicon-relevant** — matching the SE
  reporting the correct part identity from OTP (`ALIF_PN = AE822FA0E5597LS0`)
  regardless of which part the config file names.
- **The HFXO trim fields already matched our AE822** independently: the
  reference board's own clock register readback (`XO_REG1` →
  `xtal_cap:8 gm_pfet:16 gm_nfet:16`) agrees with the stock file's
  `HFXO_CAP_CTRL`/`HFXO_PFET_GM_CTRL`/`HFXO_NFET_GM_CTRL`.
- **What actually binds the ATOC to a part is the `tools-config -a` step**,
  per Alif, not this file — `app-gen-toc`/`app-write-mram` key off the part
  `tools-config` selected, not the `device` string.

**No new device-config file ships with this change**, in either `alp-sdk` or
`alp-sdk-internal`. Alif's answer is a functional guarantee ("works with
either E7 or E8"), not a field-by-field spec — it settles *whether* to use
the stock file as-is without individually certifying every field (e.g. the
`firewall` block). `app-device-config.json` also remains a licensed SETOOLS
deliverable carrying Alif-owned configuration beyond the `device` string, so
a hand-produced copy would still be inventing vendor-owned content rather
than qualifying it, independent of Alif's answer.

The documented guidance: use the stock `app-device-config.json` unmodified,
as the reference board does; do not hand-edit its `device` field. alp-sdk#1701
was item 3 of the Alif escalation tracked at alp-sdk#1700 — closed.
