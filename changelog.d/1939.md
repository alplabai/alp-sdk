### Added — regression coverage for the three GATT read/write context-pool branches #1620 left unexecuted (#1939)

`changelog.d/1620.md` shipped the `_read_ctx_pool` / `_write_ctx_pool` +
`alp_slot_try_claim()` / `alp_lifecycle_cas()` design in
`src/backends/ble/zephyr_drv.c` and recorded three of its branches as
unexecuted anywhere — not in CI, not on the bench: the abandon path (a
timed-out caller winning the `LIVE -> ABANDONED` CAS), the
`alp_lifecycle_cas()` loss (a late callback finding its ctx already
abandoned), and the `ALP_ERR_BUSY` refusal (a claim against an exhausted
pool). `native_sim` ships no BLE controller, so no real peer can drive any
of them.

`z_gatt_read()`'s and `z_gatt_write()`'s post-timeout handling is split out
into `_read_ctx_on_timeout()` / `_write_ctx_on_timeout()` so a
`CONFIG_ZTEST` seam can drive the exact abandon-path code directly instead
of needing a live `bt_gatt_read()`/`bt_gatt_write()` to ever time out for
real. New `CONFIG_ZTEST`-only seams in `src/backends/ble/zephyr_drv.c`, in
the same style as the existing `alp_ble_test_read_cb()` (issue #480) and the
pattern this tree already uses elsewhere for the same offline-controller
problem (`alp_adc_stream_read_test_sync_hook`,
`g_rpc_dispatch_test_sync_hook`):

- `alp_ble_test_read_timeout()` / `alp_ble_test_write_timeout()` — drive
  `_read_ctx_on_timeout()` / `_write_ctx_on_timeout()` on a ctx that never
  had its callback fire, proving the caller wins the abandon CAS and
  returns `ALP_ERR_TIMEOUT` with the slot left claimed, not freed.
- `alp_ble_test_read_cb_after_abandon()` / `alp_ble_test_write_cb_after_abandon()`
  — call `ble_read_cb()` / `ble_write_cb()` on a ctx that starts
  `BLE_PROC_ABANDONED`, proving the callback's own CAS loses and returns via
  `_read_ctx_free()` / `_write_ctx_free()` without touching the
  caller-visible buffer or signalling `ctx->done`.
- `alp_ble_test_set_ctx_pools_exhausted()` + `alp_ble_test_fake_conn_be()` —
  claim every pool slot and supply a `ble_conn_be` whose `bt` is non-NULL
  but never dereferenced, so `tests/zephyr/ble_gatt_server` can drive the
  real, registered `ops->gatt_read()` / `ops->gatt_write()` through the
  actual `ALP_ERR_BUSY` return — safe offline because the busy check runs
  before either op would touch a live connection.

New tests in `tests/zephyr/ble_gatt_server/src/main.c`:
`test_client_read_timeout_abandons_procedure`,
`test_client_write_timeout_abandons_procedure`,
`test_client_read_cb_after_abandon_loses_cas`,
`test_client_write_cb_after_abandon_loses_cas`,
`test_client_gatt_read_busy_when_pool_exhausted`,
`test_client_gatt_write_busy_when_pool_exhausted`. All three branches named
in #1620 and #1939 are exercised; none of the new tests take a shortcut that
would also pass against the pre-#1620 code — each drives the real
production function, not a reimplementation.
