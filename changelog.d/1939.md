### Added — real coverage for the GATT context pool's CAS loss and `ALP_ERR_BUSY` refusal; the abandon path is bench-owed (#1939)

`changelog.d/1620.md` shipped the `_read_ctx_pool`/`_write_ctx_pool` +
`alp_slot_try_claim()`/`alp_lifecycle_cas()` fix for the GATT read/write
context-lifetime bug with its regression test still owed: three branches of
the pool state machine in `src/backends/ble/zephyr_drv.c` -- the abandon path
(a caller's timeout winning the `LIVE -> ABANDONED` CAS), the CAS loss (a
late `ble_read_cb()`/`ble_write_cb()` losing that same CAS because the
caller already won it), and the `ALP_ERR_BUSY` refusal (`z_gatt_read()`/
`z_gatt_write()` refusing once `_read_ctx_alloc()`/`_write_ctx_alloc()`
return `NULL` against an exhausted pool) -- had zero execution anywhere, CI
or bench. `native_sim` ships no BLE controller, so no real peer can drive
`z_gatt_read()`/`z_gatt_write()` end-to-end offline to reach them.

New `CONFIG_ZTEST`-only seams in `src/backends/ble/zephyr_drv.c`, in the same
style as the existing `alp_ble_test_read_cb()` (issue #480):

- **CAS loss** (genuinely covered): `alp_ble_test_read_cb_loses_cas_after_abandon()`
  / `alp_ble_test_write_cb_loses_cas_after_abandon()` pre-abandon a synthetic
  ctx via the real `alp_lifecycle_cas()` call, then feed it into the real
  `ble_read_cb()`/`ble_write_cb()` so its own CAS genuinely loses -- against
  the actual production callbacks, not a reimplementation.
- **`ALP_ERR_BUSY` refusal** (genuinely covered, driven through the production
  entry point): `alp_ble_test_gatt_read_busy()` / `alp_ble_test_gatt_write_busy()`
  exhaust the real pool through `_read_ctx_alloc()`/`_write_ctx_alloc()`, then
  call the real (`static`) `z_gatt_read()`/`z_gatt_write()` with a non-NULL
  `bt` sentinel that the pool-exhaustion check refuses before ever
  dereferencing it. Both seams require their own claiming loop to have
  actually reached the pool's real capacity before calling into
  `z_gatt_read()`/`z_gatt_write()` -- otherwise they return `ALP_ERR_NOT_READY`
  instead, distinct from the `ALP_ERR_BUSY` the test asserts, so a broken
  allocator (one that refuses every claim, or a pool already exhausted on
  entry) fails the test loudly instead of answering `ALP_ERR_BUSY` for the
  wrong reason.
- **Pool-exhaustion tautology avoided**: `alp_ble_test_read_ctx_pool_exhausts()`
  / `alp_ble_test_write_ctx_pool_exhausts()` report the claim count rather
  than re-reading the same `_read_ctx_alloc() == NULL` condition the loop
  already exited on, and only probe for a spare slot once every real slot is
  confirmed held -- freeing that probe immediately rather than leaking it if
  a bug ever lets it succeed.
- **Abandon path: declared bench-owed, not seamed.** `z_gatt_read()`'s /
  `z_gatt_write()`'s own timeout-driven `alp_lifecycle_cas(LIVE ->
  ABANDONED)` stays zero-executed -- no offline seam reaches it without
  reimplementing the timeout race itself. Tracked as bench-owed in
  `docs/test-plan.md` instead of claimed.

All seams are `#if defined(CONFIG_ZTEST)`-gated, the same guard the file's
existing `alp_ble_test_read_cb()` seam already used -- a release build never
sees these symbols at all, so this changes no production behaviour.

**Still not closed by this change:** the abandon branches above, plus
`z_gatt_read()`/`z_gatt_write()`'s own calls into `bt_gatt_read()`/
`bt_gatt_write()`, stay `BENCH-UNVERIFIED` and need a real two-device bench
proof. `src/backends/**` is bench-held per #1937; this change is authored
only, not merge-eligible on its own.
