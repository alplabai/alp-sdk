### Fixed — BLE self-close and mbox close left two use-after-free-shaped gaps (#1644)

`alp_ble_scan_start()`'s deferred self-close branch — taken when `alp_ble_close()`
is called reentrantly from inside a scan callback (#756) — called `_free_radio(h)`
with **no `_conn_pool` walk at all**. #1697 added that walk to `alp_ble_close()`
only, so a radio closed from inside its own scan callback while connections were
live left every `c->state.radio` back-pointer dangling at a recycled radio slot.
The walk is now factored into a shared `_disconnect_radio_conns()` helper called
from both `alp_ble_close()` and the self-close branch, at the same point in each
(after the op drain, before `ops->close()`), so the two teardown paths cannot
drift apart again the way they just did.

`src/backends/mproc/zephyr_drv.c`'s `z_mbox_close()` disabled the channel and
freed its `mbox_be` state, but never called `mbox_register_callback(..., NULL,
NULL)` first — `z_mbox_set_callback()` registers that same `mbox_be` pointer as
the Zephyr mbox driver's callback `user_data`, so the registration outlived the
memory it pointed at. `z_mbox_close()` now unregisters before freeing (disable →
unregister → free). This is defence-in-depth restoring the documented invariant
("stop backend callbacks before the slot is released"), not a demonstrated live
crash — with the channel already disabled the stale registration is not known to
be reachable.

Regression coverage: `tests/yocto/ble_dispatch_conn_pool_orphan.c` gains a fourth
scenario (`test_self_close_releases_conn_slots`) driving the self-close path with
a live connection and asserting the conn slot is released and the peer link
disconnected through the backend — mutation-tested by reverting only the new
`_disconnect_radio_conns()` call on the self-close branch (fails 2/2 assertions)
and restoring it (passes 24/24 in that binary).
