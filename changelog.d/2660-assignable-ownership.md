### Added — one machine source for per-product core ownership: `assignable:` + board.yaml `ownership:` (#2660)

`metadata/e1m_modules/v2n/core-ownership.yaml` keeps `core_ownership:` for fixed facts and gains an `assignable:` block keyed by E1M instance (`e1m_uart0`, `e1m_uart1`, `e1m_spi0`, `e1m_can0`, `e1m_can1`), each with a `default` (`a55`), the `candidates` that have a real backend today, and references to existing `(peripheral, pad)` pinmux rows. A project overrides a default with a top-level `ownership: {<instance>: <core>}` in `board.yaml`; the loader rejects an unknown instance or a core outside `candidates`, and `--emit system-manifest` gains an additive `ownership:` map (omitted for SoMs without assignable resources). `core-ownership-v1.schema.json` is new and `validate_metadata.py` checks that assignable rows exist in `metadata/pinmux/v2n.yaml`, are not also fixed rows, and name real SoC cores. `m33` is a candidate only for `e1m_spi0`; UART0 waits for the P51 RX pull-up bench proof, UART1 has no CM33 node, CAN-FD has no CM33 driver. No generator output changes yet.
