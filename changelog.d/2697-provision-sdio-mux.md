### Added — provisioning takes the microSD out through the EVK SDIO mux, no operator step (#2697)

- **`sd_out_emmc_boot` replaces the operator step `dsw1_xspi_remove_sd`.** Leg 2 no longer asks for the card to be pulled. On the provisioning SD Linux it persists the GD32 `BOOT_CONFIG` flag `SDMUX_EN_HIGH` over the bridge I2C link (opcode `0x42`, `linux_target.gd32_sd_out_flag_set()`; a SET moves no pad, so it cannot pull the root), cold-boots into the eMMC Linux, then drives IO29 `SDIO_MUX_EN` high there with `linux_target.sdio_mux_set()` and re-reads the stored flag. The flag keeps the SD out across every later cold cycle, so `cold_boot_test` runs without the card. The mux write is write-only: a bridge GPIO read reconfigures the pad and moved the mux on the bench (#2701), so the pad is never read, and `SDIO_MUX_SEL` is never touched. Disconnecting is refused while Linux runs from the SD (mmcblk1). A unit already on the eMMC skips the flag and the cold cycle. Not yet benched.
