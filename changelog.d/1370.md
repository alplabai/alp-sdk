### Removed — the GD32 and CC3501E firmware trees, and the two unit suites that linked them (#1370)

The bridge firmware now lives in its own repositories (ADR 0031), so
`firmware/gd32-bridge/` and `firmware/cc3501e/` are gone from this repo. The
host halves — `chips/gd32g553/`, `chips/cc3501e/` — are unchanged, and the wire
contract stays single-sourced.

`tests/unit/gd32_bridge_ota` and `tests/unit/gd32_bridge_transport` go with
them. Those two suites deliberately linked the **real** firmware sources rather
than mocks, so with the firmware removed they pointed at deleted files and
failed to configure at all:

```
alp.unit.gd32_bridge_ota on native_sim/native/64 error
  (CMake Error at CMakeLists.txt:13 (target_sources): Cannot find source file:)
```

They were **moved, not deleted** — they now run in
[gd32-bridge-firmware](https://github.com/alplabai/gd32-bridge-firmware) as a
host-only `ctest` job against a small ztest shim, byte-identical to the
originals. A test that lives in a different repository from its subject is a
test nobody runs, and repointing them at an optional external checkout would
have meant a suite that silently stops running whenever that checkout is
absent.

The host-side GD32 coverage in this repo is unaffected:
`tests/zephyr/chips/gd32g553/` still exercises the driver against the committed
wire vectors, whose regeneration is now checked by the firmware repo's own CI.
