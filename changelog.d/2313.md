### Fixed — AEN bench scripts: chunk mem8 reads >0x10000 and clear NVIC in openocd-ram-run.sh's HE path (#2313)

Two AEN bench-script gaps surfaced while bench-verifying #2299 on an
E1M-AEN803 EVK (2026W36-0009):

- `scripts/bench/aen/ram-run.sh` and `reread.sh` read the RAM console with a
  single JLinkExe `mem8 <addr>,<size>`. JLinkExe caps `NumBytes` at
  `0x10000` (`NumBytes should be <= 0x10000`), so any read larger than that
  returned nothing at all — silently, which is why `aen-inference-energy`
  had shrunk its buffer to exactly `0x10000` to work around it instead of
  fixing the read. A shared `bench_mem8_chunks()` helper (`bench-env.sh`)
  now splits any read into `mem8` chunks of at most `0x10000` bytes each,
  and both scripts route their read session through it; the existing
  line-oriented decoders need no change, since the chunked dump lines still
  land in the transcript in strict address order.
- `scripts/bench/aen/openocd-ram-run.sh`'s HE (and shared HP) path zeroed
  MSPLIM/PSPLIM before resuming a freshly loaded image but left NVIC state
  untouched. A resident HE app that left an IRQ enabled or pending ran the
  new image straight into that app's ISR the moment IRQs unmasked — seen:
  IRQn 333 (`CDC_SCANLINE0`), core stuck at IPSR `0x15D`. The script now
  clears every NVIC ICER and ICPR register (n = 0..15, IRQ 0-511) before
  `resume`, in addition to the existing MSPLIM/PSPLIM clear.

Not changed: a pre-load core/AP-identity assertion for the J-Link path
(read `0x58000000` HE ITCM before loading) was scoped out — `ram-run.sh`'s
JLinkExe generic `Cortex-M55` attach has no per-core AP selector to check
against in the first place (unlike `openocd-ram-run.sh`'s AP-addressed
core selection), so there is no non-trivial place to hang the assertion at
this layer without restructuring how that script attaches.
