### Fixed — V2M102/V2M103 and V2N102/V2N103 kernels no longer report the V2M101/V2N101 machine model (#2657)

The V2M101/V2M102/V2M103 machines all boot one board dtb,
`e1m-v2m101-x-evk.dtb`, and the V2N101/V2N102/V2N103 machines share
`e1m-v2n101-x-evk.dtb`. Both dtbs hard-coded the first SKU in their root
`model`, so an E1M-V2M103 printed
`Machine model: ALP E1M-V2M101 on E1M-X-EVK (RZ/V2N + DEEPX DX-M1)`.
The `model` strings are now SKU-neutral (`ALP E1M-V2M on E1M-X-EVK ...`,
`ALP E1M-V2N on E1M-X-EVK ...`). The module's own SKU still reaches Linux
from its identity EEPROM through U-Boot's `/chosen/alp,sku`. The root
`compatible` strings are unchanged, so the brcmfmac board-named firmware
links and the dtb name U-Boot loads stay the same.

`tests/scripts/test_board_dts_model_names_no_sku.py` fails if a board dts
that more than one machine builds names a SKU in its `model`.
