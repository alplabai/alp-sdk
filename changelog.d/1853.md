### Fixed — the boot banner now warns when the compiled SoM `hw_rev` disagrees with the live EEPROM manifest (#1853)

The SDK compiles E1M pad routing for `board.yaml`'s `som.hw_rev` (falling
back to the SKU preset's `default_hw_rev`), and separately reads the SoM's
*actual* revision from the on-module EEPROM manifest at boot — but nothing
compared the two. On the AEN family, three pads (`E1M_GPIO_IO8`,
`E1M_GPIO_IO10`, `E1M_GPIO_IO21`) resolve to a *different chip* depending on
which revision is right, so a build could be compiled to drive a CC3501E
GPIO proxy for a pin that is physically wired to the Alif SoC (or vice
versa), with no diagnostic anywhere: `alp_hw_info_assert_matches_build()`
existed but had zero call sites in the tree.

The boot banner (`CONFIG_ALP_SDK_BANNER`, on by default) now compares the
live manifest's `hw_rev` against the newly-emitted
`CONFIG_ALP_SDK_SOM_HW_REV` (`scripts/alp_orchestrate.py`, from the same
`som.hw_rev` pad routing was compiled against) and prints a loud warning on
a disagreement. This is a warning, not a boot refusal, by default: a
factory-fresh module with no EEPROM manifest yet (`ALP_ERR_NOT_PROVISIONED`)
is an expected state and never trips it, and bricking a developer's board
over a revision string is a worse failure mode than a possibly-wrong pin. A
production build that would rather halt closed opts in via the new
`CONFIG_ALP_SDK_HW_REV_MISMATCH_FATAL`.

Not implemented here, and deliberately so: refusing to *dispatch* only the
specific pads whose route actually differs between hw_revs (the issue's
"stronger guard"). That needs a build-time-emitted table of which `E1M_*`
pads are hw_rev-ambiguous for a given SKU plus every peripheral-class
dispatcher consulting it — a cross-cutting change across the whole dispatch
layer, not a boot-banner-sized fix. `CONFIG_ALP_SDK_HW_REV_MISMATCH_FATAL`
is today's coarser mitigation: it halts before any pad is ever dispatched,
at the cost of covering the whole app rather than just the ambiguous pads.

Bench-gated: verified against a crafted manifest under native_sim
(`tests/zephyr/hw_info`); not yet re-verified against the physical bench
module (`E1M-AEN801 r1`, serial `2617-0001`) that reported the original
mismatch.
