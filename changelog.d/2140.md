### Fixed — TAS2563 TDM clock fault is now armed, and a live TDM-detect readback is now available (#2140)

`TAS2563_FAULT_TDM_CLOCK` reads `INT_LTCH0[2]`
(`include/alp/chips/tas2563.h:346` ("TAS2563_FAULT_TDM_CLOCK")), but
`INT_MASK0`'s reset value `FCh` leaves that bit masked and a masked event
never latches at all -- nothing in the driver unmasked it, so the flag read
clear whether the TDM/I2S clock was present, stopped, or never valid.
Measured on `e1m-aen-evk-03` from the TAS2563 phase of
`examples/aen/aen-evk-demo` (`src/main.c`, "Phase 11"): the flag stayed
`0x00000000` both while playing and after `alp_audio_out_stop()`,
discriminating nothing (SLASET3D §7.5.28-§7.5.31, p.77-80, already cited at
`include/alp/chips/tas2563.h:749` for the other three `INT_MASK` registers).

`tas2563_configure_fault_pin()` now clears `INT_MASK0` bit 2 as part of
binding the fault pin
(`chips/tas2563/tas2563.c:655` ("reg_update(ctx, TAS2563_REG_INT_MASK0")),
citing the register address already modelled by the fake at
`tests/zephyr/chips/src/fake_tas2563.c:97` ("INT_MASK0   §7.5.28 p.77") and the
bit position already recorded in the driver header
(`include/alp/chips/tas2563.h:749`, pre-fix, "`INT_MASK0[2]`"). A caller
binding a fault pin gets every safety-relevant latch reaching both IRQ_N and
`tas2563_read_faults()`, TDM clock loss included, rather than having to know
to write `INT_MASK0` directly. `tas2563_read_faults()`'s doc comment
(`include/alp/chips/tas2563.h:819` ("@note A masked event never latches"))
now states which faults are armed by default: over-temperature/over-current
(`INT_MASK0`), VBAT brown-out/speaker open-short (`INT_MASK1`) and VBAT POR
(`INT_MASK2`) at reset, TDM clock error once a fault pin has been configured
(#2140), and `INT_MASK3` (`FFh`) masked wholesale with nothing in this driver
unmasking it.

A new public accessor, `tas2563_read_tdm_detect()`
(`include/alp/chips/tas2563.h:893`, implemented at
`chips/tas2563/tas2563.c:754`), decodes the LIVE auto-rate detector at `DSP
Mode & TDM_DET` (register `0x11`, read-only, SLASET3D §7.5.19 Table 7-119,
p.73) into a `tas2563_tdm_detect_t` (`include/alp/chips/tas2563.h:387`): a
detected SBCLK:FSYNC ratio, a detected sample-rate pair, and a `clock_valid`
flag. This answers a different question from `TAS2563_FAULT_TDM_CLOCK`
above: that bit is a latched history of clock faults, gated on a fault pin
having been bound; this readback is unlatched, needs no fault pin, and
reflects what the auto-rate detection engine sees on the wire right now.
Register `0x11` resets to `7Fh` (`FS_RATIO=Fh` "Invalid ratio", `FS_RATE=7h`
"Error condition"), which the function decodes as `clock_valid == false`
with no special-casing needed. Table 7-119 -- the register's own field
description -- disagrees with §7.4.2 Table 7-23 "PCM Audio Sample Rates"
(p.40) and Table 7-24 "PCM SBCLK to FSYNC Ratio" (pp.40-41) at the edges of
both fields (Table 7-23 marks `FS_RATE` `000b`/`010b` Reserved where Table
7-119 gives them real rates; Table 7-24 marks `FS_RATIO` `0h`-`3h` Reserved
and `Fh` "Error Condition" where Table 7-119 decodes `00h`-`03h` as real
ratios and `0Fh` specifically as "Invalid ratio"); the decode follows Table
7-119 -- what the silicon reports back on this exact read -- and the field
macros' comment in `chips/tas2563/tas2563.c:89` names both tables rather
than picking one silently, the same discipline `samp_rate_code()` already
applies on the write side.

`examples/aen/aen-evk-demo`'s TAS2563 phase ("Phase 11", `src/main.c`) now
prints `tas2563_read_tdm_detect()` alongside `tas2563_read_faults()` at both
the fault baseline (`examples/aen/aen-evk-demo/src/main.c:4374`) and the post-teardown re-read
(`examples/aen/aen-evk-demo/src/main.c:4610`), rather than swapping the latch for the live read: the
latch answers "did a clock fault ever happen", the live read answers "what
is the clock doing right now", and the phase now reports both. The existing
`TAS2563_FAULT_SHUTDOWN_CAUSES` exclusion of `TAS2563_FAULT_TDM_CLOCK`
(`examples/aen/aen-evk-demo/src/main.c:4592`, #2146) is unchanged by this -- the live reading is
additional diagnostic output, not a new pass/fail gate.
