### Added — the build plan lists the `${NAME}` placeholders it leaves for the build host or the device (#2696)

A board.yaml value written as `${NAME}`, such as `ota.server.tenant: "${MENDER_TENANT_TOKEN}"` in `examples/connectivity/iot-fleet-ota` and `production-deployment`, is copied verbatim into a slice config artefact for the build host or the device to fill. Nothing in the plan told it apart from a plan path token (`${SDK_ROOT}`, `${PROJECT_ROOT}`, `${PYTHON}`), so tan refused both examples' whole plan as an unresolved token (alplabai/tan-cli#1302).

The plan now carries a top-level `deferredPlaceholders`: the sorted names, always present and `[]` when there are none. It is additive under `schemaVersion` 1 (`metadata/schemas/build-plan-v1.schema.json`); a plan without the field is still valid.

`emit_build_plan` refuses a plan in which a `${NAME}`:

- collides with a plan token (`SDK_ROOT`, `PROJECT_ROOT`, `PYTHON`, `TOOLCHAIN_ROOT`), which a consumer would replace with a checkout path;
- is not upper-case (`[A-Z][A-Z0-9_]*`);
- does not appear as `${NAME}` in the project's board.yaml;
- sits in a config artefact that is not a `.conf` file, which CMake would expand itself (the same rule tan-cli#1306 applies);
- or appears outside `configArtefacts`.

The list only tells a consumer to leave these names alone. It does not make them resolve: on Yocto the emitted `MENDER_TENANT_TOKEN ?= "${MENDER_TENANT_TOKEN}"` refers to itself, and nothing passes the host's environment variable through to BitBake. That was already the case before this change and is not fixed here.

### Changed — a `${NAME}` placeholder on a live Zephyr Kconfig line is refused (#2696)

`ota.server.url: "${HAWKBIT_HOST}"` used to emit `CONFIG_HAWKBIT_SERVER="${HAWKBIT_HOST}"`, on the assumption that the build system substitutes it later. Nothing does: the pinned Zephyr v4.4.1 `.conf` loader only unescapes a string value, so the firmware would have carried the literal text as its server name. `_slice_alp_conf` now refuses any placeholder on a live line, which also stops `tan`'s configure-time `alp_project.py --emit zephyr-conf`. A commented line, such as the Mender-MCU-client hints, is still allowed. The test that pinned the old pass-through is replaced by one that pins the refusal.
