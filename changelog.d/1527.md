### Fixed — `scripts/bench/**` was linted by nothing, in CI or locally (#1527)

`stage_shellcheck` in `scripts/test-all.sh` was never invoked by any GitHub
Actions workflow — the only `shellcheck` that ran in CI was
`onramp-clean-container.yml`'s, scoped to `scripts/bootstrap.sh` alone
(`grep -n shellcheck .github/workflows/pr-static-analysis.yml` returned
nothing). On top of that, `stage_shellcheck`'s own glob was the flat,
non-recursive `scripts/*.sh`, so it never reached `scripts/bench/aen/*.sh`
even when run locally. Nothing under `scripts/bench/` was shellchecked
anywhere. That gap is exactly why
`scripts/bench/aen/flash-update-log-firewall-probe.sh:147`'s stray literal
`n` argument to `JLinkExe` (#1478, an SC1012-class defect) sat undetected —
it was still live on `dev` and is fixed in this same change, since turning
on the new gate would otherwise redden on its own addition.

Fixed two ways, so CI and the local wrapper agree on what "clean" means:

* `.github/workflows/pr-static-analysis.yml` gains a `shellcheck-bench` job
  that shellchecks every file `git ls-files 'scripts/bench/**/*.sh'` finds,
  **one file per `shellcheck` invocation** — batching every file into a
  single invocation was tried and rejected: shellcheck's cross-file
  source-following analysis silently dropped a real per-file `SC2034`
  finding (`flash-jlink-mramxip.sh`'s `GD32_DPIDR`) when run alongside the
  `bench-env.sh` it sources. `-S warning`, matching `stage_shellcheck`'s own
  severity for `scripts/test-all.sh` — `SC1012` (the `\n`-as-literal-`n`
  class) is warning-severity, so `-S error` alone would not have caught
  #1478.
* `scripts/test-all.sh`'s `stage_shellcheck` gets the same recursive
  `scripts/bench/**` sweep at `-S warning`, via the same `git ls-files`
  pattern `stage_bash32_parse` already uses, so the local gate stays a real
  mirror of the CI one instead of drifting back out of sync.

Turning the gate on surfaced two pre-existing `SC2034` findings, both kept
rather than deleted and documented with a `# shellcheck disable=SC2034`:
`flash-jlink-hp.sh`'s `OBJ` (this flow reads its beacon via J-Link `mem32`,
not `$OBJ-nm`/`-readelf`, unlike every sibling `flash-jlink*.sh`; the
assignment is kept as a toolchain-resolves preflight) and
`flash-jlink-mramxip.sh`'s `GD32_DPIDR` (kept alongside `AEN_DPIDR`'s pin as
the documented wrong-board value — deleting either half of that pair
previously weakened the wrong-board MRAM-write gate during #1488 and had to
be reverted).

`docs/ci/README.md`'s `pr-static-analysis.yml` row is updated to mention the
new `shellcheck` coverage.
