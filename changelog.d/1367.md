### Removed — `scripts/alp_cli/explain.py`; corrected `docs/cli.md`'s two now-false `tan explain` claims (#1367)

`tan explain --code <CODE>` shipped in `alplabai/tan-cli#627` (released
`v0.6.0`), porting the `ALP-Bxxx` / `ALP_ERR_*` diagnostic-code lookup out of
`scripts/alp_cli/explain.py`. That wrapper's only remaining consumer was
`scripts/alp_cli/main.py`'s own `click.group`, itself retired in this
change (#1368); `tests/scripts/test_alp_explain.py` retired with it. The
generator/emitter side is untouched: `scripts/gen_error_catalog.py` and
`metadata/error-catalog.json` stay exactly as before — `explain.py` never
read `docs/diagnostics/*.md` or the `ALP_ERR_*` enum, only the catalog
`gen_error_catalog.py` already produces, so nothing here is orphaned.

`docs/cli.md`'s `explain` comparison row and its `tan explain` verb section
both stated `tan explain` "never takes a diagnostic `CODE` lookup" and that
an `ALP-Bxxx` code "is decoded ... not by `tan explain`". Both are corrected:
`tan explain --code ALP-Bxxx` is documented as the third selector alongside
`--template`/`--target`, the one mode that reads an SDK checkout (via the
`--sdk-root` ladder), verified end-to-end against a real `tan 0.6.0` and this
checkout's own `metadata/error-catalog.json`.
