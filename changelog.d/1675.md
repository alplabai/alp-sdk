### Added — CI gate: no two I2C devices may declare the same 7-bit address on the same bus (#1675)

`scripts/check_i2c_address_uniqueness.py` groups every declared I2C device by bus and by
7-bit address across `metadata/e1m_modules/*.yaml`'s `on_module.i2c_devices.<bus>.devices[]`,
`metadata/boards/*.yaml`'s flat top-level `i2c_devices:` list, and `metadata/boards/*.yaml`'s
`audio.codecs[]` list, and fails on any address claimed more than once on the same declared
bus. `assembled: false` devices are excluded; `assembled: optional` devices are NOT --
a part fitted only on some board variants still occupies its address when it is fitted.

The two pre-existing, open collisions this catches on the real tree (#1163: TMP112 vs
TPS628640, both on `brd_i2c` address `0x48` — TMP112 at
`metadata/e1m_modules/E1M-V2M101.yaml:51` and TPS628640's `deepx_lpddr_0v85` at
`metadata/e1m_modules/E1M-V2M101.yaml:57`, with the identical pair at
`metadata/e1m_modules/E1M-V2M102.yaml:47` and `metadata/e1m_modules/E1M-V2M102.yaml:53`)
are allowlisted in the script with the tracking issue named; the gate does not guess an
I2C address to make itself green.

Wired into `pr-metadata-validate.yml`'s `validate` job; `metadata/**` was already in that
workflow's `paths:` filter so both `metadata/e1m_modules/**` and `metadata/boards/**` already
retrigger it, and `scripts/check_i2c_address_uniqueness.py` itself is now added to the filter
too.

An `ALLOWLIST` entry excuses **one known set of claimants, not the address
forever**. The first cut of this gate keyed the allowlist on
`(file, bus, address)` alone; adding a third device at the allowlisted #1163
address then returned exit 0 with no output, so the gate silently accepted a
brand-new instance of the very collision it exists to catch. Each entry now
records the exact claimant set it excuses, and a collision whose claimants
differ from that set is reported normally. Covered by a regression test that
seeds a third claimant at an allowlisted address.

**Three defects found in review of the first two cuts, fixed here.**

The allowlist's claimant set was compared as a `frozenset`, which collapses
duplicates. `devices` has no `uniqueItems`, so two rows may legitimately carry
the same `chip=`/`role=` label -- and a THIRD claimant whose label matched one
already excused was therefore accepted silently at an allowlisted address.
Reproduced by duplicating the `tmp112` row in
`metadata/e1m_modules/E1M-V2M101.yaml`: three devices on `brd_i2c` `0x48`, gate
exit 0, no output. That is the same hole the per-address allowlist exists to
avoid, one level down. Now compared as a multiset, with a regression test that
seeds a duplicate-label third claimant.

A declared address above `0x77` is no longer treated as a distinct address. The
schema's pattern allows up to `0xFF`, so a device entered in 8-bit write-address
form -- `0xD0` for the 5L35023B, the form its own chip YAML quotes -- compared
unequal to the real `0x68` claimant and could never collide with it.

The docstring claimed to read "three declared-device shapes ... all three". That
overclaimed: `metadata/chips/*.yaml` instance tables carry an `addr_7bit` with a
free-text `scope:` rather than a machine-readable bus key, and
`examples/**/board.yaml` carries `hw_info.eeprom.{bus,addr_7bit}`. Both are now
named as deliberate exclusions with the reason, alongside a new, honest statement
that **cross-file joins are not performed**: a carrier's flat `i2c_devices:` and a
mounted SoM's `e1m_i2c*` bus can be the same physical bus
(`XEVK_I2C_BUS_SENSORS` is `ALP_E1M_X_I2C0`), but they live in different files and
the gate compares within a file only. Closing that would need a declared
SoM-to-carrier bus mapping the tree does not have.

A partially-declared `audio.codecs[]` entry is now reported instead of skipped.
`audio:` is a wholly open object in `metadata/schemas/board-preset.schema.json`
(`additionalProperties: true`, no inner shape) and this gate is its only reader
under `scripts/`, so a renamed key drifts unnoticed in both directions. An entry
carrying an address but no `i2c_bus` was dropped by a bare `continue` -- quietly
removing a real claimant from the comparison, which is how the gate goes green on
a collision it never saw. The failure summary now says "problem(s) ... (collisions
and/or uncomparable entries)" rather than calling an uncomparable entry a
collision.
