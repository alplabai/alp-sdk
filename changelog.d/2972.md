### Changed — `pr-metadata-validate.yml` is safe to require: `metadata-validate · all` summary context, `merge_group` trigger (#2972)

The `check_*.py` gate workflow had a `paths:` filter on `pull_request`/`push` and no `merge_group:` trigger, so requiring it would have blocked every PR touching no watched path (#1474) and hung the merge queue (#1415). The trigger is now unfiltered, the path list lives in a `detect` job, and a static-named `metadata-validate · all` summary job always reports (skip is a pass only when `detect` found nothing). On `merge_group` the gate steps re-run and the pytest sweep is skipped. The maintainer adds the context to `dev` branch protection after this merges.
