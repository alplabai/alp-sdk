### Added — `alp_camera_get_fps()` reports the frame rate the camera actually settled on (#2279)

`alp_camera_config_t::fps` is a request: the sensor or mode picks the nearest rate it supports, and until now the caller could not find out which one. `alp_camera_get_fps(camera, &fps_x1000)` returns the rate the backend read back at open, in thousandths of a frame per second, so fractional rates such as 29.97 fps (29970) survive.

The three Zephyr video-class backends (`zephyr_video`, `v2n_n44_isp`, `alif_isp_pico`) record it from `video_get_frmival()` right after applying the request. A driver that cannot report its frame interval, the stub backend and the NULL-driver path all answer `ALP_ERR_NOSUPPORT`. A NULL output pointer returns `ALP_ERR_INVAL`, and a NULL or closed handle returns `ALP_ERR_NOT_READY`.
