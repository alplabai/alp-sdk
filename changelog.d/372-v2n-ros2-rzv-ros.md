### Added - ROS 2 on V2N/V2M is an opt-in, layer-gated feature built on upstream `meta-ros` and Renesas `rzv_ros` (Refs #372)

`meta-alp-sdk` now consumes upstream `meta-ros` (Humble, scarthgap) and the optional Renesas `meta-rzv2-ros-humble` layer from `rzv_ros` instead of carrying its own ROS 2 set. The ROS recipes (`alp-perception`, the new `alp-ros2-temperature`, `packagegroup-alp-ros`) moved to `dynamic-layers/ros2-humble-layer/`, so a `bblayers.conf` without `meta-ros` parses and builds ROS-free. `ALP_ENABLE_ROS2` (default: on when the `ros2-humble-layer` collection is present) gates the `alp-ros` image feature; `1` without the layer is a parse error. `LAYERRECOMMENDS` named `meta-ros2-humble`, which no layer provides; it now names the real collections `ros2-humble-layer` and `rzv2-ros-humble`. New teaching example `examples/v2n/v2n-ros2-som-temperature` (portable `<alp/temperature.h>` only, `[UNTESTED]`; publishes `/alp/soc_temperature` from `alp_temperature_read_soc_milli_c()`, and `/alp/som_temperature` once a Linux on-module backend exists; the recipe stays out of `packagegroup-alp-ros` until the example is on `main`), a bring-up page `docs/bring-up-ros2.md`, and a not-bench-verified HIL spec. micro-ROS on the CM33 stays an ADR-only item (ADR 0035). Nothing was built or run on silicon.
