### Fixed — AEN twister builds `hal_alif`'s SE service code at `-O2` again (#2509)

`hal_alif`'s `se_service_process_toc_entry()` fills the Secure Enclave packet's
fixed-width, not NUL-terminated `send_entry_id` with
`strncpy(dst, image_id, IMAGE_NAME_LENGTH)`. At `-O2` GCC reports
`'strncpy' specified bound 8 equals destination size`, and the AEN twister
job's `-Werror` failed every scenario that builds it, the Trace Runner
example among them. A new `hal_alif` patch copies `strnlen(image_id,
IMAGE_NAME_LENGTH)` bytes with `memcpy` into the already-zeroed packet, the
same bytes without the warning (`zephyr/patches.yml:925`
("hal_alif/0015-se-service-toc-entry-id-memcpy.patch")).

Verified by building the Trace Runner's `a32_render`, `a32_render_npu_input`
and `m55_render` scenarios for both AEN801 and AEN803 M55-HE with
`CONFIG_COMPILER_WARNINGS_AS_ERRORS=y` against `hal_alif` v2.3.0 plus patches
0001-0015: all six build clean.
