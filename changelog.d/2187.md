### Fixed — a Flow D ATOC query that could not run no longer points the operator at `--replace-atoc` (#2187)

`bench_flowd_atoc_guard()` routes to the real resident-ATOC query whenever
`SE_UART` is exported — whether or not the variable names a device that can
actually answer. A **stale or wrong** `SE_UART` therefore took the query path,
the query failed, and the shared `bench_atoc_replace_guard()` aborted (exit 5)
with a remedy naming **`--replace-atoc`**: the "I checked and still want to
replace it" override, recommended for a check that demonstrably never ran.
`--atoc-unqueryable` is ignored on that path by design, and `unset SE_UART` —
the actual fix — was named nowhere in the output.

This was always fail-closed: nothing was written, and that is unchanged. The
defect is what the refusal *teaches*. `scripts/bench/aen/flash-jlink.sh:40`
states the habit that must never form
(`will pass this on every single Flow D run`), and #2029/#2027 kept the two
flags distinct for exactly that reason. This path re-conflated them from the
other direction: the no-check state demanded the checked-and-override flag.

**The refusal is unchanged; only the remedy it prints is flow-aware.** The
unverified branch now selects its closing lines on `$BENCH_ATOC_FLOW` at
`scripts/bench/aen/bench-env.sh:1223`
(`if [ "${BENCH_ATOC_FLOW:-A}" = D ]; then`), which
`bench_flowd_atoc_guard()` sets for the duration of its call at
`scripts/bench/aen/bench-env.sh:1315` (`local BENCH_ATOC_FLOW=D`):

- **Flow A** is unchanged and still reads
  `scripts/bench/aen/bench-env.sh:1239`
  (`Confirm by hand what is resident, then re-run with --replace-atoc`).
  There `SE_UART` *is* the transport, so a human confirming by hand and
  overriding is the only way past.
- **Flow D** is instead told to fix or unset `SE_UART` — preferring `LG_PLACE`
  over a raw `/dev/ttyUSBn` path, which `bench-env.sh` already warns is
  enumeration-ordered and has been measured swapped on this bench
  (#2032/#2064) — and is told explicitly not to reach for the override, at
  `scripts/bench/aen/bench-env.sh:1236`
  (`NOT --replace-atoc: that flag asserts you checked what is resident, and`).
  Flow D never needs a serial device, so a set-but-unanswering `SE_UART` is
  almost always a stale value rather than a board problem.

`local` scoping means the selector restores whatever an outer frame held, so a
Flow A guard called later in the same shell is unaffected — verified by calling
both guards in sequence against the issue's own stub and confirming each prints
its own remedy.

**Option (a) from the issue was deliberately not taken.** Honouring
`--atoc-unqueryable` whenever the query fails would let a broken cable or a
wrong device path on a slot that *does* have an SE-UART (`e1m-aen-evk-01`)
silently downgrade into a blind write — strictly worse than the current
behaviour, and the #2025 failure mode. Distinguishing "no SE-UART on this slot"
from "SE-UART wired but currently broken" needs a signal the guard does not
have. This is option (b): the safety property is untouched, and only the
misleading advice is fixed.

### Note on the citations this change shifted

Inserting into `bench_atoc_replace_guard()` moved `changelog.d/2027.md`'s three
citations into the same file, and the two halves behaved exactly as #2186
predicts, which is worth recording while it is fresh:

- Its two **anchored** citations went red and were re-derived with
  `scripts/check_changelog_citations.py --fix`, as the gate instructs.
- `--fix` then resolved one of them **wrongly**, and said so: the anchor
  `bench_atoc_replace_guard` occurs eight times in the file, so the tool
  reported `AMBIGUOUS` and chose the nearest match, a comment line, over the
  call site the fragment's own parenthetical quotes. Corrected by hand to
  `scripts/bench/aen/bench-env.sh:1316`. The anchor is weak because `_ANCHOR`
  stops at the first `"`, truncating a quoted code snippet to its first token —
  the #2184 shape.
- Its third citation, an **un-anchored** range naming the function's extent,
  drifted silently from `1230-1289` to `1256-1336` and the gate stayed green,
  because an un-anchored citation is range-checked only and both ranges are
  valid. Found by reading, not by the gate. Corrected too.

Neither correction is load-bearing for this fix; they are recorded because
#2186 is open on precisely this and one more measured instance is useful to it.
