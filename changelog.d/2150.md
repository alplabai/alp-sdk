### Fixed — an RX-only path could still stop or reprogram the shared I2S bit clock out from under a live TX stream (#2150 phase 1)

**Not full duplex.** #2150 itself is filed as a full-duplex feature request.
This is phase 1 only: the shared bit-clock ownership gap the driver's own
file header already named as a known remaining hazard after #2149. Refs
#2150; `i2s_dw_configure()` still maps `I2S_DIR_BOTH` to `-ENOSYS` and
`dev_data->dir` is still a single field
(`zephyr/drivers/i2s/i2s_dw.c:248` ("struct i2s_dw_data {")), both
deliberately unchanged.

**Why now.** #2149 made the TX underrun ISR exit deliberately leave
`CER.CLKEN` set so a TAS2563 on the same bus does not read bit-clock loss as
its own cue to latch SHUTDOWN. `rx_stream_disable()` and `rx_stream_start()`
were the two remaining places that could still pull that clock out from
under a transmitting stream, reopening the exact bug #2149 just closed —
this driver has one CGU-derived bit clock shared by both directions, not one
per direction.

**Fixed.** A new helper, `tx_clock_is_live()`
(`zephyr/drivers/i2s/i2s_dw.c:1176-1180` ("static bool tx_clock_is_live(const struct i2s_dw_cfg *i2s, const struct i2s_dw_data *dev_data)")),
decides whether TX is depending on the shared clock right now:
`I2S_STATE_RUNNING` qualifies, and so does `tx.clk_restart_skip_ok` **on its
own, regardless of state** — ANDed with the hardware `CER.CLKEN` bit itself
(`i2s_clock_is_enabled()`) so software state alone can never claim TX is
live.

**Round-3 review finding: the first version of this fix shipped with a
reachable silent-amp hole.** It qualified the flag only when
`tx.state == I2S_STATE_ERROR`, narrower than the flag's own documented
contract. `I2S_TRIGGER_PREPARE` moves TX `ERROR`→`READY` without clearing
the flag, and `z_start()`'s own PREPARE-retry
(`src/backends/i2s/zephyr_drv.c`) commonly leaves TX parked there for as
long as its producer stays stalled — not a narrow window, as an earlier
draft of this note claimed, but the exact gap the field exists to close, for
however long recovery takes. With `state == READY && flag == true &&
CER.CLKEN == 1` reachable, the old ERROR-only check answered "TX not live"
and let an RX stop/overrun gate the clock the flag was protecting. Dropping
the state qualifier — the flag's own comment already documents it as
state-independent — closes that hole; the `i2s_clock_is_enabled()` AND
covers the case a hardware-only check would get wrong the other way
(`CER.CLKEN` reads 1 from `i2s_dw_initialize()` onward, so hardware alone
would gate an RX-only stream that never had a live TX at all), and for free
closes PM suspend's own gap too: `i2s_suspend()` gates `CER.CLKEN`
unconditionally without touching `tx.state`, so a suspend mid-stream can
leave `tx.state == RUNNING` with the clock actually off — the hardware read
correctly answers "not live" for that case without any separate fix.

- `rx_stream_disable()` — the single shared body reached from
  `STOP`/`DRAIN`/`DROP` (via `stream->stream_disable`) and all four of
  `i2s_rx_irq_handler()`'s `goto rx_disable` routes (the `ERROR` exit, the
  `STOPPING` exit, and the failed-alloc / failed-`queue_put()` exits) — now
  skips `i2s_clock_disable()` when TX is live
  (`zephyr/drivers/i2s/i2s_dw.c:1473` ("if (!tx_live) {")), and deliberately
  leaves `tx.clk_restart_skip_ok` untouched in that case, since the clock
  never actually stopped. When TX is not live, behaviour is unchanged from
  before this fix.
- `rx_stream_start()` now skips reprogramming
  `clock_control_set_rate()`/CCR when TX is live at the SAME
  `frame_clk_freq`
  (`zephyr/drivers/i2s/i2s_dw.c:1269` ("clk_needs_reprogram = !tx_live;")),
  mirroring the `clk_needs_reprogram` shape #2149 already established in
  `tx_stream_start()`. If TX is live at a DIFFERENT rate, RX cannot silently
  retune the one shared divider without also retuning TX's stream out from
  under it, so it now returns `-EBUSY`
  (`zephyr/drivers/i2s/i2s_dw.c:1197-1208` ("return -EBUSY;")) before touching
  any hardware state or allocating a block, instead of pretending to
  succeed. `-EBUSY` was chosen over `-ENOTSUP` (this is not a permanent
  incapability) or `-EINVAL` (the RX config is fine on its own; the conflict
  is with the CURRENT shared clock state) — retrying once TX stops, or
  reconfigures to the same rate, succeeds. When TX is not live, behaviour is
  unchanged from before this fix.

**Documentation gap, also from round-3 review: the driver's own header
under-counted its known remaining gaps.** It named one; there are two.
Alongside the pre-existing channel-enable gap (`rx_stream_start()` and
`tx_stream_start()` each still unconditionally disable the OTHER
direction's channel-enable bit on every start), `i2s_dw_configure()` writes
`dev_data->dir`
(`zephyr/drivers/i2s/i2s_dw.c:397` ("dev_data->dir = dir;")) on every call,
and that single field is the ONLY thing `i2s_dw_isr()` consults to decide
whether to run `i2s_tx_irq_handler()` at all. Every RX-owning path this fix
protects requires RX to have been configured, which overwrites `dir` to
`I2S_DIR_RX` and permanently stops TX's IRQ from firing — so a "live" TX can
no longer refill its FIFO once RX is configured, and `tx.state ==
I2S_STATE_RUNNING` becomes stale software state from that point on. This fix
still delivers real value in that case (the amps key on BCLK presence, and
`tx_clock_is_live()` correctly keeps `CER.CLKEN` set for a TX the driver
itself can no longer service), but `tx.state == RUNNING` must not be read as
"TX is actually streaming" once RX has been configured. Both gaps are
full-duplex territory and stay with #2150's later phase(s).

**Public API surface.** `alp_i2s_start()`'s `@return` now documents the new
`ALP_ERR_BUSY` outcome
(`include/alp/i2s.h:144-149` ("ALP_ERR_BUSY (issue #2150 phase 1")) —
`-EBUSY` reaches callers as `ALP_ERR_BUSY`
(`src/common/alp_errno.h:70-72` ("case EBUSY:")), passed through untouched
by `z_start()` and `src/i2s_dispatch.c`. No ABI snapshot change: this is a
new value already reachable through the existing `alp_status_t` mapping, not
a new symbol — `python3 scripts/abi_snapshot.py --diff
docs/abi/v0.16-snapshot.json` reports "ABI unchanged".

**Known remaining gap, out of scope for phase 1:** `rx_stream_start()` and
`tx_stream_start()` each still unconditionally disable the OTHER
direction's channel-enable bit (`i2s_tx_channel_disable()` /
`i2s_rx_channel_disable()`) on every start — a genuinely concurrent RX+TX
session would still have one direction's channel silenced by the other's
(re)start, clock ownership aside. `dev_data->dir` being a single field (see
above) is the same territory from the ISR-dispatch side. Both are
full-duplex territory and stay with #2150's later phase(s), and are now
explicitly bounded — not the underrun-recovery `PREPARE` window, which this
fix's `tx_clock_is_live()` now covers correctly.

**Not verified on silicon.** No hardware access for this change. The bench
check still owed: on `e1m-aen-evk-03`, an RX overrun during active TX must
leave `CER=0x00000001` and both TAS2563 amps at `PWR_CTL=0x0c`.

**Tests.** `tests/unit/i2s_dw_underrun` — the suite that compiles
`zephyr/drivers/i2s/i2s_dw.c` directly against a RAM-backed register block —
gains four cases: RX `STOP` with TX `RUNNING` leaves `CER.CLKEN` set
(mutation-proven: reverting `rx_stream_disable()`'s `if (!tx_live)` guard to
unconditional gating turns it RED); RX `STOP` with no TX stream configured
still gates the clock, unchanged; RX `START` with TX `RUNNING` at the same
rate does not call `set_rate` AND leaves `CCR` itself untouched
(mutation-proven: deleting `rx_stream_start()`'s second
`if (clk_needs_reprogram)` guard around `i2s_configure_clock()` left all 12
cases green before this addition; the `CCR` sentinel assertion now catches
it); RX `START` with TX `RUNNING` at a different rate returns `-EBUSY`,
never touches `set_rate`, and never allocates (and leaks) an RX slab block
before refusing (mutation-proven: moving the `-EBUSY` return below
`k_mem_slab_alloc()` now goes RED on the slab's
`k_mem_slab_num_free_get()` count)
(`tests/unit/i2s_dw_underrun/src/test_i2s_dw_underrun.c` new
`test_rx_stop_with_tx_running_keeps_clock`,
`test_rx_stop_with_tx_idle_gates_clock`,
`test_rx_start_with_tx_running_same_rate_skips_reprogram`,
`test_rx_start_with_tx_running_different_rate_fails`). The pre-existing
`test_rx_start_invalidates_tx_restart_skip` case, which asserted the
ERROR-only qualifier's hole as correct behaviour, is renamed
`test_rx_start_rejected_preserves_tx_restart_skip` and now asserts the RX
start is refused with `-EBUSY` and `clk_restart_skip_ok` survives the
rejection (mutation-proven: re-adding the ERROR-only qualifier turns it
RED). `twister -p native_sim/native/64 -T tests/unit/i2s_dw_underrun`:
12/12 test cases pass.
