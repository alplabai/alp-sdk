### Fixed — tas2563 driver no longer accepts init at the write-only broadcast address (#1846)

`tas2563_init()`'s `addr_is_valid()` accepted `TAS2563_I2C_ADDR_BROADCAST`
(`0x48`) as a valid instance address, which the connectivity-probe read
(REVID) and every later `tas2563_read_revision()`/`tas2563_set_mode()` call
then targeted through `ctx->addr`. On a bus where an unrelated device is
strapped to `0x48` (e.g. an INA236 current monitor), those reads/writes land
on that device's registers instead of the amp -- a real EVK pre-respin had
exactly this collision (see `metadata/boards/e1m-evk.yaml`'s U28/U32 notes,
#1163/#1659).

`tas2563_init()` now rejects `TAS2563_I2C_ADDR_BROADCAST` with
`ALP_ERR_INVAL`; only the four documented per-chip AD0/SPICLK straps
(`TAS2563_I2C_ADDR_GND_DIRECT` .. `TAS2563_I2C_ADDR_VDD_DIRECT`) are
accepted. The broadcast address stays defined for reference (it is a real,
datasheet-documented write-only global-call address a future group-write-only
helper could use) but is no longer usable through this read-capable,
per-instance driver context.
