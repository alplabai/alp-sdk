### Fixed — `scripts/bench/aen/bench-env.sh` resolved the SE-UART from a raw device path with no default and no labgrid resolution, and 11 scripts selected a J-Link probe by a serial three probes share (#2032)

The maintainer's hard rule: **every bench connection goes through labgrid,
addressed by PLACE NAME, never touched by hand.** `bench-env.sh` violated it
at the root: `SE_UART="${SE_UART:-}"` took a raw device path from whatever
the caller happened to export, with no labgrid resolution anywhere in the
file. 11 scripts under `scripts/bench/aen/` selected their J-Link probe with
`-SelectEmuBySN`, which cannot disambiguate on this bench — all three probes
answer the same cloned OEM serial. A stale device-path table caused the
2026-09-07 incident: it had the SE-UART and app-console paths for one board
**swapped** (pointing SETOOLS at the app console, not the SE-UART), and
named a J-Link USB path that actually belongs to a **different** board.

`LG_PLACE` is now the primary input. Set it and `bench-env.sh` resolves
`SE_UART`, the console device (`LG_CONSOLE_DEV`/`LG_CONSOLE_HOST`/
`LG_CONSOLE_PORT`), and the SWD probe's real USB path (`LG_SWD_PATH`) LIVE
from `labgrid-client -p "$LG_PLACE" show` — parsing the resource blocks the
same way `board-farm/bin/jlink-run.sh` already does (anchor on each
resource's own header line, never a naive whole-output search that can
latch onto the `matches:` list's repeated resource names). The reservation
is verified held (`show`'s `acquired:` non-empty) before anything resolves;
a lapsed reservation aborts the sourcing caller loudly rather than silently
resolving stale values, and there is no default place -- an unset `LG_PLACE`
never falls back to guessing a board. `LG_COORDINATOR` has no default
either: a coordinator address is bench-specific infrastructure, not a
portable SDK value, so `LG_PLACE` set with `LG_COORDINATOR` unset aborts
with an actionable message instead of silently trying `labgrid-client`'s own
`127.0.0.1:20408` fallback.

A raw `SE_UART` remains a supported escape hatch for genuinely off-labgrid
work (`erase-storage.sh`'s BENCH-VERIFIED run is the documented case), but
exporting it with no `LG_PLACE` now prints an explicit warning naming the
hazard (stale/unstable `/dev/ttyUSBn` numbering, wrong-board risk). `LG_PLACE`
wins whenever both are set.

**Known limitation, left for follow-up:** none of the 8 remaining
`-SelectEmuBySN` call sites (`flash-run.sh`, `ram-run.sh`, `erase-storage.sh`,
`flash-update-log-dual.sh`, `flash-update-log-firewall-probe.sh`,
`read-update-log-proof.sh`, `reread.sh`, `flash-all-flowd.sh` -- the other 3,
`flash-jlink.sh`/`flash-jlink-hp.sh`/`flash-jlink-mramxip.sh`, are owned by
PR #2029) are converted to route through `board-farm/bin/jlink-run.sh`, the
namespace-masking wrapper that actually disambiguates same-serial probes.
Not cleanly wireable in this change: `jlink-run.sh` recognises `-CommandFile`
to inject a firmware-update suppression ahead of it, and every one of these
8 scripts passes `-CommanderScript` instead, and each issues several
separate `JLinkExe` invocations per run (preflight/write/boot/read) rather
than the single pass-through invocation `jlink-run.sh` wraps -- routing them
through it is a larger, separate change. `bench-env.sh` exports
`LG_SWD_PATH` for anyone driving `jlink-run.sh` by hand in the meantime;
these 8 scripts are left exactly as they were, still relying on `JLINK_SN`
plus the existing SW-DP IDR safety gate (`bench_jlink_assert_aen_dpidr`) to
catch a wrong-board attach.

Tests (`tests/scripts/test_bench_labgrid_resolver.py`) feed the resolver
REAL captured `labgrid-client show` output (not synthesised text) for all
three AEN bench places, including a real interactive-pty capture to pin the
CRLF line-ending handling a hand-typed fixture would not exercise.
