### Fixed — the GD32 bridge protocol doc no longer says a second FFT `chain_bind` is accepted (#1717)

`docs/gd32-bridge-protocol.md` §3.x and the `CHAIN_BIND` section still said
the firmware did not guard the single FFT block, so two streams could both
bind FFT chains. Since protocol v0.10 (`gd32-bridge-firmware` PR #121), a
second FFT-terminal bind returns `STATUS_NOSUPPORT`, exactly like the FAC
guard, and the refused chain stays open so the host can retry the same
`chain_id`. Both sections now say so, matching the doc's own v0.10 history
entry.
