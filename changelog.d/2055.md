### Fixed — the ATOC unwritable-TMPDIR test now skips where its precondition cannot be built, instead of failing (#2055)

`test_atoc_guard_aborts_when_tmpdir_is_unwritable`
(`tests/scripts/test_bench_jlink_connect_guard.py:1025`) builds its
precondition with `unwritable.chmod(0o500)` and then expects
`bench_atoc_replace_guard()`'s `mktemp` to fail inside that directory. On
Windows that precondition never holds: `os.chmod` only toggles
`FILE_ATTRIBUTE_READONLY`, and that attribute does not stop a directory from
accepting new entries. Measured on Windows 11 with Python 3.12.10, a
directory chmod'ed `0o500` reads back `0o555`, `os.access(dir, os.W_OK)`
returns `True`, and a file writes into it without complaint. `mktemp`
therefore succeeded, the guard returned `0`, and the assertion demanding `5`
failed with the transcript path — `unwritable-tmp/test-tag-atoc-before.BoNwrZ`
— naming the very file that proves the directory was still writable.

This never reddened CI, and the reason it did not is unrelated to the defect:
GitHub's `windows-latest` resolves `bash` to the WSL launcher with no
distribution installed, so `_NEEDS_BASH`
(`tests/scripts/test_bench_jlink_connect_guard.py:59`) skips the whole module
there before this test is reached. On a Windows developer box with a real
`bash` on `PATH` — Git Bash or MSYS2, the setup `docs/cross-platform-setup.md`
describes — the module does not skip, and this one test fails among 43 that
pass.

The fix follows the discipline the file already sets for `bash` itself:
probe the capability by performing it rather than by trusting the platform.
`_dir_still_accepts_a_new_file()` (`tests/scripts/test_bench_jlink_connect_guard.py:66`) touches a probe file in the directory after
the `chmod`; if the write succeeds, the unwritable-TMPDIR precondition does
not hold on this host and the test skips with a reason that says so, naming
this issue. Where `chmod` does make the directory refuse a write, the probe
fails, and the test runs and asserts exactly what it asserted before —
including the specific `cannot create the pre-write ATOC transcript` abort
message that distinguishes this failure mode from the unrelated downstream
redirect failures an earlier revision of the test could not tell it from.

A sweep of `tests/scripts/` found no other test building a precondition out
of a restrictive `chmod`; the remaining `chmod` calls all add the execute bit
to a fixture script, which behaves the same everywhere.
