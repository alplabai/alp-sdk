### Fixed — pinned all 12 mutants that survived a post-merge review of #1365 split B, corrected a false size-precedence history and a false mutation-testing claim (#2010)

A mutation review of #1365 split B (#1983, merged as `2fd045411`) ran 30
mutants against `pytest tests/scripts/` plus `check_emit_snapshots.py`,
`check_atoc_reservation.py`, and `check_system_manifest.py`. 12 survived
(A8, A9, A10, M1, C3, C4, C6, C9, C11, C12, P1, P4). All 12 are closed here
— each with a new or extended test that goes red under the exact mutant and
green once reverted.

**`scripts/alp_orchestrate/memregion.py`'s `_region_size_bytes` (mutant M1)**
— the comment justified checking `size_kib` before `size_mib` as "matching
this module's one prior caller (`check_atoc_reservation.py`'s now-retired
`_region_size_kib`)". False: on `origin/dev` before split B, this module's
only two callers were `carveout.py` and `partition.py`, both mib-first via a
key-presence check (`if "size_mib" in region: ...`); `check_atoc_reservation.py`
was NOT a caller then — it carried its own private, unrelated
`_region_size_kib` (kib-first), which split B retired in favour of importing
this module. Restored mib-first precedence to match the module's real prior
behaviour and corrected the comment. The `memory_region` schema permits both
`size_mib` and `size_kib` on one region and no shipped preset sets both, so
this has no real-preset evidence either way — pinned by
`TestRegionExtent::test_size_mib_wins_when_both_fields_are_valid_ints`
(`{size_mib: 2, size_kib: 64}` must resolve via `size_mib`) rather than left
to change silently again.

**`scripts/alp_orchestrate/carveout.py`'s `_region_ipc_eligibility`
(mutant C4)** — `derived_eligible = wa == "customer_runtime"` dropped to
`= True` unconditionally survived every gate because
`TestUnclassifiedWriteAuthorityLegCoverage` was positive-only. Added
`test_outside_aperture_authored_row_with_wrong_write_authority_blocks` and
`..._with_no_write_authority_blocks`: an outside-aperture, preset-authored
row with `write_authority` anything other than `customer_runtime` (or
absent) must refuse — exactly the hazard the function's own docstring names,
"a future authored OSPI XIP row must NOT silently become an IPC candidate".
`changelog.d/1365-split-b.md` claimed this leg was "mutation-tested:
dropping it turns that test red" — true only for the opposite direction
(mutant C5, already killed); corrected that fragment in place.

**The other 10 mutants, by ID:**
- **C3 / C11** (`ram` leg of `_region_ipc_eligibility`) — likely
  UNREACHABLE on any SoM shipped today: `cls == "ram"` requires
  `not is_preset_authored`, but every Alif preset that resolves an aperture
  also authors an explicit `memory_map:` block, and no non-Alif SoM ever
  resolves an aperture at all (`git grep -n "carveout:" metadata/socs/` is
  empty). Kept, not deleted — a future minimal Alif SoM port relying
  entirely on SoC-level `memory_regions:` would reach it for real — and
  documented in place with the reachability precondition. Pinned by direct
  call (`TestRamLegReachability`), the only way to exercise it today.
- **C6** (unresolved-base ordering) — `carveout:` must be checked before
  `write_authority` (#1365 split B review MAJOR 2); no preset authors both
  fields on an unresolved-base row, so this was defensive-only and unpinned.
  `TestUnresolvedLegOrdering::test_unresolved_base_honours_carveout_false_over_customer_runtime`
  closes it with `{"base": "TBD", "carveout": False, "write_authority":
  "customer_runtime"}`.
- **C9** (`_MAX_EXCLUDED_DETAIL`, 6) — unpinned by any behavioural test;
  pinned directly (`TestMaxExcludedDetailCap`). The reasoning stands:
  `board.schema.json`'s `/$defs/ipc_entry` sets `endpoints.minItems: 2`, and
  every AEN SKU's `memory_map:` has exactly 7 rows, so 5 is the true
  ceiling on any SKU shipped today.
- **C12** (terminal ADR-0034 clause-4 refusal) — one direct-call assertion
  (`TestUnresolvedLegOrdering::test_unresolved_base_with_neither_flag_refuses_terminal`).
- **A8** (`is_partition_inside_aperture`'s low-edge boundary,
  `lo >= full_lo` vs `lo > full_lo`) — untested and live: `mcuboot` is flush
  with the aperture base on all 7 AEN SKUs. Added
  `test_true_for_a_proper_subset_flush_with_the_low_edge`.
- **A9** (`resolve_aperture`'s `isinstance(base, bool)` guard on
  `soc_flash_base`) — the module docstring claimed the move from
  `check_atoc_reservation.py`'s original `_resolve_aperture` was "unchanged
  in behaviour"; false, the original guarded only `mram_mb` against a
  Python `bool`, not `base` itself. Corrected the docstring ("moved and
  hardened") and pinned the guard with a synthetic SoC spec
  (`test_none_when_soc_flash_base_is_a_bool`) since no real
  `metadata/socs/**` file can carry a JSON boolean there.
- **A10** (`region_extent`'s `isinstance(base, bool)` guard) —
  pre-existing behaviour, carried over verbatim; folded into
  `TestRegionExtent` (`test_unresolved_when_base_is_a_bool`).
- **P1** (`partition.py`'s legacy `carveout: false` fallback in
  `_is_flash_sub_partition`) — the fallback the docstring's "MAJOR 3" and
  the non-Alif no-op argument both rest on had no test; no non-Alif preset
  authors `carveout: false` today. Direct-call pin with an explicit
  `aperture=None` (`TestLegacyCarveoutFallback`).
- **P4** (`resolve_storage_partitions`'s hoisted `aperture`) — P2/P3 were
  killed only via a direct-call sentinel path, so the derived verdict was
  never proven load-bearing through the actual production entry point. Added
  one synthetic `memory_map:` row (strictly inside the declared aperture, no
  `carveout:` key authored) where the derived and legacy verdicts genuinely
  disagree, and drove it through `resolve_storage_partitions()` itself
  (`TestDerivedVerdictLoadBearingEndToEnd`). Under the mutant the entry still
  blocks, but for the WRONG reason (the unrelated #1556 unverified-dt_label
  gate catches it instead) — proving the derived aperture-containment check
  is the one actually deciding it.

Every fix above was verified by re-applying its exact mutant in a disk copy
of the tree (never the branch) and confirming the new test goes red with
the assertion text quoted in its own docstring/message, then reverting.
