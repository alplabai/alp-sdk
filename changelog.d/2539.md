### Added — model-zoo-v1 schema, data, and validator gate (#2539)

Lands the model-zoo **data** half of ADR-0028
(`docs/adr/0028-tan-owns-the-model-engine.md`, `Status: Proposed`):
`metadata/model_zoo/` and `metadata/schemas/model-zoo-v1.schema.json` are
hardware truth owned by alp-sdk; the engine that reads them (`tan model
zoo` / `tan model add`) is planned to live entirely in tan-cli
(tan-cli#1286) — no second implementation, no parity apparatus.

- `metadata/schemas/model-zoo-v1.schema.json` — new schema for one model
  per file (`metadata/model_zoo/<id>.yaml`):
  - `schema_version: 1` (`const`), matching `model-perf-v1.schema.json`'s
    own shape.
  - `kind: model | fixture`. `fixture` is a wiring/smoke entry (e.g.
    `example-tiny`, the honest fixture this issue ships) that must never
    carry a hardware claim or an unreviewed upstream link — enforced by
    an `allOf` of two `kind`-gated `if`/`then` pairs: `kind: fixture`
    requires `task: smoke`, an empty `validated_soms`, and a `bundled`
    source; `kind: model` forbids `task: smoke`. `scripts/validate_metadata.py`'s
    `_check_model_zoo_semantics` repeats both checks for a friendlier,
    specific error message.
  - `task` is a closed kebab-case enum (`image-classification`,
    `object-detection`, `person-detection`, `keyword-spotting`,
    `voice-activity-detection`, `anomaly-detection`, `noise-suppression`,
    plus `smoke`, reserved for fixtures).
  - `license` is a closed, permissive SPDX allowlist (`Apache-2.0`,
    `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `CC0-1.0`) with no
    `LicenseRef-*` escape — it describes the linked upstream model's/
    bundled starter's own WEIGHTS licence, not the training dataset's.
    Extending the allowlist is a maintainer legal-review decision
    recorded in the new `metadata/model_zoo/README.md` in the same
    change as the schema edit, mirroring `metadata/libraries/README.md`'s
    own process. Copyleft (including AGPLv3 — Ultralytics YOLO
    checkpoints like `yolo11n` ship under it), non-commercial, and
    vendor-customer-only terms are rejected until explicitly admitted.
  - `source` is EXCLUSIVELY either an upstream `{url, sha256}` link
    (`url` is `https://` only, no userinfo/credentials, no embedded
    whitespace; `sha256` required alongside it) or a `{bundled}` path
    into `metadata/model_zoo/starters/` (`starters/<file>`, flat, no
    `../` escape, no absolute path) — no weight redistribution either
    way.
  - `validated_soms[]` lists the real SKUs this exact model has been
    bench-run on; empty means none have been — `tan model zoo --sku
    <SKU>` matches no entry with an empty list, never "unfiltered". Each
    listed SKU must match the repo's real SKU family/digit pattern and
    name a real, shipped `metadata/e1m_modules/<sku>.yaml` preset.
  - `compile` is structurally identical to `board.schema.json`'s
    `models[].compile` (the shape `tan model add` writes into a
    project's board.yaml) — a dedicated test
    (`test_compile_matches_board_schema_definition`, `description` keys
    stripped before comparing, with a self-test proving the stripping
    doesn't make the comparison vacuous) keeps the two from drifting
    apart, since this repo has no cross-file `$ref` resolution.
  - `example_app`, when present, is an `examples/<category>/<name>` path
    (same shape as `template-catalog-v1.schema.json`'s `example`) that
    must resolve to a real, tan-buildable (`board.yaml`-carrying)
    example — checked whenever this checkout has an `examples/` tree.
  - Every `$`-anchored pattern (`id`, `url`, `sha256`, `bundled`, the
    `validated_soms[]` SKU pattern, `example_app`) is written
    `...$(?!\n)`: jsonschema validates `pattern` with `re.search`, and
    Python's bare `$` matches either at the true end of string or
    immediately before a single trailing `\n`, so an unescaped `$`
    alone would let a value with a stray trailing newline slip past
    every pattern in this schema.
- `metadata/model_zoo/example-tiny.yaml` + `starters/example-tiny.tflite`
  — one honest `kind: fixture` smoke entry. The starter is a
  byte-for-byte copy of `tests/fixtures/models/tiny_int8.tflite`, a
  synthetic, non-trained INT8 fixture reproducible via
  `tests/fixtures/models/gen_tiny_model.py` — no real model's weights
  are shipped.
- `scripts/validate_metadata.py` — validates every
  `metadata/model_zoo/*.yaml` against the schema plus cross-checks a
  schema can't express: `id` matches filename; `source.bundled` resolves
  to a real, byte-exact-case-matching file strictly inside `starters/`
  (a case-insensitive filesystem like macOS APFS can resolve a
  wrong-case path locally while case-sensitive CI 404s the same string);
  every `validated_soms[]` SKU names a real SoM preset; the `kind`<->
  `task` tie; and, when `examples/` exists, that `example_app` names a
  real directory with a `board.yaml` (only probed once the value already
  fullmatches the schema pattern, so a schema-invalid value doesn't also
  get a misleading disk-probe message). A dedicated collector
  (`_collect_model_zoo_files`, mirroring `_collect_model_perf_files`'s
  structural-violation-as-failure design) treats a stray file directly
  under `metadata/model_zoo/` or a file nested more than one level under
  `starters/` as a failure, visible in `main()`'s own output. A new
  `_check_model_zoo_starters` rejects an orphan (unreferenced) starter or
  one over the 64 KiB size cap — a mechanical, not human-judgment, guard
  for "genuinely tiny, no weight redistribution" (a `stat()` `OSError` is
  itself reported as a failure, never silently treated as "size
  unknown, assume fine"). This gates the entry's *shape* and that a
  claimed SKU/example *exists*; it cannot and does not gate that the SoM
  was actually bench-validated — that remains the entry author's
  responsibility.
- New `metadata/model_zoo/README.md` — the zoo's data-only scope (per
  ADR-0028), the entry shape, the `kind`/`fixture` rules,
  `validated_soms`' empty-means-unvalidated semantics, and the licence
  allowlist with its legal-review extension rule. Notes that the
  `examples/aen/aen-npu-inference*` demos have no `board.yaml` and so
  cannot be linked as `example_app` today (loosening that requirement is
  a future, additive decision). Also records that upstream
  `Megvii-BaseDetection/YOLOX` is Apache-2.0, but RUHMI's
  `yolox-S_VOC.onnx` (the benched build,
  `src/yocto/inference_drpai.cpp:19` ("RUHMI's yolox-S_VOC.onnx")) has
  unrecorded terms of its own
  (`metadata/model_perf/README.md:13-14` ("ONNX Runtime CPU: YOLOX-S/VOC"))
  and is not admitted until verified; and that DEEPX's MIT `dx-modelzoo`
  (`docs/vendor-partnerships.md:241` ("Reference models")) does not
  relicense an Ultralytics-derived weight, which stays AGPLv3 wherever
  it ships (`docs/vendor-partnerships.md:242` ("YOLO fork for DEEPX NPU")).
- `docs/README.md` — documents the data asset under "Models / edge-AI",
  linking the new `metadata/model_zoo/README.md`.
- `tests/scripts/test_model_zoo_metadata.py` — tests covering the
  schema (every field, every closed enum/pattern including the
  trailing-newline edge case on each `$`-anchored pattern, the
  `kind`/`task` cross-checks, and the `compile` structural-equality
  drift guard against `board.schema.json`) and the validator's semantic
  checks (id/filename, bundled resolution + case-exactness, SKU
  existence, `example_app` existence + `board.yaml`, orphan/size-capped
  starters, and a `main()`-level integration test proving an invalid
  entry flips the gate's exit code).

Out of scope, per ADR-0028: `scripts/alp_model/zoo.py`
(`load_zoo`/`filter_by_sku`/`fetch_source`) and its tests — those port into
tan-cli under tan-cli#1286, not here.
