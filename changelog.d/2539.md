### Added — model-zoo-v1 schema, seed entry and validator gate (#2539)

Lands the model-zoo **data** half of ADR-0028: `metadata/model_zoo/` and
`metadata/schemas/model-zoo-v1.schema.json` stay in alp-sdk as hardware
truth, while the model engine (`tan model zoo` / `tan model add`, tan-cli#1286)
lives entirely in tan-cli — no second implementation, no parity apparatus.

- `metadata/schemas/model-zoo-v1.schema.json` — new schema, its contract
  frozen before the first tag it ships in (adversarial-review round, same
  PR):
  - `schema_version: 1` (`const`) required, matching
    `model-perf-v1.schema.json`'s own shape verbatim (`npu-ops-v1` has no
    `schema_version` field to match).
  - `kind: model | fixture` required, each enum value with its own
    `description`. `kind: fixture` is now enforced BOTH at the schema
    level (a draft 2020-12 `if`/`then`: `validated_soms.maxItems: 0` +
    `source.required: [bundled]`) AND in `_check_model_zoo_semantics`
    (kept for a friendlier, specific error message than jsonschema's own
    if/then text) — never a hardware claim, never an unreviewed upstream
    link.
  - `source` is EXCLUSIVELY either an upstream `{url, sha256}` (`https://`
    only — tightened to `^https://[^\s/?#@]+/\S+$` (no userinfo/
    credentials either), rejecting a bare `https://`, an embedded
    space/newline, a host with no path, or a `user:pass@host` — sha256
    REQUIRED via `dependentRequired` + a `oneOf` whose branches each
    forbid the other shape's fields) or a `{bundled}` path into
    `metadata/model_zoo/starters/` (now pattern-constrained to
    `^starters/[A-Za-z0-9._-]+$` — no `../` escape, no absolute path, no
    subdirectory, all rejected by the SCHEMA itself, not just the
    validator); no weight redistribution either way.
  - `validated_soms[]` SKUs must match the repo's real SKU family/digit
    pattern (`^E1M-(AEN[3-8][0-9]{2}|V2N[0-9]{3}|V2M[0-9]{3}|NX9[0-9]{3})$`,
    same as `som-preset-v1`/`model-perf-v1`), with a `description` stating
    empty means "no SoM bench-validated yet" — never "unfiltered".
  - `compile` is now structurally identical to `board.schema.json`'s
    `models[].compile` (the shape `tan model add` appends into a
    project's `board.yaml`) — copied verbatim (its own `description`
    reworded for the zoo's context: paths resolve relative to the
    CONSUMING project's board.yaml after `tan model add` copies this
    block in, not to this manifest) rather than a cross-file `$ref`
    (every validator in `scripts/validate_metadata.py` is instantiated as
    `jsonschema.Draft202012Validator(schema)` with no resolver/registry,
    and no schema in this tree uses a cross-file `$ref` anywhere, so one
    would not actually resolve here; this mirrors
    `board-preset.schema.json`'s own documented mirroring of
    `board.schema.json`'s `route_entry`). A dedicated test
    (`test_compile_matches_board_schema_definition`, description keys
    stripped before comparing) asserts the two stay structurally equal so
    they can't silently drift apart, with a second test
    (`test_compile_drift_guard_still_catches_a_real_structural_difference`)
    proving the description-stripping doesn't make that guard vacuous.
- `metadata/model_zoo/example-tiny.yaml` + `starters/example-tiny.tflite` —
  one honest smoke entry, now `schema_version: 1` + `kind: fixture`. The
  starter is a byte-for-byte copy of the existing
  `tests/fixtures/models/tiny_int8.tflite` (synthetic INT8
  FULLY_CONNECTED weights, reproducible via
  `tests/fixtures/models/gen_tiny_model.py` — no upstream model's weights
  are shipped). `validated_soms: []`: this is a wiring fixture, never
  bench-run on real silicon, so it carries no SoM claim `tan model zoo
  --sku` could mistake for hardware validation — now ENFORCED, not just
  documented, by the `kind: fixture` cross-check.
- `scripts/validate_metadata.py` — the `MODEL_ZOO_SCHEMA`/`MODEL_ZOO`
  block now collects via `_collect_model_zoo_files` (mirroring
  `_collect_model_perf_files`'s structural-violation-as-failure design)
  instead of a bare glob, so a stray file directly under
  `metadata/model_zoo/` or nested more than one level under `starters/`
  is a FAILURE, not silently invisible. `_check_model_zoo_semantics`
  gates: `id:` matches filename; `source.bundled` resolves to a real file
  strictly inside `metadata/model_zoo/starters/` (never an escape or a
  dangling path) AND is a byte-exact (case-sensitive) match against the
  real directory listing (`_bundled_case_exact`) — a case-insensitive
  host filesystem (macOS APFS, Windows) can resolve a wrong-case path
  locally while case-sensitive CI (Linux) 404s the identical string;
  every `validated_soms[]` SKU names a real
  `metadata/e1m_modules/<sku>.yaml` preset (a pattern-valid-but-fictitious
  SKU like `E1M-AEN899` is caught here, not by the schema); and `kind:
  fixture` implies empty `validated_soms` + `bundled` source. A new
  `_check_model_zoo_starters` cross-checks the whole `starters/` tree:
  every file must be referenced by some entry's `source.bundled` (an
  orphan starter is untracked payload with no entry accounting for it),
  and every starter must be at most `_MODEL_ZOO_STARTER_MAX_BYTES` (64 KiB)
  — a mechanical, not human-judgment, guard for "genuinely tiny, no
  weight redistribution" (a `stat()` `OSError` is now itself reported as
  a failure, not silently treated as "size unknown, assume fine"). The
  model-zoo `main()` block's own collector failures (a stray/misplaced
  file) are now actually PRINTED, not just counted into the exit code --
  the same print loop the model_perf block already had. This gates the
  entry's *shape* and that a claimed SKU *exists*; it cannot and does not
  gate that the SoM was actually bench-validated — that remains the entry
  author's responsibility.
- `docs/README.md` — documents the new data asset under "Models / edge-AI",
  including the `kind`/`schema_version`/`compile`-alignment contract.
- `tests/scripts/test_model_zoo_metadata.py` — 63 tests: schema + semantic
  coverage for every item above (schema_version/kind required + valued
  correctly; the `kind: fixture` cross-checks at BOTH the schema and
  semantic layers; the `compile` structural-equality drift guard (with a
  self-test proving it still catches a real difference) + an
  unknown-compile-key rejection; the tightened url/bundled patterns, each
  direction, including no-userinfo; the new collector's stray-file/
  nested-too-deep structural failures, now visible in `main()`'s own
  stdout; orphan-starter and size-cap rejections, including a `stat()`
  `OSError`; the case-exact bundled-path check, as a portable unit test
  of the underlying primitive, an end-to-end integration test, AND a
  host-independent wiring test that forces the branch via monkeypatch so
  Linux CI exercises it too), plus everything from the initial landing (valid
  entry, malformed/uppercase sha256, unknown top-level field, missing/
  duplicate/malformed/nonexistent `validated_soms`, missing/escaping
  bundled path, and a `main()`-level integration test proving an invalid
  entry actually flips the validator's exit code).

Out of scope, per ADR-0028: `scripts/alp_model/zoo.py`
(`load_zoo`/`filter_by_sku`/`fetch_source`) and its tests — those port into
tan-cli under tan-cli#1286, not here.
