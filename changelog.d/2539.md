### Added — model-zoo-v1 schema, seed entry and validator gate (#2539)

Lands the model-zoo **data** half of ADR-0028: `metadata/model_zoo/` and
`metadata/schemas/model-zoo-v1.schema.json` stay in alp-sdk as hardware
truth, while the model engine (`tan model zoo` / `tan model add`, tan-cli#1286)
lives entirely in tan-cli — no second implementation, no parity apparatus.

- `metadata/schemas/model-zoo-v1.schema.json` — new schema. `source` is
  EXCLUSIVELY either an upstream `{url, sha256}` (`https://` only, sha256
  REQUIRED — `dependentRequired` plus a `oneOf` whose branches each forbid
  the other shape's fields, so `{url, bundled}` or `{bundled, sha256}`
  cannot sneak past a `required`-only `oneOf`) or a `{bundled}` path into
  `metadata/model_zoo/starters/`; no weight redistribution either way.
  `validated_soms[]` SKUs must match the repo's real SKU family/digit
  pattern (`^E1M-(AEN[3-8][0-9]{2}|V2N[0-9]{3}|V2M[0-9]{3}|NX9[0-9]{3})$`,
  same as `som-preset-v1`/`model-perf-v1`).
- `metadata/model_zoo/example-tiny.yaml` + `starters/example-tiny.tflite` —
  one honest smoke entry. The starter is a byte-for-byte copy of the
  existing `tests/fixtures/models/tiny_int8.tflite` (synthetic INT8
  FULLY_CONNECTED weights, reproducible via
  `tests/fixtures/models/gen_tiny_model.py` — no upstream model's weights
  are shipped). `validated_soms: []`: this is a wiring fixture, never
  bench-run on real silicon, so it carries no SoM claim `tan model zoo
  --sku` could mistake for hardware validation. The schema's
  `validated_soms` now allows an empty array (was `minItems: 1` on the
  closed alp-sdk#933 prototype this was ported from).
- `scripts/validate_metadata.py` — new `MODEL_ZOO_SCHEMA`/`MODEL_ZOO`
  block (glob `metadata/model_zoo/*.yaml`, schema pass +
  `_check_model_zoo_semantics`: `id:` matches filename, `source.bundled`
  resolves to a real file strictly inside `metadata/model_zoo/starters/`
  (never an escape or a dangling path), and every `validated_soms[]` SKU
  names a real `metadata/e1m_modules/<sku>.yaml` preset — a
  pattern-valid-but-fictitious SKU like `E1M-AEN899` is caught here, not
  by the schema. This gates the entry's *shape* and that a claimed SKU
  *exists*; it cannot and does not gate that the SoM was actually
  bench-validated — that remains the entry author's responsibility.
- `docs/README.md` — documents the new data asset under "Models / edge-AI".
- `tests/scripts/test_model_zoo_metadata.py` — schema + semantic coverage:
  valid entry, url-without-sha256/file://-scheme/mixed-source-field
  combinations rejected, malformed/uppercase sha256 rejected, unknown
  field rejected (`additionalProperties: false`), missing/duplicate/
  malformed/nonexistent `validated_soms` entries rejected, missing/
  escaping bundled path rejected, and a `main()`-level integration test
  proving an invalid entry actually flips the validator's exit code.

Out of scope, per ADR-0028: `scripts/alp_model/zoo.py`
(`load_zoo`/`filter_by_sku`/`fetch_source`) and its tests — those port into
tan-cli under tan-cli#1286, not here.
