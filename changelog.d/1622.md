### Fixed — three E1M-EVK `adc:` entries described nets that don't exist on the board (#1622)

Issue #1622's premise was inverted: the hand-authored `EVK_ARD_A0` / `EVK_MB_ANA`
macros in `include/alp/boards/alp_e1m_evk.h` (both `ALP_E1M_ADC0`, with a comment
that mounting an Arduino shield and a mikroBUS click together contends the
channel) were already correct. It was the **generated** `metadata/boards/e1m-evk.yaml`
`adc:` block that was wrong, traced against the authoritative netlist
(`E1M-EVK-2626-R2_pinmap.csv` in `alp-sdk-internal`):

- **`EVK_ADC_BOARD_ID` (`E1M_ADC0`)** claimed a carrier-side BOARD_ID resistor
  divider. No `BOARD_ID` net exists anywhere in the pinmap — the only `*_ID`
  nets are the three USB ID pins. `ANA_S0` is net `ARD.A0`, reached from
  mikroBUS `CK_ANA` through `R52` (series), `R63` (pulldown) and `C60`
  (filter) — the genuinely shared Arduino-A0/mikroBUS-ANA input the
  hand-written header already documents. Renamed to `EVK_ADC_ARDUINO_A0`,
  matching the `EVK_ADC_ARDUINO_A1..A5` convention.
- **`EVK_ADC_MB_AN` (`E1M_ADC6`)** claimed the mikroBUS click AN pin — but
  mikroBUS ANA is `E1M_ADC0` (above); no Click net touches `ANA_S6`. `ANA_S6`
  is net `A6`, a DAC0 output loopback sense: `R88` from `DAC0_OUT`, `R89`
  pulldown, `C107` filter. Renamed to `EVK_ADC_DAC0_LOOPBACK`.
- **`EVK_ADC_VBAT_SENSE` (`E1M_ADC7`)** claimed a 4:1 battery-voltage divider.
  There is no `VBAT` net in the pinmap at all. `ANA_S7` is net `A7`, a DAC1
  output loopback sense: `R90` from `DAC1_OUT`, `R91` pulldown, `C108`
  filter. Renamed to `EVK_ADC_DAC1_LOOPBACK`. No example used the old macro
  to read a battery — `examples/` has no consumer of any of the three old
  names — so nothing was silently measuring a DAC loopback and calling it
  VBAT.

No legacy compat: the three old macro names are gone, not aliased.
`include/alp/boards/alp_e1m_evk_routes.h` regenerated via
`scripts/gen_board_header.py`; `tests/scripts/test_gen_board_header.py`'s
"not generated" list (previously listing `EVK_ARD_A0` / `EVK_MB_ANA` next to a
stale comment naming the old macros) updated to reference the corrected names.
`alp.lock`'s `digests.metadata` and `docs/abi/v0.16-snapshot.json` regenerated
to match, along with the two affected `tests/fixtures/emit-snapshots/proj-aen.*`
goldens.

Not touched, deliberately: `hw_revisions.r1.board_id.adc_channel: TBD` a few
lines below the `adc:` block is a separate, still-accurate placeholder for a
BOARD_ID path the EVK schematic hasn't assigned a net for yet — it was already
`TBD`, consistent with "no BOARD_ID net exists today". `docs/board-id.md`
documents that unrelated EEPROM-authoritative SoM `board_id` concept and
doesn't reference these ADC macros.

### Added — a reusable record for INTENTIONAL public-symbol removals (#1622)

Renaming the three macros above is a real, deliberate ABI removal against
whatever last shipped (`EVK_ADC_VBAT_SENSE` in particular is actively
dangerous to keep — it invites reading a battery voltage off a DAC output
loopback), and the ABI freeze gate had no way to record "removed on purpose,
here's what to use instead" — only "removed" full stop.

`docs/abi/removed-symbols.json` is the new record: one entry per removed
symbol, carrying its header, category, the release it left in, the issue
number, a one-sentence customer-actionable reason, and the replacement symbol
(or an explicit `null` when none exists). `scripts/abi_snapshot.py`'s
`diff()` now loads it (`load_removed_allowlist`, hard-erroring on a malformed
entry) and reports a matching removal as `ALLOWED macro
alp/boards/alp_e1m_evk_routes.h::EVK_ADC_BOARD_ID (intentional removal, #1622
-> EVK_ADC_ARDUINO_A0)` instead of a bare `REMOVED` — still visible in the
diff for review, just no longer unexplained, and never matching the freeze
gate's `grep -q '^  REMOVED '` or the exit-code check that gates the PR. A
removal with no allowlist entry still fails exactly as before. See
`docs/abi/README.md`'s "Recording an INTENTIONAL removal" for the full
mechanism, and `docs/abi/removed-symbols.json` for the three entries this
issue adds.

Upgrading past this release: if your code referenced `EVK_ADC_BOARD_ID`,
`EVK_ADC_MB_AN`, or `EVK_ADC_VBAT_SENSE`, switch to `EVK_ADC_ARDUINO_A0`,
`EVK_ADC_DAC0_LOOPBACK`, or `EVK_ADC_DAC1_LOOPBACK` respectively — there is
no compat alias for any of the three.
