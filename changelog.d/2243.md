### Fixed — whole-repo doc audit: wrong and misleading claims corrected (#2243)

A whole-repo documentation audit (every md surface cross-checked against the
current code, metadata, schemas, and workflows) found a set of claims that
were factually wrong. Corrections, each verified before editing:

`docs/v0.6-tbd-and-assumptions.md` no longer claims an in-tree
`cc3501e-v0.4.0.bin` (+ `.sha256`/`.sig`): per ADR 0031 the CC3501E firmware
lives in the `cc3501e-bridge-firmware` repository, and AEN modules ship from
production factory-flashed with the latest firmware (v0.9.0 as of this
change); OTP updates stay recovery-only. The never-shipped
`cc3501e_usb_bootloader` flash-backend row is marked historical, and §6.5's
`src/yocto/rpc_yocto.c` pointer is re-aimed at the real
`src/backends/rpc/yocto_drv.c`/`yocto_uio_drv.c`.

`docs/threat-model.md` now states honestly that the SDK registers no BLE
pairing/bonding callbacks — pairing policy is application-owned (Zephyr host
stack or CC3501E firmware), not an SDK-enforced mitigation — and records that
`keys/` tracks the release-signing PUBLIC key. `docs/bring-up-v2n.md`
reverses the stale "OTA host helpers not yet shipped" paragraph (the full
`gd32g553_ota_*` set is on `include/alp/chips/gd32g553.h` and
silicon-validated) and expects the current 0.9.x wire protocol from
`GET_VERSION` instead of 0.1.0. `docs/bring-up-v2n-m1.md` and
`docs/firmware-quickstart.md` stop instructing a 0x48 probe for the DEEPX
LPDDR buck (that address is the on-module TMP112; the buck's address is TBD).
`docs/bring-up-aen.md` replaces the "host-side helper TBD" paragraph with the
shipped `cc3501e_init()`, the `examples/aen/aen-cc3501e-bringup/` helper, and
the `alp companion` console verbs. `docs/tutorials/11-mqtt-tls-publish.md`
now compiles: `broker_uri`/`ca_file`/`keepalive_s` replace the three
invented field names, and `docs/tutorials/04-cross-family-portability.md`
drops the nonexistent `include/alp/log.h`. `README.md` names `ssd1306`
instead of the nonexistent `ssd13xx`. `AGENTS.md` matches ADR 0026 (tan owns
the planner; `alp_orchestrate` output is provisional and needs
`PYTHONPATH=scripts`). `docs/zephyr-version-policy.md` records that
`hal_alif` is our own top-level west pin (v2.3.0), `docs/e1m-pinout.md` fixes
the E1M-X pad range (A1..AR64) and the e1m-spec v1.0 lock, and
`docs/board-config-hardware.md`, `docs/ci/README.md`,
`docs/branching-and-merge-policy.md`, `docs/cc3501e-companion-commands.md`,
`docs/_aen-runbook-section.md`, `CONTRIBUTING.md`, and
`docs/contribution.md` get their respective dead pointers, conventions,
required-check, console-surface, and matrix corrections.
