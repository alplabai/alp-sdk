### Fixed — adc,camera: stop advertising unapplied ADC triggers, fix ADC ref/sign handling, reject unnegotiable camera formats (#2923, #2924, #2978)

- ADC (alif_e7, alif_e8): ALP_ADC_CAP_HW_TRIGGER is no longer advertised; alp_alif_adc_set_trigger_source() accepts only ALP_ALIF_ADC_TRIGGER_SOFTWARE and returns ALP_ERR_NOSUPPORT for any other source (it previously stored a value nothing applied), and returns ALP_ERR_NOT_READY on a closed handle instead of dereferencing NULL. alp_adc_open() now fails with ALP_ERR_NOSUPPORT on these backends when the channel has no zephyr,vref-mv (adc_alif has no internal reference), instead of reporting 0 uV with ALP_OK from read_uv. (#2923, #2978)
- ADC (zephyr_drv): a single-ended sample of 16 bits or less is now zero-extended; only differential channels are sign-extended, so a 16-bit reading of 0xC000 or above no longer reads back negative. (#2924)
- Camera (zephyr_video): alp_camera_open() returns ALP_ERR_NOSUPPORT for MONO_VLSB, YUV420_PLANAR and NV12 instead of silently keeping the sensor default. Note that MONO_VLSB is the enum's zero value, so a hand-built alp_camera_config_t with an unset format now fails to open; use ALP_CAMERA_CONFIG_DEFAULT or set the format. Releasing a buffer the application does not hold returns ALP_ERR_INVAL instead of re-enqueuing it twice. (#2923)
- Known follow-up: unit tests for the zephyr_video format rejection and held-buffer tracking are not yet written (no zephyr_video registry harness).
