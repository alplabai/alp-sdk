### Fixed — `alif_pdm.c` ignored the Zephyr `dmic` contract; `<alp/audio.h>` PDM capture returned `ALP_OK` then read nothing (#2133)

`alp_audio_in_open()` + `alp_audio_in_start()` returned `ALP_OK` on the E1M-AEN801's HP PDM mics, then every `alp_audio_in_read()` timed out with an empty FIFO. `dmic_alif_pdm_configure()` (`zephyr/drivers/audio/alif_pdm.c`) broke the standard Zephyr `dmic` API contract two ways: it read `req_chan_map_lo`'s low byte VERBATIM as the hardware channel-enable mask instead of decoding the standard `dmic_build_channel_map()` nibble encoding, and it never left the PDM clock-mode field `MICROPHONE_SLEEP` nor programmed per-channel FIR/gain. The portable `src/backends/audio/zephyr_drv.c` backend used the standard encoding correctly, so it was the one broken by the driver's divergence: for its 2-channel request the verbatim read produced `0x10` (hardware channel 4 only) instead of `0x03` (hardware channels 0 and 1, where the EVK's mics actually are).

Fixed by making the driver honour the contract itself: a dependency-free translation header, grounded in the register layout and HWRM 15.7.4.3.1's even/rising-odd/falling edge rule (`zephyr/drivers/audio/alif_pdm_chanmap.h:21` ("hw_channel = (pdm_controller * 2) + lr")), replaces (not ORs) the channel-enable field and rejects a duplicate/out-of-order map the ISR cannot honour; per-channel FIR/gain defaults are primed in `configure()`, with the actual `PDM_MODE` write deferred to `DMIC_TRIGGER_START` so `configure()` alone cannot start the block sampling. `configure()` validates the requested `pcm_rate` against a HWRM/DFP-grounded clock-mode table (`zephyr/drivers/audio/alif_pdm.c:450` ("{ 8000U, PDM_MODE_STANDARD_VOICE_512_CLK_FRQ, 512000U },"), `zephyr/drivers/audio/alif_pdm.c:463` ("{ 16000U, PDM_MODE_HIGH_QUALITY_1024_CLK_FRQ, 1024000U },"), `zephyr/drivers/audio/alif_pdm.c:472` ("{ 32000U, PDM_MODE_WIDE_BANDWIDTH_AUDIO_1536_CLK_FRQ, 1536000U },"), and `zephyr/drivers/audio/alif_pdm.c:516` ("{ 48000U, PDM_MODE_FULL_BANDWIDTH_AUDIO_3071_CLK_FRQ, 3072000U },")) AND the board's own mic clock range, a board-level DT fact (`clk-frequency-min`/`clk-frequency-max` on `alif,alif-pdm.yaml`) rather than something the driver or an app invents -- the portable backend's own generic clock window is unchanged (`src/backends/audio/zephyr_drv.c:284` (".min_pdm_clk_freq = 1000000,")). HWRM 15.7.5.3.1's back-to-back `PDM_CTL0` write-spacing requirement is honoured by `pdm_ctl0_write_spacer()` (`zephyr/drivers/audio/alif_pdm.c:539` ("static void pdm_ctl0_write_spacer(const struct device *dev)")) before every `PDM_CONFIG_REGISTER` write; `pdm_force_sleep()` (`zephyr/drivers/audio/alif_pdm.c:561` ("static void pdm_force_sleep(const struct device *dev)")) forces the block's channel-enable and clock-mode fields inert on a genuine cold boot only, so a fresh image no longer silently inherits whatever mode/channels the PREVIOUS image left running.

**Drop reporting.** A slab-alloc miss, a delivery-queue overflow (oldest block evicted), or a genuine hardware FIFO overflow (`PDM_ERROR_IRQ`'s status-register bit 0, `zephyr/drivers/audio/alif_pdm_reg.h:82` ("#define PDM_ERROR_IRQ_FIFO_OVERFLOW_STAT (0x1U << 0U)") -- distinct from the enable register's bit 1 this used to test) each set a new sticky `overrun` flag (`zephyr/drivers/audio/alif_pdm.c:375` ("bool overrun;")) at every drop site (`zephyr/drivers/audio/alif_pdm.c:1277`, `zephyr/drivers/audio/alif_pdm.c:1440`, and `zephyr/drivers/audio/alif_pdm.c:1472`, each setting it), checked by `dmic_alif_pdm_read()` before every `k_msgq_get()` so a caller gets `-EIO` instead of silently splicing the next block onto the gap (`zephyr/drivers/audio/alif_pdm.c:1167` ("if (pdata->overrun) {")); the flag clears only in `DMIC_TRIGGER_STOP`, after it frees the in-progress block and drains the queue, so a restart without a prior `STOP` cannot erase the report. `DMIC_TRIGGER_START`/`dmic_alif_pdm_configure()`'s refuse/no-op/proceed decisions are pure functions, `pdm_decide_start()`/`pdm_configure_allowed()` (`zephyr/drivers/audio/alif_pdm_trigger_state.h:56` and `zephyr/drivers/audio/alif_pdm_trigger_state.h:93`), mirroring `dmic_mcux.c`'s `DMIC_STATE_ACTIVE`/`DMIC_STATE_ERROR` handling (ZEPHYR_BASE `zephyr/drivers/audio/dmic_mcux.c`): START refuses `-EIO` when unconfigured or still flagged `overrun`; `configure()` refuses `-EBUSY` while a capture is active, so a second `configure()` call can no longer force-sleep the hardware or swap `mem_slab` out from under an in-progress capture.

**Resume/suspend hygiene.** `pdm_hw_bringup(dev, cold_init)` (`zephyr/drivers/audio/alif_pdm.c:1513` ("static int pdm_hw_bringup(const struct device *dev, bool cold_init)")) only force-sleeps on a genuine cold boot -- `PM_DEVICE_ACTION_RESUME` no longer wipes a prior session's hardware channel-enable field. `PM_DEVICE_ACTION_SUSPEND` (`zephyr/drivers/audio/alif_pdm.c:1616` ("case PM_DEVICE_ACTION_SUSPEND: {")) disables interrupts and zeroes `record_data` BEFORE freeing/draining the in-progress buffer and queue (mirroring `DMIC_TRIGGER_STOP`'s ordering, closing a use-after-free/double-free race the ISR could otherwise run into), and resets `clk_mode` to `PDM_MODE_MICROPHONE_SLEEP` (`zephyr/drivers/audio/alif_pdm.c:1682`) as a fail-safe against the hardware channel-enable/FIR/GAIN registers NOT surviving the low-power transition -- a post-resume `DMIC_TRIGGER_START` now always refuses as "not configured" rather than risk proceeding over dead register state. Latent today (`CONFIG_PM_DEVICE` is off on every board this driver ships on).

**Errno mapping.** `alp_audio_in_read(..., timeout_ms=0)` reaches `k_msgq_get(K_NO_WAIT)`, which returns `-ENOMSG` for "nothing queued yet"; the shared `alp_status_from_zephyr_errno()` baseline has no arm for it and falls through to `ALP_ERR_IO` ("dropped data, sticky") instead of `ALP_ERR_TIMEOUT`. Fixed with a local override in `src/backends/audio/zephyr_drv.c`'s `errno_to_alp()` (`alp_status_from_zephyr_errno_ex()`, `src/backends/audio/zephyr_drv.c:140`), kept local rather than touching the shared baseline header to stay minimal against `fix/2132-audio-out-start-defers-until-first-block`'s concurrently in-flight edits to the same file's `out` paths.

**Gain clamp.** `pdm_set_ch_gain()`'s `ch_gain` is only meaningful in `PDM_CH_GAIN`'s 12-bit field; a caller-supplied value above `PDM_CH_GAIN_MAX` (`0xFFF`) used to be written unclamped, truncating to bits [11:0] -- `0x1000` exactly truncates to 0 (mutes the channel), the opposite of what a caller raising gain would expect. Since the function returns `void` (existing public API), it now clamps through `pdm_ch_gain_clamp()` (`zephyr/drivers/audio/alif_pdm_reg.h:56` ("static inline uint32_t pdm_ch_gain_clamp(uint32_t ch_gain)")), called from `pdm_set_ch_gain()` (`zephyr/drivers/audio/alif_pdm.c:883` ("ch_gain = pdm_ch_gain_clamp(ch_gain);")) and from `pdm_apply_channel_defaults()`'s `cfg->channel_gain` application (`zephyr/drivers/audio/alif_pdm.c:606` ("pdm_set_ch_gain(dev, hw_ch, cfg->channel_gain);")), with a `LOG_WRN` instead of a silent truncation. `PDM_INIT`'s `BUILD_ASSERT` independently bounds the DT `channel-gain` property to `0x001..PDM_CH_GAIN_MAX` at build time (`zephyr/drivers/audio/alif_pdm.c:1735` ("BUILD_ASSERT(DT_INST_PROP_OR(n, channel_gain, 0x200) >= 0x001 && \")); an inverted `clk-frequency-min`/`clk-frequency-max` DT range is independently caught the same way (`zephyr/drivers/audio/alif_pdm.c:1717` ("BUILD_ASSERT(!(DT_INST_NODE_HAS_PROP(n, clk_frequency_min) && \")).

`examples/aen/aen-pdm-mic-alif` moves onto the standard contract: it measures the ACHIEVED sample rate (frames delivered / elapsed wall-clock time, excluding the first read's startup latency) rather than only checking "PCM varies", requires it within ±5% of the requested rate, treats a driver-reported drop (`dmic_read()` returning `-EIO`) as an outright `FAIL` regardless of what the surviving blocks measured (`examples/aen/aen-pdm-mic-alif/src/main.c:394` ("verdict = "), `examples/aen/aen-pdm-mic-alif/src/main.c:403` ("verdict = "), and `examples/aen/aen-pdm-mic-alif/src/main.c:412` ("verdict = ")), and gates `PASS` on at least one channel's peak-to-peak clearing a documented floor above idle noise, re-derived directly from silicon (see below) rather than assumed (`examples/aen/aen-pdm-mic-alif/src/main.c:123` ("((4U * 128U * DT_PROP(PDM_NODE, channel_gain)) / PDM_GAIN_BASELINE_0X200)")) -- `PASS` (`examples/aen/aen-pdm-mic-alif/src/main.c:419` ("verdict = ")) is worded as "above the idle-noise floor", not "live audio": this example has no controlled stimulus of its own, so the actual acoustic verification is the loopback below, scoped to mic ch0/ch1 only. `examples/aen/aen-evk-demo`'s sound-baseline loop reads `SOUND_BASELINE_BLOCKS + 1` blocks and skips the first (settling transient), so the baseline itself still accumulates the full `SOUND_BASELINE_BLOCKS` (`examples/aen/aen-evk-demo/src/main.c:4357` ("for (unsigned b = 0; b < SOUND_BASELINE_BLOCKS + 1u; b++) {")) -- reading only `SOUND_BASELINE_BLOCKS` and then skipping the first left just `SOUND_BASELINE_BLOCKS - 1` in the baseline, weakening it. That path needs a mic sample rate whose PDM clock is >= 1.2 MHz on this EVK: at the example's `SOUND_SAMPLE_RATE_HZ` (16000, mode 4's 1024 kHz clock) the board overlay's `clk-frequency-min = <1200000>` rejects it with `-EINVAL`, so the baseline/correlation path is exercised only once a mic-capable rate is available independent of the speaker rate (issue #2134, software resample). `<alp/audio.h>` documents the settling requirement generically -- discard the first block after start/restart, duration is backend-specific (`include/alp/audio.h:118` ("-- discard the first block after start/restart; the settling")) -- with the measured figure (see below) kept in the Alif binding, not the portable header.

New host-testable regression: `tests/unit/alif_pdm_chanmap` (12 cases) locks the channel-map translation against the portable backend's and the example's exact requests, plus `pdm_ch_gain_clamp()`'s boundary (`0xFFF` passes through unchanged; `0x1000` and `0xFFFFFFFF` both clamp to `PDM_CH_GAIN_MAX`) -- mutation-checked: removing the clamp (`return ch_gain;` unconditionally) fails exactly the two out-of-range cases, 10/12; restored, 12/12. `tests/unit/alif_pdm_trigger_state` (6 cases) locks `pdm_decide_start()`'s refuse/no-op/proceed decision and `pdm_configure_allowed()`'s active-capture refusal (`tests/unit/alif_pdm_trigger_state/src/test_alif_pdm_trigger_state.c:79` ("ZTEST(alif_pdm_trigger_state, test_configure_refused_while_active)") and `tests/unit/alif_pdm_trigger_state/src/test_alif_pdm_trigger_state.c:84` ("ZTEST(alif_pdm_trigger_state, test_configure_allowed_while_idle)")); mutation-checked per case. `tests/unit/errno_mapping` (`test_zephyr_enomsg_baseline_is_io_not_timeout`, `tests/unit/errno_mapping/src/test_errno_mapping.c:86`) pins the shared baseline's `-ENOMSG` answer; `tests/unit/audio_in_enomsg_timeout` (`test_nonblocking_empty_read_is_timeout_not_io`, `tests/unit/audio_in_enomsg_timeout/src/test_audio_in_enomsg_timeout.c:30`) exercises `zephyr_drv.c`'s override end to end against a fake DMIC backend -- deleting the override fails this test; restoring it passes.

**Silicon evidence, `e1m-aen-evk-03`.** Register-level configuration: `PDM_CONFIG_REGISTER` read back matching the requested channel map and mode, held throughout capture; the 16 kHz build's DT-range guard is confirmed (`dmic_configure -> -EINVAL`, register never written). 48 kHz mode 7: `measured_rate_hz=48000` exactly, `slab_missed=0`, `overrun=0`, no `-EIO` for the full run (commit `68a169977`). Acoustic capture at 48 kHz on mic ch0/ch1 (PDM controller 0) ONLY is separately verified by a speaker-to-mic loopback -- the `PROBE_LOOPBACK` mode of `examples/aen/aen-i2s-tas2563-probe` on branch `test/u46-i2s-tas2563-on-reworked-mux` (issue #2143), NOT this driver's own example, which has no controlled stimulus: TAS2563 speakers (independently verified audible) played known tones at gain `0x200` (readback-confirmed); Goertzel-bin analysis (2 s windows, first 200 ms discarded) found the 1 kHz bin at 9.3/0.1 dB (ch0/ch1) in silence rising to 43.4/48.8 dB at volume 16 and 57.8/57.6 dB at volume 48, a 500 Hz bin at 54.7/56.6 dB that only lit up during the 500 Hz stimulus window (staying within -9.8..+5.3 dB everywhere else), and peak-to-peak (the probe's own `loop_chan_result_t.p2p`) rising from 128/128 in silence to 651/652 at 1 kHz/volume 48. **The D2 pair (HW 4/5) is register-level verified only, never acoustically tested.** An early raw hex dump of the capture-start transient (from the same unattended 30 s bench build later found not to be a genuine clap test) showed roughly 7 zero samples followed by ~25 samples of ring-down at 48 kHz -- under 1 ms total; documented in `zephyr/dts/bindings/audio/alif,alif-pdm.yaml`'s decimator-settling description (its comma-bearing filename isn't a checkable `path:NNN` citation). **Still unmeasured:** full-scale headroom at gain `0x200` (`examples/aen/aen-pdm-mic-alif/src/main.c`'s peak-to-peak floor, re-derived from this same loopback data, has NOT itself been re-run on silicon -- a silent room is expected to report `INCONCLUSIVE` and a replayed tone `PASS`, but that is a prediction from the derivation, pending a bench confirmation run).
