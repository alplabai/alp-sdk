### Fixed — `alif_pdm.c` ignored the Zephyr `dmic` contract; `<alp/audio.h>` PDM capture returned `ALP_OK` then read nothing (#2133)

`alp_audio_in_open()` + `alp_audio_in_start()` returned `ALP_OK` on the E1M-AEN801's HP PDM mics, then every `alp_audio_in_read()` timed out with an empty FIFO. `dmic_alif_pdm_configure()` (`zephyr/drivers/audio/alif_pdm.c`) broke the standard Zephyr `dmic` API contract two ways: it read `req_chan_map_lo`'s low byte VERBATIM as the hardware channel-enable mask instead of decoding the standard `dmic_build_channel_map()` nibble encoding, and it never left the PDM clock-mode field `MICROPHONE_SLEEP` nor programmed per-channel FIR/gain — only the Alif-specific `pdm_mode()`/`pdm_channel_config()`, which a standard `dmic` consumer has no reason to call, did that. The portable `src/backends/audio/zephyr_drv.c` backend used the standard encoding correctly, so it was the one broken by the driver's divergence: for its 2-channel request the verbatim read produced `0x10` (hardware channel 4 only) instead of `0x03` (hardware channels 0 and 1, where the EVK's mics actually are).

Fixed by making the driver honour the contract itself. A new dependency-free header translates the standard channel map into the hardware channel-enable mask, grounded in both the register layout and the bench-proven example's raw bitmask (`zephyr/drivers/audio/alif_pdm_chanmap.h:21` ("hw_channel = (pdm_controller * 2) + lr")). `dmic_alif_pdm_configure()` now calls it and replaces (never ORs into) the channel-enable field (`zephyr/drivers/audio/alif_pdm.c:238` ("rc = alif_pdm_chanmap_translate(config->channel.req_chan_map_lo,")). `configure()` also now selects a real PDM clock mode from `streams[0].pcm_rate` and primes every enabled channel's FIR/gain/phase/peak-detect defaults itself (`zephyr/drivers/audio/alif_pdm.c:153` ("static const struct pdm_clock_mode_entry pdm_clock_modes[] = {")), sourced verbatim from the Alif reference via `examples/aen/aen-pdm-mic-alif`; only the bench-proven `STANDARD_VOICE_512` @ 16 kHz entry is populated, and any other `pcm_rate` is rejected with `-EINVAL` rather than left silently asleep — no coefficients were invented for the other 9 clock modes. `pdm_mode()`/`pdm_channel_config()` stay public for an app that wants to override the defaults.

`examples/aen/aen-pdm-mic-alif` moves onto the standard contract: it now builds its channel map with `dmic_build_channel_map()` (`examples/aen/aen-pdm-mic-alif/src/main.c:86` (".req_chan_map_lo = dmic_build_channel_map(0, 0, PDM_CHAN_LEFT) |")) and no longer calls `pdm_mode()`/`pdm_channel_config()`/`pdm_set_ch_*()` by hand — the driver now does that setup itself. Its README's "MICROPHONE_SLEEP" step is updated to match.

New host-testable regression: `tests/unit/alif_pdm_chanmap` locks the translation with the portable backend's exact 2-channel map, the example's 4-channel map, and an invalid-map rejection case (`tests/unit/alif_pdm_chanmap/src/test_alif_pdm_chanmap.c:29` ("ZTEST(alif_pdm_chanmap, test_backend_2channel_map_enables_hw_0_and_1)")). The old verbatim `& 0xFF` behavior was confirmed red against this exact suite (all 4 cases fail) before the fix, and green (4/4 pass) after.

The clock-mode change is not unit-testable — it drives a PDM analog block with no host model — and needs a silicon bench run to confirm live PCM, the same result already recorded for the working-by-hand version of the example (`docs/aen-bench-bringup.md:35` ("| **PDM mics** | ✅ PASS | Live varying PCM = real audio. |")).

`examples/aen/aen-evk-demo`'s phase 11 opens the HP PDM mic through `<alp/audio.h>` (`alp_audio_in_open()`, `examples/aen/aen-evk-demo/src/main.c:4320` ("mic    = alp_audio_in_open(&(alp_audio_config_t){")) — the exact portable path this issue fixes — but only when built with `AEN_EVKDEMO_SOUND_PLAYBACK=1` (playback off, the default, never opens the mic); no source change was needed there, it inherits the fix through the driver. The LP PDM node (`lppdm@43002000`, same `alif,alif-pdm` compatible, disabled by default) shares `dmic_alif_pdm_configure()` and inherits the fix automatically once enabled. `tests/zephyr/audio` does not reference `dmic`/`pdm` and is unaffected.
