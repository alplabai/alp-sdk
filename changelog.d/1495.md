### Fixed — board-config docs cited a stale preset-adoption count and a removed `routes_via:` key (#1495)

`docs/board-config-schema.md:254` claimed "66 do today — 46 on `e1m-evk`, 20
on `e1m-x-evk`"; the real counts are 100 `board.yaml` files under
`examples/` (`find examples -name board.yaml | wc -l`), 75 on `e1m-evk`
(`grep -rl '^preset: e1m-evk' examples --include=board.yaml | wc -l`) and 25
on `e1m-x-evk` (same, `e1m-x-evk`). The doc now cites 100/75/25.

Separately, `metadata/templates/board.yaml:160` and
`docs/board-config-schema.md:246` still advertised a `routes_via:` key on
`e1m_routes:` entries. `$defs.route_entry` in `board.schema.json` is
`additionalProperties: false` and does not accept that key — it was removed
from the schema in an earlier release (SoM concern, moved to the SoM
preset's `pad_routes.dispatch:`) — so a customer copying the template and
using the key it advertises got a hard validation rejection. The dead key is
removed from both the template comment and the doc prose.
