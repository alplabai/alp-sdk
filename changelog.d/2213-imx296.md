### Added — Sony IMX296 Zephyr sensor driver + Raspberry Pi Global Shutter Camera shield (#2213)

`zephyr/drivers/video/imx296.c` adds a Sony IMX296 driver for the
InnoMaker-GS-camera-compatible module (IMX296LQR-C colour part), authored
from the Sony IMX296 datasheet — no permissive-licence IMX296 driver exists
anywhere to consume (not in upstream Zephyr v4.4.1, hal_alif, or Espressif
esp_cam_sensor; Linux's and libcamera's are GPL/LGPL and were not read while
writing this file). ADR-0017-ADJACENT, BENCH-UNVERIFIED. All-pixel scan
mode only: 1456x1088, the frame the sensor actually transmits (the datasheet's
1440x1080 recording area plus the colour-processing margin it sends rather
than crops), `SRGGB10P` RAW10, **1 MIPI CSI-2
data lane** (unlike the sibling OV5647/OV9281 shields, both 2-lane), 60.3
frame/s, 37.125/54/74.25 MHz INCK (any other frequency rejected at runtime
with `-ENOTSUP`). Controls: exposure, analogue gain (0.1 dB step), H/V
flip, pixel rate (118.8 Mpix/s), link frequency (594 MHz). The datasheet
defines no readable chip/product-ID register for this part, so probe uses a
documented readable-register (STANDBY) sanity check instead.

The new `raspberry_pi_global_shutter_camera` shield wires the sensor's
54 MHz `fixed-clock`, CCI address 0x1A, and single-lane endpoint onto the
same board-agnostic `raspberry_pi_camera_module_2`-style label contract as
its siblings (`chosen zephyr,camera`, `&csi_interface`, `&csi_ep_in`,
`&csi_i2c`); build with
`SHIELD="<carrier-connector-shield> raspberry_pi_global_shutter_camera"`.
The 54 MHz oscillator must match the module's actual crystal — see
`zephyr/boards/shields/raspberry_pi_global_shutter_camera/doc/index.rst`.

IMX296 and OV5647 join `tests/zephyr/video_sensors` as compile-coverage
(no emulator), alongside the OV9281 runtime ztest that landed via #2247. See
`docs/camera-shields.md` for the full driver/shield/control reference,
including the RAW10 frame-buffer memory footprint (3,168,256 bytes per frame —
must live in SRAM/DDR, not TCM).
