### Added — regression coverage for the CC3501E GPIO proxy's delegated-path owner handle (#1618)

The code fix for this issue (the platform GPIO backend recovering a garbage
owner pointer for a proxy-delegated pin, via `CONTAINER_OF` on a sidecar
member that isn't a `struct alp_gpio`) already landed on `dev` as
`alp_z_gpio_open_owned()` (#1706) while this branch was in flight; that
version takes the owning handle's state as an explicit parameter rather than
the `open_delegated` ops-table entry this branch originally added, and is
kept as-is here.

What this branch still adds, because nothing on `dev` exercises it yet:
`tests/zephyr/peripheral/src/gpio_proxy.c`, under the new
`alp_sdk.peripheral.cc3501e_proxy` scenario. It opens two delegated handles
so the adjacent `_sides[]` slot holds a recognisable pattern, arms a
rising-edge IRQ on the first, drives the edge on `gpio_emul0`, and asserts
the callback fires once with the handle it was registered against — against
the real, already-landed `alp_z_gpio_open_owned()` path, through the public
`<alp/*.h>` API only (no dependency on the superseded `open_delegated`
shape). Before either fix landed, the whole image died with `rc=-11`
(SIGSEGV) inside `_isr_thunk` on this scenario.

The scenario is scoped to its own image rather than added to `prj.conf`: the
proxy registers at priority 200, above the platform backend's 100, so
enabling it globally would route every existing GPIO test in that directory
through it.

**Not verified on silicon.** `native_sim` proves the pointer is right; it
does not prove the interrupt path works on an M55. Needs an E1M-AEN801
bench pass driving an edge on a delegated pin.
