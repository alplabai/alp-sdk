### Fixed — the CC3501E GPIO proxy handed the platform backend a non-handle, so an ISR called a function pointer built from the next pool slot (#1618)

`src/backends/gpio/cc3501e_proxy.c`'s `px_open` delegated every non-routed pin to
the platform backend with `z->open(pin_id, &s->inner, caps)`, where `s->inner` is
a member of the proxy's own `proxy_side_t` sidecar. The platform backend then
recovered an owning handle from it by container arithmetic:

```c
	s->owner = CONTAINER_OF(st, struct alp_gpio, state);
```

`state` is the **first** member of `struct alp_gpio`, so that `offsetof` is 0 and
the arithmetic silently "succeeds" on anything it is given. `owner` became
`(struct alp_gpio *)&s->inner` — a `proxy_side_t` reinterpreted as a much larger
handle, whose `cb` field lands past the end of the slot, **inside the next
`_sides[]` entry**. `_isr_thunk` then read that as a function pointer and called
it in interrupt context.

Reachable on shipping configurations, not a theoretical layout hazard.
`CONFIG_ALP_SDK_GPIO_CC3501E_PROXY=y` appears in `examples/aen/aen-cc3501e-gpio`,
`examples/aen/aen-cc3501e-bringup` and `examples/aen/aen-cc3501e-companion-tour`,
and with the shipped weak-EMPTY `cc3501e_gpio_routes[]` table **every** pin takes
the delegated path — the LEDs, `WIFI_EN` and `nRESET` included. `z_close` read
`s->owner->edge` through the same bad pointer.

`alp_gpio_ops_t` gains `open_delegated`, which takes the owning handle
explicitly. `px_open` recovers the genuine owner from its own `state` argument —
which really is `&outer->state`, so the container arithmetic is valid at *that*
layer — and passes it down; a backend whose `open_delegated` is NULL is refused
with `ALP_ERR_NOSUPPORT` rather than silently falling back to the broken path.
`z_open` now routes through the same body, so there is one open implementation
rather than two.

Two alternatives were rejected. Giving the proxy a real `struct alp_gpio` to
delegate through does not work: the dispatcher populates `cb`/`cb_user` on the
**outer** handle, so an inner handle's `cb` is always NULL and the interrupt would
silently never fire — safely broken is still broken. Forwarding `state` itself in
place of `&s->inner` does not work either: both layers write `state->be_data`, and
the platform backend would clobber the proxy's own sidecar pointer.

`alp_gpio_ops_t` is internal (`src/backends/gpio/gpio_ops.h`), not under
`include/alp/`, so this adds no public symbol and needs no ABI-snapshot regen.
`sw_fallback.c` and `testing_drv.c` leave the new member NULL, which is correct —
neither is a delegation target.

Regression test: `tests/zephyr/peripheral/src/gpio_proxy.c`, under the new
`alp_sdk.peripheral.cc3501e_proxy` scenario. It opens two delegated handles so the
adjacent `_sides[]` slot holds a recognisable pattern, arms a rising-edge IRQ on
the first, drives the edge on `gpio_emul0`, and asserts the callback fires once
with the handle it was registered against. Before the fix the whole image died
with `rc=-11` (SIGSEGV) inside `_isr_thunk` — the garbage `cb` read as a
non-NULL address — taking 110 later test cases down with it.

The scenario is scoped to its own image rather than added to `prj.conf`: the
proxy registers at priority 200, above the platform backend's 100, so enabling it
globally would route every existing GPIO test in that directory through it.

**Not verified on silicon.** `native_sim` proves the pointer is right; it does not
prove the interrupt path works on an M55. Needs an E1M-AEN801 bench pass driving
an edge on a delegated pin.
