### Fixed — the AEN A32 machine confs stopped asserting a `meta-alif-ensemble` BSP branch that does not exist (#1968, #1971)

`e1m-aen801-a32.conf` carried an active, uncommented `require
conf/machine/devkit-e8.conf # meta-alif-ensemble @scarthgap`. Neither the
file nor the branch exists: a fresh clone of
`github.com/alifsemi/meta-alif-ensemble` (verified 2026-09-05) has exactly
one branch, `devkit-ex-b0`, whose `conf/machine/` carries only
`appkit-e7.conf`, `devkit-e5.conf`, `devkit-e7.conf` — no `devkit-e8.conf`
anywhere public (#1968). The `require` is now commented out, following the
sibling `e1m-aen701-a32.conf`'s existing honest pattern for the same
situation.

Both files' headers repeated the same false narrative — that
`meta-alif-ensemble` has a `scarthgap` branch matching this repo's Yocto
series. It does not, and even granting the missing file existed, the one
real branch is structurally incompatible with Scarthgap: its
`conf/layer.conf` declares `LAYERSERIES_COMPAT_meta-alif-ensemble =
"warrior zeus"` (Yocto 3.0, 2019) against `meta-alp-sdk`'s Scarthgap
(5.0.11) baseline (#1971). Both headers now say plainly that
`e1m-aen801-a32` and `e1m-aen701-a32` are non-buildable placeholders today,
cite #1968 and #1971 for the two independent reasons, and note that
whether Alif's login-gated support portal carries a Scarthgap-compatible
layer is unconfirmed. `meta-alp-sdk/README.md` and `docs/bring-up-aen.md`
already carried this corrected account (PR #2006); the two machine confs
were the only remaining spot still asserting the old, false one.

No functional change: `scripts/alp_orchestrate/orchestrator.py`'s
`YOCTO_MACHINE_UNBUILDABLE` denylist already refused both MACHINEs before
this fix and is untouched here. Neither MACHINE builds after this change
either — that needs a Scarthgap-compatible BSP that does not exist yet.
