### Added — `alpcamerasrc` GStreamer source for the V2N CRU (CR10)

**`tools/gst-alpcamerasrc/` adds a GStreamer element on `<alp/camera.h>` that outputs `GRAY8`, `GRAY16_LE` and `NV12` (mono: Y = pixel, UV = 128) from the CRU's `CR10` capture, so `alpcamerasrc ! video/x-raw,format=NV12 ! omxh264enc ! h264parse ! rtph264pay` is a valid camera-to-H.264 pipeline.** `v4l2src` and `videoconvert` cannot read `CR10`. The new `gst-plugin-alp-camera` recipe is part of `packagegroup-alp-camera` on V2N/V2M machines; the conversions have a host test, `tests/yocto/gst_alpcamerasrc_convert.c`. It has not been run on silicon yet. Plugin licence string is `Apache 2.0` (GStreamer rejects others). See `docs/v2n-camera-csi.md`.

**`alpcamerasrc` also takes colour Bayer sensors with no ISP: it opens `ALP_PIXFMT_RAW10` and debayers on the CPU with a 2x2 superpixel into half-size `NV12` (1456x1088 sensor, `NV12` 728x544).** The colour IMX296 offers only `SBGGR10` and failed `alp_camera_open` with `ALP_ERR_NOSUPPORT` on the mono path. Property `bayer-order` (default `bggr`) names the order because `<alp/camera.h>` does not report it, and `r-gain` / `b-gain` set a fixed white balance; there is no AWB or AE. The debayer has a host test for all four orders; not run on silicon yet.
