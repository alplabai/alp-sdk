### Fixed — `check_cross_platform.py`'s `IMPLICIT-ENCODING` rule no longer demands a fix that cannot be applied, and no longer skips `**kw` subprocess helpers (#2197)

Before the #2197 drain starts, the rule itself gets fixed, so that no
baselined site is one the drain cannot clear.

**Some `.open()` calls were flagged even though the suggested fix cannot be
applied.** `tokenize.open()` has no `encoding=` parameter, so following the
advice raises `TypeError`. `tarfile.open(..., mode="w")` is also not a
text-mode open: its `"w"` is a tar mode. Four baselined sites had these shapes,
and one of them used a function-scope `import tarfile as _tf`. The check now
resolves the call's owner through `import m` / `import m as a` at any scope,
and through a module-level `from m import open`. It skips modules whose `open`
takes no `encoding=`: `scripts/check_cross_platform.py:692`
("_OPEN_WITHOUT_ENCODING_MODULES: frozenset"). The list also includes `os`,
because `os.open(path, flags=...)` would otherwise be read as a text open.
`from m import open` inside a function is not honoured, because treating it
file-wide would exempt every builtin `open()` in the file. `.open()` on an
owner the check cannot resolve, such as `widget.open()`, is still flagged.

**`Path.open()`'s mode was read from the wrong argument.** The mode was always
taken from the second positional argument. That is correct for
`open(file, mode)`, but `Path.open(mode)` takes the mode first. As a result,
`path.open("rb")` in `scripts/provision_som.py` was flagged while
`open(p, "rb")` was not. The slot now depends on the call shape:
`scripts/check_cross_platform.py:846`
("_open_mode_is_binary(node, 1 if builtin_shape else 0)"). The builtin, every
module-level `m.open(file, mode)` (so `gzip.open(p, "rb")` stays unflagged and
`gzip.open(p, "rt")` stays flagged) and any call with two or more positionals
read the second slot. Only a one-argument method call such as
`Path.open("rb")` reads the first.

**`os.fdopen()` was never checked.** Its call name is `fdopen`, so the check
never matched it, although it opens text mode by default just like `open()`.
It is now matched when its owner resolves to `os`, with the builtin
`(fd, mode)` shape: `scripts/check_cross_platform.py:695`
("_OPEN_CALL_NAMES: frozenset[str]"). This adds one finding,
`scripts/flash_backends/swd_probe.py`'s `os.fdopen(fd, "w")`, under that
file's existing baseline entry.

**`subprocess` helpers that forward `**kw` were never checked.** A blanket
`**kwargs` skip hid 13 `_run(*args, **kw)` helpers that call
`subprocess.run([sys.executable, ...], text=True, **kw)`. Their `**kw` passes
through `cwd`/`env`/`check`, not an encoding. A subprocess call whose explicit
`text=True` proves text mode is now flagged even when `**kw` is also passed:
`scripts/check_cross_platform.py:809`
("if name not in _SUBPROCESS_TEXT_CALLS and any("). `read_text`, `write_text`
and `open` calls with `**kw` are still skipped: nothing in the call proves the
mode or rules out an encoding, so the check does not guess. Three of the 13
helpers were in files outside the baseline, so they are fixed here. Each one
now passes `encoding="utf-8"` and makes the Python child write UTF-8, merged
over any `env` the caller passes (an explicit `env=None` falls back to
`os.environ`): `tests/scripts/test_check_doc_drift.py:16`
("env={**(kw.pop("), and the same line in
`test_check_i2c_bus_doc_consistency.py` and `test_check_version_doc_sync.py`.
The other ten are in files that are already baselined and will be drained
there.

**The baseline advice described an escape hatch that does not exist.** The
baseline comment and the size-pin failure message both pointed to "an inline
exemption at the call site". The module docstring says there is none, and the
scanner has none. Both now say the same thing:
`scripts/check_cross_platform.py:357` ("there is no inline exemption (see the").

**The baseline shrinks from 139 to 137 files.**
`scripts/check_write_text_newline.py` and
`tests/scripts/test_alp_model_adapters.py` no longer produce any finding,
because their only findings were the false positives above. The shrink-only
size pin moves with them: `tests/scripts/test_check_cross_platform.py:536`
("len(linter.IMPLICIT_ENCODING_BASELINE) <="). The total number of baselined
findings goes from 478 to 484. Five false positives are gone, and eleven real
sites are now counted: ten that the `**kw` skip used to hide and the
`os.fdopen()` above.
