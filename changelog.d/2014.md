### Fixed — the build-plan CWD-independence test compared the whole envelope, including the live git commit, and could redden on a race that had nothing to do with CWD (#2014)

`tests/scripts/test_orchestrate_buildplan.py::test_emit_build_plan_app_paths_independent_of_cwd`
calls `emit_build_plan()` twice from two different working directories and
asserted that the two returned envelopes were equal in full. That included
`sdkCommit`, which `scripts/alp_orchestrate/buildplan.py::_sdk_commit()`
resolves with a live `git rev-parse --short HEAD` on every call. Any
concurrent git operation in the same worktree between the two calls — a
commit from another agent, a rebase, a branch switch — moved `sdkCommit`
between them and failed the assertion for a reason unrelated to the
CWD-independence property the test exists to guard (issues #596 and #865).
It fired for real on 2026-09-06:

```
AssertionError: {'sdkCommit': '3dadd4584'} != {'sdkCommit': 'a284f7647'}
```

The CWD-independence comparison now excludes exactly the envelope keys
whose value is read from ambient process/repository state rather than
derived from the test's inputs, via a new module-level
`_ENV_DERIVED_ENVELOPE_FIELDS` constant. Tracing `emit_build_plan()`'s full
call graph turned up exactly one such key: `sdkCommit`. Its sibling
`sdkVersion` (`_sdk_version()`, read from `metadata/sdk_version.yaml`) is
deliberately left in the comparison — it only moves on a deliberate
release-version bump, never as a side effect of ordinary concurrent
commit/rebase/branch-switch activity, the same asymmetry
`scripts/check_emit_snapshots.py` already encodes for the golden-snapshot
gate (a comment on the new constant also reconciles this against
`tests/parity/seam1_field_diff.py`, which drops `sdkVersion` too, but for
the opposite reason: that harness diffs a frozen cross-release oracle
against the current checkout, where `sdkVersion` is guaranteed to differ
by construction — not the same-checkout, two-in-process-calls case this
test is making). Every path, token, and slice the test actually exists to
pin is still compared byte-for-byte via plain dict equality. `sdkCommit`'s
own shape (a lowercase-hex string, or `None` when `git` genuinely isn't
available) is not re-checked in this test; that check already lives, and
now stays, in `test_emit_build_plan_carries_sdk_provenance` alone, so the
two tests don't carry two independent copies of the same assertion.

`test_emit_build_plan_deterministic`, a sibling in the same file that calls
`emit_build_plan()` twice back-to-back and compared the raw JSON strings for
byte-identity, was exposed to the same race. It is fixed more directly:
`_sdk_commit` is pinned to a constant for the duration of the test via
`monkeypatch`, so the original byte-for-byte string comparison — including
`sdkCommit`, and including the serialization details (key order, `indent=2`,
the trailing newline) an exclusion-based fix would stop covering — is kept
exactly as it was. No other whole-envelope comparison of `emit_build_plan()`
output was found elsewhere in `tests/scripts/`.
