### Fixed — the shipped CC3501E prebuilt answered a wire protocol the host refuses (#1733)

`cc3501e-bridge-firmware:prebuilt/` shipped `cc3501e-v0.3.0.bin`, built at wire
protocol **4**. The protocol moved to **5** in #1610/#1655 (`OTA_UPDATE_MODE`,
opcode `0x47`) but `firmware-version.txt` was never bumped, so the repo kept
shipping a blob that a host built from this tree rejects outright at
`GET_VERSION` — and two different builds both called themselves `0.3.0`. All
six AEN SoM presets pinned that blob as their `helper_firmware.cc3501e_otp`
payload.

- New prebuilt `cc3501e-v0.4.0.bin` (+ `.sig`, `.sha256`) at wire protocol 5,
  signed with the VALIDATION vendor key; `firmware-version.txt` is now `0.4.0`
  and the image reports `fw_version=0x0400`.
- `E1M-AEN{301,401,501,601,701,801}.yaml` repointed at the new blob.
- `cc3501e-bridge-firmware:README.md` leads with the prebuilt flashing recipe
  (verify signature → drop into the flash-set → `programmer -i XDS110`), with
  building from source as the fallback it should be. Building previously
  required TI ticlang 5.1.1 + SimpleLink Wi-Fi SDK 10.10.01.08 + SysConfig
  1.28.0 + Wi-Fi toolbox 4.2.4 just to obtain a working companion.
- `docs/cc3501e-bridge.md` gains the **GPE anti-rollback stamp** as a fourth
  version axis. It is not the SemVer, it is burned irreversibly into the part
  as a monotonic floor, and a stamp below that floor makes the programmer
  report success while the device keeps the old image.
- Documented that `ti/regen_flashset.sh`'s epoch-derived version is not a
  release scheme: its high byte wraps every ~194 days, so it is not monotonic
  over a part's life (run today it yields `0.144.51.196`, below the
  `0.149.63.0` floor already burned into the bench unit).
- Flagged an unresolved contradiction: `prebuilt/CHANGELOG.md` and
  `regen_flashset.sh` require GPE `major = 0`, while
  `ti/package_cc3501e_prod.ps1` and `ti/validate_gpio_bench.ps1` default to a
  `major = 1` stamp and comment that major must be `>= 1`. Releases use `major = 0`;
  the `>= 1` path is unverified and left untouched rather than guessed at.
