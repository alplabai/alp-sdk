### Fixed — populated the `quick` quality profile (#1463)

`metadata/quality-tasks-v1.json`'s `quick` profile had selected exactly zero
check-script tasks since it was introduced (`cd71de060`, PR #762) — the
tan-cli surface case that runs `tan quality --profile quick` (`tan-cli`
repo, `scripts/tan-surface/cases.sh` around line 326) has been passing
`rc=0` against an empty task set the entire time, silent since PR #1432 gave
that shape its own diagnosis ("NO TASKS SELECTED -- nothing was checked.
This is not a pass.") but never populated the profile itself.

Membership is measured, not guessed: every task in the 60-strong `pr` profile
was timed (median of 3 runs) and classified by whether it shells out
(`subprocess`, including a bare `git`) or needs a build/toolchain dependency.
`quick` = pure-Python, no subprocess of any kind, no toolchain, and a median
comfortably under half a second on the real tree — 36 of the 60 `pr` tasks
clear that bar. The other 24 either shell out (`git`, `alp_project.py`,
`west`) or walk large trees (`examples/**`, `docs/**`) slowly enough that
"quick" would be a lie. The bar itself is now written into the registry's own
root `description` so the next gate's author knows which profile it belongs
in without re-deriving this. No task was removed from `pr`/`full`/`release`,
and no gate was added or renamed.

`python3 scripts/alp_quality.py --profile quick` now runs 36/36 and exits 0
on a clean tree.
