### Fixed — populated the `quick` quality profile (#1463)

`metadata/quality-tasks-v1.json`'s `quick` profile had selected exactly zero
check-script tasks since it was introduced (`cd71de060`, PR #762) — the
tan-cli surface case that runs `tan quality --profile quick` (`tan-cli`
repo, `scripts/tan-surface/cases.sh` around line 326) has been passing
`rc=0` against an empty task set the entire time, silent since PR #1432 gave
that shape its own diagnosis ("NO TASKS SELECTED -- nothing was checked.
This is not a pass.") but never populated the profile itself.

Membership is measured, not guessed: every task in the 60-strong `pr` profile
was timed (median of 3 runs) and classified by whether it shells out
(`subprocess`, including a bare `git`) or needs a build/toolchain dependency.
`quick` = pure-Python, no subprocess of any kind, no toolchain, and a median
under half a second on the real tree — 36 of the 60 `pr` tasks clear that
bar. The other 24 either shell out (`git`, `alp_project.py`, `west`) or
exceed the 0.5 s bar. The bar itself is now written into the registry's own
root `description` so the next gate's author knows which profile it belongs
in without re-deriving this. No task was removed from `pr`/`full`/`release`,
and no gate was added or renamed.

`python3 scripts/alp_quality.py --profile quick` now runs 36/36 and exits 0
on a clean tree.

### Fixed — enforced the `quick` profile's own membership bar (#1463 round 2)

The criterion above was written into `metadata/quality-tasks-v1.json:3` as
prose only — nothing checked it, so `quick` could be silently re-emptied,
or stuffed with a slow/shelling task, and every gate and test would still
pass. `scripts/check_quality_registry.py` now asserts `quick` is non-empty,
`quick ⊆ pr`, and no `quick` member's script executes `import subprocess`
at module load time (a top-level import only — a lazy in-function import
some other, non-`quick` task uses does not count). The subprocess/toolchain
exclusion is a hermeticity rule (must run clean in a dirty tree or a bare
checkout with no `git`/`west` on `PATH`), not a speed proxy — three of the
gates it excludes (`doxygen-output-untracked` 0.041 s,
`emit-kconfig-contract` 0.044 s, `changelog-citations` 0.051 s) are the
fastest in the whole registry, faster than every `quick` member. The root
`description`'s "walks the whole example/doc tree" exclusion clause was
also removed — it was false: `scripts/check_doc_drift.py` and
`scripts/check_example_sdk_root.py` both `rglob()` their whole tree and are
`quick` members; the timing rule already covers what that clause was
trying to say.
