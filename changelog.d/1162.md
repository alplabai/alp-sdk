### Documented — the GD32 bridge HiL soak's quarantine notes still described six rows as skipped, but every row runs active (#1162)

`examples/v2n/v2n-gd32-bridge-hil-soak/src/main.c`'s `tests[]` table has had
every row at `quarantined = false` since the fixes landed, but the comment
block above it and the README's "Quarantine list" section still read as if
`pwm_capture`, `adc_stream`, `qenc`, `tmu`, `ota_get_state` and `trng` were
presently skipped — `adc_stream` most dangerously, since its comment still
described an actively destructive DMA-contention failure mode as "still
quarantined" when the code runs it every cycle.

Both are rewritten to describe what actually happened. Five of the six rows
(`pwm_capture`, `qenc`, `tmu`, `ota_get_state`, `trng`) were never broken HAL
bodies: the `transport_spi.c` slave-cursor rewind bug plus the host masking
every error reply's true status behind `ALP_ERR_IO` made their failures
indistinguishable from real defects, fixed in `2e30b9d09`. `trng` also had a
real hardware fault-latch condition underneath (`TRNG_STAT = 0x48`), now
handled. `adc_stream` was a genuinely separate, genuinely destructive firmware
defect — circular DMA without `CTL1.DDM` plus an unenabled `RCU_DMAMUX`
clock — fixed in `ffdc66ee5`, not merely a transport artefact like the other
five. Both fixes landed 2026-06-04 and were validated 253/253 across a 20-row
soak by 2026-06-06 (`docs/test-plan.md`).

The README's per-test table had drifted the same way, on rows the fixes
above never touched: `adc_stream`'s row still described the pre-fix `>0
samples` DMAMUX regression check instead of the current two-read paced
assertion; `dac`'s row still said `1650 mV` when the setpoint moved to
`600 mV` in `824403359` (jumper-safe under the X-EVK Tier-B bench's ADC0
jumper); `qenc`'s row said the read "reads exactly 0" when the code stopped
asserting a position value once the floating-encoder drift was understood
(round-trip only, value ignored); and `adc_stream_guard` — the fw v0.2.8
converter-ownership guard added in `d1879bcfe` — had no row at all. The
"Reading the output" section's sample log line also still said `19/19 PASS`
for a 20-row table. All four are corrected; the other sixteen rows were
checked against their `t_*` functions and are accurate as written.

No `quarantined` flag or test logic changed — this is a documentation-accuracy
fix only.
