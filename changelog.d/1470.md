### Added — per-NPU op-support metadata asset (ADR-0028)

`metadata/npu_ops/{ethos_u,drpai,deepx_dxm1}.json` publish, per backend, the
TFLite builtin op identifiers (`CONV_2D`, `DEPTHWISE_CONV_2D`,
`FULLY_CONNECTED`, ...) that backend's compiler is known to accept, validated
against the new `metadata/schemas/npu-ops-v1.schema.json`. These are
conservative seed lists (`"version": "2026.07-seed"`), deliberately
under-populated rather than over-populated: an op absent from the list costs a
pessimistic CPU-fallback verdict, while an op wrongly present costs a false
"fits" that would only surface as a customer's failed compile. `cpu` has no
file -- it is the universal fallback and is never looked up.

`scripts/validate_metadata.py` now schema-checks every
`metadata/npu_ops/*.json` alongside the existing per-directory metadata
checks. Nothing consumes this data yet; it lands standalone ahead of the
`tan.model.analyze` static-fit estimator that will read it.
