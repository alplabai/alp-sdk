### Added — per-NPU op-support metadata asset (ADR-0028)

`metadata/npu_ops/{ethos_u,drpai,deepx_dxm1}.json` publish, per backend, a
conservative documented-subset seed of the operator identifiers that
backend's compiler is known to *document* support for -- not a known-accept
set; refine from bench probing. Each file declares an `op_namespace`
(`tflite` or `onnx`) naming the vocabulary its `supported_ops` are spelled
in, since each backend's compiler ingests exactly one source format and they
do not agree: `ethos_u` is TFLite builtins (`CONV_2D`, `DEPTHWISE_CONV_2D`,
`FULLY_CONNECTED`, ...), while `drpai` and `deepx_dxm1` are ONNX operators
(`Conv`, `Gemm`, `AveragePool`, ...) because DRP-AI TVM and dxcom are both
ONNX frontends. Validated against the new
`metadata/schemas/npu-ops-v1.schema.json`. These are conservative seed lists
(`"version": "2026.08-seed"`), deliberately under-populated rather than
over-populated: an op absent from the list costs a pessimistic CPU-fallback
verdict, while an op wrongly present costs a false "fits" that would only
surface as a customer's failed compile. `cpu` has no file -- it is the
universal fallback and is never looked up.

`scripts/validate_metadata.py` now schema-checks every
`metadata/npu_ops/*.json` alongside the existing per-directory metadata
checks, plus two semantic cross-checks the schema can't express: `backend:`
must match the manifest filename, and `op_namespace:` must match the
backend's compiler ingest format. Nothing consumes this data yet; it lands
standalone ahead of the `tan.model.analyze` static-fit estimator that will
read it.
