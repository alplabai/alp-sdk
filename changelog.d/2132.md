### Fixed — `alp_audio_out_start()` / `alp_i2s_start()` before the first write failed on the Alif DesignWare I2S driver (#2132)

`alp_audio_out_start()` called before the first `alp_audio_out_write()` — the
open, set_volume, start, then stream order every in-tree caller uses
(`examples/aen/aen-evk-demo/src/main.c`, `examples/aen/aen-i2s-tas2563-probe`,
`examples/audio/audio-loopback`, `examples/audio/audio-noise-suppression`) —
failed `ALP_ERR_NOMEM` (`-7`) on the Alif DesignWare I2S driver
(`snps,designware-i2s`). Traced to `zephyr/drivers/i2s/i2s_dw.c`'s
`tx_stream_start()` dequeuing a block from its TX ring buffer at
`I2S_TRIGGER_START` time and returning `-ENOMEM` when the buffer is empty
(`zephyr/drivers/i2s/i2s_dw.c:144-147` ("Ring buffer is empty")) — the `-7`
there does not mean out of memory, it means "START with nothing queued".
`examples/audio/i2s-tone` calls `alp_i2s_start()` the same way and hits the
same trap on the same silicon; its "TX starts fronting underrun silence"
comment was wrong for this driver and is corrected alongside the fix.
**Proven on silicon** (`e1m-aen-evk-03`): `alp_audio_out_open+set_volume(4)
+start(I2S3)` now returns `0` (was `-7`), the priming writes succeed, and
both TAS2563 amps go ACTIVE.

Fixed once at the lowest shared layer both `<alp/i2s.h>` and `<alp/audio.h>`
route through — `src/backends/i2s/zephyr_drv.c`, not the audio backend above
it. `z_start()` defers the real `I2S_TRIGGER_START` when the TX side has
nothing queued yet, instead returning `ALP_OK` with a `tx_pending_start` flag
set (`src/backends/i2s/zephyr_drv.c:328`
("if (h->cfg.direction == ALP_I2S_DIR_TX && !s->tx_block_queued)")).
`z_write()` retries the real trigger every time a block is queued while
still pending. Write-then-start — a block already queued when
`alp_i2s_start()` is called — still triggers immediately via `z_start()`'s
own trigger call, unchanged.

Stopping a stream that never really started (`tx_started` false, whether
because `start()` was deferred and never fired, or never called at all)
no longer forwards to `I2S_TRIGGER_DRAIN`: `i2s_dw.c`'s `STOP`/`DRAIN` refuse
a trigger on a stream that never reached `I2S_STATE_RUNNING`
(`zephyr/drivers/i2s/i2s_dw.c:301-304` ("STOP trigger: invalid state"),
`zephyr/drivers/i2s/i2s_dw.c:315-321` ("DRAIN trigger: invalid state")), even
though real blocks may still be sitting in the TX ring holding slab memory.
`z_stop()` now issues `I2S_TRIGGER_DROP` instead, which works from `READY`
too and releases everything queued
(`src/backends/i2s/zephyr_drv.c:352`
("if (h->cfg.direction == ALP_I2S_DIR_TX && !s->tx_started)")).

A second, related defect in the same area: `z_close()` only issued
`I2S_TRIGGER_DROP` when the dispatcher's `h->started` was true, so a TX
handle that only ever queued blocks (write before start, or a start whose
retry never fired) left real slab-block pointers in the driver's TX ring /
in-flight `mem_block` when its slab was `k_free()`'d. The next `open()` on
that device would dequeue a pointer into freed memory, and the completion
path would free it into the NEW handle's slab — memory corruption, not just
a leak. `z_close()` now DROPs unconditionally for TX; RX stays gated on
`h->started` exactly as before, byte-identical to `i2s_dw`'s own
`rx_stream_disable()`, which only ever ran when RX had actually been
triggered (`src/backends/i2s/zephyr_drv.c:481`
("if (dev != NULL && (h->cfg.direction == ALP_I2S_DIR_TX || h->started))")).

**Two defects found in a second review round, after the first fix landed
and was re-reviewed against reusable probe apps:**

- **A write could report frames as pushed that were never actually
  queued.** A failed START retry inside `z_write()` used to return the
  failure without releasing the block it had just queued, so the audio
  layer's chunked write loop (and a caller reading `out_frames`) could not
  tell "nothing was queued" apart from "queued, but the deferred start
  still failed" — both came back `ALP_ERR_IO`. Reproduced: write, write
  (fills the 2-block slab, stream never started), write with a short
  timeout returns `ALP_ERR_TIMEOUT` with `out_frames` still reporting 32
  frames pushed — audio that was never queued. Fixed: a failed retry now
  issues `I2S_TRIGGER_DROP` on the block it just queued before returning
  the error — while a start is pending the ring holds only that one block,
  so DROP releases exactly it, never a sibling write's
  (`src/backends/i2s/zephyr_drv.c:426`
  ("(void)i2s_trigger(dev, _to_dir(h->cfg.direction), I2S_TRIGGER_DROP);")).
  An I2S write that returns an error now NEVER leaves a block queued, so
  the audio backend's chunked loop again counts a chunk toward
  `out_frames` ONLY on `ALP_OK`, restoring `out_frames`'s original "frames
  actually pushed" meaning (`include/alp/audio.h`, `include/alp/i2s.h`).
  This also makes `alp_i2s_write()`'s doc claim "every subsequent write
  retries the trigger until it succeeds" literally true: the slab can no
  longer fill up with un-started blocks under sustained START failures.

- **A successful START didn't always clear the pending flag.** Sequence:
  start (deferred) → write (START retry fails, block dropped by the fix
  above) → start (explicit retry; nothing is queued yet post-fix, so this
  defers again rather than triggering) → write (fires the real trigger).
  Before this fix, `z_start()`'s immediate-trigger success path set
  `tx_started` without clearing `tx_pending_start`, so if that path were
  ever reached with `tx_pending_start` still true (e.g. before the DROP
  fix above closed off the specific sequence that exposed it, or via any
  future code path that queues a block without going through the retry
  logic), the next write would retry a START on an ALREADY-RUNNING stream
  and get `i2s_dw`'s `-EIO` — every later write into a stream that is
  actually playing would then fail. Fixed by construction, not by patching
  one call site: `_mark_tx_started()` clears `tx_pending_start` in the
  same assignment as setting `tx_started`, and is now the ONLY place
  either can be set true; `_mark_tx_stopped()` is the ONLY place a TX
  stream returns to idle, clearing all three flags together
  (`src/backends/i2s/zephyr_drv.c:302`, `:312`). The invariant
  `tx_started ⇒ !tx_pending_start` now holds regardless of which path
  reaches it.

**Concurrency (also from the second review round):** the first fix's docs
added a "calls on one handle must not run concurrently" restriction to the
`[ABI-STABLE]` `<alp/i2s.h>`/`<alp/audio.h>` headers — narrowing an
ABI-stable contract instead of protecting the new state. The dispatcher
deliberately only counts in-flight ops (`src/i2s_dispatch.c`), it does not
serialize them, so a genuine cross-thread race existed: thread A's write()
queuing a block while thread B's stop() concurrently DROPs it could leave
A's later flag-set stamping a stale "queued" over an empty ring — the
`#2132` symptom returning via a race. Fixed with a `k_spinlock` in the
sidecar guarding the three `tx_*` flags and the `i2s_trigger()` calls that
change them — never held across `k_mem_slab_alloc()` or the Zephyr
`i2s_write()` API call, both of which can block
(`src/backends/i2s/zephyr_drv.c:169`). The doc restriction is removed; a
narrow residual race remains between `i2s_write()` returning and the lock
being acquired to record it, documented at the lock's own declaration as a
known ceiling (closing it fully needs the queue-and-flag-update to be one
atomic operation, not available from the Zephyr I2S driver API today).

The RX side does not carry the empty-queue trap: `i2s_dw.c`'s
`rx_stream_start()` allocates a fresh block from its own `k_mem_slab`
instead of dequeuing from a caller-filled ring buffer, so RX `start()` is
never deferred. The Yocto/ALSA and sw_fallback audio-out backends already
returned `ALP_OK` for a start before any write (ALSA's `snd_pcm_prepare()`
needs no queued data either); this fix makes the Zephyr/I2S backend
observably match them instead of diverging by backend.

One related, smaller behaviour change falls out of routing everything
through `tx_started`/`tx_pending_start` rather than the dispatcher's
`h->started`: `alp_i2s_stop()`/`alp_audio_out_stop()` on a handle that was
opened but never started or written to now returns `ALP_OK` (a harmless
`DROP` no-op) instead of the pre-existing `-EIO` a bare `DRAIN` used to
surface in that case.

Regression tests: `tests/unit/i2s_start_defer/` proves the deferred-start
state machine directly against `<alp/i2s.h>` with a fake I2S device that —
unlike `tests/unit/i2s_write_bounds`'s always-succeeds fake — models the
DesignWare driver's empty-queue `TRIGGER_START` refusal, its `-EIO` on an
already-running `START` and a not-running `STOP`/`DRAIN`, and `DROP`'s
unconditional release of every queued block back to the real `k_mem_slab`
captured at `configure()` time; covers start-then-write, write-then-start
(now also pinning that a follow-up write doesn't spuriously retry),
stop-with-no-write, the stranded-blocks repro, a running-stream
stop/restart cycle, close-then-reopen with no stale block, a forced START
failure retrying across 5 consecutive writes (past the 2-block slab depth,
proving the slab can no longer exhaust), fault-clear recovery, and the
explicit-restart-after-failed-retry sequence. The fake's forced-failure
knob (`fake_i2s_force_start_fail()`) pins this backend's own retry/DROP
bookkeeping under an injected fault — it does not claim that exact
sequence is reachable on real `i2s_dw`, which only fails `START` on an
empty ring or an already-running stream; see `fake_i2s.c`'s own header
comment. `tests/unit/audio_out_start_defer/` proves the `<alp/audio.h>`
composition on top, including the volume-scaled chunked write loop
(stereo, more than 128 frames per block, `set_volume(4)` — the exact shape
the silicon repro used) and that a failed deferred-start retry does NOT
count toward `out_frames`.
