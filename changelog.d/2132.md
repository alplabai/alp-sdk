### Fixed — `alp_audio_out_start()` before the first write failed `ALP_ERR_NOMEM` on the Alif DesignWare I2S driver (#2132)

`alp_audio_out_start()` called before the first `alp_audio_out_write()` — the
open, set_volume, start, then stream order every in-tree caller uses
(`examples/aen/aen-evk-demo/src/main.c`, `examples/aen/aen-i2s-tas2563-probe`,
`examples/audio/audio-loopback`, `examples/audio/audio-noise-suppression`) —
failed `ALP_ERR_NOMEM` (`-7`) on the Alif DesignWare I2S driver
(`snps,designware-i2s`). Traced to `zephyr/drivers/i2s/i2s_dw.c`'s
`tx_stream_start()` dequeuing a block from its TX ring buffer at
`I2S_TRIGGER_START` time and returning `-ENOMEM` when the buffer is empty
(`zephyr/drivers/i2s/i2s_dw.c:144-147` ("Ring buffer is empty")) — the `-7`
there does not mean out of memory, it means "START with nothing queued".

Fixed once in the shared backend every caller routes through
(`src/backends/audio/zephyr_drv.c`), not by reordering callers.
`z_out_start()` now defers the real `alp_i2s_start()` trigger when nothing
has been queued yet, instead returning `ALP_OK` with a `pending_start` flag
set (`src/backends/audio/zephyr_drv.c:476` ("if (!be->block_queued)")).
`z_out_write()` fires that deferred start the moment it actually queues a
block, and a trigger failure discovered there surfaces from that same write
call, not from `start()` (`src/backends/audio/zephyr_drv.c:601`
("be->block_queued = true;")). Write-then-start — a block already queued
when `alp_audio_out_start()` is called — still triggers immediately,
unchanged. Stopping a pending-but-never-written stream no longer forwards to
`alp_i2s_stop()`: `i2s_dw.c`'s `STOP`/`DRAIN` refuse a trigger on a stream
that never reached `I2S_STATE_RUNNING`
(`zephyr/drivers/i2s/i2s_dw.c:301-304` ("STOP trigger: invalid state"),
`zephyr/drivers/i2s/i2s_dw.c:315-321` ("DRAIN trigger: invalid state")), so
`z_out_stop()` now just clears the pending flag and returns `ALP_OK`
(`src/backends/audio/zephyr_drv.c:499`
("if (be->pending_start || !be->started)")).

The RX side does not carry the same trap: `i2s_dw.c`'s `rx_stream_start()`
allocates a fresh block from its own `k_mem_slab` instead of dequeuing from
a caller-filled ring buffer, so `alp_audio_in_start()` is unchanged. The
Yocto/ALSA and sw_fallback audio-out backends already returned `ALP_OK` for
a start before any write (ALSA's `snd_pcm_prepare()` needs no queued data
either); this fix makes the Zephyr/I2S backend observably match them
instead of diverging by backend. `alp_audio_out_start()`'s doc comment
(`include/alp/audio.h`) now says the real hardware start can be deferred to
the first write.

Regression test: `tests/unit/audio_out_start_defer/` adds a fake I2S device
that — unlike `tests/unit/i2s_write_bounds`'s always-succeeds fake — models
the DesignWare driver's empty-queue `TRIGGER_START` refusal and its refusal
to `STOP`/`DRAIN` a non-running stream, and covers start-then-write,
write-then-start, start-then-stop-with-no-write, and a start failure
surfacing from the first write.
