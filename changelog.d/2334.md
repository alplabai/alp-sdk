### Fixed — IMX335 full-resolution mode's `Y_OUT_SIZE` overrun, not yet bench-verified (#2334)

Upstream Zephyr's `drivers/video/imx335.c` all-pixel mode table
`imx335_bin_none` wrote `Y_OUT_SIZE` (`0x3056`) = `0x07ac` (1964 lines) for
a 2592x1944 format -- the same overrun class `zephyr/patches/zephyr/
0004-imx335-2lane-link-freq-and-binning.patch` already fixed for the
2x2-binned path (#2327). Both this driver's own `imx335_init_params`
(`Y_OUT_SIZE` `0x0798` = 1944) and the mainline Linux imx335 driver's
full-resolution mode table (`raspberrypi/linux`, branch `rpi-6.12.y` --
register value carried as a hardware fact, no GPL code copied) agree on
1944; `imx335_bin_none` is corrected to match. Patch 0004 extended
(sha256 updated in `zephyr/patches.yml`), applies clean against a pristine
Zephyr v4.4.1 checkout.

No corresponding `HNUM`/`WINMODE` change was needed: unlike `imx335_bin_2x2`
(which set an explicit, bench-derived `HNUM` this driver had no formula
for), `imx335_bin_none`'s `HNUM` (restored to `0x0a20` = 2592 by #2327's own
fix) already matches both `imx335_init_params` and the Linux full-resolution
table, and its `AREA2_WIDTH_1`/`AREA3_WIDTH_1` pair (40 / 3928) already
matches the Linux table too -- there is no known analogous width defect at
full resolution, only the line-count one.

**Not yet bench-verified.** A 2592x1944 RAW10 frame (~6.3 MB) does not fit
the 4 MiB SRAM0 budget every IMX335 example currently captures into, so
this fix cannot be proven against a captured full-resolution frame with the
current examples. A scratch-only diagnostic recipe (outside this repo, not
built by any CI job here) counts CPI HSYNC edges between VSYNC edges to
measure the exact transmitted line count without writing frame data to
memory -- see `docs/camera-shields.md`'s "Full-resolution mode: why it
can't be captured, and how to verify it without capturing it" section for
the plan and its safety argument. Until that diagnostic runs on real
silicon, treat this as a register-table correction verified against two
independent reference tables, not a bench result.

`metadata/chips/imx335.yaml` gains a note recording the same
not-yet-bench-verified status.
