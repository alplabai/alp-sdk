### Fixed — E1M-X EVK USB 3.0 Type-A host port VBUS was never enabled (#2611)

The carrier VBUS switch for the USB 3.0 host port is enabled by E1M-X pad AQ10 (`I2S1_SDO`) = RZ/V2N P15, which no DT node claimed, so the port was unpowered and nothing enumerated. `reg_usb30_vbus` in `meta-alp-sdk/recipes-kernel/linux/linux-renesas/e1m-x-evk.dtsi` (`regulator-name = "usb30-vbus";`) now drives P15 high at boot. The 6.1 usb3 PHY and rzv2h xHCI drivers consume no vbus supply, so it is `regulator-always-on` + `regulator-boot-on`. Bench-proven on E1M-V2M103 (2026-10-01): a USB stick enumerates on xhci and a 16 MB read/write passes. The USB 2.0 VBUS enable (P13) is untouched.
