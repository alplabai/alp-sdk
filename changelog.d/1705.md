### Fixed — `i2c-master`'s README pointed at a sibling example as bare prose a scaffold cannot resolve (#1705)

`examples/peripheral-io/i2c-master/README.md`'s troubleshooting bullet named
`examples/peripheral-io/i2c-scanner` as a bare inline code span rather than a
markdown link. tan-cli's scaffold vendoring runs `--emit scaffold` through a
doc-link rewriter that only rewrites markdown link syntax (`](...)`) and is
documented as intentionally not normalising bare prose cross-references, so once
vendored into a customer project -- which carries neither `scripts/` nor the
sibling example -- that bullet became a dead pointer with no path the reader could
follow.

Now a real relative link, matching the two links to the same referent this README
already carried at its top and in its "see also" list. `scaffold.sensor-v2n101.snap`
embeds this README and is regenerated: exactly one line changes, and every changed
character is the link syntax itself.

This completes #1705. Its first half (`examples/bringup/board-selftest/README.md`'s
`scripts/program_eeprom.py` reference) landed earlier; this half was deliberately
deferred because #1269 was concurrently regenerating the same golden, and fixing
both at once would have collided on that fixture.
