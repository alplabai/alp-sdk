### Fixed — `board-selftest`'s README pointed at `scripts/program_eeprom.py` as bare prose a scaffold can't resolve (#1705)

`examples/bringup/board-selftest/README.md`'s `ALP_ERR_NOT_PROVISIONED`
troubleshooting bullet named `scripts/program_eeprom.py` as a bare inline code
span rather than a markdown link. tan-cli's scaffold vendoring runs
`--emit scaffold` through a doc-link rewriter that only rewrites markdown link
syntax (`](...)`) and is documented as intentionally not normalising bare prose
cross-references -- so once vendored into a customer project, which carries no
`scripts/` directory, that bullet became a dead pointer with no path or link the
customer could follow. Same defect class as #1688.

Now a real relative link, matching the shape this same README already uses for
`docs/portability.md` and the three `include/alp/*.h` references. Note the depth:
the README lives at `examples/bringup/board-selftest/`, so repo root is
`../../../`, not the `../../` the issue text suggested -- that would have
resolved to a nonexistent `examples/scripts/program_eeprom.py`. The link target
was resolved and confirmed to exist.
