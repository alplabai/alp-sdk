### Fixed — `uhc_xhci_alif` implements the full UHC API instead of a skeleton (#388)

The driver self-identified as a "SKELETON" with 16 `TODO(aen401-bench)`
markers, and `examples/peripheral-io/usb-host-storage/README.md` called it a
"compile-only skeleton" — accurate at the time, but issue #388's later triage
comments found register bring-up (`first_light`), command/event-ring
processing, and single-device root-hub enumeration had since landed; only
the transfer path, bus ops, and the event-ring IRQ were still unwritten.

`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1360` (`uhc_xhci_alif_ep_enqueue`) and
`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1420` (`uhc_xhci_alif_ep_dequeue`) now
build real TRBs on a per-endpoint ring (control over the existing EP0 ring;
bulk/interrupt on a small pool configured via a Configure Endpoint Command,
`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1011` ("static struct xhci_ring *uhc_xhci_alif_ep_ctx_get(struct uhc_xhci_alif_data *data,")) and wait for completion with the same bounded-
polling pattern `uhc_xhci_alif_enumerate()` already used. `SET_ADDRESS` on
EP0 is short-circuited to success rather than re-sent on the wire, since
Address Device already assigned it in `*_enable()`.

`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1233` (`uhc_xhci_alif_disable`) and
`:1255` (`uhc_xhci_alif_shutdown`) now really stop the controller (clear
USBCMD.R/S, poll HCH, gate the PHY/clock); `:1268`
(`uhc_xhci_alif_bus_reset`) plus new `bus_suspend`/`bus_resume` drive real
PORTSC sequences per the xHCI spec.

`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1505` ("IRQ_CONNECT(DT_INST_IRQN(n), DT_INST_IRQ(n, priority),") wires a real `IRQ_CONNECT` (IRQ 101);
`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:1185`
(`uhc_xhci_alif_isr`) drains the event ring for hotplug (connect/disconnect)
notification once `*_enable()` arms `IMAN.IE`. Every synchronous poll
(`uhc_xhci_alif_wait_event`,
`zephyr/drivers/usb/uhc/uhc_xhci_alif.c:665` ("Brackets the poll with irq_disable(irqn)/irq_enable(irqn): the same")) brackets itself with
`irq_disable`/`irq_enable` on the controller's IRQ so it can never race the
ISR over the shared event-ring consumer state on this single-core M55.

Added `xhci_alif_flush`/`xhci_alif_invd` (cache maintenance around every
CPU/xHC DMA handoff — rings, contexts, transfer buffers), since the
controller is an AXI-master DMA engine that bypasses the M55 D-cache.

**Unverified on silicon** (stated plainly, not bench-run): `ep_enqueue`/
`ep_dequeue`, bus suspend/resume, disable/shutdown, the event-ring ISR and
its `irq_disable`/`irq_enable` race argument, and whether the cache-
maintenance calls are the right ones for this target's D-cache
configuration. Only `first_light` + the `enable()`/`enumerate()` bring-up
path (unchanged here) was proven on an E8 EVK. End-to-end enumeration of a
real device on the EVK also needs the D+/D- signal-path fix issue #388's
triage comments describe — a separate, hardware blocker.

`examples/peripheral-io/usb-host-storage/README.md`,
`examples/peripheral-io/usb-host-storage/board.yaml`, and
`zephyr/drivers/usb/uhc/Kconfig.xhci_alif` are corrected to describe the
above instead of "compile-only skeleton" / "TODO(aen401-bench)" throughout.
