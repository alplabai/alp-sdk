### Fixed — `sw_fallback` audio backend accepted and discarded any volume, and its #1648 regression test never called the entry point it guards (#2002)

`c19c3bc75` (#1790) closed #1648 tier 1 on the Yocto and Zephyr audio-out
backends: `alp_audio_out_set_volume()` now returns `ALP_ERR_NOSUPPORT`
instead of accepting a volume it can never apply. The fix did not reach
the third backend. `src/backends/audio/sw_fallback.c:161`
(`sw_out_set_volume`) discarded both arguments and returned `ALP_OK`
unconditionally — the exact accept-and-discard shape #1648 exists to
close. `sw_fallback` is a null sink (`out_write` discards every frame),
so unlike the Yocto/Zephyr siblings — which can scale `S16_LE` and only
refuse `S24_LE`/`S32_LE` — it can scale **no** format, so `include/alp/
audio.h:230-237`'s contract was false for every format on this backend,
not just 24/32-bit.

`sw_out_set_volume` now returns `ALP_OK` only for `vol == 255` (full
scale, a no-op on every format) and `ALP_ERR_NOSUPPORT` otherwise,
regardless of the open format.

Second, separate defect: `tests/unit/audio_volume_guard/src/
test_audio_volume_guard.c` was the only shipped regression test for
#1648, and it exercised `alp_audio_volume_settable()` — the extracted
guard predicate shared by the Yocto/Zephyr backends — but never any
backend's actual `out_set_volume`. Counted on `origin/dev`: 14 calls to
the guard, 0 to `alp_audio_out_set_volume()` or any backend's real op.
That circularity survives a backend forgetting to call the guard, a
backend passing the wrong format into it, the dispatcher discarding the
backend's return code, or (after this fix) `sw_out_set_volume`
regressing back to unconditional `ALP_OK` — each reintroduces #1648
exactly, and the old test would stay green through all of them.

The dispatcher's `alp_audio_out_open()` selects exactly one backend via
`alp_backend_select()` with no fallback, and `zephyr_drv` registers
unconditionally at priority 100 for the `"*"` wildcard
(`zephyr/CMakeLists.txt`) — so it always wins arbitration ahead of
`sw_fallback` (priority 0), and its own `out_open()` needs a real I2S
device or refuses outright. No live `alp_audio_out_t` handle backed by
`sw_fallback` is reachable through the public API on `native_sim`. The
test now fetches `sw_fallback`'s registered `out_set_volume` directly
from the backend registry (`alp_backend_select()` +
`alp_backend_select_next()`, the same pattern `tests/unit/
audio_registry` already uses) and calls that real function pointer —
the exact one `alp_audio_out_set_volume()` dispatches to — for
`S16_LE`/`S24_LE`/`S32_LE` at both refused and full-scale volumes,
asserting both the return code and that a refused call does not record
the requested volume.

Mutation-killed: reverting only `sw_out_set_volume`'s body to the old
`(void)state; (void)vol; return ALP_OK;` in an isolated copy of the tree
turns `test_sw_fallback_real_out_set_volume_refuses_non_unity_every_
format` red —
`Assertion failed ... test_audio_volume_guard.c:151: (rc not equal to
ALP_ERR_NOSUPPORT) format 0 vol 0: sw_fallback can scale nothing,
expected ALP_ERR_NOSUPPORT, got 0` — while the original guard-only tests
stay green, confirming they alone would have missed the regression.

Refs #1648.
