### Fixed — 41 dispatcher call sites trusted every backend to populate the full ops vtable, with no dispatcher-side guard (Closes #1641)

15 of the 33 `src/*_dispatch.c` class dispatchers called an op-table function
pointer (`h->state.ops->read`, `->write`, `->start`, ...) with only `open`/
`close` checked `!= NULL` at backend registration — every other slot was
trusted to be populated. This is **not a live crash fix**: every
currently-registered backend (`testing_drv.c`, `zephyr_drv.c`, and friends)
populates every non-`close` op for these classes, so no reachable NULL-deref
existed in-tree before this change. It closes a **contract gap** in the
dispatcher/backend ABI — the first partial vendor port that leaves one op
slot unset would have hit it.

`adc_dispatch.c`, `camera_dispatch.c`, `counter_dispatch.c`, `dac_dispatch.c`,
`display_dispatch.c`, `gpu2d_dispatch.c`, `i2c_dispatch.c`, `i3c_dispatch.c`,
`jpeg_dispatch.c`, `power_dispatch.c`, `qenc_dispatch.c`, `rtc_dispatch.c`,
`spi_dispatch.c`, `uart_dispatch.c` and `wdt_dispatch.c` now guard all 41
sites the same way `storage_dispatch.c` already did: `ops->foo == NULL` ->
`ALP_ERR_NOSUPPORT`, exactly one `alp_handle_op_leave()` per exit path.
`<alp/adc.h>`, `<alp/counter.h>`, `<alp/dac.h>`, `<alp/rtc.h>` and
`<alp/wdt.h>` gained `ALP_ERR_NOSUPPORT` on the `@return` lists of the
functions where it is now a reachable outcome (the other ten headers already
documented it).

`tests/zephyr/conformance/src/main.c` adds a guard-mutation proof: it opens a
real UART handle, points it at a local copy of its own backend's ops table
with `write` NULLed, and asserts `alp_uart_write()` returns
`ALP_ERR_NOSUPPORT`. Reverting the guard under test turns this from a clean
`zassert` failure into a SIGSEGV (`rc=-11`) that blocks the two ZTESTs after
it — proof the guard is load-bearing, not decorative.
